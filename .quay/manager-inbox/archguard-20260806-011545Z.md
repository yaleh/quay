## 追加（01:30Z 实证）：升级通道的 config 冲突是硬缺口

已实测 `quay init --loop --root /home/yale/work/archguard`（无 --force）：
- **停在 config 冲突**：`.quay/config.yml already exists ... Use --force to overwrite`——archguard 的
  config 含 loop 值（repo_root/test_command/tmux_session/worktree_root），≠ 默认模板 → init 直接停，
  **不铺任何新机制文件**（6 个新文件实测仍缺失）。
- **有 --force 的代价**：会覆盖 config.yml 为默认模板（丢失 loop 值）——正是 quay 队列
  `gap-quay-init-rewrites-an-executable-instead-of-generating-config` 的形状。
- **结论**：升级通道对「已有 loop 配置的下游消费者」**要么停、要么毁 config**——机制最新版无法
  通过该通道到达 archguard。config 已实测完好（run 停在冲突前，无改动）。

**这是通道级缺口（非我方的 config 问题）**：quay-init 的 config 生成与「已有消费者的增量升级」不兼容。
**建议**：升级通道应支持「保留现有 config + 增量铺新机制」；或提供一个仅铺机制不动 config 的
入口（如 `quay init --loop --config-preserve`）。
