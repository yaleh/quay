# archguard 外层报告 #12 — 新机制静态判据分析（第 3 问：判据会错吗）

**时间**: 2026-08-06
**回应**: 你问「还有没有可自主验证的工作」——有：8 个新机制无法经升级通道安装（config 冲突），
但机制在 quay 侧可读，我做**静态判据分析**（第 3 问：判据在此生态位会不会给错答案）。

## 判据×archguard 生态位矩阵

| 机制 | 判据 | 兼容性 / 盲区 |
|---|---|---|
| dead-loop-check（L2） | N 分钟内 transcript user 消息或 git 提交 | **兼容**。archguard transcript 结构（tool_result 以 user 写回）兼容；对我当前停止态判 dead 是准确的（非误报） |
| claim-task（两机认领） | 共享裸仓分支推送原子认领 | **不适用**——archguard 单机无共享裸仓，照搬会因缺基础设施误判（适用性盲区） |
| slot-refill（槽位回填） | 槽空闲 + 可派发候选 | **阈值不匹配风险**——archguard 并发 cap 3 ≠ quay 的；我落地的治本 AC（check-adr/lint gate）改变派发资格形状，slot 判据可能误判 |
| verify-delivery-surface（L1 六类） | 六类交付面覆盖 N/6 | **需安装后验**——archguard 交付结构（tasks/单库 vs quay）可能不同，报 <6 虽完整（假阴性风险） |
| self-report-vocab-audit | 内层自报措辞 vs 工厂语义 | **词汇版本风险**——新工厂语义 vs archguard 部署的旧文档版本（0.3.13），自报用旧词汇会被误判不收敛 |
| laydown-set-check | 派生铺设集全绿 | **兼容**（框架无关，铺什么验什么） |
| 多源心跳 | transcript + 多源 | **兼容**（archguard 内层已用 transcript 心跳） |
| taskWorkLanded 第三信号 | AC checkbox 计数（`countAcCheckboxes`） | **收尾时序盲区**——archguard 的 AC 由内层勾、DoD 由外层翻；checkbox 信号可能把「内层已勾 AC、外层未翻 done 的 not-yet-flipped 任务」误判为已关闭（超报） |

## 结论（第 3 问）

4 个机制在 archguard 生态位**有具体盲区**：claim-task（不适用）、slot-refill（阈值）、
self-report-vocab（词汇版本）、taskWorkLanded 第三信号（收尾时序）。这 4 个若照搬进 archguard，
判据会给错答案——**这正是「子代照亮亲代」要的**：quay 侧判据在 quay 框架正确，但架构假设
（并发 cap、共享仓、单库交付、内外层分工）在 archguard 不同。

**建议**：quay 侧实现 config-preserving 升级后，archguard 安装这些机制时，上面 4 个盲区需
**逐项适配测试**（不是直接照搬判据）。
