# Experiment 2 as a transfer test: what transferred, what's genuinely new

Source: `experiments/quay-core-bootstrap/iterations/iteration-10.md` §11
(Practical Convergence Assessment, AUTHORITATIVE), the closing "Problems
identified for next iteration" section (verbatim findings for experiment
3), and `experiments/quay-core-bootstrap/directives/archive/`.

## What experiment 2 was testing

Experiment 2 inherited experiment 1's methodology (Layer-2
`quay:author`/`quay:execute` Skills, the `task check` gate, the directive
lifecycle, the G3 out-of-band audit discipline — all already documented
in `.claude/skills/quay-native-methodology/`) and tested whether it
transfers to a new domain: Core ABI symmetry across CLI/MCP/Web UI, Web UI
verification, action-delivery mode, and quay-native backlog health. It
ran 10 iterations.

## What transferred cleanly

- The Layer-2 Skill Method-step structure and degraded-fallback pattern
  transferred without modification — QC-001 through QC-010 all went
  through write-proposal → review-proposal → write-plan → review-plan →
  gate (author) and implement → self-audit-ac → gate-check (execute)
  exactly as experiment 1 defined them.
- The `task check` gate mechanics transferred (same artifact-completeness
  + checked-state + recursive-children-done logic, no regressions
  reintroduced).
- The directive pending/archive lifecycle transferred and was used
  actively (DIR-001, DIR-002, DIR-003 — see
  `g3-audit-dispatch-drift-case-study.md`).
- The G3 "never self-certify" discipline transferred as a *design*, though
  its execution drifted for 3 iterations before DIR-003 corrected it (see
  `g3-audit-dispatch-drift-case-study.md`) — the correction mechanism
  itself (a human directive) is evidence the discipline's guardrail
  property held even when execution drifted.

## What did NOT transfer / stayed stalled the same way

Three of the four V_meta factors stalled for the **same structural
reason** as experiment 1, now reconfirmed with 10 more iterations of
comprehensive search (not just per-iteration checks):

- **effectiveness (0.26)**: same two missing preconditions as experiment
  1 — no scope-matched, single-file/logic-change/no-network-I/O task has
  organically arisen. The comprehensive search (iteration 10 §3b
  re-trigger 1) found, for the first time in 10 iterations, a *candidate*
  shape (GitHub issue #4, `bin/quay-native.js` resolveTasksDir fix) — but
  it is a pre-existing QN-* task, not a QC-* task generated by this
  experiment's own objectives, so the re-trigger does not formally fire.
- **reusability (0.79)**: same as experiment 1 — no organic demand for
  GitHub Provider body/title writes, reconfirmed at the code level
  (`github-client.js` audited again in iteration 10 §3b re-trigger 2).
- **validation (0.64)**: tracks `σ_QC` against the inherited floor; see
  `sigma-inherited-floor-trap.md` for the specific arithmetic reason this
  cannot move within experiment 2's natural scope.

## What is genuinely new (experiment 2's actual contribution)

- **completeness moved** (0.74 inherited → 0.77), the only V_meta factor
  that showed real movement in experiment 2 — driven by narrowing the
  characterization from "no primitive" (experiment 1's finding) to
  "conditional primitive, confirmed reliable across three complexity
  tiers, conditionality-only gap remaining" (see
  `manda-reliability-envelope.md`). This is a genuine evidentiary update,
  not a resolution of the underlying gap (daemon + non-self broker is
  still required).
- The manda-daemon address bug and fix (`manda-daemon-address-bug.md`).
- The G3-audit-via-manda anti-pattern and DIR-003 correction
  (`g3-audit-dispatch-drift-case-study.md`).
- The mathematical-ceiling diagnostic, applied concretely and early
  (`v-meta-ceiling-diagnostic.md`).
- The σ_QC-vs-inherited-floor arithmetic, named explicitly as a design
  trap for future experiments (`sigma-inherited-floor-trap.md`).
- All four instance objectives (Done-when clauses) reached and held at
  1.0 from iteration 3 onward — a deliverable experiment 1 never
  produced, since experiment 1's V_instance topped out at 0.6016.

## HALT vs. CONVERGED (preserve this distinction)

Experiment 2's closure is **HALT with practical convergence accepted**,
explicitly **not** CONVERGED — the same closure *type* as experiment 1,
for structurally related reasons (both blocked by V_meta factors
requiring external events their own objectives do not generate). Do not
present either experiment's methodology as "proven" or "converged" in a
downstream consuming scope; both are honest inheritance snapshots of a
halted, not-fully-converged process.

## Findings for any experiment 3 design (quoted from iteration-10.md, closing section)

> 1. **Effectiveness**: any experiment targeting effectiveness improvement
>    should design objectives that organically generate scope-matched
>    source-logic tasks (single-file, logic change, no network I/O). This
>    experiment's documentation and browser-test objectives do not
>    generate this class of task. Issue #4 (GitHub issue, pre-existing)
>    is the nearest candidate shape found in 10 iterations of
>    comprehensive search.
>
> 2. **Reusability**: any experiment targeting reusability improvement
>    should design objectives that organically require GitHub Provider
>    body/title writes. Alternatively, re-examine whether the v1 scope
>    constraint (QN-024) should be lifted given accumulated evidence of
>    need (or lack thereof).
>
> 3. **Completeness**: the conditionality gap (manda daemon + non-self
>    broker required) can only be closed by an environment change
>    providing an unconditional fresh-context primitive. This is
>    environmental, not a Skill content gap. Experiment 3 design cannot
>    fix this through Skill evolution alone.
>
> 4. **Validation**: the inherited floor (σ_strict = 0.8493) dominates
>    validation until σ_QC exceeds it — requiring ~57+ native-gate tasks
>    from a denominator of 10. Any experiment 3 should either (a)
>    reconsider the validation scoring formula's floor mechanics, or (b)
>    design for more native-gate tasks per iteration by including work
>    that naturally generates native-triple-provenance (source-logic
>    work, not documentation).
>
> 5. **σ_QC growth pattern confirmed**: four consecutive native-gate
>    documentation tasks confirm the {native,native,native} provenance
>    pattern is reproducible. The pattern itself is not the bottleneck —
>    the denominator growth is.
