## 演练记录

本文档是 GOAL-905（goal 分支第二次演练）A 批的第 1 篇，内容刻意无害，只为给演练提供一个
可被托管文档存储读出的真实对象。

### 本篇负责验证什么

**并发落地。** A 批三条任务（`gap-goal905-drill-docs-a` / `-b` / `-c`）同时开 worktree、
同时改盘、几乎同时 fan-in 回同一个 `goal/GOAL-905`。本篇要回答的问题是：三条 fan-in 撞在
一条目标分支上时，第二条与第三条会不会因为目标分支已经被前一条推进而 ff 失败。

### 观测点

| 观测点 | 期望 | 取数方式 |
|---|---|---|
| 三条任务的 worktree 是否同时存在 | 是 | `git worktree list` |
| 三条任务的 Touches 是否相交 | 否 | 各自任务体 `## Touches` |
| fan-in 目标分支 | `goal/GOAL-905` | 任务 `goal_ac` → AC-905 → branch-mode |
| 非快进重试次数 | 记录实际值 | Evidence 节 |

### 为什么这篇文档的正文有实质长度

内容长度本身就是演练的一部分：一份只占一行的文件无法区分「合并真的搬运了内容」与
「合并只是把路径带过去了」。本篇连同同批另外 7 篇，共同构成一个可测量的字节量，
让并入后的差分有东西可看。

### 可见性边界

本文档只存在于 `goal/GOAL-905` 分支上。并入 `develop` 之前，预览实例的 `/doc` 页能列出
它，而生产实例列不出——因为生产读的是 `develop` 的 `docs-managed/`，那里此刻还没有
`DOC-910`。这个差异是演练要看到的，不是故障。
