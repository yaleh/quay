## 演练记录

本文档是 GOAL-905（goal 分支第二次演练）A 批的第 5 篇，内容刻意无害。

### 本篇负责验证什么

**预览自动装配。** 托管文档存储扫描的是 `docs-managed/` 目录本身，不是任何一份手工
维护的清单。本篇要验证的是：把文件放进目录，预览实例就能列出它——不需要改注册表、
不需要重启、不需要任何一步「记得去做」的人工动作。

### 自动装配的判据

| 环节 | 自动 | 需要手工？ |
|---|---|---|
| 文档进入目录 | git 合并 | 否 |
| 存储扫描到它 | `readdirSync` 全目录 | 否 |
| 预览页列出它 | 每次请求重新读 | 否 |
| 前端标题显示 | 直接取 frontmatter `title` | 否 |

四行全「否」才是自动装配。任何一行变成「是」，演练就退化成了「有人记得去注册」，
那与机制无关。

### 一个容易混淆的点

「能被存储读出」与「能被预览列出」是两件事。前者是 `document-store.ts` 的 `get`/`list`，
后者走的是 `serve-doc.ts`。本篇观测前者（因为判据是一条可直接跑的 `node -e`），但演练的
最终目的是后者——`/doc` 页面上真的出现 `goal 分支第二次演练 A-5` 这一行。

### 可见性边界

本文档只存在于 `goal/GOAL-905` 分支上。并入 `develop` 之前，预览实例的 `/doc` 页能列出
`DOC-914`，生产实例列不出；两者读的是同一份代码、不同的工作树，差异只来自分支。
