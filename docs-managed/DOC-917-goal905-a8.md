## 演练记录

本文档是 GOAL-905（goal 分支第二次演练）A 批的第 8 篇，也是 A 批的最后一篇，内容刻意无害。

### 本篇负责验证什么

**落地之后不再被派发。** 一批任务经 goal 分支落地后，它们应当离开 ready 池，不再被
promotion-driver 选中。如果落地之后它们仍在池子里，演练会陷入「落地—再派—再落地」的
循环，而每一轮循环都会在 goal 分支上叠一个新提交。本篇（作为本批最后一篇）负责把这条
收尾条件摆出来，供 GOAL-028 的 AC-321/322/323 取读数时对照。

### 收尾的三个读数

| 读数 | 位置 | 期望 |
|---|---|---|
| 三条任务的状态 | 任务体 `status:` | 均为 `done` |
| 三条任务的提交在不在 goal 分支上 | `git merge-base --is-ancestor` | 是 |
| 三条任务的提交在不在 develop 上 | 同左 | 否（合并前） |

第三行有时效性：一旦有人把 `goal/GOAL-905` 并入 `develop`（这不是本演练任务的动作），
第三行会翻成「是」。所以这一行必须在演练收尾的那一刻采，不能事后补采。

### 本批的完整性

A 批共三篇任务、八篇文档（DOC-910…DOC-917）。本篇是第 8 篇，它的存在使文档数凑满 8——
少一篇，本批任务的 AC 就会红，演练的读数也就不可用。

### 可见性边界

本文档只存在于 `goal/GOAL-905` 分支上。并入 `develop` 之前，预览实例的 `/doc` 页能列出
`DOC-917`，生产实例列不出。这条差异在 A 批全部落地、且 goal 分支尚未并入 develop 时，
应当是稳定的、可重复观测的。
