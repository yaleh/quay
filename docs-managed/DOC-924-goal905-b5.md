## 演练记录

本文档是 GOAL-905（goal 分支第二次演练）B 批的第 5 篇，内容刻意无害。

### 这一篇负责验证什么

**预览自动装配。** 预览实例跑的是 goal 分支，它读的是 `docs-managed/` 这个目录。
「自动装配」指的是：一篇新文档只要以正确的文件名与 frontmatter 落进这个目录，
它就会出现在 `/doc` 页面上——不需要注册、不需要在别处登记一个 id、不需要改任何代码。

这条性质一旦不成立，失败方式是**静默的**：页面照样渲染、照样 200，
只是少了那几行。所以演练不能只看「页面还活着」，必须看**具体某个 id 在不在列表里**。

### 装配链路上每一环的承担者

| 环节 | 承担者 | 若它失灵的可见症状 |
|---|---|---|
| 文件名解析 | `fileNameForId`（`DOC-92X-` 前缀匹配） | 存储 `get()` 返回 null |
| frontmatter 解析 | `parseFrontmatter` | 抛「missing YAML frontmatter block」 |
| view-model 组装 | `createDocumentStore().get()` | 字段缺项或值不对 |
| 列表渲染 | Web UI `/doc` 页 | 页面正常但没有本篇 |

### 演练要拿到的读数

- 预览实例上，DOC-920…DOC-927 八个 id **都能被列出**；
- 生产实例上，同样的八个 id **都不被列出**；
- 两者的差异**只**来自分支不同，不来自任何人为开关。

中间那一行才是重点。只有「预览有、生产没有」同时成立，
才说明看到的是分支隔离，而不是「恰好两边都读到了同一份缓存」。

### 不属于本文档的事

- 不规定 `/doc` 页的渲染细节与排序规则。
- 不把「八个 id 都在」写成任何自动检查的前置：那是 Evidence 里的一次实测读数。
