## 演练记录

这是 GOAL-905 第二次演练 C 批的第 3 篇。本篇盯的是**真实大小并入**：演练文档本身
不是空壳——每篇都有三十行以上正文、一张表、一个小节——所以并入时走的是一条有真实
体积的合并路径，而不是「零字节 diff 也算过」的那条捷径。

之所以要单独写一篇来讲体积，是因为「能产出」与「已产出」是两件事：一个只有标题的
占位文件同样能让列表页多出一行，却证明不了这条路径在真实大小下仍然工作。本篇的
存在本身就是这条断言的读数。

### 本次演练要验证什么

- 每篇 ≥30 行，且行数由 `wc -l` 直接读出，不由任何自报字段推断；
- 8 篇的合计体积足够让 fan-in 的 merge 真正搬运内容，而不是只搬一个空 blob；
- 文件名的 slug 与 frontmatter 里的 `id` 一致，`document-store` 能按 id 反查回文件。

|---|---|---|
| 1 | DOC-930 | `DOC-930-goal905-c1.md` |
| 2 | DOC-931 | `DOC-931-goal905-c2.md` |
| 3 | DOC-932 | `DOC-932-goal905-c3.md` |
| 4 | DOC-933 | `DOC-933-goal905-c4.md` |

### 它只存在于 goal/GOAL-905

并入 `develop` 之前，本篇只在 `goal/GOAL-905` 上：预览实例的 `/doc` 页列出 DOC-932，
生产实例列不出。读者若要验证，只需在两个实例上分别打开 `/doc` 并对文件名取差集。

## 备注

「真实大小」不是指文件要很大，而是指它不是 fixture 注入出来的空壳——关掉注入 seam
之后，这条读数仍然取得到。
