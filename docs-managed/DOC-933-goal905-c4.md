## 演练记录

这是 GOAL-905 第二次演练 C 批的第 4 篇。本篇的角度是**刷新**：文档被并入 goal 分支
之后，预览实例的 `/doc` 页需要在下一次读取时看到它，而不是等到进程重启或缓存过期。

刷新的判据必须是直接量。「页面能打开」不是判据，「同一进程、第二次读取能列出 DOC-933」
才是。按位置判定而不是按关键词判定——页面 HTML 里出现「DOC-933」这串字符不算命中，
`document-store` 按 id `get()` 返回非空才算。

### 本次演练要验证什么

- 并入 goal 分支后，无需重启预览实例即可在 `/doc` 列出本篇；
- 刷新前后两次读取的差集恰好是本批 8 篇，不多不少；
- 若差集为空，报「未刷新」；若差集多于 8，说明混入了别的批次的文档，同样要报。

|---|---|

| 并入 goal 分支之后（goal 视图） | 非空，status=draft |

### 它只存在于 goal/GOAL-905

本篇只在 `goal/GOAL-905` 上存在。预览实例能列出它、生产实例列不出，这个差值就是
「预览自动装配 + 刷新」这条链路的可见证据；并入之后差值归零，演练结束。
