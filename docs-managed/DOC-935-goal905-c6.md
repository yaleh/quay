## 演练记录

这是 GOAL-905 第二次演练 C 批的第 6 篇，也是本批第 6 篇落到 goal 分支的产物。本篇
回到**并发落地**，但换一个切面：不是问「三批能不能同时到」，而是问「三批同时到的时候，
`goal/GOAL-905` 上的提交顺序是否有任何一批被覆盖」。

覆盖是一种很难看见的失败：后到的推送如果在非快进时被强推，前一批的提交会消失，而
列表页只是少了几行——与「本来就没派」同形。所以本篇要求的是一个可枚举的读数：本批
8 篇必须能一次性全部列出，缺任何一篇都算红。

### 本次演练要验证什么

- 并发 ff 队列不丢提交：本批 8 篇全部可在 goal 分支上枚举到；
- 缺任何一篇时，失败必须报出**缺的是哪一篇**，而不是只报一个布尔假；
- 「读不懂」与「没列出」要能区分——读取失败不能被伪装成一个空的成功列表。

| 读数 | 含义 |
|---|---|
| 8 | 全部到齐 |
| 0 < N < 8 | 有提交被覆盖或 fan-in 漏合并，需点名缺哪几篇 |
| 读取异常 | 未评估，不得当作 0 |

### 它只存在于 goal/GOAL-905

本篇只在 `goal/GOAL-905` 上：并入前预览实例的 `/doc` 能列出 DOC-935，生产实例列不出。
并入后它随合并进入 develop。

## 备注

第三行的「未评估」是本篇真正想强调的——把读取失败当成空列表，是这类演练里最容易
骗过自己的失败形态。
