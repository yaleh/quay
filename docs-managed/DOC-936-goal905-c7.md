## 演练记录

这是 GOAL-905 第二次演练 C 批的第 7 篇。本篇再谈一次**落后 develop 的追平**，但聚焦
在「追平之后，本任务自己的产物是否还是原来的那一份」。

追平会引入别人的提交，也可能改到同一批目录里的文件。判据是：追平合并完成之后，
DOC-936 的内容与自己提交时逐字节一致。如果追平时发生了静默改写（例如冲突被某一方
无条件覆盖），行数可能不变而内容已经不同——所以这里比的是内容，不是行数。

### 本次演练要验证什么

- merge develop 后，本任务提交的 8 个文件内容不变（按文件哈希比对）；
- 追平引入的改动不落在 `docs-managed/DOC-93*.md` 这 8 个路径上；
- 若确实发生冲突，冲突要用编辑手段解决并留下痕迹，不能跳过。

| 检查 | 手段 |
|---|---|
| 内容未变 | 合并前后对每个文件取哈希并比对 |
| 未越界改写 | 合并后 `git diff --name-only` 只应出现他人路径 |
| 冲突已解决 | 提交历史里有对应的 merge 提交，无残留冲突标记 |

### 它只存在于 goal/GOAL-905

本篇只存在于 `goal/GOAL-905` 上。并入 `develop` 之前，预览实例的 `/doc` 页能列出
DOC-936，生产实例列不出；并入之后它随合并进入 develop，可由人另行清理。

## 备注

「行数不变但内容变了」是这类合并里最隐蔽的一种失败，本篇把它单列成第一行检查项，
就是为了让判据落在内容上而不是体积上。
