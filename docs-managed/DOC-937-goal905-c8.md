## 演练记录

这是 GOAL-905 第二次演练 C 批的第 8 篇，也是本批的收尾篇。前七篇各挑了一个角度，
本篇把它们收在一处，作为 C 批的自述：本批要同时验证并发落地、落后 develop 的追平、
真实大小并入、刷新、预览自动装配这五条，并且必须经 `goal/GOAL-905` 落地。

收尾篇的作用不是重复，而是给出一个可以整体核对的清单：读者只需拿这一篇的表格，
对照 A / B / C 三批的落地结果，就能判断第二次演练是否真的走通。

### 本次演练要验证什么

| 角度 | 落点 | 承载篇 |
|---|---|---|
| 并发落地 | 三批同时 ff 不丢提交 | C-1、C-6 |
| 落后 develop 的追平 | 先 merge 后 ff 仍成立 | C-2、C-7 |
| 真实大小并入 | 非空壳、内容有体积 | C-3 |
| 刷新 | 并入后无需重启即可见 | C-4 |
| 预览自动装配 | 预览可见 / 生产不可见 | C-5、C-8 |

五条角度共用一句断言：本篇只存在于 `goal/GOAL-905` 上，并入之前预览实例的 `/doc`
页能列出 DOC-937，而生产实例列不出；并入之后它随合并进入 develop。

### 落到 develop 意味着什么

本任务由 `goal_ac: AC-907` 识别，派发时 mergeTarget 解析为 `goal/GOAL-905`。因此如果
最终发现本篇出现在 develop 而 goal 分支上没有对应提交，那不是演练成功，而是接线
缺陷——需要在 Evidence 里记下实际的 mergeTarget，而不是把它当作一次通过。
