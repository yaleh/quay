# 一个机制被当作噪声丢掉,而它的记录也从未落地

**日期**:2026-08-03(管理者,回收 tmpfs 时捡到)
**触发**:清理 `/tmp` 时发现 meta-cc 的一个 worktree 里有个未提交的 `adr/`

---

## 事实链

| 时刻 | 事件 | 证据 |
|---|---|---|
| 2026-07-29 | 写下 `ADR-001-dod-gate-template-dispatch.md`,`status: accepted` | 文件本身,49 行 |
| 同期 | 实现写进 `packages/quay-native` | ADR 正文:「implemented upstream in quay-native's task check (DIR-066)」 |
| 之后 | **另一个里程碑把它丢了** | `9f4a80f3`:「**Discarded unrelated concurrent DIR-066 changes to packages/quay-native (not part of this milestone)**」 |
| 至今 | 机制不在仓里 | `git log -S'Finding' -- packages/quay-native/src/store.ts` ⇒ **0 个提交**(正控制 `-S'artifactSections'` ⇒ 1,查法有效) |
| 至今 | ADR 也不在仓里 | 只存在于 `/tmp` 的 tmpfs worktree 里,五天,重启即消失 |

## 为什么五天没人发现

**因为两条线索同时缺失,而它们本可以互相指认:**

- 机制没了,但**没有记录说它本该在** ⇒ 从代码看不出少了什么
- ADR 在,但**从未进入任何仓** ⇒ 从记录看不到它没生效

**一份未提交的决定 + 一次被丢弃的实现 = 完全静默。**
任何一边落地了,另一边的缺失都会露出来。

## 这是 `Π_{S→E}` 第二步的死法,且是新形态

`意图 ──①──> 守卫(写出来) ──②──> 接线(真的会被执行)`

先前统计的 12 次里,至少 6 次死在 ②。**那 6 次的死法是「写了但没接线」。**
这一次不同:**接线过,然后被第三方以「无关变更」为由主动丢弃。**

这个形态更难防,因为:
1. 丢弃它的人**判断没错**——那些改动确实不属于他那个里程碑
2. 被丢的一方**没有留下任何回执**——ADR 没提交,所以丢弃时看不到代价
3. 并发里程碑的隔离设计**本来就鼓励**丢掉工作树里的意外改动

## 可执行的推论

**并发隔离下,「丢弃无关改动」必须留痕。**
`git worktree` 隔离让每个里程碑只关心自己的文件,这是对的;
但**丢弃动作本身应当产出一条记录**(丢了哪些路径、属于哪个任务),
否则被丢的一方永远不知道自己被丢了——**丢弃是静默的,而写入不是**。

## 对 meta-cc 冷启动的直接影响

`taskCheck` 现在要求 `allArtifactsPresent`(Proposal+Plan+AC+DoD 全齐)对**每一个**任务。
meta-cc 用的是 DIR 模板(`## Finding` / 无 `## Plan`)⇒ **dod 闸结构上不可满足**。
DIR-066 当时的实测:**20 次 dod 失败对 3 次通过**,任务靠绕过闸达到 ready。

⇒ **meta-cc 冷启动前必须先解决这个**,否则它的任务第一天就会撞上一个不可能通过的闸,
然后学会绕过闸——**而「绕过闸」一旦成为习惯,闸就等于不存在**。
