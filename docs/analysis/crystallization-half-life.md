## 1. 要测的量

ADR-004 主张：**只以散文存在的承重规则会被密度先验反复侵蚀，必须变成 fail-closed 的可执行检查**
（硬形变 / Π_{S→E}）。这条主张在本仓库一直是**轶事支撑**（CLAUDE.md 里若干「同日再犯三次」的记述），
没有分布。本文把它变成分布：

- 每条 ADR：`{落笔日期, enforcement 字段值, 强制首次落地提交 SHA 与日期, 间隔天数, 状态}`
- 间隔分布：中位 / p90 / 最大值 + 「至今无产物」的**完整清单**（不是抽样）
- CLAUDE.md 硬规则侧：逐条判定有无产物（该文件对多条自标「靠自觉」，可作真值锚），
  并与脚本的**独立结构读数**做一致性核对

### 1.1 判定的五个取值，以及为什么必须多于两个

| 状态 | 含义 |
|---|---|
| `已强制` | enforcement 声明点名的产物**在盘上且可解析**、有首次落地提交，且没有任何「子面未生效」信号 |
| `部分` | 有产物在盘上，但至少一个**声明面**未生效：产物是断链符号链接 / 曾落地后被移除 / 声明的产物从未落地 / 声明已接线而 GateEvent 载体为零事件 |
| `无产物` | 有声明但**没有任何产物在盘上**（含 `E3, deferred` 这类占位声明、被 reserved 的门、曾落地后又被移除且无替代） |
| `N/A` | 声明明确判定该规则**不可机械强制**（ADR-011 认可的处置），**不算「无产物」** |
| `无法判定` | 读不到 / 解析不了（ADR 不可读、落笔日期三源皆空、产物落地无法取得）。**独立取值**（硬规则 3b） |

`无法判定` 与 `N/A` 都不与 `无产物` 或 `已强制` 合并 —— 一个只能报「判不了」的对象若与
「判过且没有」或「判过且有」共用输出，它就再也无法区分「查过」与「没查成」（硬规则 3b）。
门事件载体 `.quay/gate-events.jsonl` 读不到时，本工具报 **`not-evaluated`**，绝不报「零事件」：
「载体不在」与「载体在且计数为零」是两件事，后者才是证据。

## 3. 读数二：ADR-007 正控制（谓词有效性的检验）

ADR-007 是本任务 Finding 里的**单点证据**。工具对它的判定是：

```
ADR-007  2026-07-19 → 2026-07-20（间隔 1 天）  状态 = 部分
caveats:
  ① enforcement 已接线但 per-milestone 判据无产物
  ② 声明的产物是断链符号链接（在盘上但解析不到目标）
```

两条 caveat 都由**结构事实**产生，不是关键词命中：

1. **①（per-milestone 面）**：`.quay/config.yml` 的 `gates.adr` 声明了 `ADR-007`（=`adr-007` 门已接线，
   这是 ADR-007 自己的注释称的「HALF 1 / the gate wiring」），而 `.quay/gate-events.jsonl`
   在 **103765 条** GateEvent 中 `adr-007` 计数为 **0**（同一读法下 `goal`=103072、`complete`=420、
   `dod`=77、`acceptance`=8 —— 谓词对已知为真的样本命中过，所以这个 0 是真零，不是仪器故障）。
   声明的接线在、per-milestone 判据的执行产物至今为零。
2. **②（instrument 面）**：声明点名的 `experiments/quay-perpetual-stream/scripts/git-lens-*.ts`
   解析到的是 **断链符号链接**（目标 `plugin/scripts/git-lens-*.ts` 已于
   `archive/2026-09-07-zero-call-scripts/` 归档）—— 产物在盘上、目标不存在。
   `git-lens-selfcheck.sh` 实跑也返回 FAIL。

**与人工核对一致**：ADR-007 自己的注释（2026-09-13）写着 HALF 2 已 LANDED，但同时写着
`⚠️ NOT ENFORCED on the mechanical fan-in flip`；HALF 1 的 instrument 有 `KNOWN ROT`。
即「已接线、但至少一个声明面至今没有生效的产物」。工具给出 `部分` 且两条 caveat 正对这两处。

**这是本工具的正控制，也是它的边界**：工具读的是**声明 + 载体 + git 落地**，
不判「load-bearing」与否（那是 ADR-004 自己 deferred 的 E3 谓词，见 §4）。

> 它在本读数里与「没跑」同形。佐证它确实没跑的两条独立读法：ADR-007 的注释自陈

## 4. 读数三：CLAUDE.md 硬规则侧

**18 条**规则条目（`1..12` 连同 `3b/4b/4c/5b/11b/12b`）：

| 量 | 值 |
|---|---|
| 自标「靠自觉」（至少一个 `〔**无产物，靠自觉**〕` 标注） | **7**（`1, 3b, 4, 4b, 5, 10, 11b`） |
| 纯「有产物」（有 `〔产物…〕` 且无「靠自觉」标注） | **9**（`2, 3, 4c, 5b, 6, 7, 8, 11, 12`） |
| 混合（两类标注都有） | 2（`1`, `4`） |
| 未标注（连 `〔产物…〕` 都没有） | 2（`9`, `12b`） |
| 一致性核对**不一致** | **0** |

**核对方法（两条独立读法对照）**：
- 真值锚 = 该条规则块里的 `〔产物…〕` / `〔**无产物，靠自觉**〕` 标注（文件中自报）；
- 脚本判定 = 把 `〔产物…〕` 里**点名的文件产物**（反引号内的代码路径）逐个到盘上解析，
  并要求至少一个出现在**已执行的登记面**（`scripts/test.sh` / `plugin/scripts/runner-static-gate.ts`
  / `.quay/config.yml`）里。
- 结论：全仓库只有**规则 2** 点名了文件产物（`drive-contract-check.ts`、
  `test-framework-policy-check.ts`），两者都在盘上**且都出现在已执行的登记面** ⇒ 一致；
  其余「有产物」条目点的是**方法**而非文件（如规则 11「一条命令可查」、规则 12「必须带发生率读数」），
  没有可解析对象 ⇒ 判为「有产物但未点名文件产物」，**不算不一致**（无对象可核 ≠ 名不落地）。
- **`未标注`（9、12b）单列为独立取值**，不计入不一致：没有自标就没有可对照的第二读法，
  「无法核对」不得与「核对过且一致」同形（硬规则 3b）。

> 这条核对的**能力边界**（如实写下）：它能抓到的是「自标有产物但点名产物不落地 / 无人执行」；
> 对「自标无产物」的条目，它**没有独立反证**（没有点名对象就无从解析）。所以 0 不一致
> 只是「没有被点名的产物名不落地」，**不是**「所有标注都成立」的证明。

### 4.1 顺带暴露的一个形态

`未标注` 的两条里，**规则 9 自己是「可见性 ≠ 执行」那条**（「该给它造产物，不是把它写得更醒目」），
而它自己的规则块里没有任何 `〔产物…〕` 标注 —— 一条要求别人造产物的规则，自己没造。
`12b` 同形（它讲的正是「发生率要查历史」，而它自己不带任何产物标注）。
这两条不判为不一致（无第二读法可对照），但作为「自陈与自述形态不匹配」的事实列出。

## 5. 反向结论（DoD 要求；与 ADR-004 的关系）

DoD 写明：「结论若显示『带产物与无产物的规则在再犯率上没有差别』，如实写反向结论 ——
这会直接削弱 ADR-004，必须照写不得裁剪，并在文档里点明该结论对 ADR-004 的影响。」

**先说这个量在本仓库能取到什么程度。** 本仓库**没有任何机械的再犯率载体**。
唯一的再犯信息来源是**规则自己的散文自陈**（例如规则 2「一天内同形状四次」、规则 3b「发生率已 3」、
规则 4c「一天内同形三次」、规则 5b「同日三次」）。工具因此只报「该条规则块里有没有自陈的再犯」，
并把命中的**原文片段**印出来供人复核（关键词命中在散文上天然会有假阳性，报告里可见即已审计）。

**读数（自陈再犯的规则，按是否带产物分类）：**

| 类别 | 规则号 |
|---|---|
| 带产物 **且** 自陈再犯 | `1, 2, 4, 4c, 5b, 11`（**6 条**） |
| 自标「靠自觉」 **且** 自陈再犯 | `1, 3b, 4, 4b`（4 条） |
| 未标注 **且** 自陈再犯 | （无） |

（`1` 与 `4` 同时出现在两列，因为它们的块里同时有 `〔产物…〕` 与 `〔**无产物，靠自觉**〕` 标注 —— 混合条目。）

**⇒ 反向结论：本仓库的读数不支持「有了可执行产物就不再同形再犯」。**
在**已经带产物**的规则里，有 6 条自陈了同形/同日再犯；`无产物` 的规则 4 条自陈再犯。
两个类别都出现同形再犯 ⇒ **观测不到「带产物 ⇒ 无再犯」的差别**。

**对 ADR-004 的影响（必须点明）：**

1. **ADR-004 的因果半边的直接证据在本仓库是缺席的**，不是被证否、而是**未被检验**：
   没有机械再犯载体，自陈散文既可能少报（没人记录就不存在）也可能多报（记录了才被看见）。
   本文给出的是「可执行强制的**覆盖率与延时**分布」，**不是**「产物是否抑制再犯」的分布。
   把前者当后者用，就是硬规则 4 的形态（一个能解释现象的说法，不是被检验的结论）。
2. **有一条同方向的、且可机械核的旁证：ADR-004 自己的 enforcement 字段是 `E3, deferred`。**
   即：**要求「承重规则必须变成可执行检查」的那条主规则，本身没有可执行检查**
   （§2.2 清单里的 ADR-004）—— 它的 E3 谓词从未落地，所以全库 ADR **从未被它筛过一遍**。
   这解释了 §2.1 的 12/21：不是「筛过之后仍有漏网」，而是**筛子没造出来**。
3. **对 ADR-004 的操作含义**：在造出再犯载体之前，不要用它来论证「某条新规则必须立刻机械化」。
   它可以论证**成本**（覆盖率的缺口是量出来的：accepted 里 57% 无产物），
   不能论证**收益**（有产物 vs 无产物的再犯差，本仓库没有读数）。
   DoD 里「若显示无差别则如实写」的要求，本仓库的真实答复是：**差别测不出**，
   而测不出的原因（缺载体）本身是 ADR-004 最该先机械化的一件东西。

## 6. 这份读数做不到什么（边界，写给下一个读它的人）

1. **不判 load-bearing**。ADR-004 自己把「哪些规则承重」定为 deferred 的 E3 谓词；
   本工具对 36 条 ADR **一律测量**，不做重要性加权。所以「`无产物` 25 条」里既有承重的
   （如 ADR-004/005/010）也有轻的（如一批尚未实施的 axis ADR）—— 清单是全的，权重不在本文。
2. **「已接线」读的是声明**（frontmatter `enforcement:` / 正文 enforcement 注释 + `gates.adr`），
   不是运行证明。唯一的执行证据是 GateEvent 计数，而它**只对追加事件的路径可见**（§3.1 反面读法）。
3. **声明里的路径是散文**：工具的抽取面是「带代码扩展名的路径形 token」。
   它会（a）把声明里**提到**但并非强制的文件也当产物（例：ADR-007 正文提到的 `worker-driver.ts`），
   也会（b）漏掉写成自然语言而无路径的产物。两条都不影响状态判定（判定看的是**有没有**可解析产物、
   以及有没有断链/移除/零事件这类未生效信号），但逐条 `artifacts[]` 会有噪声。
   `resolution` 字段（`exact` / `exact-removed` / `glob` / `stem` / `unresolved`）把每个 token 的
   匹配方式写出来，`altMatches` 列出同 stem 的其它文件 —— 便于人工复核。
4. **负间隔不剔除**（§2.3）：它是有信息的一类，不是脏数据。
5. **本次 `无法判定` 为 0**，不等于该取值无用 —— 它的存在由
