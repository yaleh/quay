# 用几何信息论看今晚:收缩相没有机制,而它本可以有

**日期**:2026-08-04(管理者)
**材料**:三个项目约 6 小时的实测 + 今晚全部发现

---

## 1. 一个可测的不对称

| | 数据 |
|---|---|
| 今天我新增的 `orchestration/` 文件 | **18 个**(现共 23 个规格、3550 行) |
| `plugin/scripts` | 81 个脚本、**27,839 行** |
| 今晚的收缩动作 | **4 次,全部由人发起** |
| 由机制发起的收缩 | **0** |

四次分别是:简化重装目标(「还是简单些吧」)、推翻「两个面」(「完全错了」)、
退役 `inner-state`(「还有用吗?没用就清理」)、纠正规模数字(30 倍)。

**两相呼吸(§8.3)里,膨胀相是自动的——每个发现都变成一份规格、一条 AC;
收缩相完全由人供给。** 这不是人勤快,是**机制侧没有任何东西会说「删掉它」**。

## 2. 为什么收缩不能自动:「从没响过」问不出来

`inner-state.sh` 的招牌信号 `.quay/inner-blocked.json` 在三个项目**从未产生**。
这个事实**今晚之前无法被查询**,因为:

- 监视器事件**投递到会话就消失**——`${QUAY_GLOBAL_DIR}/session-liveness/` 只有 2 个文件
- `inner-state.sh` 头部明写「除 `git log`/`git show` 外**不写任何文件**」(纯读契约)
- `session-liveness.sh` 连这句声明都没有

**纯读契约与可测性在这里冲突,而我们选了纯读。**
代价具体:**一个机制能否被证明无用,取决于它有没有留下痕迹;而我们规定它不许留痕迹。**

⇒ **`inner-state` 活了这么久,不是因为它有用,是因为「它没用」这句话无法被构造。**

## 3. Π_{S→E} 第二步的第三种死法(新)

已知两种:
1. **写了没接线**(12 次里至少 6 次)
2. **接线后被第三方当无关变更丢弃**(ADR-001 的实现,`9f4a80f3`)

今晚出现第三种:
3. **半个守卫接上了**——`a9210718` 实现了 shape 分派,但勾选规则仍是形状无关的。
   实测 DIR-099:**可观测量变了**(`shape: "finding"` 这个字段出现了)、
   **结果没变**(`ok: false`,15 个 todo 仍全堵)。

**⇒ 判据必须收紧**:守卫在 `E` 中的检验是
「移除它会让某次运行的**结果**改变」,**不是「可观测量改变」**。
一个半接上的守卫会在自己那一维报成功,而复合要求依然不满足——
**它比完全没接上更难发现,因为它产生了进展的迹象。**

## 4. L_G 第一次有了可机械化的判据

`L_G`(重新发明已有抽象)一直**没有仪器**。今晚的 `inner-state.sh` 给出了一个:

> **名字断言一个角色,数据源断言另一个。**
> 脚本名里有 `inner`(出现 17 次),而 `tmux` 命中数 **0**——它从不观测会话。
> 我们本来只有一个抽象(观测一个 tmux 里的会话),命名造出了第二个,
> 于是按名字去挂载,挂出了 **7 个**。

**可算的指标**:脚本名中的名词 vs 它实际调用的命令类(`tmux`/`git`/`curl`/`node`…)。
**名实不符 = L_G 候选。** 一次 grep 的成本,而它能抓到「我们已经有这个抽象了」这类
迄今只能靠人眼发现的东西。

## 5. 结晶提案(按性价比排)

### 提案 1(最高):事件落盘 + 零触发报告 —— **收缩相的机制化**

- 所有观测事件写共享 `jsonl`(与 AC20c 同一件事,但这里的理由不同:
  **不是为了共享订阅,是为了让「从没响过」可被查询**)
- 定期报告「**声明了但从未触发**」的机制清单

**它直接产出删除候选**,这正是收缩相缺的那个力。
今晚三个发现里它至少能抓到两个(`inner-state`、`inner-blocked`)。

**与纯读契约的冲突要正面处理**:写事件日志本身不改变被观测对象的状态空间
(不碰工作树、不碰 git),与「`--report` 不许写文件」不是同一件事。
**把「不许写任何文件」收窄为「不许写被观测者的状态」。**

### 提案 2:名实一致检查(L_G 仪器)

脚本名词 vs 实际数据源,不符即报。见 §4。

### 提案 3:守卫的移除测试(Π_{S→E} 仪器)

已有的 mutation-test the checkers(`353dfe69`)扩展一步:
**删掉一个守卫,是否有某次运行的结果改变**——看结果,不看可观测量(见 §3)。

### 提案 4:规则的跨介质清单

同一条规则「按命令位置匹配,不用裸子串」在 `runtime-usage-inventory` 有测试,
**在进程枚举里没有**——我今晚因此犯了三次(`pgrep -f` 自杀、数 `node --test` 数到自己、
枚举监视器枚举到自己)。

**规则应当带「适用介质清单」**,而不是在一个介质上写完测试就算结晶完成。
**同一条规则在不同介质上要各犯一次才学会——这本身是可预测的,因此是可预防的。**

## 6. 诚实的限度

- 上面四条全是 **`L_D` / `L_T` 面的机械化**。
- **`L_S`(扰动下的行为方差)仍然只有一个仪器**(mutation-test the checkers),
  而它测的是 checkers 自己,不是整个系统。
- **今晚我自己三次自匹配就是 `L_S` 的实例,没有任何仪器抓到**——
  抓到它的是人的一句「你现在在用 monitor 观测三个 outer 吗?」
- 连续数学(Fisher / 自然梯度 / 内蕴维数 / ρ)在这里**一次也没用上**,
  与 ADR-006 的判断一致:**它不是严格性的来源**。
