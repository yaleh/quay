## 1. 口径（先定口径，再谈数字）

- **任务体量 `s`（变更行）**：该任务最后一次 `Merge branch 'develop' into task/<id>` 提交相对其 develop 一侧父提交
  （`git diff --numstat <merge>^2 <merge>`）的插入+删除行数之和，只计**代码与测试**文件；
  排除 `tasks/`、`.quay/`、`goals/` 与 lockfile（它们是记账，不是工作量）。
- **落地轮 wall / 失败轮 wall / 总 wall**：`.quay/worker-outcome.jsonl` 中该任务各记录的 `wall_clock_ms`。
  成功/失败**不内联比较 `final_state` 字面量**，而是经 `classifyFinalState`（rework-predictors.ts）
  分成四个可区分的类：`success` / `legacy-alias`（死取值）/ `non-landed` / `unrecognized`。
- **总 wall** = 该任务**全部** worker 轮（含失败轮）的 wall 之和；这是「这个任务一共烧了多少 worker 时间」的直接量。
- **worker 小时/1000 变更行** = 档内 Σ总wall(小时) ÷ Σ变更行 × 1000。区间为**按任务重采样**的 bootstrap 95%（1000 次，seed 20261007）。
- **样本 < 10 的档不给任何统计量**（标 `insufficient`）——那不是「读数为 0」，是「读不出来」。

## 3. 成本模型

`T(s) = (a + b·s/100) + f(s)·(c + d·s/100)`，其中 `f(s) = f0 + f1·log10(s/300)` 为每任务失败轮数。
三阶段最小二乘：落地轮 wall ~ a + b·s/100；失败轮 wall ~ c + d·s/100；失败轮数 ~ f0 + f1·log10(s/300)。
失败轮那一阶段以**失败轮**为单位（一个任务的每个失败轮各算一个观测点，等价于以轮数为权重的回归），
落地轮与失败轮数两阶段以**任务**为单位；bootstrap 三阶段都按任务重采样。
区间为按任务重采样的 bootstrap 95%。

| 参数 | 含义 | 值 | 95% 区间 |
|---|---|---|---|
| a | 落地轮固定成本（min） | 18.49 | [16.34, 19.45] |
| b | 落地轮每 100 行的斜率（min/100 行） | 0.070 | [0.044, 0.358] |
| c | 失败轮固定成本（min） | 22.18 | [15.31, 32.63] |
| d | 失败轮每 100 行的斜率（min/100 行） | 0.250 | [-0.332, 0.320] |

## 5. 已知限制

- **只含已落地任务**：样本来自「有 `Merge branch 'develop' into task/<id>` 提交」的任务。
  从未落地、或落地路径不同（没有那次 merge）的任务不在样本内——选择效应，不是全量。
- **体量是最后一次 merge 时的快照**：其后追加的提交（若不在该 merge 里）不计入；
  被排除的记账文件（`tasks/` 等）也不算体量，所以 s 是**代码+测试**的规模，不是 PR 总行数。
- **相关，不是因果**：难度不可观测，「难任务更大也更常返工」能产生同样的表。本文所有读法都是**相关**。
- **任务之间不独立**：同一批 worker、同一套测试、同一时段；bootstrap 区间只反映**抽样**不确定性，
  不反映工人/时段效应，因此区间比真实不确定性**窄**。
- **首次成功率只判「第一轮是否 `success`」**：`legacy-alias`（死取值）与 `unrecognized` 都不算成功；
  观测到 unrecognized 取值时说明载体里出现了本脚本读不懂的状态字，应先去核对口径再读本表。
- **多项目合计的 root 列表是显式给出的**（见上方复跑命令）——本脚本不扫描、不发现项目，
  少传一个 root 就是少一份样本，且不会有任何提示。
- **表是「生成那一刻」的快照，不是常量**：观测窗是活的（`.quay/worker-outcome.jsonl` 每轮追加、
  任务随落地进入样本），所以本文的表与今天再复跑一次的结果在**低位小数与 n** 上必然不同
  （本例同一窗内 943 → 953 个可测任务）。**逐格一致只在「生成于」那一刻成立**；
  量级与排序（最小档最贵、最大档最便宜）在噪声内稳定。**引用任何一个数字前先复跑本文顶部那条命令**，
  并把本文的表与「生成于」一起更新——「表与正本一致」是**生成时刻**的判据，不是长期不变量。
- **与前版 SKILL.md 数字的差异（逐条）**：前版数字来自一次未留脚本的读数，本次复跑对照如下——
  * 每 1000 变更行的成本量级与排序**复现**（最小档最贵、最大档最便宜）；具体值随观测窗推进略有变化。
  * 「每任务约 0.94 个失败轮」**复现**（f0 = 0.94）。
  * 「落地轮 = 17 min + 0.35 min/100 行」**未复现**：本次为 a = 18.49 min、b = 0.070 min/100 行
    （b 的区间很宽，见上表——这条斜率在本数据上不是一个稳定的量，不要引用单个点值）。
  * 「失败轮数不随规模上升」**取假**：≥1500 行的档失败轮数明显更高（见 §2 读法）；
    但按吞吐口径（每 1000 变更行）规则不受影响，故 `## Granularity` 的三条规则不改。
