## 2. 人发现的那四条有共同点

| # | 我做了什么 | 我漏了什么 |
|---|---|---|
| 4 | 每 tick 记压力与 load | **从没问过「我的监视器在看什么」** |
| 9 | e2e 有双向负控制、有改名测试 | 它查的是**文件内容里的路径字符串** |
| 10 | `/live` 降级完美、「无数据 vs 读失败」已分开 | **它显示的与事实相反** |
| 12 | 验 AC3 查了三提交链、逐字节比对、幂等性 | **唯独没查「内层在跑什么」** |

**⇒ 我设计的检查，测的是我设想的失效。**

而人四次都不是通过设计检查找到的——是**让我起一个服务、看一个页面、看一眼屏幕**。

**这不是「人比模型强」，是通道不同**：
人提供**真实使用**与**对屏幕上实际有什么的注意**；
管理者提供**测量**与**跨项目状态**；
外层提供**领域自查**。**三条通道的盲区互不重叠。**

这正是文档 (c)「放大的是人机通道而非任一端」的实测形态。

## 3. 挣到的修正：`Π_{S→E}` 不是一次映射，是两次

文档把 `Π_{S→E}`（region → executable check）当作一次映射：把连续意图钉成可执行守卫。

**今天的十二次说明它有两步，而失败集中在第二步**：

```
意图 ──①──> 守卫（写出来、可执行）──②──> 接线（真的会被执行）
```

| 死在哪一步 | 实例 |
|---|---|
| ② | #1 契约检查器**写好了、没有执行者** |
| ② | #2 e2e **写好了、没人跑** |
| ② | #3 `concurrency: 4` **声明了、没有判据脚本** |
| ② | #7 机制**装了、循环没起** |
| ② | #12 内层文档**铺了、没有读者** |
| ② | #11 遥测脚本**在、没往该写的地方写** |
| ①的伪装 | #6 负控制**存在，但探针不可能失败** |

**至少六次死在第二步，一次死在「第一步看起来完成了其实没有」。**

**为什么这一步在文档里没有名字**：因为在几何叙述里，一个 executable check 一旦写出来就**默认在 `E` 里**——
而现实中「写出来」和「在 `E` 里」之间隔着**接线**，而接线本身是软的、会被忘记、且**从外部与已接线同形**。

**⇒ 补一条判据**：一个守卫是否在 `E` 里，判据不是「它存在」，
而是「**移除它会不会让某次运行失败**」。今天所有第二步的失败，都能被这一问当场问出来。

## 4. (a) 与连续动力学层：今天零次

**(a) 带闭包的类型化目标**：管理者一次都没用 `L_T/L_C/L_D/L_G/L_S` 问过「哪根轴还暗」。
起作用的是 **AC 的结构**（可执行判据、`## Contract` 六键），**不是几何命名**。
**不把它算作 (a) 的功劳**——那正是文档 §4 判死的事后归因。

**连续动力学层**：没算过 Fisher、没算过本征维度、没算过 ρ，**也没有任何地方需要它们**。
文档 §4 的自我判决在今天完全成立。

## 5. 限度

- 一天、一台机器、两个真实项目、一个人
- 「三条通道盲区互不重叠」是**今天的分布**，不是**结构性证明**——
  换一个人、换一组任务，分布会变
- 第 3 节那条修正是**从失败反推的**，不是预测出来的；
  它的检验要等下一次有人**在写守卫时就问「移除它会不会让某次运行失败」**，
  看那一问能不能在事前挡住第二步的失败
