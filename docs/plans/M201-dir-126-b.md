## Guardrails / rollback / real-landing verification

- **Guardrail — fail-closed by construction.** Every new CLI-error path (unparseable JSON,
  non-zero exit with no verdict) returns `needs-human`/`preflight-check-failed`, never silently
  falls through as if Preflight passed — mirrored directly from `Admission`'s own
  `admission-check-failed` precedent (Grounded facts above).
- **Guardrail — calibrate-then-enforce.** No detector may set `blocking:true` in the shared
  `PREFLIGHT_CALIBRATED` map until its own known-bad/known-good/ambiguous-valid triad (Stage 6) is
  green; Stage 9's real dispatch must show all five `true` before being treated as DoD evidence.
- **Guardrail — reuse, never re-derive.** Stages 2/3 are structured so that a `grep -n
  "splitListAwareBlocks\|splitSentences" prepare-admission-check.ts` and a `grep -n "checkTouches\|
  countBoxes\|parsePlanStages" prepare-admission-check.ts` both show real imports from
  `wiring-coverage-check.ts`/`task-schema.ts`/`milestone-preparation-check.ts` — a Build that instead
  reimplements any of these (including re-deriving an AC count locally instead of importing
  `countBoxes`) is a Plan deviation, not an acceptable variant.
- **Rollback.** Every stage's diff is additive (new exports, new functions, two new insertion
  points, new fixtures) except Stage 2's two `export` keywords — reverting any single stage's commit
  restores prior behavior with no cross-stage entanglement; `prepare-milestone.js`'s two insertion
  points are each a self-contained `if (...) { return {...} }` block that can be deleted without
  touching surrounding phases (Stages 4/5 are independently revertible). If Stage 9's real dispatch
  surfaces a false positive against a genuinely valid task, the fastest safe rollback is flipping
  that one detector's `PREFLIGHT_CALIBRATED` entry back to `false` (non-blocking/logged), not
  reverting the whole phase.
- **Real-landing verification.** Land requires: (a) the combined Stage-9 test command green, (b)
  `sync-vendor.sh --check` clean (Stage 8), (c) the real non-fixture dispatch journal (Stage 9)
  showing `preflight-rejected` before any content-agent label on the seeded-bad path and unchanged
  `ProposalAuthors`/`PlanCheck` dispatch on a valid path, (d) a fresh independent audit (per the
  task's own DoD item 5) tracing the real production import graph for both insertion points — not
  merely `--selftest`/unit-test reachability — confirming WIRING-CLAIM 1 and WIRING-CLAIM 2 against
  the actual committed `prepare-milestone.js`, both mirrors.
