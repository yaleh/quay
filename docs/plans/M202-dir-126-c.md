## Guardrails / rollback / real-landing verification

- **Guardrail — fail-closed by construction.** Every new CLI-error path in the Stage-4 decision
  block returns typed `needs-human` (`resume-decision-failed` for unparseable/non-zero,
  `reuse-terminal-release-failed` for a failed embedded release), never silently falls through as
  cold or resume — mirroring `Admission`'s own `admission-check-failed` precedent (line 156).
  Exceptions inside `decideResumeGeneration`'s evaluation wrap to `cold`/`decision-exception` at
  the CLI layer (evaluation-order step 3).
- **Guardrail — dispatch-count invariant.** Explicit `true`/`false` paths add ZERO new dispatches
  (the call itself is skipped, not just the decision forced); the omitted path adds AT MOST one
  (`resume-decision`, and zero when no prior record exists); every terminal keeps exactly one
  dispatch (record-generation replaces release, piggybacked — never a second call). Stage 7's
  journal evidence asserts these counts, not just end-state outcomes.
- **Guardrail — Touches containment (mechanical, not prose).** AC9/R9's `git diff --stat` against
  `prepare-admission-check.ts` (both mirrors) and `.gitignore` must be empty on every landing
  commit; the read-only imports (`PREFLIGHT_POLICY_VERSION`, `releaseLease`, `isDirectEntry`,
  `extractSection`) are verified zero-diff by that same check. Every stage `- Files:` line above
  names only the six declared Touches, satisfying DIR-126-B's `preflightTouchesMismatch` at this
  Plan's own `--preflight-plan` time.
- **Guardrail — review-unconditional non-regression.** `phase('ProposalReview')` (line 275) stays

  (line 173) in file order, so it structurally cannot reach `PlanAuthor` (506) or `Receipt` (617)
  — AC5 is proven from file structure, then confirmed by journal.
- **Rollback.** Every stage's diff is additive (new exports, new CLI tail, new helpers, new
  fixtures) except Stage 4's `const`→`let` token and Stage 5's 15 like-for-like call replacements.
