## Grounded facts this Plan relies on (re-verified live against `d4d46629`, 2026-08-01)

- **DIR-047 precedent is the template.** `store.ts` has `resolveDefaultStatus(value)` (L26–32)
  returning the value unchanged when valid / throwing a clear error when illegal, and
  `createStore(tasksDir, opts?: { defaultStatus?: string })` (L124) with
  `const storeDefaultStatus = opts?.defaultStatus ?? "todo"`. `write()` applies it in the
  NEW-task branch only: `frontmatter.extra = extra ?? {};` (L565) then
  `if (frontmatter.status === undefined) frontmatter.status = storeDefaultStatus;` (L567–570).
  `bin/quay-native.ts` `loadDefaultStatus()` (L87–102) reads `default_task_status` from the
  enabled provider's block in `.quay/config.yml` (mirroring Core's `activeProvider()`) and
  **invokes `resolveDefaultStatus()` on the configured value before returning** (L100–101 — the
  fail-closed wiring the new `loadDefaultSchema()` copies verbatim). It is called at the MCP path
  (L134–138 → `startMcpServer({ ..., defaultStatus })`) and the CLI `task` path (L313–318 →
  `createStore(resolveTasksDir(), { defaultStatus })`).
- **Schema validation rule (AC5).** A schema value is valid iff it is a non-empty string matching
  `/^v\d+$/` ("v1", "v2", …). Invalid examples pinned by AC5: `"v1.0"`, `"v"`, `""`.
  `resolveDefaultSchema(value)` returns the value unchanged when valid and throws
  `invalid default_task_schema "<value>" — must match /^v\d+$/ (e.g. "v1", "v2")` otherwise —
  the single-source validator called by `loadDefaultSchema()` at config load, so CLI and MCP fail
  closed BEFORE any task is created (DoD2/DoD6).
- **store.ts has no existing schema special-casing.** `grep` for `schema`/`extra.schema` in
  `store.ts` returns nothing today — `extra` is an opaque passthrough (L331, L516, L557, L565).
  The schema default is therefore purely additive: applied ONLY in the new-task branch, alongside
  the status default, and never touched in the patch branch (L557 `if (extra !== undefined)
  frontmatter.extra = extra;` stays byte-identical — AC4).
- **`task create` has no `--help` today, and does not support `--extra`.** Only `init` has a
  `--help`/`-h` branch (bin/quay-native.ts L256–257). DoD5 requires `quay-native task create
  --help` to mention the default schema behavior, so Stage 3 adds a small `task create --help`
  branch documenting the flags `task create` ACTUALLY implements — `--title/--status/--labels/
  --parent/--body/--json` — AND the `default_task_schema` (and `default_task_status`)
  creation-default behavior. `--extra` is deliberately NOT listed: the create handler builds its
  patch ONLY from `title/status/labels/parent/body` (bin/quay-native.ts L393–415) and never reads
  `flags.extra` (only `task edit` does, L364), so a help text naming `--extra` would document a
  flag the command does not implement (FINDING 2 resolution — AC2's explicit-wins case is
  exercised at the store and MCP `task_write` surfaces instead).
- **AC7's Core-CLI path.** `quay task create` (packages/quay/bin/quay.ts L743–786) builds a patch
  `{ title, ... }` and calls `client.taskWrite({ id, ...patch })` through `withProvider()` — the
  native provider's MCP `task_write` handler (mcp-server.ts L92–123, `extra:
  z.record(...).optional()` L111) funnels into the same `createStore().write()`, so the schema
  default is applied identically. AC7's test drives the REAL Core CLI against a workspace whose
  config points native's `mcp_entry` at the real quay-native bin — the same
  `writeConfig(workspaceRoot, …)` helper shape `default-status.test.mjs` uses (L33–44).
- **Test convention (AC8).** `default-status.test.mjs` (231 lines) uses `node:test` + `assert`,
  a `tmpDir()`/`writeConfig()` helper pair (L28–44), `execFileSync` against
  `packages/quay-native/bin/quay-native.ts` with `QUAY_NATIVE_TASKS_DIR` env (CLI e2e, section 3),
  and `@modelcontextprotocol/sdk` `Client`/`StdioClientTransport` for the MCP section 4. Section 3
  also pins the fail-closed shape (L166–184): illegal config value → `execFileSync` throws, stderr
  names the problem, no task file created. `default-schema.test.mjs` mirrors this section
  structure 1:1 for `extra.schema` (AC9 is the same illegal-value fail-closed test, plus an MCP
  server-start failure assertion).
- **Coverage measurement basis (AC8, F3-grounded).** `--experimental-test-coverage` reports
  WHOLE-FILE line coverage per source file, so a single test file covers only a slice of `store.ts`.
  Verified live on this repo (node v26.5.0, 2026-08-01): `default-status.test.mjs` ALONE →
  `store.ts | 56.03 | ...` (row[1] line column), while the full
  `packages/quay-native/test/*.test.mjs` suite → `store.ts | 89.48 | ...`. The ≥80% AC8 threshold
  is therefore reachable only from a whole-suite run (or a diff-scoped measurement), NOT from an
  isolated run of the new file — Stage 3 measures coverage over the whole quay-native suite, and
  the presence of `default-schema.test.mjs` in that run can only increase store.ts's covered lines
  (never decrease them), so 89.48% is a conservative lower bound for the actual Stage-3 run.

  place the `/^v\d+$/` rule lives; `bin/quay-native.ts`'s `loadDefaultSchema()` invokes it and
  throws on illegal values BEFORE any task is created, and `mcp-server.ts` forwards the already
  validated value (never re-derives the rule). A second copy of the regex in a surface file is
  drift (ADR-004 single-source), enforced by the Stage-2 GREEN of the fail-closed tests.
- **G3 — creation-only, backward compatible:** the schema default is applied ONLY in the
  new-task branch of `write()` (next to the status default), never in the patch branch and never
  when the key is absent — byte-for-byte identical behavior for every existing call that does not
  set `default_task_schema` (AC3/AC4, plus the unchanged `default-status.test.mjs` regression).
- **G4 — fail-closed discipline:** a `default_task_schema` configured to an illegal value makes
  the CLI `task create` exit non-zero with a clear error naming the key AND the MCP server fail to
  start — NO task is ever created with an invalid schema. Mirrors DIR-047's
  `default-status.test.mjs` section-3 fail-closed wiring (DoD6 requires the callsite wiring, not
  just the validator). Both asserted by the Stage-1 e2e cases.
- **G5 — concurrency boundary:** this milestone never self-initiates a concurrent dispatch; if the
  DIR-123 fan-in ever runs it concurrently (worktree-isolated), Land remains the sole
  shared-checkout mutator and the fan-in owns the merge (OUTER-LOOP step g). In the serial path,
  no other `execute-milestone` dispatch may overlap this one against the same checkout (CLAUDE.md
  shared-working-tree rule). Read-only inputs G1 are cross-milestone-safe by construction.

## Rollback

- **Mid-stage:** a failed Stage-1/2/3 command is fixed in-place within the same worktree before
  proceeding (no partial Land); the RED evidence for Stage 1 is preserved before Stage 2 flips it.
- **Post-Land regression:** the full-suite GREEN is a Land precondition; a regression surfacing
  only on `master` after Land (e.g. `default-status.test.mjs` breaking) triggers
  `quay retreat DIR-101 --reason <specific>`, a fix commit, and a fresh acceptance-gate run — the
  `tasks/DIR-101.md` status ticks written at Land are un-ticked (DIR-020 discipline) until the
  re-run passes.
- **Backward-compat drift:** if any existing task's `extra.schema` were altered by the new default
  (it must NOT be — G3), that is a REFUTED-finding candidate for the acceptance audit
  (deviation-log per DIR-017), not a silent fixture tweak.

## Plan-check stopping rule

The PlanAuthor/PlanCheck loop follows the standardized rule: at most **3** Plan-check rounds;
success only when `F_i = 0` (zero findings) on a round. After round 3 with `F_i > 0`, the Plan is
returned for revision rather than dispatched — never a silent proceed.
