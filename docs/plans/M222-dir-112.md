- Detail: the single control-flow edit, specified with real symbols:
  1. Add `execFile` to the `:92` import (keep `execFileSync` — still used after step 3 by the 4
     shared-block direct seeding calls at 174/178, 337/348).
  2. Rewrite `run()` (`:125-139`) to a promise-returning `execFile`-based version preserving the
     exact `{status, stdout, stderr}` shape: on success `resolve({ status: 0, stdout, stderr: "" })`;
     on error `resolve({ status: typeof err.code === "number" ? err.code : 1, stdout: err.stdout ??
     "", stderr: err.stderr ?? String(err) })`. The literal `err.status ?? 1` symbol does NOT port
     to the async API: the async `execFile` error has no `status` property (`err.status` is always
     `undefined`, verified on this repo's Node v26.5.0), so following it literally would collapse
     every failure to status 1 and silently discard real exit codes (e.g. exit 3 → 1). Map from
     `err.code` instead — numeric on a normal non-zero exit (real exit code preserved verbatim,
     e.g. exit 3 → status 3) and `null` under signal-death → fall back to 1 — which exactly
     reproduces the sync `run()` failure-path semantics the task's Requested Action #1 asks to
     preserve. Every call site becomes `const r = await run(...)`.
  3. Add a sibling `runNative(args, opts)` promisified helper (same `{status, stdout, stderr}` shape
     and the same `typeof err.code === "number" ? err.code : 1` failure mapping as step 2, spawning
     `["node", nativeBin, ...args]`) for the 19 direct seeding calls that live in the PARALLEL
     blocks (lines 880/884/888, 1110/1116/1121, 1196/1201/1206, 1268/1273/1278, 1368/1373,
     1428/1433, 1486, 1543/1545) so the parallel set contains zero blocking synchronous I/O (a sync
     `execFileSync` inside a parallel async block would block the event loop and serialize the
     timing win away). The 4 shared-block seeding calls (174/178, 337/348) stay `execFileSync`.
  4. Extract each numbered `{ ... }` block into `async function block<N>() { ... }` (`block1` …
     `block25`). WITHIN each block, calls stay strictly sequential (`await run(...)` in existing
     order) — each block's create→edit→check ordering is preserved verbatim.
  5. Invocations in `main()`: `await block1(); … await block12();` then
     `await Promise.all([block13(), block17(), block18(), block19(), block20(), block21(), block22()]);`
     then `await block14(); await block15(); await block16(); await block23(); await block24();
     await block25();` — the parallel set is hoisted to the block-13 position (after block 12). This
     reorder is safe: the 7 parallel blocks are filesystem-isolated (own mkdtemp stores, zero shared
     reads), and the textually-intervening serial blocks 14/15/16 depend on nothing the parallel set
     produces.
  6. Attribution (AC #4): add `let currentBlock = "";` and prefix `assert()`'s PASS/FAIL output with
     ``[${currentBlock}]``. SERIAL blocks set `currentBlock = "<tag>"` at entry (e.g. `"b1-task-list"`,
     `"b9-serve"`, `"b25-page-size"`) — safe because serial blocks run one-at-a-time (no interleaving
     during their `await run()`). PARALLEL blocks use a block-scoped tagged assert
     `const a = makeTaggedAssert("b13-prefix")` (etc.), where `makeTaggedAssert(tag)` returns a
     closure incrementing the shared `failures` counter and printing ``[<tag>] PASS/FAIL`` — a shared
     `currentBlock` global would interleave-misattribute under `Promise.all`, so only the closure
     form is used in the 7 parallel blocks; their `assert(` call sites rename to `a(` with condition
     and message strings byte-identical (the tagging closure is a control-flow change, not an
     assertion-value change — AC #1).
  7. The global `failures` counter remains the single total (safe by construction — single-threaded
     event loop, increments only inside `assert`/tagged assert).
  End by re-running the Stage-1 grep: `grep -q "await Promise.all"` now exits 0 — Stage-1 RED is
  GREEN. The in-progress `git diff` (not yet committed) is the AC #1/#5 reviewable artifact.

## Guardrails

- **The parallel set is fixed, exhaustive, and closed.** Only blocks 13/17/18/19/20/21/22 — each
  constructing its OWN `mkdtempSync` workspaceRoot (`:861/:862`, `:1088/:1089`, `:1177/:1178`,
  `:1249/:1250`+`:1349/:1350`, `:1410/:1411`, `:1465/:1466`, `:1523/:1524`) — may appear inside the
  single `Promise.all`. Every block that touches the shared task store or the shared
  `workspaceRoot/.quay/config.yml` — the write/restore pairs at `419/449`, `585/645`, `701/781`,
  `807/841`, the 4b/5b status mutations (`:295-301`, `:337-350`), block 9's shared-store HTTP server,
  block 25's `allTasks.length === 2` sanity, and the shared-store reads of blocks 1-7/14/15/16/24/25 —
  is enumerated forbidden-in-parallel and must be serially `await`ed in existing order. Shared-state
  concurrency is designed out, not accepted as risk; no accepted-risk decision is required.
- **Assertions and fixtures are verbatim (AC #1).** Zero edits to any `assert` condition/message
  string or any fixture value. Only the import, the `run()`/`runNative()` bodies, block wrappers,
  `await` prefixes, the one `Promise.all`, and tagging lines change. Enforce with
  `git diff <base> <land> -- packages/quay/test/cli.test.mjs` reviewing to control-flow only. The
  Stage-6 negative-control flip is the ONE deliberate, temporary exception — it is reverted by a
  byte-identical `cp` backup before the Land diff is produced.
- **Spawn-count greps use fixed-string mode (`grep -Fc`).** The pattern `execFileSync("node", [nativeBin`
  is a literal substring, not a regex — the repo's default grep (ugrep 7.5.0) rejects the
  unterminated `[` with `mismatched [ ]` (exit 2), so every stage command uses `grep -Fc` (verified:
  `grep -Fc 'execFileSync("node", [nativeBin'` returns 23 on the base file; the bare `grep -c`
  form errors out and would abort Stage 9's `&&` chain, silently drop Stage 5's count, and never
  record Stage 1's baseline).
- **Preserve the sync `run()` failure-path SEMANTICS, not the literal `err.status ?? 1` symbol.**
  The sync error's `err.status` (numeric exit code on a normal non-zero exit, `null` under
  signal-death) does not exist on the async `execFile` error — `err.status` is `undefined` there
  (verified on this repo's Node v26.5.0), so porting the literal symbol would collapse every
  failure to status 1 and silently discard real exit codes (e.g. exit 3 → 1), diverging from the
  sync behavior the task's Requested Action #1 preserves. The async `run()`/`runNative()` failure
  path must map `typeof err.code === "number" ? err.code : 1` (numeric `err.code` on a normal exit,
  `null` under signal-death → 1), which exactly reproduces the sync behavior. Preserve the exact
  `{status, stdout, stderr}` return shape.
- **Within-block ordering is preserved.** Each block's create→edit→check calls stay strictly
  sequential (`await run(...)` in existing order). Never parallelize inside a block — parallelism is
  at the block level only.
- **The parallel set contains zero blocking synchronous I/O.** Any `execFileSync` inside a parallel
  async block would block the event loop and serialize the timing win — the 19 direct seeding calls
  in the parallel blocks are routed through the async `runNative()` helper; only the 4 shared-block
  seeding calls keep `execFileSync`.

  interleave-misattribute under `Promise.all`). The global `currentBlock` is used only by serial
