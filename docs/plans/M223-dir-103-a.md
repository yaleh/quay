## Guardrails

- **No-write invariant (AC4/AC5) is asserted, not assumed.** The dry-run branch NEVER calls
  `runGate` (whose unconditional `appendGateEvent(logPath, event)` call is at `engine.ts:64`) and NEVER imports or invokes any
  `lifecycle.ts` status writer (`runComplete`/`runPromote`). Its only observable effects are the

  `runAcceptanceCapture`, and `console.*` — no store/log/lifecycle import added to the branch.

  CLI-level block must assert that the acceptance command actually executed (its stdout and/or the
  `dry-run: exit <code>` line appeared) IN ADDITION to the no-write invariant — so a feature-absent
  usage-error abort fails the block instead of passing it on the negative half.

  task get` is not a valid subcommand (`list|view|create|edit|check` only; it prints usage and exits
  1). The AC5 block reads the fixture's `status` via

  native task file frontmatter.
