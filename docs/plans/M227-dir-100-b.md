     **Typecheck constraint (the repo's REAL gate, not cosmetic):** the five entry interfaces
     (`It0Entry`/`FixedEntry`/`TestPassEntry`/`CoverageFloorEntry`/`RedGreenEntry`,
     `types.ts:21-58`) are interfaces, so they have NO implicit index signature and are NOT
     assignable to `Record<string, unknown>`. A `fieldPresent(entry: Record<string, unknown>, …)`
     param makes every call fail the repo's own `tsc --noEmit` gate (`ts-typecheck-gate.test.mjs`

     ```ts
     // DIR-100-B: per-type required fields. name is required for all five entry-bearing
     // arrays; adr is a string array (guarded at its own loop, unchanged).
     const REQUIRED_FIELDS: Record<string, readonly string[]> = {
       it0: ["name", "script", "argsKey"],
       fixed: ["name", "script"],
       testPass: ["name", "command"],
       coverageFloor: ["name", "command", "floor"],
       redGreen: ["name", "red", "green"],
     };

     // Per-field presence predicate — mirrors EACH field's current silent-skip guard exactly
     // (loader.ts:146/158/165/169/173), so the registered-gate set is byte-identical.
     // Param is `unknown`, NOT `Record<string, unknown>` (see typecheck constraint above).
     function fieldPresent(entry: unknown, field: string): boolean {
       const v = (entry as Record<string, unknown>)[field];
       switch (field) {
         case "name":
         case "script":
         case "argsKey":
           return Boolean(v); // mirrors `!entry?.name/script/argsKey`
         case "command":
         case "red":
         case "green":
           return typeof v === "string"; // mirrors `typeof ... !== "string"`
         case "floor":
           return typeof v === "number"; // mirrors `typeof ... !== "number"`
         default:
           return true;
       }
     }

     function emitEntryDiagnostics(type: string, entry: unknown): void {
       const e = entry as Record<string, unknown> | undefined; // unknown -> indexable (see constraint above)
       const missing = (REQUIRED_FIELDS[type] ?? []).filter((f) => !e || !fieldPresent(e, f));
       if (missing.length === 0) return;
       const name = typeof e?.name === "string" && e.name.trim() !== "" ? e.name : "<unnamed>";
       for (const field of missing) {
         // error-severity (gate will not be registered); stderr-only channel (M228 routes later).
         process.stderr.write(`error: ${type} gate '${name}' missing required field '${field}' — gate will not be registered\n`);
       }
     }
     ```

     ```ts
     for (const entry of it0) {
       if (!entry || !fieldPresent(entry, "name") || !fieldPresent(entry, "script") || !fieldPresent(entry, "argsKey")) {
         emitEntryDiagnostics("it0", entry);
         continue;
       }
       ...
     ```
     Equivalently for `fixed` (name/script), `testPass` (name/command), `coverageFloor`
     (name/command/floor), `redGreen` (name/red/green) — ALL with the same no-cast call
     `emitEntryDiagnostics("<type>", entry)` (the `unknown` param accepts any entry type, so no

     above). The factory calls (`:150/162/166/170/174`) and the well-formed entry path are
     UNCHANGED. A null/non-object entry (e.g. `it0: [null]` or a string in the array) hits
     `emitEntryDiagnostics` with `entry` falsy → `<unnamed>` + all required fields, then
     `continue` — matching today's `!entry?.name`-driven skip, now loud.
  3. **The `adr` loop (`:152-156`) is untouched** (string array, own guard already loud enough /
     out of scope).

## Guardrails

- **Skip-set invariant (AC5) is preserved, not changed.** `fieldPresent` mirrors each field's
  EXACT current guard (`Boolean(v)` for name/script/argsKey; `typeof === "string"` for
  command/red/green; `typeof === "number"` for floor), so the set of registered gates is
  byte-identical to base. A malformed entry is skipped exactly as today — now with a diagnostic.
  Enforce by review: because the sibling child M226/DIR-100-A is expected to land FIRST and also
  edits `loader.ts`, master's `loader.ts` at M227 Land contains BOTH children's hunks — a
  base-relative `git diff 5bc637d2 <M227-land>` would NOT isolate M227's changes. Diff the M227
  branch/commit against its PARENT (the M226 land commit, or the merge-base of the M227 branch)
  instead — e.g. `git diff <M226-land> <M227-land> -- packages/quay/src/gate/config/loader.ts` —
  which shows the five factory calls and all well-formed-entry control flow textually unchanged,
  only the guard lines and the new helpers differing. Stage 4's full suite is the mechanical net.
- **`tsc --noEmit` is a real gate, not cosmetic — the snippet is the VERIFIED-compiling form.**
  `fieldPresent`/`emitEntryDiagnostics` take `unknown` (indexing internally via
  `as Record<string, unknown>`) BECAUSE the five entry interfaces have no implicit index
  signature: a `Record<string, unknown>` param fails `tsc --noEmit` with TS2345 on every call
  site, and `entry as Record<string, unknown>` fails with TS2352 (must go through `unknown`
  first) — both reproduced with the repo's own `npx tsc --noEmit` and pinned by
  `ts-typecheck-gate.test.mjs` A2 inside Stage 4's full suite. The error would NOT surface in
  Stages 1–3 (node --test type-strips .ts without typechecking), so only Stage 4 catches a
  regression. Do not rewrite the params/casts during implementation without re-running Stage 4.
- **stderr-only, stdout untouched.** Diagnostics are written via `process.stderr.write` (never
  `console.log`/stdout, never `console.error`'s wrapping). `quay gate --list` stdout is
  byte-identical — enforced by Stage 5's stdout capture. This is the precise channel DIR-100-C's
  `QUAY_GATE_DIAGNOSTICS` sink will later route; M227 does NOT build the env var (out of scope).
- **Diagnostic message shape is pinned.** `error: <type> gate '<name>' missing required field
  '<field>' — gate will not be registered`, with `<unnamed>` when the entry's `name` is absent
  (the task's "the entry name (if present)"). The `error: ` severity prefix is the
  grep-confirmable label DIR-100-C's taxonomy AC will assert. The Stage-1 tests assert this exact
  string.
- **DIR-100-C is NOT anticipated here.** No `QUAY_GATE_DIAGNOSTICS`, no sink abstraction, no
  `warn` taxonomy. Adding any of that would duplicate M228's scope and create a merge hazard.
- **Sibling coordination (M226/DIR-100-A).** Both children touch `loader.ts` + the new test file.
  The loader edits are disjoint by function (`readGatesConfig` vs `loadWorkspaceGates`); Stage 1
  creates-or-appends the test file. **Helper-symbol rule (module-load safety):** the appended
  blocks MUST reuse the first child's existing top-level helpers (`tmpWs`, stderr recorder) and
  must NEVER re-declare a top-level symbol that already exists in the file — a duplicate
  `tmpWs` is a module-load SyntaxError that breaks the whole merged test file, the first child's
  blocks included. Only M227-specific helpers (`captureStderr`) under names confirmed absent are
  added. A Land-time merge conflict still fails closed to needs-human (never
  `--ours`/`--theirs`); do not force it.
- **Test glob ownership (ADR-019/DIR-109):** all suite invocations use `scripts/test.sh` (the
  canonical glob owner) read-only — never hand-write a second glob copy.
- **Touch-set discipline:** every stage's `- Files:` line names only the two code files in the
  task's `## Touches`; `docs/plans/M227-dir-100-b.md` never appears on a `- Files:` line
  (mechanically enforced by `prepare-admission-check.ts`'s `preflightTouchesMismatch` detector via
  `--preflight-plan`).
- **Loop hygiene (DIR-027, CLAUDE.md):** the autonomous loop runs on `master` and is paused by the
  repo-root `.halt` present at authoring. Do not remove `.halt` while working; before un-halting
  run `experiments/quay-perpetual-stream/scripts/restart-readiness-check.sh`. Never race the loop
  on `master`.
- **Stop rule:** at most 3 Plan-check rounds; success only at F_i = 0; otherwise escalate
  `needs-human` — never land on a nonzero residual.

## Rollback

- Any Stage 1–4 failure: fix forward within the stage's budget, or abandon the uncommitted working
  tree (`git checkout -- packages/quay/src/gate/config/loader.ts
  packages/quay/test/gate-diagnostics.test.mjs`) — nothing is landed before the milestone Land
  commit.
- Post-Land regression (Stage 5 refutation): `git revert <land-commit>` on `master` restores the
  original silent-skip behavior. Safe because the change is additive-and-guard-replacing only: a
  new module-level `REQUIRED_FIELDS`/`fieldPresent`/`emitEntryDiagnostics` + five guard-line
  edits + one new test file. It persists no new state, changes no store format, and touches no
  existing control flow beyond the five guards — the revert is a pure text revert with no
  migration. (If M226's `gate-diagnostics.test.mjs` landed in between, revert touches only M227's
  appended blocks; do not clobber M226's.)
- If Stage 4 finds a registration-behavior change (a well-formed gate that previously registered
  no longer does, or vice versa — an AC5 violation the suite would catch), do NOT merge: fix
  `fieldPresent`'s per-field predicate to match the exact base guard and re-run Stages 1–4, then
  re-audit.
