## Guardrails

- **The channel is the single source; A/B route through it, never around it.** `emitDiagnostic`
  is the ONE emission point (`resolveGateDiagnosticsSink` is its only writer). A/B's diagnostic
  emission (M226 unrecognized-key scan, M227 per-entry validation) calls `emitDiagnostic` — the
  executor must NOT introduce a second, parallel write path to `process.stderr`/files, and must
  NOT bypass the sink. **Reconciliation with A/B's landed state (shared `loader.ts` + shared test
  file):** at execution time, check `git log --oneline` for the M226 (`DIR-100-A`/fail-loud scan)
  and M227 (`DIR-100-B`/per-entry validation) land commits. If either has landed, M228's Stage-2
  wiring reuses/adapts its existing `emitDiagnostic(...)` call sites in `loader.ts` instead of
  re-adding them (no duplicate scans, no duplicate tests); if neither has landed, M228 wires the
  anchor sites itself so its own ACs are verifiable. In BOTH orders the severity taxonomy is
  consistent because `DiagnosticSeverity`/`SEVERITY_LABEL`/`emitDiagnostic` are defined exactly
  once in `loader.ts`. Because A/B/C share the SAME new `gate-diagnostics.test.mjs`, the Stage-1
  RED premise is conditional (see Stage 1 Command): if a sibling landed first, reconcile C's
  additions into the landed file (merge, never overwrite) and treat Stage 1's expected exit as
  Stage 2's GREEN rather than a fresh RED. Record the chosen order + reconciliation in the absorb
  entry.
- **stdout is structurally off-limits.** The sink's stderr/file writers never touch
  `process.stdout`; `gate --list` stdout is exactly `listGates(workspaceRoot).join("\n")`
  (quay.ts:1131). No code path in this milestone may add a `console.log` diagnostic.
- **Fail-quiet is preserved for a clean workspace.** A correctly-configured `.quay/config.yml`
  emits ZERO diagnostics (AC of the sibling tasks; the channel must not regress
  `gate-config-loader.test.mjs`'s silent-data-loss and clean-workspace cases). `gates:` parsed as
  null/scalar/array degrades to the current empty shape with no false diagnostic and no
  `Object.keys(null)` throw — the section scan is skipped for arrays too (F2: `typeof [] ===
  "object"`, and `Object.keys(array)` yields numeric index keys that would falsely read as
  unrecognized sections). Per-gate `cwd`/`timeoutMs` are ALWAYS known — the Stage-2 (e) warn
  known-set is PINNED ∪ {`cwd`, `timeoutMs`} — so a valid entry using DIR-046-B's per-gate
  `cwd`/`timeoutMs` never emits a spurious `warn`.
- **Empty/whitespace-only env value is stderr, never a file.** `resolveGateDiagnosticsSink` routes
  `""` and whitespace-only values to `process.stderr` exactly like the absent case (Proposal §1,
  Chosen mechanism). A whitespace string is a legal Linux filename, so treating it as a path would
  silently create a junk file instead of writing stderr — this must not happen. Asserted at Stage 1
  (T1), Stage 2 (b), and Stage 4 (iv).
- **Unwritable/invalid file paths fall back to stderr, never crash.** The file-mode append stream
  MUST attach an `error` listener (Proposal §1, Chosen mechanism): a path whose parent directory
  does not exist (ENOENT) or that names a directory (EISDIR) causes the sink to fall back to
  `process.stderr` — the listener re-emits to stderr the diagnostic line(s) queued to the failed
  stream and swaps the sink's writer to the stderr writer, so `gate --list` NEVER exits nonzero on
  an unhandled WriteStream `error` from a bad `QUAY_GATE_DIAGNOSTICS` value. Asserted at Stage 1
  (T3), Stage 2 (b), and Stage 4 (iii).
- **Once-per-process env read.** `resolveGateDiagnosticsSink` memoizes the sink per process; tests
  that toggle stderr/quiet/file do so via separate `runQuay` subprocesses (each a fresh process
  that reads `QUAY_GATE_DIAGNOSTICS` once), never by mutating `process.env` mid-process and
  expecting the memoized sink to change. **In-process stderr capture ordering (F1):** the
  direct-import unit tests (T1, T4) that assert stderr output must patch/spy
  `process.stderr.write` BEFORE the FIRST `emitDiagnostic` call in the test file — the memoized
  `cachedSink` binds `process.stderr.write` when first resolved, so a patch applied after the
  first emission is never observed by the sink. **Single mode per module instance (F5,
  probe-corrected):** because the sink is memoized, ONLY the mode active at the first resolution is
  observable in a given module instance; a cache-busting query import DOES create a fresh module
  record on Node v26.5.0 (probe: `plain === q1` is false; only same-query-twice and
  relative-vs-fileURL-with-same-query dedupe — see problem state), so in-process quiet/file
  assertions are technically possible, but the plan deliberately keeps them OUT of the shared test
  file's in-process surface. The shared test file therefore asserts the DEFAULT-stderr mode
  in-process (T1, T4) and the quiet/file/empty-whitespace modes ONLY through fresh `runQuay`
  subprocesses (T2, T3, T1's empty case) — never an in-process `emitDiagnostic` call that would
  hit the already-memoized sink.
- **Severity labels are data, not prose.** AC4 is satisfied by `SEVERITY_LABEL` + the `error`/`warn`
  literals at the loader call sites (grep-confirmable), never by a prose claim in the plan or
  absorb entry.
- **Touch-set discipline.** Every stage's `- Files:` line names only `packages/quay/src/gate/
