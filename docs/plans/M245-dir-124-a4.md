  stale-fixture-FAIL, corrected-fixture-PASS, and 3-known-discrepancies-detection fixtures flip
  GREEN. The stale fixture file under `experiments/quay-perpetual-stream/test/fixtures/` must produce at least one `failures[]`
  entry and exit 1. The corrected fixture must produce zero `failures[]` and exit 0. The 4 real
  source files must produce a RED finding for each of the 3 known discrepancies (not vacuously
  green). The node-invocation-consistency check must produce a WARN (not FAIL) for the
  `--no-warnings` divergence between the two workflow files.

Symbols:

- `extractMeta(source)` -- regex-parse `export const meta = { ... }` literal, yields `{ name,
  description, phases: [{title, detail}, ...] }`. Returns `null` with parse-error detail if
  unparseable.
- `extractPhases(source)` -- find all `phase('...')` call sites via regex anchored at
  expression context (negative lookbehind for `//` on the same line), yield `{ labels: Map<string,
  number>, uniqueCount, callCount }`.
- `extractAgents(source)` -- find all `await agent(` / `agent(` call sites, yield
  `{ callCount, labels: [...] }`.
- `extractNodeInvocations(source)` -- count `node --experimental-strip-types` with and without
  `--no-warnings`, yield `{ countWithWarnings, countWithoutWarnings }`.
- `extractReturnOutcomes(source)` -- find all `{ outcome: '...' ...}` and `return { ...
  outcome: '...' ... }` literal outcome values in the body (excluding comments and agent-prompt
  template strings), yield `Set<string>`.
- `extractWorktreeRefs(source)` -- count `_useWorktree` / `_isolationPlan` / `isolationMode`
  references in the body, yield `{ present: bool, refCount }`.
- `extractGateDispatch(source)` -- parse the gate dispatch array labels from `parallel([...])`
  in the body, yield `{ gateLabels: string[], count }`.
- `checkFile(filePath)` -- run all assertions against one source file, return `{ file,
  failures: [...], warnings: [...] }`.
- `checkAll(files[])` -- iterate over an array of file paths, run `checkFile` on
  each, aggregate findings. Returns `{ ok, failures, warnings }`.
- `main(argv)` -- CLI entry: parse `--files` / `--json` flags, run `checkAll`,
  output results (JSON if `--json`, human-readable otherwise), exit 0 if `failures.length === 0`,
  exit 1 otherwise, exit 2 on environment error (missing file, unparseable metadata).

Assertions per claim class (mapped to ACs):

- **Phase-set alignment (AC5):** Parse `meta.phases[]` entries and compare the unique label set
  against `extractPhases()` output. Any phase in body not in metadata is FAIL; any phase in
  metadata not in body is FAIL. Re-entrant labels (same label at multiple call sites) are
  counted as ONE logical phase for set comparison; call-count multiplicity is reported
  separately as a detail.
- **Return-outcome alignment (AC6):** Parse the `outcome:` literal strings from
  `meta.description` (e.g. `"done"|"needs-human"|"building"`) and compare against
  `extractReturnOutcomes()` output. Any outcome value claimed in metadata description but
  ABSENT from all body return sites is FAIL (stale claim). An outcome value in the body but
  not in metadata description is WARN (missing documentation).
- **Agent-count alignment (AC7):** If `meta.description` includes a numeric claim about agent
  dispatches (regex: `\d+\s*agent`), compare against `extractAgents().callCount`. Mismatch is
  FAIL.
- **Node-invocation consistency (AC8):** Compare `extractNodeInvocations()` between the two
  workflow files. Mismatched `--no-warnings` convention (one file uses it, the other does not)
  with no explicit documenting comment is WARN. A comment containing `intentional` or
  `intentionally` adjacent to the node invocation line counts as documented divergence and
  suppresses the WARN.
- **Worktree/isolation mention (AC8 extended):** If `meta.description` or any phase detail
  mentions "worktree" / "isolation", verify `extractWorktreeRefs().present` is true -- a
  false claim is FAIL. Conversely, `extractWorktreeRefs().refCount > 5` without any metadata
  mention is WARN (not FAIL -- metadata omission is less dangerous than a false claim).
- **Cache/resume claim:** If `meta.description` mentions "caching" / "cache" / "resume" /
  "resumable", verify corresponding body patterns exist. Stale claim is FAIL.
- **Gate-count claim:** If `meta.description` or any phase detail mentions a specific gate
  count or names a specific gate, verify the gate dispatch array in the body contains matching
  labels. Stale claim is FAIL.
- **Mirror byte-identity:** `.claude/workflows/<name>.js` and `plugin/workflows/<name>.js`
  MUST be byte-identical for each workflow name. Mismatch is FAIL. (Checked in the test file,
  not in the conformance script itself, to avoid circular dependency.)
- **FAIL/WARN severity split (AC11):** The `checkFile` return object separates `failures[]`
  (false claim -- exit-impacting) from `warnings[]` (missing documentation --
  non-exit-impacting). `--json` output includes both; only `failures.length > 0` drives exit
  code 1. Follows the DIR-100-C diagnostic severity taxonomy: RED = false claim; AMBER =
  suspicious; GREEN = claim verified.
- **Regex extraction, not AST parsing (AC13):** All extraction functions above use pure
  regex/string operations on source text. The checker imports only Node.js built-ins (`fs`,
  `path`, `child_process`). Zero parser-library imports (no acorn, babel, etc.). The test suite
  verifies extraction correctness against known fixtures including the real workflow files.
- **Pure-text extraction, never eval/import (AC14):** The checker reads workflow source files
  via `fs.readFileSync` as text strings. It never `eval()`s, never `import()`s, and never
  executes the workflow source. This avoids the DSL-global-reference problem entirely (`agent`,
  `phase`, `parallel`, `log`, `args` are not importable globals).
- **Extraction function API (AC15):** Every extraction function named in the Symbols list above
  is exported and independently testable. Each is a pure function taking source text and
  returning structured data; no function has side effects or depends on global mutable state.
  The test suite exercises each extraction function independently against both the real workflow
  files and fabricated-stale fixtures, confirming their documented signatures and return shapes.
