## Purpose

`workflow-baseline-metrics.ts` is a new standalone TypeScript script that consumes DIR-124-A1's
workflow event stream (`.workflow-events/*.jsonl`), computes all 10 crystallization-document
baseline metrics mechanically from structured event fields, tags every metric with a
`metricClass` (`mechanical-runner` / `content-agent` / `unknown`), reports missing data as the
JSON string `"unknown"` (never `0` or guess), records the before-state only (no delivered-value
inference, no pass/fail policy, no gate consumption), and is strictly read-only (writes only to
stdout). Follows the established `chart-headroom.ts` / `rolling-slope-check.ts` pattern: shebang,
exported pure functions, `main()` with CLI flags, embedded RED/GREEN selftest fixtures, exit
codes 0/1/2, zero npm dependencies. Both mirrors (`experiments/` and `plugin/`) are
byte-identical at Land. The test file lives at both
`experiments/quay-perpetual-stream/test/workflow-baseline-metrics.test.mjs` and
`plugin/test/workflow-baseline-metrics.test.mjs`, covering metric computation, classification,
unknowns, cross-child consumption, exit codes, and mirror identity.

Fifth child of the DIR-124-A split (M234, `split-multi-mechanism`, 2026-07-31). A5 depends on
A1 (event-stream producer — hard dependency for real evidence; test fixtures use hand-crafted
JSONL matching A1 v1 schema shape for RED/GREEN before A1 lands). A2 (replay fixtures) and A3
(invariant-ownership manifest) are additive dependencies — metrics 4 and 7 are `"unknown"` when
those artifacts are absent; A5 produces a valid (thinner) baseline with any subset of available
sibling data. A5 has no outbound dependencies within the split — DIR-124-E consumes this
baseline.

## Design (grounded in real symbols)

### New script: `workflow-baseline-metrics.ts` (both mirrors)

Single-file TypeScript script under `node --experimental-strip-types` (the same interpreter
precedent as `chart-headroom.ts` / `rolling-slope-check.ts` / `chart2-s3-external-validation.ts`).
Zero npm dependencies beyond Node.js built-ins (`fs`, `path`). Inline CLI argument parsing via
hand-written `for`-loop over `process.argv` (matching the established convention — no shared
argument parser import).

**Shebang and entry point:**
```ts
#!/usr/bin/env node --experimental-strip-types
// workflow-baseline-metrics.ts — mechanical baseline metrics from A1 event stream
```

**Exported pure functions** (all deterministic, no randomness, no side effects in production
path):

- **`parseEventStream(eventDir)`** — reads all `*.jsonl` files from `eventDir`, streams each
  line, validates against A1 v1 schema expectations (`timing`, `agentLabel`, `commandIdentity`,
  `observedWrites`, `outcome`, `waitReason`, `resourceClaim`, `stage`, `eventKind`, `candidateId`,
  `runId`, `isolationMode`, `dispatchMode`, `attempt`, `schemaVersion`). Malformed JSON lines are
  skipped with a `parseWarning` entry `{type: "malformed-line", file, line, error}` — never
  crashes. If ALL events in ALL logs are corrupt, returns `{events: [], parseWarnings: [...],
  status: "no-data"}`. Forward-compatible: events with `schemaVersion !== "1"` produce a stderr
  warning, are processed with v1 field expectations; unknown fields silently ignored.
- **`classifyEvent(event)`** → `"mechanical-runner" | "content-agent" | "unknown"`. Rule-based
  (never LLM-judged):
  - If `event.commandIdentity` matches a known mechanical script pattern
    (`node --experimental-strip-types experiments/quay-perpetual-stream/scripts/` or
    `scripts/test.sh` or `scripts/*.sh`), or contains one of the known mechanical agent labels
    (`ceiling-check`, `gate-hash`, `line-budget`, `dogfood-evidence`, `composite-preflight`,
    `worktree-create`, `worktree-merge`, `worktree-remove`, `build-evidence-collector`,
    `emit-event-*`): `"mechanical-runner"`.
  - Priority rule when both `commandIdentity` (matching a script) and `agentLabel` (matching a
    content prefix) are present: `commandIdentity` script-match WINS — the observable mechanical
    behavior dominates.
  - If only `agentLabel` present (no script `commandIdentity`) and `agentLabel` matches a
    content-agent prefix pattern (`ProposalAuthors`, `Adjudicate`, `ProposalReview`,
    `PlanAuthor`, `PlanCheck`, `Build`, `Audit`, `domain-misfit`, `prepare-receipt`):
    `"content-agent"`.
  - If `commandIdentity` is null AND `agentLabel` is null or unrecognized: `"unknown"`.
  - If `commandIdentity` is null AND `agentLabel` is non-null but unrecognized: `"unknown"`
    (conservative — don't guess).
- **`classifyMetric(metricName, events, computation)`** → `"mechanical-runner" |
  "content-agent" | "unknown"`. Metrics 1, 3-10 are `"mechanical-runner"` (sourced from
  mechanical phase boundaries, timing readings, or CLI-invocation-pattern counts). Metric 2 is
  `"content-agent"` (accurate file-read enumeration requires more than `commandIdentity` string
  matching). If classification is ambiguous, `"unknown"`.
- **`computeChangePropagationRadius(events)`** → metric 1. Groups events by `candidateId`.
  Counts unique file paths and unique parent directories across `observedWrites` for each
  candidate. Reports `{uniqueFiles, uniqueDirectories, paths}` per candidate plus aggregate
  min/median/max. Events with null `observedWrites` are excluded.
- **`computeContextWorkingSet(events)`** → metric 2. Enumerates files each stage's agent or
  script read. Script invocations: parse `commandIdentity` for `<script-path>` and
  `--<flag> <path>` arguments. Agent invocations: use `agentLabel` to look up corresponding
  task `.md` file and charter file. `observedWrites` provides a lower-bound estimate. Stages
  with no `commandIdentity` AND no `observedWrites` report `"unknown"`.
- **`computeSharedWriterCount(events)`** → metric 3. For each candidate, computes pairwise
  intersection of `observedWrites` across all stages. Counts stage pairs with non-empty
  intersection. Reports `{sharedWriterPairs, pairs: [{stageA, stageB, commonPaths}]}`.
- **`computeDuplicateRuleCount(manifest)`** → metric 4. Parses A3's `invariant-ownership.md`
  manifest from disk. Counts rules where `## Invariant:` block's "Other occurrences" section
  contains at least one `[duplicate-to-remove]` entry. If A3 has not landed (manifest file
  absent), reports `"unknown"` with note `"A3 invariant-ownership manifest not yet available"`.
  Never re-implements A3's own duplicate detection.
- **`computePromptToCodeRatio(events)`** → metric 5. Classifies each `commandIdentity`:
  mechanical-script invocation matches `node --experimental-strip-types
  experiments/quay-perpetual-stream/scripts/` or `scripts/test.sh` or `scripts/*.sh`.
  Agent-only NL instruction has `commandIdentity` matching an agent label pattern without a
  shell-out script match. Ratio = mechanical-count / (mechanical-count + content-agent-count).
  Events with null `commandIdentity` are excluded from denominator.
- **`computeReceiptReuseRate(events)`** → metric 6. Counts end-events where
  `outcome === "skipped"` and `waitReason` matches `"cache-hit"` or `"prepared-blocked"`,
  divided by total Prepared end-events with non-null `outcome`. Candidates with no Prepared
  stage contribute a null entry.
- **`computeReplayVariance(replayFixturesDir, events)`** → metric 7. Reads A2 fixtures from
  disk (if they exist). For each fixture, extracts expected `{outcome, stage, observedWrites}`
  assertions and compares against actual events for matching `candidateId` + `stage`.
  Deterministic field comparison. Mismatches counted. If A2 fixtures do not exist, reports
  `"unknown"`.
- **`computeFailureAttributionPrecision(events)`** → metric 8. Counts events where `stage`,
  `waitReason`, AND `commandIdentity` are all non-null (all three attribution dimensions
  present). Divides by total `needs-human` end-events. Reports `{preciselyAttributed,
  totalNeedsHuman, precision}`.
- **`computeFullSuiteExecutions(events)`** → metric 9. Counts per `candidateId` events where
  `commandIdentity` includes `scripts/test.sh` (the canonical test entrypoint per
  ADR-019/DIR-109). Broken down by `stage`.
- **`computeLandFenceTime(events)`** → metric 10. Land-stage end-events:
  `landQueueMs = startedAtMs - queuedAtMs`, `landDurationMs = endedAtMs - startedAtMs`,
  `totalLandMs = landQueueMs + landDurationMs`. Per-candidate and aggregate min/median/max.
- **`computeAgentMinutes(events)`** → diagnostic. Sum of
  `timing.endedAtMs - timing.startedAtMs` across all content-agent events, converted to minutes.
  Broken down by `stage` and `agentLabel`. Mechanical-runner events excluded.
- **`computeFindingRecurrence(events)`** → diagnostic. Extracted from `outcome` + `waitReason`
  combinations across candidates. A finding is "novel" if the specific
  `{outcome, waitReason, stage}` tuple appears for the first time; "recurrent" if it appears
  across multiple candidates. Ordered by event timestamp.
- **`computeArtifactClassOutput(events)`** → diagnostic. From `observedWrites`, categorized by
  file extension and directory prefix: `code` (paths under `experiments/` or `packages/`),
  `docs` (paths under `docs/`), `tasks` (paths under `tasks/`), `milestones` (paths under
  `milestones/`), `other` (everything else). Byte counts are `"unknown"` — `observedWrites`
  records paths only, not byte deltas.
- **`buildBaselineReport(events, { manifest, replayFixturesDir })`** → the full structured JSON
  report with `schemaVersion: "1"`, `scriptVersion: "1.0.0"`, `generatedAt` (ISO8601),
  `samples` (count), `sampleRunIds`, `sampleRange`, `parseWarnings`, `metrics` (all 10 metrics
  with per-candidate and aggregate views), `diagnostics` (agent-minutes, tokens, finding
  novelty/recurrence, artifact-class output), and `status` (`"ok"`, `"no-data"`, or `"error"`).
  Every metric value is either a computed object with `evidenceStatus: "measured"` and
  `metricClass` or the JSON string `"unknown"` with `evidenceStatus: "unknown"` and a `reason`
  field. Tokens diagnostic is always `"unknown"` with note `"token usage is not in A1 v1 event
  schema — available when DIR-124-B extends the schema"`.
- **`parseInvariantManifest(manifestPath)`** → parses A3's `invariant-ownership.md` for
  `## Invariant:` blocks with "Other occurrences" sections containing `[duplicate-to-remove]`
  entries. Returns structured list of duplicate rules.

**CLI surface** (`main()` function):
```
Usage: workflow-baseline-metrics.ts [--event-dir <path>] [--manifest <path>]
       [--replay-fixtures <path>] [--json] [--selftest]

  --event-dir <path>       Event log directory (default: experiments/quay-perpetual-stream/.workflow-events)
  --manifest <path>        A3 invariant-ownership manifest (default: experiments/quay-perpetual-stream/invariant-ownership.md)
  --replay-fixtures <path> A2 replay fixture directory (default: experiments/quay-perpetual-stream/fixtures/workflow-replay)
  --json                   Emit structured JSON report to stdout
  --selftest               Run embedded RED/GREEN fixtures
```

**Exit codes:** 0 = valid report (even if all-unknown — an honest empty baseline is valid
output), 1 = selftest failure, 2 = usage/environment error (unreadable event dir, zero JSONL
files, unreadable manifest).

**Zero-sample behavior:** When zero `.jsonl` files exist in the event directory, reports
`{samples: 0, status: "no-data"}` to stdout, exits 0. All 10 metrics are `"unknown"` with
reason `"no-event-samples"`. Not an error — an honest empty baseline.

**Read-only guarantee:** The production code path never calls `writeFileSync`, `appendFileSync`,
`mkdirSync`, `rmSync`, `cpSync`, or any other filesystem mutation function. The selftest section
creates temp fixtures with `mkdtempSync`/`writeFileSync` and cleans them up with `rmSync`, but
these are only reachable via `--selftest`. Verified mechanically: `grep` for mutation functions
returns zero hits on non-selftest code.

**Selftest fixtures (embedded RED/GREEN):**
- GREEN: synthetic JSONL event stream produces correct values for all 10 metrics (AC1)
- GREEN: zero samples produces `{samples: 0, status: "no-data"}`, exit 0 (AC5)
- RED: null metric field produces `"unknown"`, not `0` (AC3)
- RED: malformed JSONL line is skipped with `parseWarning` entry (AC10)
- RED: event with no `observedWrites` contributes zero to applicable metrics (AC3)
- RED: unreadable directory exits non-zero (AC10)
- GREEN: classification table produces correct `metricClass` tags for known agent labels and
  `commandIdentity` patterns (AC2, AC12, AC13)
- RED: ambiguous event (both mechanical `commandIdentity` and content `agentLabel`) produces
  `metricClass: "mechanical-runner"` — `commandIdentity` wins (AC14)
- RED: agentLabel-only event produces `"content-agent"`; neither-match produces `"unknown"`
  (AC14)
- GREEN: every metric in output has `metricClass`; every classified event has `agentLabel` and
  `commandIdentity` (or `null`) (AC15)
- GREEN: mock A2/A3 fixtures present produces populated metrics 4 and 7 (AC8)
- RED: mock A2/A3 fixtures absent produces `"unknown"` for metrics 4 and 7 (AC8)

## Guardrails / rollback / real-landing verification

### Guardrails
- **Read-only consumer (DD10):** The production code path never calls any filesystem mutation
  function (`writeFileSync`, `appendFileSync`, `mkdirSync`, `rmSync`, `cpSync`). Verified
  mechanically: `grep` returns zero hits outside the `--selftest` section. A5 is a pure
  fire-and-forget consumer — never writes to the A1 event stream, never mutates workflow state,
  never changes lifecycle status.
- **Explicit unknowns, never zeros (DD3):** Every metric without real evidence is reported as
  the JSON string `"unknown"` with `evidenceStatus: "unknown"` and a `reason` field. The string
  `"unknown"` is semantically distinct from `0` — a consumer can distinguish "not measured"
  from "measured and found to be zero." Zero is a meaningful measurement (e.g., zero
  full-suite runs); unknown means "we don't know."
- **Before-state only (DD4):** No "quality" score, no recommendation, no pass/fail threshold.
  No gate consumption. No lifecycle decision reference. Purely a measurement instrument.
- **Rule-based classification (DD2):** `metricClass` is classified by deterministic rule-based
  matching of `agentLabel` prefix patterns and `commandIdentity` script-path patterns — never
  LLM-judged. Ambiguous entries produce `"unknown"` rather than a guess. Priority rule:
  `commandIdentity` script-match WINS over `agentLabel`. Auditable line-by-line.
- **Mechanical computation from structured fields (DD1):** Every metric is derived from A1
  event fields via deterministic functions (count, unique, fraction, delta) — no prose parsing,
  no Claude Code timeline reconstruction, no agent structured-output interpretation.
- **Cross-child dependencies additive, not mandatory (DD5):** Only A1 is hard (without event
  log files, status is `"no-data"`). A2 and A3 are additive — their absence produces
  `"unknown"` metrics, never a crash. A5 produces a valid baseline with any subset of available
  sibling data.
- **Follows established pattern exactly (DD6):** Shebang, exported pure functions, `main()`
  with CLI flags, inline `process.argv` parsing, embedded RED/GREEN selftest fixtures using
  `mkdtempSync`/`writeFileSync`/`rmSync`, exit codes 0/1/2, zero npm dependencies. Matches
  `chart-headroom.ts` / `rolling-slope-check.ts` / `chart2-s3-external-validation.ts`
  byte-for-convention.
- **Mirrors byte-identical (DD7):** Both `experiments/scripts/` and `plugin/scripts/` copies
  byte-identical at Land. Both test file mirrors byte-identical. Two `diff` gates (script pair,
  test pair) + existing mirror-diff convention enforce this.
- **Forward-compatible schema read:** Events with `schemaVersion !== "1"` produce a stderr
  warning and are processed with v1 field expectations. New v2 fields silently ignored; removed
  v1 fields produce `"unknown"`. Never crashes on schema version mismatch.
- **Fail-soft on malformed input:** A single corrupted JSONL line is skipped with a
  `parseWarnings` entry. If ALL events in ALL logs are corrupt, status is `"no-data"` (exit 0).
