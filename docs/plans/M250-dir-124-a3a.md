Symbols and implementation contract:

- `parseManifest(text)` -- uses `extractSection(text, heading)` imported from `./task-schema.ts`
  (line 73, the EXISTING canonical section parser) to extract each `## Invariant:` block. For each
  block: locates `**Authoritative owner:**` line via regex `/^\s*-\s+\*\*Authoritative owner:\*\*\s*(.+)$/im`;
  extracts path token via regex `` /`([^`]+)`\s+`\[authoritative\]`/ ``; fails (exit 2) if not parseable.
  Scans `**Other occurrences:**` lines for classification-tagged entries. Returns structured block
  objects `{ name, authoritativeOwner: { path, lineNumber }, otherOccurrences: [{ path, classification,
  rationale }] }`.
- `validateSingleOwner(blocks)` -- returns `violations[]` for any block with zero or more than one
  `[authoritative]` occurrence (AC 2: two-owner violation; also catches orphaned blocks with zero
  owners).
- `validateOwnerExists(blocks, workspaceRoot)` -- resolves each `[authoritative]` path against
  `workspaceRoot` via `path.resolve(workspaceRoot, block.authoritativeOwner.path)`, calls
  `fs.existsSync`. Returns `violations[]` for any non-existent path (AC 3: owner-exists).
- `collectDeletionList(blocks)` -- aggregates all `[duplicate-to-remove]` entries into
  `deletionList[]` array with `{ invariant, path, classification }` (AC 9: deletionList output).
- `collectMirrorList(blocks)` -- aggregates `[dsl-necessity-mirror]` entries into `mirrorList[]`.
- `collectAdapterList(blocks)` -- aggregates `[compatibility-adapter]` entries into `adapterList[]`.
- `main(argv)` -- CLI wrapper. Parses the manifest path from `argv[2]` (or `--manifest <path>`).
  If the manifest file does not exist AND `--require-manifest` is NOT set: emits JSON with
  `ok: true, totalInvariants: 0, warnings: ["no manifest found -- invariant ownership unchecked"]`,
  exits 0 (AC 8: soft-launch). If manifest absent AND `--require-manifest` IS set: exits 2 with
  diagnostic to stderr (AC 8: strict mode). Otherwise: reads the manifest, calls
  `parseManifest`, `validateSingleOwner`, `validateOwnerExists`, `collectDeletionList`,
  `collectMirrorList`, `collectAdapterList`, emits JSON to stdout, exits 0 if no violations else
  exit 1.
- The enforcement script is a pure read-only validator -- it writes nothing and mutates no state.
- Import: `import { extractSection } from './task-schema.ts'` at the top of the `.mjs` file
  (AC 6: imports extractSection, no reimplemented parser). The enforcement script contains NO
  regex-based section parsing beyond the import -- verified by grep in the test.

Exit code contract:
- 0: clean (no violations, or soft-launch missing-manifest)
- 1: invariant-ownership violation (duplicate/missing authoritative owner, or missing owner file)
- 2: usage/environment error (unparseable manifest, missing manifest with --require-manifest,
  enforcement script not found by DoD check)

plugin/scripts/workflow-invariant-ownership.mjs` -- MUST be byte-identical (AC 4: script mirror).

// --- Clause 13: Invariant-ownership gate (DIR-124-A3a) ---
// Shells out to workflow-invariant-ownership.mjs -- the invariant-ownership enforcement script
// that validates the manifest's structural integrity (one authoritative owner per invariant,
// all owner paths resolve to existing files). Runs UNCONDITIONALLY every check (mirrors
// clauses 10/11/12's shape -- always dispositioned, never conditionally-skippable).
{
  const scriptPath = path.join(__dirname, "workflow-invariant-ownership.mjs");
  if (!fs.existsSync(scriptPath)) {
    throw new DodCheckEnvError(`ERROR: sibling script not found: ${scriptPath}`);
  }
  const manifestPath = path.join(process.cwd(), "experiments", "quay-perpetual-stream", "invariant-ownership.md");
  try {
    const out = execFileSync("node", [scriptPath, manifestPath], { encoding: "utf8" });
    const parsed = JSON.parse(out);
    const summary = parsed.warnings?.length
      ? `PASS (warnings: ${parsed.warnings.join("; ")})`
      : `PASS — ${parsed.totalInvariants} invariants validated, ${parsed.violations?.length || 0} violations`;
    passes.push(`clause13-invariant-ownership: ${summary}`);
    dispositionedClauses.add("invariant-ownership");
  } catch (e) {
    if (e.status === 1) {
      const out = (e.stdout || "").toString().trim();
      let parsed;
      try { parsed = JSON.parse(out); } catch (_) { parsed = null; }
      const detail = parsed?.violations?.length
        ? parsed.violations.map((v) => `${v.invariant}: ${v.detail}`).join("; ")
        : (out.split("\n")[0] || "(no output)");
      failures.push(`clause13-invariant-ownership: FAIL — ${detail}`);
      dispositionedClauses.add("invariant-ownership");
    } else {
      throw new DodCheckEnvError(`ERROR: workflow-invariant-ownership.mjs usage/environment error (exit ${e.status}): ${(e.stderr || "").toString().trim()}`);
    }
  }
}

## Guardrails and rollback

- The enforcement script is a pure read-only validator -- it writes nothing and mutates no state.
  Rolling back this milestone means reverting the commit; no data migration or cleanup is needed.
- The soft-launch missing-manifest behavior means that if the manifest is somehow deleted after
  landing, the DoD gate does not fail (exits 0 with warning). This is deliberate: the soft-launch
  prevents a deadlocked pipeline, at the cost of silently skipping the check when the manifest is
  absent. Once the manifest lands and stabilizes, a future milestone can remove the soft-launch
  by always passing `--require-manifest`.
- Clause 13 is additive -- existing clauses 0-12 are untouched. If Clause 13 is found to be
  problematic, removing the clause block and its entries from `MECHANICALLY_UNCONDITIONAL_CLAUSES`
  and `clauseNames` reverts the DoD gate to its prior behavior with no side effects.
- The manifest is forward-only. Pre-existing milestones that lack the manifest are not
  retroactively validated. The soft-launch behavior handles the transition seamlessly.
- Plugin mirrors are byte-identical copies. If the authoritative copy changes, both mirrors must
  be updated together. The test asserts byte-identity at GREEN time.
- The three inline DSL mirrors in `execute-milestone.js` are classified as `[dsl-necessity-mirror]`,
  NOT `[duplicate-to-remove]`. Their continued existence is intentional and documented.
