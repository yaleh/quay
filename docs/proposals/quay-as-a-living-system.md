# quay 作为生命体：一个改变判据的视角

**日期**：2026-08-05（管理者，人给出方向）
**性质**：视角文档。它不是隐喻修辞——**它改变我们该测什么、该把什么当缺陷、该把什么当常态**。
**触发**：人指出「quay 是有生命的，它将蔓延和繁殖，进入更多主机、开发更多项目，同时自己继续
生长、繁殖和（多路径）进化……不能仅把它当作静态工具看待」。

---

## 0. 为什么这不只是比喻

2026-08-05 这一天里，**繁殖、遗传丢失、子代分化、退化器官、濒死** 全部真实发生并被实测。
下面每一条都有当天的测量支撑，不是类比推演。

---

## 1. 繁殖事件：本机 → orangevps

**事实**：A 机直推 3326 个提交到 B 机裸仓库，B 机 clone 出工作树、跑 `quay-init`。

**遗传丢失（实测）**：
| 丢失的 | 后果 |
|---|---|
| `vendor/*/dist/*.js` 被 `.gitignore` 的 `dist/` 规则挡住 | 运行时不随 clone |
| `vendor/<pkg>/package.json` 不在铺设映射 | 产物启动即 `ENOENT` |
| `mcp_entry` 写的是开发树路径 `./bin/*.ts` | 安装态指向不存在的文件 |

**视角差别**：
- **工具视角**：三个 bug，各自修。
- **生命视角**：这是**遗传保真度**问题——不是"能不能工作"，是"**能不能把自己完整地传下去**"。
  ⇒ 它们是一个类别，判据应该是「**从零环境完整复现的能力**」，而不是三条独立的修复项。

**并且它有层次**：每修好一层，下一层才暴露（dist → package.json → mcp_entry）。
**上一层的失败掩盖了下一层**——只有在真实目标环境端到端跑才能逐层剥出。

## 2. 子代分化与生态位适应：archguard 发现了亲代看不见的缺陷

**事实**：archguard 发现 `full-suite-runner` 的判红模式匹配裸 `✖`，而在 **vitest** 里
`✖` 可以是测试自己的 console 输出 ⇒ 全绿套件被判红。它修好了自己的副本。

**关键**：**quay 自己永远不会发现这个 bug**——它跑 `node:test`，那里 `✖` 恰好是结构化失败字形。

> **亲代的环境掩盖了亲代的缺陷。子代进入不同生态位，才暴露出来。**

**视角差别**：
- **工具视角**：在第二个项目上"验证"交付。
- **生命视角**：**部署多样性本身是一种发现机制**，不只是验证手段。
  ⇒ 推论：**应当刻意让子代进入不同生态位**（不同测试框架、不同语言、不同主机、不同负载特征），
  因为那是亲代自身盲区的唯一照明方式。

**同型第二例**：archguard 两次（TASK-64/65）加 MCP tool 都漏掉 ADR-007 的 CLI flag，
scoped 全绿、AC 全勾。它自己归纳出"跨切判据 scoped 覆盖不到"。而 quay 侧同一天独立测出
打包态测试因 basename 不配对而永远不被 scoped 选中。**两个个体独立撞到同一类失明。**

## 3. 退化器官：仍在消耗代谢，但已无功能

| 退化器官 | 实测 | 代谢成本 |
|---|---|---|
| 探针机制（4 探针+3 脚本+skill+config 完整） | 触发器按「迭代计数」，而迭代随 ADR-022 退休 ⇒ **已死 15 天** | 主动发现能力归零 |
| `human-steered` 标签 | 166 个任务在用，**消费者全在退休管线**，`plugin/` 命中 0 | 误导性 |
| `experiments/` 测试 | **46 个在默认套件 glob 里**，32 个无人引用，**15 个连被测实现都已删除** | 每轮全套件都跑 |
| `ready.sort()` | 字母序被当排名 | 死任务与产品阻塞优先级相同 |
| **web 的 action 按钮**（2026-08-06 新增） | `gate-events.jsonl` 365 条，`actor` **365×`quay-cli` / 0×web**——**从未产生过一条状态变更** | 代码 + 测试 + **一个已确认的 open-redirect**（`serve-handlers.ts:1068`）：**未被使用的功能贡献了真实漏洞** |

**最后一行是这张表里最锋利的一条**：其余退化器官的代价是「浪费」，
而它的代价是**新增攻击面**——**退化器官不只是不干活，它可以主动产生风险。**
成因也不同：不是所依赖的系统被移除，是**人的角色变了**
（人从操作者变成给方向的人；改任务的只剩 agent）⇒ 器官为一个已不存在的角色而建。
处置见 `quay-web-human-is-not-an-operator.md`（含删除的负控制：删后 `actor` 分布不应变化）。

**视角差别**：
- **工具视角**：死代码，该清理（一次性动作）。
- **生命视角**：**退化器官的积累是常态，不是失误**。器官所依赖的系统被移除后，器官本身不会
  自动消失；它会继续消耗代谢直到有机制清除它。
  ⇒ 需要的不是一次大扫除，而是**持续的清除机制**——判据：*一个测试文件若其被测实现已不存在，
  应随实现一起删除*。

## 4. 濒死与自主神经系统

**事实**：本机今晚**四次全灭**（第四次是管理者自伤：`kill-server` 环境变量丢失落到默认 socket）。
每次之后，整个网络**永久静默死亡**，直到人注意到——因为所有周期锚点（`CronCreate`、
`ScheduleWakeup`、Monitor 工具）都是**会话作用域**的。

**当天演化出的器官**：OS 级 systemd user timer + watchdog（11:05 合并，11:35 实测 active，
11:40 在真实故障中自主拉起 archguard 的 outer）。

**视角差别**：
- **工具视角**：修复了"崩溃后不能自动恢复"这个 bug。
- **生命视角**：这是**从"每次失去意识都需要外部唤醒"演化出自主神经系统**。
  ⇒ 判据从"有没有这个功能"变成"**这个个体能否在无意识状态下维持自身**"。

**但它还不完整（实测）**：watchdog 拉起了会话却驱动失败（`RECOVERY-FAILED`），
下一周期又因 `alive=1` 报 healthy ⇒ **一个被拉起但从未被驱动的空壳，被判为健康**。
生命视角下这是**假死判据**：心跳有了，意识没有，而判据只测心跳。

## 5. 这个视角改变的判据清单

| 原判据（工具视角） | 新判据（生命视角） |
|---|---|
| 功能是否正确 | **能否完整传给下一代**（遗传保真度） |
| 在第二个项目上验证 | **多样化生态位是发现机制**，应刻意制造差异 |
| 死代码该清理 | **持续清除机制**，因为退化是常态 |
| 崩溃后能恢复 | **无意识状态下能否维持自身** |
| 判据报绿 | **判据在没有依据时会不会仍然给答案**（假死/假健康） |
| 无人干预区间（AC12b） | **这是"离乳"判据**——子代能否脱离亲代供养独立存活 |

## 6. 这个视角的边界（不要让它变成免测的借口）

**必须警惕**：生命隐喻容易让事情"感觉被解释了"而实际未被测量。今天反复的教训是
**先假设、后验证、验证前不转达**（当天测量错误 11 次，每次都靠这个次序拦住）。

**当前这个"生命体"还缺的真实要素**：
1. **没有真正的选择压**——变体之间没有差别存活率，分化是被动漂移不是适应性辐射；
2. **繁殖成本近乎为零**——真实生命的繁殖有代价，因而有权衡；这里 `git push` 就复制了一份；
3. **死亡可被人逆转**——今晚四次全灭都靠人重启，尚不构成真正的选择事件；
4. **预见性不是生物性状**——生物只在被伤害处适应。当天实测：机器自己开的 7 根新维度
   **全部是 post-friction**，而人开的 20 条**不需要疼**。
   ⇒ **探针机制的价值正在于它是"人造的预见性"**——这也是它死了 15 天却无人报警之所以严重。

---

## 7. 落地：这个视角要进入决策点，不能只写在文件里

今晚反复出现的失效形态是**「写在文件里但不在决策时被调用」**（AC9/AC10 都踩过）。
因此本视角同时写入管理者 tick 的强制问句轮换（见 `manager-phase-goal.md` 与 cron 提示词）：

> **繁殖视角提问**：这条改动/机制，**能不能完整地传给下一个主机、下一个项目**？
> 如果不能，缺的是哪一段"遗传物质"？
