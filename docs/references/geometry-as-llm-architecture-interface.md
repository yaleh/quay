# 几何框架作为 LLM 软件架构接口的可用性讨论

> 本文记录一次以 manda 项目演进为实证、围绕「几何信息论（GIT）/ 语义空间」框架
> 能否帮助 LLM 理解与处理软件架构」展开的讨论。讨论对象是两套框架文本：
> (1) 一份把软件开发建模为高维语义空间 `S` 上动态采样/展开的表述（typed semantic
> graph 是 `S` 的稀疏投影 `Π_t(S)`，含 mapping-point / φ / ψ / 距离-密度-方向-残差
> 四类约束）；(2) 《基于几何信息论的未来软件开发与信息系统建设》（MDL 基本公理
> `L(X)=L(G)+L(R|G)`、可行流形 `M_T`、Fisher 度量与自然梯度、本征维度、五项统一损失、
> 扩张↔收敛「呼吸」两阶段）。
>
> 本文不是对上述框架的背书，而是一次带反驳的审计 + 一次样本外验证 + 一个建设性
> 抽象方向。结论分层给出「证据充分 / 机制成立待验 / 假统一」三档。

## 0. 讨论用的判据

一个形式化对 LLM 是否有用，只认三种价值，其余算事后叙事：

1. **生成性**：它是否改变了「去测量什么」。
2. **预测性**：它是否给出 plain reasoning 给不出的**样本外**预测。
3. **压缩/迁移**：它是否把一个语境的决策压缩迁移到另一语境。

并用 GIT 自身逻辑重设「统一表征」的判据：一个表征的价值不是「必要性」，而是
**压缩率 + 迁移率**。

## 1. manda 作为实证：三次架构反转

用 archguard（Go Atlas）+ 手工 import 核实得到的当前依赖结构：`internal/daemon`
（通信核心）与 `internal/dispatch`（任务语义）零交叉依赖，只在 `internal/mcp` /
adapter 自有 MCP 汇合；`internal/core` 只依赖 `internal/adapter` 接口。8 包、~3,100
行（非测试），无 god package，无环，entity 覆盖率 1。

结构之所以干净，是三次「做出来→真实验证→发现不对→写决策→改回来」反转的产物，
而非一次设计对：

| 反转 | 模型先验里的高密度吸引子（错） | manda 真解（低密度） | 校正本质 |
|---|---|---|---|
| 注册表 TASK-2.1→2.6/TASK-6 | 「服务发现 = registry + 心跳 TTL」 | 「在线 = daemon 已有 SSE 订阅集」 | 删 registry：`L(G)↓`，行为不变——**假支柱** |
| 进程拓扑 TASK-3 | 「daemon = 独立长驻进程」 | 「`manda watch` 进程即 server」 | 砍掉一个独立部署概念，`d↓` |
| 任务归属 TASK-9v1→decision-1→redo | 「加功能 = 接进现有 binary」（最低 `L(R\|G)` 局部步） | 「core 只通信，任务是对等 adapter binary」 | 朴素 `∇L` 指错方向，需自然梯度 `I⁻¹∇L` |

关键机制（关于 LLM 自身、去几何化后仍成立）：**LLM 寻模，缺强局部证据时被拉向训练
分布里最典型的架构**。novel 项目的真解落在先验低概率区，所以每轮 ψ 默认漂回熟悉
吸引子，收敛慢——只有可执行反馈 `E` 能翻越密度先验。（注：全文「吸引子」与「势垒」
并非两种独立事物，而是同一势景 `U` 相对不同参考系的读数；严格表述见 §8，此前各节
的分开措辞按此校准。）

## 2. E 的采样保真度上界残差可观测性（对两框架的补充）

TASK-8 的「curl 模拟 vs 真实 subagent」是最有信息量的一幕：第一轮 e2e 用 curl 冒充
subagent 跑通，`L_T=0` 验收过，**但设计仍是错的**。原因：图 `G` 里 `curl≈subagent`
（相邻节点），但语义空间 `S` 里二者沿**恰好最关键的一维**（工具面 `Monitor/TaskStop`
有、`TaskList/Agent` 无；生命周期任务结束即消亡）距离极远——这正是 proposal-v3
session/subagent 非对称表所依赖的维度。

用 curl 当采样仪器 = 让 `Π_E` 把设计成败所系的那一维压扁成 0，`L_T=0` 是沿盲维的
**伪收敛**。团队的关键动作不是写更好的代码，而是**修采样仪器**（改真 subagent 自
武装 Monitor），残差立刻显形：executor 侧治理（Claimer/Monitor）根本没接线。

- 对 GIT：`L_T` 的意义不超过 `T` 对流形相关方向的覆盖；廉价代理测试在错误轴上给出
  `L_T=0`。
- 对语义空间框架：`E` 也有投影算子 `Π_E`；当它塌缩「真解与熟悉解相异的那一维」时，
  agent 会自信地收敛到错误盆地。

## 3. 样本外验证：TASK-12.1 的预测与判定

先前作出的条件预测：**「ψ 会把 TASK-12.1（executor 执行治理）过度展开成一个重量级
controller——除非事先挖好势垒把它钉在薄-adapter 盆地里。」**

执行后实测（编译两个二进制并真跑治理 e2e，非信 commit message）：

- **保护分支触发，盆地守住。** `cmd/manda-dispatch/executor.go` 419 行，全为一次性
  子命令 `claim/release/exec/reap`；无常驻进程 / `ListenAndServe` / ticker /
  reconcile 循环 / `Controller` 类型；唯二 goroutine 只作用于单次 `exec`。
- **库一行未改。** TASK-12.1 提交未动 `internal/dispatch`（仍 797 行），只把已存在
  已测的 `Claimer`/`WatchForCancel`/`InjectCancelledFallback` 接到 CLI 表面——是
  **接线**不是造控制器。
- **过度展开的经典诱惑被显式拒绝。** 跨进程全局配额没有盖共享状态后端/常驻协调者，
  cap 保持进程内 ledger，跨进程边界写进 `docs/extensions.md` 当限制说明。
- **实跑三场景全绿**（scratch daemon）：cap=1 第二个 claim 真被拒且不发 claim 事件；
  双 claim 恰一个赢；`kill -9`→`failed` 终态，孤儿→reap 成 `cancelled`。build+vet
  干净，覆盖 82.9%。

**势垒承重、非装饰**：同一系统在 TASK-9 v1 就真按预测过度展开过（把 dispatch 塞进
core），decision-1 因此而写。钉住 12.1 的是三道**事前**势垒：(1) 可执行 import-guard
`internal/arch/importguard_test.go`（断言 core 三包永不 import dispatch，且子串匹配
主动覆盖兄弟包 `internal/dispatchmcp`）；(2) 12.1 spec 本身「只做表面接线，不改库
语义」；(3) e2e + DoD gate 在实现前定义。

**诚实修正**：decision-1 与分阶段 spec **都早于该预测**。所以那不是 out-of-sample
预测，是 retrodiction——描述了一个已被防住的机制。真正有价值的信号不是「预测中了」，
而是对照 TASK-9（反应式挖墙）与 TASK-12（前置式立规）：**项目的采样算子 `Π_t` 已从
「撞墙后挖势垒」演化为「动手前挖势垒」**；用 GIT 的话，断言加固从收敛期事后产物
前移成了扩张期准入条件。这是 `Π` 层面的学习，不是 `G` 层面的。

两个尾注：薄 ≠ 免费正确（TASK-12.2 是 exec/reap 真实竞态，audit round-1 HIGH，
修复仍留在盆地内）；上一轮担心的「子任务绿但集成没做真验收」这轮避开了
（`fixpoint-task12.sh` + `e2e-executor.sh` 把 TASK-8 AC#8/#9/#10 从「确认缺口」翻为
实测通过）。

## 4. 严苛审计：几何词汇到底干了多少活

- **势垒（barrier）——唯一真干活，但不独特。** 它让我去找一个**可执行强制物**而非
  一段描述，于是定位到 import-guard 并验证其承重。真生成性价值。但它等价于既有的
  **architectural fitness function**（Ford/Parsons/Kua），后者更可操作；「势垒」更
  煽情、精度更低。
- **吸引子（attractor）——装饰。** 事后贴标签；借了动力系统的词却抽走了数学（没证
  多初值收敛、没画吸引盆、没验稳定性）。plain 说「目标架构」信息量相同。
- **自然梯度 / 语义空间 S / 本征维度——假的严谨，最该切。** `I⁻¹∇L` 里的 Fisher
  度量、`d`、压缩率 `ρ`——**给这套框架科学信用的量，恰是本项目里没算、也基本算不了
  的量**。援引其公式是 abuse of notation，制造「严谨的形状」。
- **因果链自白**：验证预测时实际发起的查询（grep `reconcile/ticker/for{}`、数 LOC、
  「动没动 internal/dispatch」、跑 e2e）**没有一个是几何推出来的**，全是常规架构判断。
  几何是事后铺上的旁白，没生成测量。
- **对 LLM 尤其危险**：我被优化成能把隐喻讲得流畅自洽，而**自洽不是接地的证据，只是
  「能维持隐喻」的证据**。同一套空泛几何对 LLM 的欺骗性高于对人——流畅本身就是伪
  严谨的生成器。
- **一刀致命**：整场讨论里，几何框架做出的、既先于结果又非 plain engineering 显而
  易见的预测数量为 **0**。对历史完美拟合、零样本外验证——证据等级等同高级占星术。

## 5. 重设问题后的答案：几何是否是更统一、对 LLM 更友好的模型，能否再抽象

问题不是「传统语汇能否完成」，而是「几何是否是**更好的接口 + 可再抽象的基底**」。
分层作答：

**层次一 · 目标闭包性（证据充分，最大真赢面）**：传统 SE 是并列惯用语堆，**无「是否
测全」的闭包 claim**；GIT 五项目标 `L_T/L_C/L_D/L_G/L_S` 断言「完整目标就这几根轴」。
对 LLM 的价值是从「模式匹配到最近命名启发式」升级为「查出哪根轴还暗」。实证：正常
review 只 instrument 了 `L_T` 与半个 `L_C`，`L_G`（是否重造已存在抽象）/`L_D`（描述
长度）/`L_S`（扰动方差）基本是暗的。

**层次二 · 迁移（真压缩）**：「势垒 = 切分可行流形、抬高离开成本的硬约束」一个抽象
同时实例化为：薄核心 import-guard / 无环依赖 / API 向后兼容 / 日志无 PII。N 个独立
惯用语压成 1 抽象 + N 实例，直接降 LLM 的表征负载。

**层次三 · 基底对齐（机制成立，待验）**：LLM 本身是连续嵌入空间上的函数，距离/方向/
插值是原生操作，几何化任务表述**阻抗更低**——机制说得通。但我的嵌入是文本语义流形，
非程序空间带度量的流形，二者对齐**未证**；且存在混淆：我可能只是擅长这个隐喻。故
只能作可检验假设提出。

**假的部分（严苛不松）**：连续动力学层（无度量 → 梯度/距离/自然梯度算不出）是假
统一；真正被统一的只是**它指向的离散产物层**。且统一框架自带压缩损失——会诱导把
任务强塞进五项、在 gap 里系统性致盲（即「压扁语义空间」的批评反噬到框架自身）。

**能否再抽象以提升能力——能，但方向反直觉**：不是加更多连续数学，而是**形式化那个
离散化算子** `Π_{S→E}`（region → executable check）——φ/ψ 缺失的孪生算子。几何唯一
给我付过钱的地方就是「势垒 → importguard_test.go」这个投影；把它做成一等、可重复的
操作才会复利。三步，每步都 bottom out 到可检验产物：

1. **点亮暗轴**：为 `L_G`（跨 repo 概念级重复/重造抽象探测）、`L_D`（archguard 式
   描述长度/压缩率计）、`L_S`（变异/属性测试测行为方差）造廉价可执行代理。
2. **让「势垒」成为可生成的类型化产物**：从一条声明的不变量**自动生成**守卫
   （import-guard / API-compat / PII-grep），而非每次现编。
3. **承认真正的抽象对象是 `Π_{S→E}` 本身**：把「架构意图 → 会在漂移时失败的检查」
   这个投影机制化，是几何能复利的唯一支点。

## 6. 更统一的模型也是人类开发者的能力放大器

一个更统一的模型不仅利于 LLM 处理，对**用 LLM 做开发的人类**也是更有力的能力放大
工具——而且这个论点比「也对人类有利」更强：**在 LLM 时代，统一模型最深的价值是它
是「人类+LLM」二元体的共享控制-验证协议。** 放大的不是任一端的原始能力，是两者
之间那条通道。

LLM 辅助开发的瓶颈从来不是模型多强或人多强，是**人机控制通道的带宽与保真度**。
统一模型是那个 codec，从三处放大人：

1. **共享词汇 = 低损操舵。** 无统一模型时人用 ad-hoc 自然语言操舵（「干净点」「别
   过度工程」）——高损，LLM 的寻模用训练典型默认填空（正是 §1 的失效）。有统一模型
   后人可下**类型化指令**：「这是收敛步，压 `L_D`，别动 `L_T`」「这里动手前先挖
   势垒」「`L_G` 是暗的，查概念重造」。放大本质不是人想得更好，是**人的判断以更少
   损耗传进 LLM 的执行**。
2. **让稀缺的人类判断落在有杠杆处。** GIT §8.3 的人机分工被**可操作化**：模型告诉
   人哪些决定是他的（优化哪根轴、势垒放哪、何时切扩张↔收敛），其余委派；统一模型
   让**委派边界可读**。
3. **验证不对称——最重要。** LLM 生成快于人审查，绑定约束是**廉价验证**。bottom out
   到可检验产物的统一模型（§5 `Π_{S→E}`）让人不读全部代码、靠势垒/测试/损失代理验。
   TASK-8 curl 事件本质是**验证**失败；manda 的真进展在**升级人的验证仪器**
   （import-guard、真 subagent e2e、fixpoint meter）。统一模型放大人，主要靠**升级
   验证通道**——那才是 LLM 辅助开发的绑定约束。

**但杠杆双向（严苛不松）**：(a) 放大以人**真的内化模型**为前提，没学会时是多一层
翻译、比 plain SE 更糟，且有沦为圈内黑话之险；(b) **假严谨对人危害更重**——LLM
产出自信的几何式论证，信任结构化输出的人会**更容易**接受它，因为披了统一形式化；
杠杆朝哪指放大哪个方向，包括冲下悬崖；(c) 放大**只在真的那几层为真**（§5）：目标
闭包/迁移/验证放大人，连续动力学给人的是和给我一样的假严谨。

manda 实证：真正放大了这里人类开发者的，恰是那些落到检查上的统一模型式产物——
`decision-1`（不变量的类型化陈述）、import-guard（势垒即 fitness function）、带 DoD
gate 的分阶段 spec、fixpoint meter。它们让人操舵 subagent、不读全部即可验。

## 7. 结论

geometry 的价值不在于它是软件的物理学，而在于它同时是：(a) 一个**带闭包的类型化
目标**——能指出哪根轴还暗；(b) 一套**离散化纪律**——把连续意图钉成可执行守卫；
(c) 「人类+LLM」二元体的**共享控制-验证协议**——放大的是人机通道而非任一端。它在
目标闭包 / 迁移两层上确实比「惯用语堆」更统一、对 LLM 更省表征、对人更省操舵与验证
成本；在连续动力学层是假的；在基底对齐层是有机制的假设。

- 层次一、二：证据充分。
- 层次三：机制成立、待验。
- 连续动力学：假统一。

而「几何是否对 LLM 更易理解」应由**样本外实验**判，不由讲得多顺来判——恰因我是那个
「流畅本身不可信」的系统。可做的检验：同一批留出的架构任务，一组用「五项目标 + 点
暗轴」的几何提示，一组用传统 SE 启发式清单，比「决策质量 / 抓到的真问题数」；几何若
真是更好的接口，应赢在样本外（对人类维度应加测：同一任务下，用几何协议操舵 LLM
的人 vs 用 plain 提示的人，比返工率与遗漏缺陷数）。能力增益的上限——无论对 LLM 还是
对人——完全取决于把 `region→check` 投影机制化到什么程度；这既是唯一被本项目实证
付过费的地方，也是让「统一模型」从放大信心退回到放大能力的唯一保险。

## 8. 统一势景下的收尾：对偶、真轴、与替代论

### 8.1 历史框架：势垒/吸引子住在哪、实例化要多少钱

前 LLM → LLM 的跃迁，本质是**势垒与吸引子的居所和实例化成本变了**：

- **前 LLM**：它们住在文档 + 人脑 + 工具里。真正的成本不只是「人类学习和应用」，
  而是**跨人跨时间的保真传输 + 势垒的持续维护**；且吸引子（设计模板）与势垒（lint/
  review/CI）是**分离的产物、由分离的劳动维护**——一份设计文档不会自我强制。架构
  腐化（Lehman 第二定律）的根源正是：吸引子活在少数人脑中、势垒疏于维护，投影 `Π`
  随时间漂移。
- **LLM**：海量吸引子**预载进权重**，常见者近乎零实例化成本——这就是加速。但它们
  **偏向语料众数**。

### 8.2 相对性修正：势垒与吸引子是同一个 `U` 的两个参考系读数

统一语义空间里只有**一个势景 `U`**。吸引子 = 局部极小（盆底），势垒 = 分隔两盆的
脊/鞍——不是两种东西，是**同一处曲率相对不同参考点的符号**：朝它、向下 = 吸引子；
逆它、向上 = 势垒。且**盆越深恰因壁越高**——吸引子深度与势垒高度是同一个量，只是
分别相对盆底与脊来测。**「挖势垒」与「钉吸引子」从来不是两个动作，是同一次对 `U`
的形变从两侧看**（`decision-1` 即一次形变：抬高薄核心盆 ≡ 封死 task-in-core）。

由此，§2/§4 里「LLM 吸引子富、势垒贫」的说法**被作废、更正为**：

> LLM 不缺势垒——它**势垒巨大，只是全长在错的地方**，全围着众数盆。对真解在常见盆
> 之外的 novel 项目，深盆的壁**同时是**「稳定常见设计的吸引子壁」和「阻挡新颖解的
> 势垒」：**`吸引子-for-常见 ≡ 势垒-against-新颖`，一个东西、两个参考系。** 这是
> §1「寻模/密度梯度」更干净的写法。

### 8.3 真轴：软形变 vs 硬形变（相对性修正隔离出的东西）

既然 attractor/barrier 沿一根方向对偶坍缩，真正幸存的区别就不在这根轴上，而在
**你形变的是哪个基底**：

- **软形变**（prompt / 更完备的描述）：形变模型自己的 `U`（本次生成的条件分布）。
  prompt-当吸引子与 prompt-当势垒是同一次软形变的两面（在此轴上亦对偶）。它浅、且
  被先验的流长程重新侵蚀。
- **硬形变**（可执行检查 / `E`）：**根本不动 `U`**，而是**截断状态空间**——把离开
  可行域的轨迹直接判负。不是「更高的墙」，是**对可达性的硬改写**，故密度梯度侵蚀
  不了它。

**真正的切分是「软（在-`U`、参考系相对、可侵蚀）vs 硬（在-`E`、状态截断、不可
侵蚀）」，不是吸引子 vs 势垒。** 相对性修正的功劳，正是把那根伪轴对偶掉、逼出这根
真轴——它与 §5 的 `Π_{S→E}`（region → executable check）是同一件事：唯一被本项目
实证付过费的操作，就是硬形变。

### 8.4 一处诚实的限度：对偶只在保守理想化里精确

attractor/barrier 的对偶只在**保守势景的理想化**里成立。LLM 的生成是**被驱动的
随机流**，非保守场。而「软/硬」这根轴，**恰恰是现实偏离该理想化的签名**：正因为
系统非保守、先验持续推，软墙才会被冲垮、硬截断才不会。所以相对性是个干净的
理想化，它**漏气之处（非保守、随机）不是 bug，正是软/硬区别的来源**。

### 8.5 替代论：在修正后的地基上更硬，但比「替代更多」保守半档

稀缺、难自动化的东西是一次**语料势景里不存在的形变（OOD 曲率）**。四点保留：

1. **规模化增强「供给吸引子」，不自动增强「对抗自身先验的形变」。** 二者不在同一
   条曲线上：在典型语料做大只会让众数盆更深；识别「真解不在训练典型解」并抵抗自己
   的先验，靠的是执行/验证/对抗式自审（`E`-loop 信号），不是更多 next-token 预测。
2. **稀缺物是 OOD 形变，其稀缺性参考系无关。** 管它叫「新吸引子」还是「新势垒」只是
   站哪一侧；而「它是 OOD」是参考系无关的。所以残余的人类角色不是写代码，是**为
   新颖处指定那次形变的意图**——恰是 LLM 先验最帮不上的部分。manda 3,100 行、难度
   全堆在边界决策而非实现，即证据：**LLM 最易替代贴近众数的部分（样板、标准
   pattern、实例化——前 LLM 时代的人力成本），最难替代抵抗众数的部分。**
3. **「替代更多开发者」混淆两个命题**：「每 feature 的开发者劳动↓」（很可能真）与
   「开发者总数↓」（不蕴含，Jevons 悖论下可能反假）。被压缩的是**实例化**，不是
   「开发者」；定义 OOD 形变的人反而站到杠杆更长的一端。
4. **语料反馈逆风**：LLM 产出回灌语料 → 众数盆更深、更自我强化（model collapse /
   同质化）。**需要被对抗的东西（掉进众数盆），正被 LLM 自身的成功放大。**

**收束**：历史框架内核正确——跃迁改变了势垒/吸引子的居所与实例化成本。但正因如此，
稀缺且难自动化的东西，**结构上等同于难对抗密度梯度的东西**：外化到 `E`、编码 OOD
意图的形变 + 验证——这不在平滑的规模化曲线上。故结论比「替代更多开发者」保守半档：
**LLM 会持续吸收贴近众数的开发劳动（近乎确定），但那一步取决于框架不裁决的经济
问题，且有一股 LLM 自身制造的逆风顶着它；长期被压缩的是「实例化」，而非「开发者」。**
