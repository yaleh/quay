# 维度、边界与结晶：从熔融实现中发现原则

> 本文记录一次以 quay 项目最近几周（2026-07-19 → 08-30）设计演化史为实证的讨论。对象
> **不是** CLAUDE.md 的硬规则（那些是产物），而是产物背后的东西：**正确的维度、边界和
> 原则是怎么被发现的、抽象和应用的；在语义空间中如何看待这些原则、设计、以及它们的
> 演进路线。** 框架文本是《基于几何信息论的未来软件开发与信息系统建设(两阶段周期版)》
> 与其严苛审计《几何框架作为 LLM 软件架构接口的可用性讨论》，以及本项目的结晶化策略
> （`docs/proposals/exp5-crystallization-strategy.md`）。结论分层给出（证据充分 /
> 机制成立待验 / 观察项）。

## 0. 论点：维度是测出来的输出，不是设计的输入

最近几周的演化史呈现一个反复出现的形状：**正确的维度/边界/原则，从来不是设计的输入，
而是熔融的初步实现失败之后，被测量出来的输出。** 每一个「正确」都是事后锚在事故或
测量上的；每一条设计原则都带着它被发现那一天的具体失效。这不是坏消息——这是本项目
演化的正常机制，而且它有一个可复现的结构：

```
熔融实现跑起来 → 沿某个维度失效（或静默失效） → 外部压力/测量让维度显形
→ 沿该轴量出真实距离 → 画出正确边界 → 抽象成原则 → 立即受反例检验
→ 投影成可执行检查（Π_{S→E}）→ 结晶为单源
```

本文用九次真实演化（§1）支撑这个结构，然后分别解剖**发现**（§2）、**抽象**（§3）、
**应用**（§4）三个环节的机制，最后给出语义空间读法（§5）与结晶的元规则（§6）。

- 每一次的「正确维度」都在失败之后出现（状态源分裂 / 提交分叉 / 静默失效 / 锁时长测量 /

- 每一条都结晶成**可执行物**（代码路径 / 分支纪律 + ff / 脚本 / driver 编排 / ABI / ADR 记录 /
  schema validator / harness 第三态 / 单一实现），而不是停留在更醒目的散文。

## 2. 发现机制：维度只在它被压扁时显形

### 2.1 三个触发器

**① 外部压力 —— 人是唯一的样本外探测器。** FINDING-tool-crystallization-quantified 的实证：
5 例里 3 例的第一次揭发来自人的追问，不是本层的主动巡检；主动发现的两例都发生在「正在
处理另一件相关的事、顺手核对」的场合。推论：自主循环对自身的盲区结构上不可见——它的
仪器由它自己维护，它停摆时仪器读数与「一切正常」同形（这正是语义空间里「压扁」的
观测侧形态，见 §2.2）。

**② 静默失败 —— 危险的不是高频，是「失败不发声」。** 判据：`频率 × 失败是否会自己发出声音`。
workflow 周期（每 20min 一次）失败完全静默 → 21.5h 无人发现；1b 收尾（每 tick）静默 →
8.5h；A5 巡检每轮都读但判断从不产出 →「看见但没发现」数十轮。**静默的失败长什么样**：
读数照样打印、动作照样返回，只是内容是空的——它与「一切正常」同形。

**③ 测量 —— 让压扁的维度显形。** SPEC-fan-in-driver-mechanical-orchestration 的整份论证
就是三组锁时长数据：`1820–1845s` 与任务内容无关、suite 晚于锁释放、ff 仍在重试。**在测量
之前，「workflow 锁」与「driver 锁」在投影里是同一个点；测量之后，执行载体这一维被点亮。**

### 2.2 压扁原理：投影塌缩是伪收敛的根源

语义空间读法的核心诊断：**当投影仪器把「真解与熟悉解相异的那一维」压成 0 时，不同的
设计点变得不可区分，系统会自信地收敛到错误的盆地。** 本项目的历史充满同形实例：

| 压扁的投影 | 被压掉的那一维 | 后果 |
|---|---|---|
| `curl` 冒充 subagent 当采样仪器（审计文档 TASK-8） | 工具面（Monitor/TaskStop 有、TaskList/Agent 无） | `L_T=0` 沿盲轴伪收敛，设计仍是错的 |
| 六个状态源互相矛盾（08-05） | 在飞状态的真实计数 | 管理者工时耗在调和源上而非判断 |
| 检查器没有「未评估」态（硬规则 3b 三实例） | 判据是否真读过输入 | 读不懂 ⇒ 判合格，「恒绿的检查」 |
| `grep -c` 命中注释 / comm 正则恒零 | 判定对象的真实形态 | 误报「还在」/「缺失」，方向相反的假 |
| 方法学层 exit 2 承载三种含义 | 第三态（NOT-EVALUATED） | 17/77 checker 编码互不相容 |

**「维度只在它被压扁时显形」的双重含义**：压扁导致伪收敛（坏）；但压扁本身是**发现的前置**——
一个维度正是通过「它被压掉之后发生了什么」而被点亮的。测量就是把压掉的维补回来，看真解
和现解在那一维上是否分开。

### 2.3 为什么不能提前设计（自然梯度与条件性）

两阶段周期版：`X_{t+1} = X_t − η·I(X_t)⁻¹∇L(X_t)`。`I(X_t)`（局部几何）只能站在 `X_t` 上量，
不能从目标推出。本项目提供了同一句话的工程版：正确维度是 `X`（本项目当前实现）的条件，
不是目标的性质——直到实现跑起来、沿某维失效，才知道该维存在。审计文档 manda 的第三次
架构反转（朴素 `∇L` 按「最低 L(R|G) 局部步」指错方向）与 08-27 的载体反转（修锁参数不如换
执行载体）都是「∇L 指错方向、需自然梯度校正」的实例：**方向只能在当前点测，不能从终点推。**

## 3. 抽象机制：同形聚类 → 原则，且立即受反例检验

### 3.1 抽象靠同形聚类，不靠演绎

从 N 个同形实例到原则：硬规则 3b 是「同日三次、两层、三载体」压出的「没有未评估态」；
轴框架的八根轴每一根都是「为什么怀疑这里有东西」——从具体事故抽象成「这根轴问什么」。
**项目的轴框架本质上是把「抽象」这一步做成一等公民**：每根轴 = 一条 `proposed + tag: axis`
的 ADR，轴收敛成决定 = 同一条记录从 proposed 走到 accepted。这是把「发现候选维度」本身
纳入版本管理。

### 3.2 抽象后的两步修正纪律

每条抽象立即接受反例检验，且修正都当场发生：
- **频率×静默判据** → 人被指出「一串都失效」的洞 → 修正为先问**共享死因**、再问会不会发声
  （同一次崩溃/kill/压缩会一起消失的机制不是真冗余，只是换皮的 SPOF）。
- **「高频需要结晶」** → 修正为频率 × 静默的乘积，再修正为共享死因优先——**每一步都是当场
  用真实反例推翻上一个抽象**，不是层层叠更保险的措辞。
- **硬规则 4 推论四**：「能解释现象的说法不是被检验的结论」——三次都被一条命令的对照推翻
  （查动作记录 / 让两假设给出相反预测 / 改一个参数看结论翻不翻）。

### 3.3 支柱化：可复用抽象晋升为 G

当一条抽象反复支付、被多个载体复用，它从 R（残差）晋升为 G（支柱）：单源原则、可执行优于
散文（ADR-004）、enforcement-with-design（ADR-011）、ABI 边界（ADR-013）。而 ADR 本身是
决策的结晶载体：`status: proposed → accepted/superseded/deprecated`——**决定收敛成支柱，
由引擎跟踪、可被 superseded**。

### 3.4 三个层次的结晶，缺一不可

FINDING-tool-crystallization-quantified 最尖锐的发现：**结晶到文档 ≠ 结晶到执行 ≠ 结晶到
习惯**。
- send-keys 的修法写进了 `CRYSTALLIZED-reliable-send-2026-08-04.md`，但执行仍用「三次分开
  调用」这个更便宜的子集，**省掉了最贵也最可靠的那一步**——「接了一半的线」。
- `manager-tick-readings.ts` 早就存在，却因一次判错对象被判定「已替代」——**「结晶到脚本 ≠
  结晶到我的习惯」**。
- 三条是同一条纪律的三段：**判断结晶是否完成，要看动作的实际执行形态，不看文档或脚本的
  存在**。这是 §2.2 压扁原理在「应用」侧的对应物——文档/脚本存在性在投影里压掉了「是否
  真在执行」。

## 4. 应用机制：Π_{S→E} —— 连续意图 → 可执行检查

审计文档的结论：几何唯一付过钱的，是把「连续意图 → 可执行检查」的投影算子 `Π_{S→E}`
机制化——硬形变（截断状态空间，先验侵蚀不了），区别于软形变（prompt、更醒目的措辞，
会被流长程重新侵蚀）。本项目的应用侧就是 `Π_{S→E}` 的批量实例：

- **原则 → 检查**：300 个脚本、QENG 闸、单源 validator。每条原则要么有可执行产物（判据③
  条数与清单、`NOT-EVALUATED` 独立取值、发生率读数），要么自标「靠自觉」——而自标的
  那几条反复再犯（实证：硬规则 2 立条当天同形四次）。
- **仪表可跑，不可断言**（ADR-019 家族）：状态结晶让「在飞数」从散文断言变成可查询的事实；
  「验证发生过」要有单一权威载体，而不是散在 `/tmp` 旧日志。
- **enforcement-with-design**（ADR-011）：没有新规则/DoD/方法步骤被接受而不带**同一里程碑**
  里的可执行强制。这是把「应用」从可选步骤变成准入条件。
- **产品化方向**（08-28）：把散落三套实现（机械 TS + workflow 双副本 + bash 原语）集中到
  quay CLI/MCP——**一个业务过程一套实现**。这是结晶的最高一层：不只单源，是单载体。

**为什么应用必须是硬形变**：参考审计的机制解释——LLM 被拉向语料众数盆地，真解落在先验
低概率区时，只有可执行反馈 E 能翻越密度先验；软形变（更醒目的散文）会被先验的长程侵蚀
冲垮，硬形变（截断状态空间的检查）不会。本项目的全部「带产物的规则活下来、靠自觉的反复
再犯」都是这条的观测证据。

## 5. 语义空间读法：设计是点，原则是轴，演化是轨迹

### 5.1 把九次演化放进语义空间

- **设计是点**：每一个设计决定（分支模型、执行载体、状态表示、锁协议）是设计空间 `P` 中
  的一个点 `X = (G, R, A)`。
- **原则/边界是轴（坐标）**：一次发现 = 点亮一根之前被压扁的轴。ADR-025~032 的八根轴 +
  §1 的九个维度，就是本项目到目前为止**已发现的坐标清单**——不是项目「设计」出来的，
  是从事故里「读」出来的。
- **演化是轨迹**：每次发现/校正把设计点移到新位置；轨迹的收敛方向由当前点测量决定
  （§2.3 自然梯度）。扩张注入新点新轴（熵↑、d 暂时↑），收敛把区域投影到可执行检查并删
  冗余散文（描述长度↓）。这是两阶段周期版的「呼吸」在方法层自身上的运行。
- **残差 R|G**：那些还没被任何已发现原则覆盖的设计决策，就是当前残差——轴框架的本质是
  **给残差编目录**，让「还有哪根轴暗」这个问题有答案。

### 5.2 危险：投影塌缩 → 伪收敛

在语义空间里，本项目的两类已知失败都是投影塌缩：
- **沿盲轴伪收敛**（§2.2）：`L_T=0` 只证明 T 覆盖了它覆盖的方向；当投影塌掉真解与熟悉解
  相异的那一维，agent 自信地收敛到错误盆地（curl-subagent、fixture 满足的判据）。
- **本征维度假信号**：本项目的设计空间 d 目前在涨（08-06 一批八根轴、一周内多份新 SPEC）
  而在收（08-28 产品化是压缩）。**d 涨跌不是好坏本身**——扩张期 d 涨是正常熵注入；预警
  信号是**只涨不收**（新维度正交、无归并、散文副产品持续膨胀），那时才对应两阶段周期版
  的「本征维度异常预示架构腐化」。

### 5.3 诚实条款：这是视图，不是物理

审计文档的三级分级必须遵守：连续动力学层（Fisher 度量、本征维度、压缩率的数值计算）在
本项目**没有算过、也基本算不了**——援引其公式是 abuse of notation。本文的语义空间读法
只在它真正付钱的三处成立：(a) **目标闭包**（哪些轴存在，可以查；暗轴可检测）；
(b) **迁移**（同一原则跨载体实例化：ABI 边界 = import-guard = API 兼容 = 日志无 PII）；
(c) **共享控制-验证协议**（「这是收敛步，压 L_D，别动 L_T」这类类型化指令能低损传进执行）。
除此之外的连续几何是假统一，本文不援引它作为证据。

## 6. 结晶的元规则：三条引导线

综合九次演化，给「在熔融实现中结晶」的元规则：

1. **减法 + 可执行，绝不加法散文。** 结晶化策略的核心反直觉：熔融的根治不是写更多规则，
   是删表示、投影成可执行不变量。加散文喂熵（code:doc 1:9.38 的病）。**每次「要更精确」
   的冲动，先问能不能换成一次测量或一个检查。**
2. **该找哪个维度，问三个引导问题**（都已被本项目实证为有效探测器）：
   - 这个量「错的时候，谁会先知道」？答案是「下一次该产出但没产出、且没东西检查」的，
     优先级最高（频率×静默）。
   - 那个「会先知道」的机制，与对象是否共享死因？共享 ⇒ 先处理这一层（两步修正）。
   - 我们是不是把两个不可区分的点当成了同一个点？——找不到投影塌缩的实例，就还没看够
     （压扁原理）。
3. **结晶完成的标准是动作的实际执行形态**，不是文档/脚本的存在（三层结晶：文档≠执行≠
   习惯）。带产物的规则活下来，标「靠自觉」的反复再犯——这正是硬形变与软形变的分界。

## 7. 结论

最近几周的设计演化史证明：**正确的维度、边界和原则不是设计的输入，是熔融实现失效后
测出来的输出；它们在语义空间中是一根根被点亮、被编目、被投影成可执行检查的轴。** 演化的
质量不取决于开工时画得多准，而取决于三件事：发现机制是否敏于静默失败、抽象是否立即受
反例检验、应用是否真的落到动作而不是落到文档。结晶的元规则只有一条反复被实证的话：
**用测量和可执行检查去逼近正确，而不是用更精确的散文去描述正确。**

按审计文档三级标准：

- **证据充分**：维度从失效中被发现（§1 九例全部带事故/测量锚点）；压扁→伪收敛（§2.2 多例
  同形）；结晶到文档≠执行≠习惯（§3.4）；带产物的规则活、靠自觉的复犯（§4）。
- **机制成立待验**：语义空间「轨迹收敛 + 投影塌缩」读法作为因果解释（§5）——可检验，但未
  做过一轮样本外验证；「本征维度 d 用于设计空间」同前。
- **观察项**：任何把「当前 d 在涨」当作坏消息的用法——扩张期涨是正常，只涨不收才是预警；
  未做过归并率实测，不作阻塞判据。
