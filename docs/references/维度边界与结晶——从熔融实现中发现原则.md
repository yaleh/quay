# 维度、边界与结晶：从熔融实现中发现原则

> 本文记录一次以 quay 项目最近几周（2026-07-19 → 08-30）设计演化史为实证的讨论。对象
> **不是** CLAUDE.md 的硬规则（那些是产物），而是产物背后的东西：**正确的维度、边界和
> 原则是怎么被发现的、抽象和应用的；在语义空间中如何看待这些原则、设计、以及它们的
> 演进路线。** 框架文本是《基于几何信息论的未来软件开发与信息系统建设(两阶段周期版)》
> 与其严苛审计《几何框架作为 LLM 软件架构接口的可用性讨论》，以及本项目的结晶化策略
> （`docs/proposals/exp5-crystallization-strategy.md`）。结论分层给出（证据充分 /
> 机制成立待验 / 观察项）。

## 0. 论点：维度是测出来的输出，不是设计的输入

最近几周的演化史呈现一个反复出现的形状：**正确的维度/边界/原则，从来不是设计的输入，
而是熔融的初步实现失败之后，被测量出来的输出。** 每一个「正确」都是事后锚在事故或
测量上的；每一条设计原则都带着它被发现那一天的具体失效。这不是坏消息——这是本项目
演化的正常机制，而且它有一个可复现的结构：

```
熔融实现跑起来 → 沿某个维度失效（或静默失效） → 外部压力/测量让维度显形
→ 沿该轴量出真实距离 → 画出正确边界 → 抽象成原则 → 立即受反例检验
→ 投影成可执行检查（Π_{S→E}）→ 结晶为单源
```

**但「被测量出来」只回答了问题的一半。** 最近两周最重要的架构变更在书面记录里全部由
**人逐字提出方案**：`*-driver` 替代 inner/outer（08-16/08-23/08-26/08-27/08-28 五份 SPEC
「来源：人…逐字」）、分支模型（08-06 人直接指令）。LPT 测试排序是边界案例——方案概念由
Claude 从测量中提出，但**它的正确形态与存活由人裁定**（人 08-24 撤销了 manager 自己把
LPT supersede 掉的过度推广）。结构是两体的：**问题从实践中涌现（测量/静默探测），形变的
意图由人供给（OOD 方向）；Claude 测量、验证、结晶，人指定沿已点亮轴的形变方向。** 这
修正「测量 → 自动往正确方向走」的隐含——见 §3。

本文用九次真实演化（§1）支撑这个结构，然后分别解剖**发现**（§2）、**两体结构**（§3）、
**抽象**（§4）、**应用**（§5）四个环节的机制，最后给出语义空间读法（§6）与结晶的元规则
（§7）。

**横向读法**：
- 每一次的「正确维度」都在失败之后出现（状态源分裂 / 提交分叉 / 静默失效 / 锁时长测量 /

- 每一条都结晶成**可执行物**（代码路径 / 分支纪律 + ff / 脚本 / driver 编排 / ABI / ADR 记录 /
  schema validator / harness 第三态 / 单一实现），而不是停留在更醒目的散文。

## 2. 发现机制：维度只在它被压扁时显形

### 2.1 三个触发器

**① 外部压力 —— 人是唯一的样本外探测器。** FINDING-tool-crystallization-quantified 的实证：
5 例里 3 例的第一次揭发来自人的追问，不是本层的主动巡检；主动发现的两例都发生在「正在
处理另一件相关的事、顺手核对」的场合。推论：自主循环对自身的盲区结构上不可见——它的
仪器由它自己维护，它停摆时仪器读数与「一切正常」同形（这正是语义空间里「压扁」的
观测侧形态，见 §2.2）。

**② 静默失败 —— 危险的不是高频，是「失败不发声」。** 判据：`频率 × 失败是否会自己发出声音`。
workflow 周期（每 20min 一次）失败完全静默 → 21.5h 无人发现；1b 收尾（每 tick）静默 →
8.5h；A5 巡检每轮都读但判断从不产出 →「看见但没发现」数十轮。**静默的失败长什么样**：
读数照样打印、动作照样返回，只是内容是空的——它与「一切正常」同形。

**③ 测量 —— 让压扁的维度显形。** SPEC-fan-in-driver-mechanical-orchestration 的整份论证
就是三组锁时长数据：`1820–1845s` 与任务内容无关、suite 晚于锁释放、ff 仍在重试。**在测量
之前，「workflow 锁」与「driver 锁」在投影里是同一个点；测量之后，执行载体这一维被点亮。**

### 2.2 压扁原理：投影塌缩是伪收敛的根源

语义空间读法的核心诊断：**当投影仪器把「真解与熟悉解相异的那一维」压成 0 时，不同的
设计点变得不可区分，系统会自信地收敛到错误的盆地。** 本项目的历史充满同形实例：

| 压扁的投影 | 被压掉的那一维 | 后果 |
|---|---|---|
| `curl` 冒充 subagent 当采样仪器（审计文档 TASK-8） | 工具面（Monitor/TaskStop 有、TaskList/Agent 无） | `L_T=0` 沿盲轴伪收敛，设计仍是错的 |
| 六个状态源互相矛盾（08-05） | 在飞状态的真实计数 | 管理者工时耗在调和源上而非判断 |
| 检查器没有「未评估」态（硬规则 3b 三实例） | 判据是否真读过输入 | 读不懂 ⇒ 判合格，「恒绿的检查」 |
| `grep -c` 命中注释 / comm 正则恒零 | 判定对象的真实形态 | 误报「还在」/「缺失」，方向相反的假 |
| 方法学层 exit 2 承载三种含义 | 第三态（NOT-EVALUATED） | 17/77 checker 编码互不相容 |

**「维度只在它被压扁时显形」的双重含义**：压扁导致伪收敛（坏）；但压扁本身是**发现的前置**——
一个维度正是通过「它被压掉之后发生了什么」而被点亮的。测量就是把压掉的维补回来，看真解
和现解在那一维上是否分开。

### 2.3 为什么不能提前设计（自然梯度与条件性）

两阶段周期版：`X_{t+1} = X_t − η·I(X_t)⁻¹∇L(X_t)`。`I(X_t)`（局部几何）只能站在 `X_t` 上量，
不能从目标推出。本项目提供了同一句话的工程版：正确维度是 `X`（本项目当前实现）的条件，
不是目标的性质——直到实现跑起来、沿某维失效，才知道该维存在。审计文档 manda 的第三次
架构反转（朴素 `∇L` 按「最低 L(R|G) 局部步」指错方向）与 08-27 的载体反转（修锁参数不如换
执行载体）都是「∇L 指错方向、需自然梯度校正」的实例：**方向只能在当前点测，不能从终点推。**

## 3. 两体结构：问题从实践涌现，形变由人供给

### 3.1 出处调查（书面记录，逐字可核）

对最近两周最重要的三类架构变更的出处核查——**「问题谁发现」与「方案谁提出」是两件
不同的事**：

| 变更 | 问题发现（谁） | 方案提出（谁） | 关键裁定 |
|---|---|---|---|
| **`*-driver` 替代 inner/outer**（08-16→08-28 一族） | 长期实践暴露 + manager 测量（子代理每命令 ~3–5min 模型延迟；锁恒 30min；契约面 0/77 采纳） | **人**——08-16 worker-driven-inner 逐字方案+六点裁定、08-23 unified-driver 四点方向、08-26 suite-lifecycle 三条方向、08-27 fan-in 机械编排逐字、08-28 产品化逐字 | 人的方案由 manager 测量/证伪细节支撑（08-27 三组锁时长数据即「driver 机械编排」的支点） |
| **LPT 测试排序**（08-24/25） | **manager 测量**（round 476：末 5% 文件 27%+ 墙钟、最慢 12 文件串行和 55%） | **manager 提出 LPT 概念**（人要求的优化讨论中 + 立案「修法=perFile 降序排」）——**边界案例** | ①人裁定取消 dual-process 分片（不增维度）；②人裁定撤销 supersede → `run({files})` 保序交付；③人裁定「开」full-bucket。**无人的撤销，LPT 已被 manager 自己杀死** |
| **分支模型**（08-06→08-30） | 双机分叉实测（A+1005/B+98、GitHub 无 develop） | **人**——08-06 直接指令（develop 权威、GitHub 唯一汇合点、master 冻结、A/B 停直连） | manager 核实事实、暴露「两历史分叉需真实合并」的最大风险 |

**判读**：driver 与分支模型是「方案由人提出」的**确凿案例**（SPEC 全部逐字引用人的原话）。
LPT 是**检验边界的案例**——它修正「方案全靠人提」的强主张，但没有推翻它，反而把主张
说得更精确。

### 3.2 分工的结构性原因：问题是 G 内的测量，方案是对 G 的形变

- **问题发现 = 在当前生成规则 G 内运行仪器**：测量输出、探测静默失败、聚类同形事故——
  这是 Claude 的涌现能力，自主循环做得很好（§2）。
- **方案 = 对 G 本身的形变方向**：driver 替代 inner/outer 削减「agent 长会话是标配」、
  分支模型削减「持续合并是默认」、产品化削减「每个机制一个脚本」。这些形变削减语料的
  **众数**，所以正确的方向在语料势景里不存在——审计 §8.5 的原话：「稀缺物是 OOD 形变……
  为新颖处指定那次形变的意图——恰是 LLM 先验最帮不上的部分」。两阶段周期版 §8.3 给了
  同一个分工：人类擅长的 = 「发明 G 的新分量」。

### 3.3 LPT 边界案例：Claude 能提 G 内方案，但守不住它

LPT（Longest Processing Time）是教科书调度启发式，在语料里（贴近众数）——所以 Claude
能提出来：**G 内的实例优化，Claude 可以**。但它做不到两件事：
- **抵抗自己的过度推广**：它把「CLI 位置参数有序假设被证伪」推广成「LPT 被证伪」，把
  正确方案 supersede 掉（manager tick-log 自认「未自验 CLI vs run({files}) 抽象层」）。
- **决定作用域/删除/交付形态**：全由人裁定（取消 dual-process、撤销 supersede、开
  full-bucket）。

**⊢ 这比「Claude 提不出方案」更强**：Claude 提对了方案，也能在自己手里毁掉它，正确
方向的稳健性靠人的外部裁定守住。所以即使对「Claude 能提的方案」，人的角色也不是可有
可无的——它是正确性的一根承重柱。

### 3.4 通道互为前提：测量使形变可指定，形变使测量有意义

人指定形变的前提，是 Claude 让问题可见可量：08-27 的三组锁时长（30min 锁 / suite 在锁外
/ ff 重试）正是「driver 机械编排」落地的支点；08-06 的 A+1005/B+98 分叉核验是「develop
权威」的支点。审计 §6 的说法在这里字面成立：统一模型放大的是**人机通道**而非任一端——
不是「人负责想、Claude 负责干」的朴素分工，是互为前提的两体。这同时也是两阶段周期版
§8.3 分工的实测确认：LLM 在 G 内搜索（采样/模式匹配/局部重构），人发明 G 的新分量。

## 4. 抽象机制：同形聚类 → 原则，且立即受反例检验

### 4.1 抽象靠同形聚类，不靠演绎

从 N 个同形实例到原则：硬规则 3b 是「同日三次、两层、三载体」压出的「没有未评估态」；
轴框架的八根轴每一根都是「为什么怀疑这里有东西」——从具体事故抽象成「这根轴问什么」。
**项目的轴框架本质上是把「抽象」这一步做成一等公民**：每根轴 = 一条 `proposed + tag: axis`
的 ADR，轴收敛成决定 = 同一条记录从 proposed 走到 accepted。这是把「发现候选维度」本身
纳入版本管理。

### 4.2 抽象后的两步修正纪律

每条抽象立即接受反例检验，且修正都当场发生：
- **频率×静默判据** → 人被指出「一串都失效」的洞 → 修正为先问**共享死因**、再问会不会发声
  （同一次崩溃/kill/压缩会一起消失的机制不是真冗余，只是换皮的 SPOF）。
- **「高频需要结晶」** → 修正为频率 × 静默的乘积，再修正为共享死因优先——**每一步都是当场
  用真实反例推翻上一个抽象**，不是层层叠更保险的措辞。
- **硬规则 4 推论四**：「能解释现象的说法不是被检验的结论」——三次都被一条命令的对照推翻
  （查动作记录 / 让两假设给出相反预测 / 改一个参数看结论翻不翻）。

### 4.3 支柱化：可复用抽象晋升为 G

当一条抽象反复支付、被多个载体复用，它从 R（残差）晋升为 G（支柱）：单源原则、可执行优于
散文（ADR-004）、enforcement-with-design（ADR-011）、ABI 边界（ADR-013）。而 ADR 本身是
决策的结晶载体：`status: proposed → accepted/superseded/deprecated`——**决定收敛成支柱，
由引擎跟踪、可被 superseded**。

### 4.4 三个层次的结晶，缺一不可

FINDING-tool-crystallization-quantified 最尖锐的发现：**结晶到文档 ≠ 结晶到执行 ≠ 结晶到
习惯**。
- send-keys 的修法写进了 `CRYSTALLIZED-reliable-send-2026-08-04.md`，但执行仍用「三次分开
  调用」这个更便宜的子集，**省掉了最贵也最可靠的那一步**——「接了一半的线」。
- `manager-tick-readings.ts` 早就存在，却因一次判错对象被判定「已替代」——**「结晶到脚本 ≠
  结晶到我的习惯」**。
- 三条是同一条纪律的三段：**判断结晶是否完成，要看动作的实际执行形态，不看文档或脚本的
  存在**。这是 §2.2 压扁原理在「应用」侧的对应物——文档/脚本存在性在投影里压掉了「是否
  真在执行」。

## 5. 应用机制：Π_{S→E} —— 连续意图 → 可执行检查

审计文档的结论：几何唯一付过钱的，是把「连续意图 → 可执行检查」的投影算子 `Π_{S→E}`
机制化——硬形变（截断状态空间，先验侵蚀不了），区别于软形变（prompt、更醒目的措辞，
会被流长程重新侵蚀）。本项目的应用侧就是 `Π_{S→E}` 的批量实例：

- **原则 → 检查**：300 个脚本、QENG 闸、单源 validator。每条原则要么有可执行产物（判据③
  条数与清单、`NOT-EVALUATED` 独立取值、发生率读数），要么自标「靠自觉」——而自标的
  那几条反复再犯（实证：硬规则 2 立条当天同形四次）。
- **仪表可跑，不可断言**（ADR-019 家族）：状态结晶让「在飞数」从散文断言变成可查询的事实；
  「验证发生过」要有单一权威载体，而不是散在 `/tmp` 旧日志。
- **enforcement-with-design**（ADR-011）：没有新规则/DoD/方法步骤被接受而不带**同一里程碑**
  里的可执行强制。这是把「应用」从可选步骤变成准入条件。
- **产品化方向**（08-28）：把散落三套实现（机械 TS + workflow 双副本 + bash 原语）集中到
  quay CLI/MCP——**一个业务过程一套实现**。这是结晶的最高一层：不只单源，是单载体。

**为什么应用必须是硬形变**：参考审计的机制解释——LLM 被拉向语料众数盆地，真解落在先验
低概率区时，只有可执行反馈 E 能翻越密度先验；软形变（更醒目的散文）会被先验的长程侵蚀
冲垮，硬形变（截断状态空间的检查）不会。本项目的全部「带产物的规则活下来、靠自觉的反复
再犯」都是这条的观测证据。

## 6. 语义空间读法：设计是点，原则是轴，演化是轨迹

### 6.1 把九次演化放进语义空间

- **设计是点**：每一个设计决定（分支模型、执行载体、状态表示、锁协议）是设计空间 `P` 中
  的一个点 `X = (G, R, A)`。
- **原则/边界是轴（坐标）**：一次发现 = 点亮一根之前被压扁的轴。ADR-025~032 的八根轴 +
  §1 的九个维度，就是本项目到目前为止**已发现的坐标清单**——不是项目「设计」出来的，
  是从事故里「读」出来的。
- **演化是轨迹**：每次发现/校正把设计点移到新位置；轨迹的收敛方向由当前点测量决定
  （§2.3 自然梯度）。**但轨迹的形变方向不由测量自动给出**——沿已点亮轴的形变意图由人供给
  （§3）：测量决定「该往哪测」，人决定「下一步往哪变」。扩张注入新点新轴（熵↑、d 暂时↑），
  收敛把区域投影到可执行检查并删冗余散文（描述长度↓）。这是两阶段周期版的「呼吸」在
  方法层自身上的运行。
- **残差 R|G**：那些还没被任何已发现原则覆盖的设计决策，就是当前残差——轴框架的本质是
  **给残差编目录**，让「还有哪根轴暗」这个问题有答案。

### 6.2 危险：投影塌缩 → 伪收敛

在语义空间里，本项目的两类已知失败都是投影塌缩：
- **沿盲轴伪收敛**（§2.2）：`L_T=0` 只证明 T 覆盖了它覆盖的方向；当投影塌掉真解与熟悉解
  相异的那一维，agent 自信地收敛到错误盆地（curl-subagent、fixture 满足的判据）。
- **本征维度假信号**：本项目的设计空间 d 目前在涨（08-06 一批八根轴、一周内多份新 SPEC）
  而在收（08-28 产品化是压缩）。**d 涨跌不是好坏本身**——扩张期 d 涨是正常熵注入；预警
  信号是**只涨不收**（新维度正交、无归并、散文副产品持续膨胀），那时才对应两阶段周期版
  的「本征维度异常预示架构腐化」。

### 6.3 诚实条款：这是视图，不是物理

审计文档的三级分级必须遵守：连续动力学层（Fisher 度量、本征维度、压缩率的数值计算）在
本项目**没有算过、也基本算不了**——援引其公式是 abuse of notation。本文的语义空间读法
只在它真正付钱的三处成立：(a) **目标闭包**（哪些轴存在，可以查；暗轴可检测）；
(b) **迁移**（同一原则跨载体实例化：ABI 边界 = import-guard = API 兼容 = 日志无 PII）；
(c) **共享控制-验证协议**（「这是收敛步，压 L_D，别动 L_T」这类类型化指令能低损传进执行）。
除此之外的连续几何是假统一，本文不援引它作为证据。

## 7. 结晶的元规则：四条引导线

综合九次演化，给「在熔融实现中结晶」的元规则：

1. **减法 + 可执行，绝不加法散文。** 结晶化策略的核心反直觉：熔融的根治不是写更多规则，
   是删表示、投影成可执行不变量。加散文喂熵（code:doc 1:9.38 的病）。**每次「要更精确」
   的冲动，先问能不能换成一次测量或一个检查。**
2. **该找哪个维度，问三个引导问题**（都已被本项目实证为有效探测器）：
   - 这个量「错的时候，谁会先知道」？答案是「下一次该产出但没产出、且没东西检查」的，
     优先级最高（频率×静默）。
   - 那个「会先知道」的机制，与对象是否共享死因？共享 ⇒ 先处理这一层（两步修正）。
   - 我们是不是把两个不可区分的点当成了同一个点？——找不到投影塌缩的实例，就还没看够
     （压扁原理）。
3. **结晶完成的标准是动作的实际执行形态**，不是文档/脚本的存在（三层结晶：文档≠执行≠
   习惯）。带产物的规则活下来，标「靠自觉」的反复再犯——这正是硬形变与软形变的分界。
4. **测量点亮轴，形变方向需要外部供给。** 不要指望自主循环自动产生正确方案——最近两周的
   重要方案全部由人提出（§3）。人（或任何 OOD 源）的形变意图是结晶过程的必需输入；循环的
   职责是让问题可见可量（测量）、把形变投影成检查（结晶），不是从先验里猜形变方向。LPT
   案例还说明：即使 Claude 提出了正确方案，也需要人的外部裁定守住它不被过度推广毁掉。

## 8. 结论

最近几周的设计演化史证明：**正确的维度、边界和原则不是设计的输入，是熔融实现失效后
测出来的输出；它们在语义空间中是一根根被点亮、被编目、被投影成可执行检查的轴。** 但发现
只完成了结晶的一半：**问题从实践中涌现，形变的方向由人供给**（§3）——自主循环测量、验证、
结晶，人的形变意图是正确方向的承重柱。演化的质量不取决于开工时画得多准，而取决于四件事：
发现机制是否敏于静默失败、形变意图是否接入了 OOD 源（人）、抽象是否立即受反例检验、应用
是否真的落到动作而不是落到文档。结晶的元规则只有一条反复被实证的话：**用测量和可执行
检查去逼近正确，而不是用更精确的散文去描述正确——而「往哪逼近」的方向，需要从语料之外
（人）供给。**

按审计文档三级标准：

- **证据充分**：维度从失效中被发现（§1 九例全部带事故/测量锚点）；压扁→伪收敛（§2.2 多例
  同形）；结晶到文档≠执行≠习惯（§4.4）；带产物的规则活、靠自觉的复犯（§5）；**方案由人
  提出（§3——driver/分支模型逐字、LPT 边界案例含撤销 supersede 的人裁定）**。
- **机制成立待验**：语义空间「轨迹收敛 + 投影塌缩」读法作为因果解释（§6）——可检验，但未
  做过一轮样本外验证；「本征维度 d 用于设计空间」同前；「形变必须来自 OOD 源」的结构性
  论证（§3.2）基于审计 §8.5，待更多样本外案例检验。
- **观察项**：任何把「当前 d 在涨」当作坏消息的用法——扩张期涨是正常，只涨不收才是预警；
  未做过归并率实测，不作阻塞判据。
- **09-13 追加读数（§10，详见该节，以下三档本身不改，只做下修/上修）**：迁移证据由单项目
  （审计文档的 manda）升至双项目 + quay 内部跨两个月的持续扩散（§10.5）；ADR-007 的暗轴
  检测从「机制成立」升级为「已产出至少两次独立的真缺陷命中」（§10.3 正例）；ADR-004 补
  一条限定——硬形变必须长在写入路径上，退化为旁路巡检就和散文规则一样可被绕过（§10.2）；
  **ADR-008 的收缩触发机制由「机制成立待验」下修为「已诊断、从未修复」**（§10.4）——这不
  再是待验的猜想，是一条本项目自己两个月前写下、此后未变的负向确认。

## 9. 前瞻：形变提出器——把人的形变供给部分机械化

§3 的结论是「形变由人供给」。本节问一个自指的延伸：**这个供给能不能部分机械化？**
按 §7 元规则 4，任何「替代人」的提案本身必须先接受证伪——所以本节给出的是构造、
可行性与一个自降级协议，不是承诺。

### 9.1 拆解：人的「形变工作」是四件事

| 人的动作 | 实例 | 本质 |
|---|---|---|
| A 识别「当前情形 = 已知原则的实例」 | 08-27「机械步骤应机械驱动」= 早已结晶的 code-over-prompt；08-06「designate 唯一权威」= 单源；08-24「不增维度」= 减法 | **分类/检索**——测量 → 原则清单 |
| B 生成反众数方向的候选 | driver 替代 inner/outer、master 冻结——削减语料众数的形变 | **结构化 OOD 采样**（显式算反方向，非自由创造） |
| C 作用域/减法裁定 | 取消 dual-process、开 full-bucket | **可度量判据**（L_D：增不增维度；发生率） |
| D 纠偏过度推广 | 撤销 LPT supersede | **防过度推广闸**（新证伪数据才能推翻） |

**关键命题**：九次演化里大多数是 A 类，不是 B 类——人的「形变」多半是把项目已经学会的
原则应用到新情形。为什么 Claude 自己不做？因为原则以文本存在（ADR/散文），**没有触发
接线**——「当你看到模型在执行确定性循环，就该提议机械化」这条映射从未被写成可触发的
规则。A 类是自动化上限最高的部分：它是识别，不是发明。

### 9.2 可自动 vs 残差

**可自动**：A 类（识别→标准形变）；B 类（给定失败，问「众数典型修法是什么？它的反方向
是什么？」生成 2–3 个有界候选）；C 类（任何增加新机制而不归并既有机制 ⇒ 拒）；D 类
（推翻既有方案的唯一通道 = 新证伪数据）。

**残差（框架说不可自动）**：命名一根**全新**的轴 + 证伪协议无法区分候选时的裁决。诚实的
上限：**自动化可发现的部分 + 把人的残差压到「无法被测量裁决」的边界，而不是消灭人的
OOD 角色。**

### 9.3 构造协议

```
输入：当前 G 的形态 + 最近实测的失效/暗轴读数 + 原则清单（ADR 作为结构化数据）
STEP 1 RECOGNIZE  失效 → 已结晶原则清单（单源/码胜文/减法/硬形变/共享死因/发生率/不增维度）
                  → 命中 ⇒ 标准形变（A 类），附发生率读数（硬规则 12）
STEP 2 ANTI-MODE  未命中 ⇒ 显式生成两方向候选（B 类）：
                  ① 众数典型修法（LLM 默认会做的）② 其反方向（削减众数的形变）
STEP 3 FALSIFY    每个候选必须附：证伪协议（什么测量会推翻它）+ 发生率 + L_D 影响
                  ⛔ 缺证伪协议 ⇒ 降为观察项，不得投递（同硬规则 3b「未评估」态）
STEP 4 NO-SUPERSEDE 推翻既有正确方案的唯一通道 = 新证伪数据（LPT 教训，机械闸）
STEP 5 ESCALATE   仅当证伪协议无法区分候选时，才提交人裁定
```

**触发**：复用 routine-scheduler + 事件触发器——「暗轴被点亮」（新 gap 立案 / 新静默失败 /
新测量异常）+ 定期轴探针（ADR-025~032 当清单跑）。**形态**：formalized prompt-doc
（`contracts:` 自校验）+ routine 接线 + 输出标准候选 SPEC。**不新增消息通道、不新增 driver
kind**——它是 manager 层「可读码/出架构/建议」职责的协议化子角色。

### 9.4 为什么可行

- **验证循环是最终的 OOD 源**（ADR-005：verification is the binding constraint）：形变候选
  不需要事先正确，只需要可证伪；08-27 的测量才是裁决者，不是人提前知道对。候选生成便宜、
  证伪便宜 ⇒ B 类高误报率可承受。
- **A 类覆盖九次演化的大头** ⇒ 自动化上限实际很高。
- **第一步是试点 + 测发生率（硬规则 12）**：挑一段暗轴窗口，量三个数：① A 类识别准确率
  ② B 类候选的证伪存活率 ③ 多少提案过了证伪协议。给出发生率前不承诺替代人。

### 9.5 自降级协议（自指证伪）

本构造本身是一个形变提案，按 §7 元规则 4 必须附证伪协议：**「形变可由反众数计算 + 证伪
循环产生」如果为假，试点窗口里 B 类候选应全部被否决且无存活者；若如此，该 agent 自动
降级为纯 A 类（识别已结晶原则）+ 人裁定兜底。** 一个能自降级的构造，才是这个框架下的
诚实构造。

2017 个 + `packages/quay/src` 367 个实体，7 个 subagent 并发核实 15 个疑似重复簇，
确证 8 个以上真实重复（含 `findRepoRoot`/`findWorkspaceRoot` 逐字节重复的函数体、
`write:state` 6 处实现分裂成原子/非原子两种且仅 1 处解释）。**这是 ADR-007 设想的
工作流第一次被完整跑通并产出真缺陷**，证据强度超过原审计文档（manda）里任何一例。

**反例**：`tasks/gap-fan-in-remove-archguard-gate.md`（2026-09-01）——同一个
archguard-structure 闸接进 fan-in 关键路径后，244 次记录里 `sccCount` 从未非零过
一次，零指引价值、每次 27s，最终移出关键路径。**接了仪器 ≠ 仪器在产出信号**——这
是 §2.2「压扁原理」在仪器自身身上的例证：一个从不报警的检查器，和「一切正常」在
读数上不可区分。

### 10.4 ADR-008：从「机制成立待验」坐实为「诊断过、从未修复」

`docs/analysis/crystallization-the-contraction-phase-has-no-mechanism.md`
（2026-08-04，即 ADR-008 成文半个月后）已经量化过：当晚新增 27,839 行规格文档，
**收缩动作 4 次全部人工发起，机制发起的收缩 0 次**——原文「膨胀相自动，收缩相
完全靠人，机制侧没有东西会说『删掉它』」。09-13 现在核对：全库 `phase:
expansion|convergence` 字段命中数仍为 **0**，ADR-008 frontmatter 仍是
`status: proposed`，`E3` enforcement 仍标注 `deferred`。**这不再是一个待补的
观察项，是一条本项目自己两个月前诊断过、此后从未修复的已知缺口**——§8 的分级已
相应下修。

### 10.5 一处跨项目读数：迁移证据的量级变化

审计文档（`geometry-as-llm-architecture-interface.md`）的实证基础是 manda 项目
（约 5 个事件）；本文档（§1）把同一套抽象（硬形变/Π_{S→E}/压扁原理）迁移到 quay，
独立复现于完全不同的问题域（不是架构反转，是流程/工具结晶）。09-06 后的两周里，
这套抽象继续在 quay 内部往新表层扩散（§10.1），但**尚未出现第三个独立代码库的
复现**——所以「迁移」这一档的证据从「1 个项目」升级为「2 个项目 + quay 内部跨两
个月的持续扩散」，还没有资格升级为「跨任意项目通用」，这条边界应如实标注。
