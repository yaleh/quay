# 目标:quay 产品化交付改进到什么程度,才值得在 user scope 重装并重新冷启动两个项目

**人 2026-08-04 提问定的目标。** 判据必须机械可判,因为**重装的代价是两套循环停摆 + 两轮重新验证**
(meta-cc 这次从启动会话到循环跑起来约 40 分钟,还不含我下的四次裁决)。

---

## 0. 门槛的形状:先预演,再动真项目

**不要拿 archguard 和 meta-cc 当试验场。**

**G0(便宜的前置门)**:在一个**一次性目标**上(空临时目录 + 一个新会话)照文档跑完整流程,
**人工补丁数 = 0**。这一条不过,不许碰两个真项目。

理由:预演的代价是几分钟,重装两个真项目的代价是两套循环停摆。
**把贵动作挡在便宜动作后面**——这与重活令牌串行化是同一条原理。

---

## 1. 五条硬判据(全过才重装)

### G1 — 文档路径零补丁

在一个**已装过旧版 quay** 的目标上,照 README 的命令序列跑完,
**目标外层自己的缺口清单为空**,且冷启动六键 `MONITORS-MOUNTED` / `MONITORS-DELIVERING` /
`CRON-CREATED` / `INNER-DRIVEN` / `TELEMETRY-RECORD` / `FIRST-TASK` **全部 true**。

**判据是「零补丁」,不是「所有缺陷已修」**——新缺陷总会有,
要求的是**已知的那些不再复现,且没有新的阻断性缺陷需要人工绕过**。

### G2 — 升级是整体替换

- 落地的**每一个文件与产物字节相同**(`cmp` 全过,0 处不同)
- **`CONFLICT ... skip` 这条路径不被触发**(理想情况是它不再存在)
- **幂等**:紧接着再装一次,`git status` 无变化

今天实测的基线:meta-cc 落地 23 个可比对文件,**2 个不同**(两份 tick 文档)。
**G2 要求这个数字变成 0。**

### G3 — 两目标字节相同(最强的一条负控制)

同一产物装进 archguard 和 meta-cc,**两边落地的文件互相字节相同**,
**唯一不同的是那个配置文件**。

这条一旦成立,文本替换在结构上就不可能存在,G2 自动成立。
**它比 G2 更强,也更容易查——两个目录 `diff -r` 即可。**

### G4 — 循环真的干成活,不只是启动

冷启动后,目标项目**通过闸**(不是绕过闸)端到端完成 **≥1 个任务**。

**没有这条,验证的只是安装,不是方法论。**
对 meta-cc 而言这要求 dod 闸的模板分派先修好——
否则 41 个 Finding 任务堵着,循环启动了却无事可做。

### G5 — 升级不孤立既有状态

重装后,目标项目已有的 `.workflow-events/` 遥测、`orchestration/tick-log.md`、
`escalations.md`、gate 事件**仍可读且语义不变**。

**升级不许让历史证据失效**——那等于用一次升级抹掉了积累的度量基线。

## 2. 必须在 G0 之前关掉的已知缺陷(2026-08-03 冷启动实测清单)

| # | 缺陷 | 归属 |
|---|---|---|
| 1 | **落地时文本替换**(人已裁定:错的、太脏) | 设计 |
| 2 | `init` 的 `LOOP_SCRIPTS` 硬编码,不含 cold-start 步骤 3/5 要用的两个脚本 | init |
| 3 | `init` 不检测真实 tmux 会话,写猜测值进配置 ⇒ 活着的内层被误报 gone | init |
| 4 | `init` 不铺 `tick-log.md` / `escalations.md`,而 tick 步骤 5/8 假设它们存在 | init |
| 5 | tick 文档内**三套互斥的驱动机制**(CronCreate / ScheduleWakeup / `/loop`) | 文档 |
| 6 | 外层 tick 文档引用的 **6 个编排文件全缺** | 文档 |
| 7 | init skill 步骤 3 不传 `--plugin-root`,宿主经 Skill 调用不注入 ⇒ fail-closed | skill |
| 8 | `monitor-mount-check` 的 `ownedByThisSession` 判据比现实严,成功挂载被判失败 | 判据 |
| 9 | **dod 闸拒绝 Finding 模板任务**(meta-cc 41 个,14 个 todo 全堵) | 产品 |
| 10 | `vendor/quay/dist/quay.js` **1.3MB 撞大文件 pre-commit 钩子**(常见配置,非目标怪癖) | 打包 |

**第 1、9 两条是设计/产品级,其余是交付面。** 第 9 条不修则 G4 不可能成立。

---

## 3. 明确不构成重装理由

- **单条缺陷修好**——每次重装两个项目的代价太高,**攒批**
- **版本号变了 / 重新构建过**——那不是改进的证据
- **「感觉好多了」**——本仓不接受这类判据
