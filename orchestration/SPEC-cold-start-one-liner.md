# 规格：把冷启动压成「一两行命令 + 两个 skill + 内层零操作」

**提出**：人 2026-08-03 ——「安装应当使用一两行命令行（还没发布到 GitHub，本地稍复杂点可接受）；
在 outer 初始化和冷启动应当各只需要一行非常简单的 `/` skill 或 mcp 命令；inner 不需要操作最好。」
**定义者**：管理者。**实现者**：quay 外层 + 内层（走项目正常流程）。

| 阶段 | 目标 | 现状 |

## AC

- [ ] **AC1（可数判据）**：从零到「双层循环在目标项目里跑起来并派出第一个任务」，
      **人/agent 需要输入的命令 ≤ 4 条**（1–2 行安装 + 1 行 init + 1 行冷启动）。
      判据：在一个全新项目上实跑并**记录每一条输入**，条数可数。

- [ ] **AC2**：**参数可推导者不得要求输入**。
      当前 `quay-init --loop` 要求 `--test-command`（失败关闭，这是对的），
      但**它可以被检测**：`package.json` 的 `test` 脚本、`go.mod` ⇒ `go test`、
      `Cargo.toml` ⇒ `cargo test`、有 `scripts/test.sh` ⇒ 用它。
      判据：检测出来后**显示给人确认**，而不是要求人先知道。
      **检测不出来时仍须失败关闭**——不许猜一个默认值。

- [ ] **AC3**：**残留清理并入安装**，不作为独立的一步要人记得。
      判据：安装命令自己检测热拷贝残留（内容与产物不同的同名文件）并处置；
      **处置方式必须可见**（报告清了哪些、备份在哪），不是静默覆盖。

- [ ] **AC4**：**监视器挂载并入冷启动 skill**。
      判据：冷启动后 `inner-state.sh` 与 `session-liveness.sh` 两个进程都在，
      **不需要人分别挂**。且两者不合并的理由随文档走（已有）。

- [ ] **AC5**：**inner 零操作**。
      判据：整个流程中**不需要向内层会话输入任何东西**——
      它要么由冷启动 skill 驱动，要么读安装好的文件自行开始。

- [ ] **AC6（负控制）**：**在一个没有 quay 开发树的环境里实跑一次**。
      判据：把 `/home/yale/work/quay` 改名后，那 ≤4 条命令仍能走通。
      **这条不过，前面五条都不算数**——因为整个目标是「别人能用」。

- [ ] **AC7**：**README 里那段命令序列与实跑的一致**。
      判据：逐字对照，不是"大意相同"。

## 明确不做

- **不追求「一键」**——人说的是一两行命令加两个 skill，不是一个按钮。
  把四条压成一条会把可诊断性也压掉：四条里哪条失败，现在是可分辨的。
- **不为此改 `.quay/config.yml` 的 schema**（产品配置面，要走产品评审）。
- **不猜测试命令**——检测不出就失败关闭，这条比少一个参数重要。
