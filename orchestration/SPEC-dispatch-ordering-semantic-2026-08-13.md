## 2. 目标形态：按"结构 vs 语义"切，而不是给机制打补丁

```
机制负责【能不能派】    disjointness · deps-ready · self-touch · 非 PARKED · 非 compound
                        —— 结构性判断，机制从未出错（当日 disjointness 判断零错例）
inner 负责【先派谁】     语义判断
                        —— 语义性判断，机制从未对过（value 三轴 1/21 发火）
```

**这条划分让 manager 此前提的三个改动作废**（strategic 轴扩谓词 / blocking 读 depends_on 反向边 /
同尺寸集按优先级 tiebreak）：**那三条都是在教机制做语义判断**，而证据说明它不适合。

### 2.1 顺带取消的一个先例风险

「todo→ready 不考虑优先级」同时取消了当日那次**定向晋升**的两难：
manager 曾批准「取闸放行集合的严格子集」并特意写明"这不是绕闸"以防被引为先例。
**新划分下该动作不存在** —— outer 尽力晋、不做选择，也就没有"批准过手工挑选"这个先例。

## 4. 倾向的传递：正本、通知、产物三者分开

### 4.1 为什么 SendMessage 单独用会失败

```
compact 后不可重读   ← manager-tick-sending.md 逐字理由；当日 manager 违反 4 次，
                       最有价值的 A19 重写规格幸存是因为 outer 抄进了任务体，不是因为消息还在
无单一正本           ← 多条消息累积，"当前倾向"靠 inner 记忆排序 ⇒ 不可核
无法验证用的是哪一版  ← 没有任何机制能回答"inner 现在按什么在选"
```

### 4.2 为什么文件单独用也会失败（失败点不同）

**写了不代表读了。** 当日实证：manager 自己的 `A0b⑤(b)`（跑机件前先打印 Usage 行）
**连续 4 轮未覆盖**，原因是"它要求在动作那一刻多做一步，而那一步的产物之后没有任何人再用"
⇒ 纯开销 ⇒ 被跳过。**一个没有产物的"每轮去读某文件"会重蹈同一形态。**

### 4.3 设计：三件分开

```
正本   文件（单一、git 可见、可 diff、抗 compact、跨会话重启存活）
通知   SendMessage 只说「倾向变了，去重读」——【不承载内容】
产物   inner 的派发记录必须带：
         ① 倾向文件的【内容指纹】（git blob hash 或 mtime+首行摘要）⇒ "用的是哪一版"可核
         ② 一句「为什么选它」                                      ⇒ "按倾向选还是随便选"可核
```

**产物是这条设计的承重部分**（C17）：没有它，"读了没读"在记录上不可区分 ⇒ 只能靠意志 ⇒ 必然失守。

### 4.4 倾向文件的结构

```
默认段     manager 不在时生效（例：红窗优先 → gap 优先于 DIR → 其余任选）
覆盖段     manager 在时的当前倾向（本阶段：AC42–AC53 相关任务优先）
维护者字段 谁负责更新它
```

**没有默认段与维护者字段，manager 消失后倾向文件会变成孤儿**：内容还在、没人更新、而 inner 仍按它选
—— 那正是当日反复出现的形态（写着的东西比它的前提活得久：`kind`、被退休的「≤80 行」判据、
C4「manager 的写落 integration」、AC44 判据3 的 8/6/6）。

## 5. 衍生要求：机制输出不该再是有序列表

**如果排序权归 inner，`recommended` 就不该再带序。**
现在它有序，而那个序正是退化的 `1/cost` ⇒ **inner 拿到有序列表会被锚定**，
即使它有语义倾向，也很难无视"机制推荐的第一个"。

⇒ **机制输出改为无序可行集**，或按明显无意义的稳定序（字典序）排并明确标注"序无意义"。
**否则新划分名义上把排序权给了 inner，实际仍由 `1/cost` 决定。**


## 7. 不覆盖

- **不改 disjointness 的地位**：它是**安全约束**不是偏好；manager 已裁定「优先级不得越过它」，本 SPEC 不动。
- **不引入人工打分或新的 priority 字段**：当日已证"没有读者的字段等于不存在"；语义判断交给 inner，
  不再试图把它编码成分数。
- **不要求 inner 解释每一次不选**：只要求解释**选了什么**（一句），避免把产物变成负担而被跳过（同 4.2 的教训）。
- **不规定倾向文件的具体路径与格式**：那属实现面；本 SPEC 只规定它必须有正本、默认段、维护者字段与产物。
