# 规格:仪器收进单一入口(先收缩,再暴露,最后才新增)

**人 2026-08-04**:「把更多仪器集成到一个入口并把这个入口更好地暴露给 Claude Code——
这符合几何信息论的结晶方向。**写更多散落的仪器不是,它们很难重用**。」

## 现状

| | |
|---|---|
| quay MCP 暴露的工具 | **17 个**(`task_*` / `gate_*` / `adr_*` / `action_*` / `lifecycle_*` / `config_validate`)——**全是任务板** |
| `plugin/scripts` 的仪器 | **81 个**,只能靠记住路径 `node --experimental-strip-types plugin/scripts/<name>.ts` |
| 普查器结论(2026-08-03) | live **36** · library 72 · ci-only 1 · dormant 7 · never-runs-test 8 · **unaccounted 81** |
| 脚本总数 | **205 → 207**,尽管退役物理删了约 51 个 —— **种群再生和修剪一样快** |

**一个佐证**:管理者在自己产品的源码里**连查两次都没数出那 17 个工具**,第三次读文件才对。
**可发现性不是抽象问题。**

## 三步,顺序不可换:先收缩,再暴露,最后新增

### 第一步(收缩):重跑已有普查器,不要新写

`plugin/scripts/runtime-usage-inventory.ts` **已存在**。拿到当前数字,给 **81 个 `unaccounted`** 每个一个处置:
保留(并说明理由)/ 退役 / 归入 library。

- **AC1**:普查重跑,`unaccounted` 每一项有处置,**「以防万一」不是理由**。
- **AC2(可判收口)**:**脚本总数下降**。205→207 是失败信号——**这一步不让数字下降就是没做**。

### 第二步(暴露):`live` 的仪器进 MCP,声明是筛选器

- **AC3**:每个进入口的仪器**声明它让什么原本不可机械提问的问题变得可提问**,
  **那句声明就是 MCP 工具的 description**。
- **AC4(筛选器,不是形式)**:**说不出自己回答什么问题的脚本,进不了入口**。
  ⇒ 「进入口」这件事本身强制收缩,而**不是把 81 个原样搬进去**。
- **AC5**:进入口后,调用方式从「记住路径 + `--experimental-strip-types`」变成 Claude Code 自动发现的工具。

### 第三步(新增):基于 meta-cc 的封装

管理者用 **4 次工具调用 + 手工算间隔**才得出「任务耗时 64% 在等套件」。**它应该是一次调用**:

```
task_time_breakdown(taskId) → { waitingPct, workingPct, fullSuiteRuns, gaps[] }
```

底下查 meta-cc,上面是一个 quay 工具。

- **AC6**:该工具**必须在第一、二步之后**才做。
  **先收缩再膨胀,否则入口一开始就装了不该装的东西。**

## 为什么这是结晶而不是又一个脚本

- **81 条要记的路径 → 1 个自动发现的入口**
- **声明要求是硬筛选**:回答不出「我解决什么问题」的东西被挡在外面
- **两个已有 MCP(quay + meta-cc)之间那层手工分析被固化成可复用的工具**,而不是每次重做
