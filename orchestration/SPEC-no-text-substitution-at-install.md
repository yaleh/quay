# 裁定:落地不许改写文件内容(人 2026-08-03)

**人的原话**:「它们是错的,太脏了。当 quay 升级时,这些在本地被修改过的文件是无法维护的。」

## 现状与波及面(实测)

`quay-init.sh` 在把文件拷进目标项目时做**文本替换**:

| 占位符 | 替换为 | 出现在 |
|---|---|---|
| `/home/yale/work/quay` | `$REPO_ROOT` | 20 个文件 |
| `scripts/test.sh` | `$TEST_COMMAND` | **62 个文件** |
| `quay-0:0.0` | `$TMUX_SESSION` | 5 个文件 |
| `plugin/loop/*.md` | `orchestration/*.md` / `docs/analysis/*.md` | 路径重写 |

**每次落地改写 60 多个文件。**

## 为什么这是错的(不是实现瑕疵,是设计错误)

**升级时无法判定一个文件为什么与产物不同**:是替换改的,还是使用者改的?
两者在文件系统上完全同形。⇒ 唯一安全的动作是**跳过**。

**这已经发生了**:`quay-init` 对内容不同的已存在文件走 `CONFLICT ... skip`(archguard 实测)。
于是**升级静默地不生效,目标项目留着旧机制**——而且从外面看装得好好的。
这正是本仓最贵的那类失败:**存在≠生效**,且**看起来已安装比没安装更糟**。

**附带的第二个坑**:占位符 `/home/yale/work/quay` 是一个**在本机真实存在的路径**。
替换一旦失败,在别的机器上会响亮报错(路径不存在),**在这台机器上会静默指向 quay 的开发树**。

## 正确的方向:配置驱动,不是文本改写

- **AC1(硬判据)**:落地的每一个文件**与产物字节相同**。
  `cmp` 可查,升级 = 整体替换,**不存在 CONFLICT 路径**。
- **AC2**:项目相关的值集中在**一个**文件里(扩展 `.quay/config.yml`,或 `.quay/loop.env`):
  `repo_root` / `test_command` / `tmux_session`。**只有这个文件是目标项目私有的。**
- **AC3**:脚本与 tick 文档在**运行时**读这些值,不在落地时烘焙进去。
  markdown 里不再出现任何具体仓库路径或测试命令的字面量。
- **AC4(负控制,最有力的一条)**:把同一产物装进**两个不同项目**,
  两边落地的文件**互相字节相同**;唯一不同的是那个配置文件。
  **这条一旦成立,升级就不可能再有冲突。**
- **AC5**:升级路径要有真实测试——装旧版 → 装新版 → 断言所有落地文件等于新产物,
  且目标项目的配置**没有被覆盖**。

## 与正在进行的 meta-cc 冷启动的关系

meta-cc 的冷启动正在用**现有的替换机制**跑。**不要中止它**——
它会产出这个缺陷的具体数字:落地完成后,统计 meta-cc 的落地文件里有多少与产物不同。
**那个数字就是升级时会被跳过的文件数。**
