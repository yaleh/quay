# 规格：`outer-liveness.sh` 产品化

**提出**：人 2026-08-03 ——「这个 monitor 脚本应当进一步产品化、通用化和参数化。使用 quay 的项目都需要使用它。」
**定义者**：管理者（`quay-0:manager`）。**实现者**：`quay-0:tools`。
**这份文件只定义「要什么」和「怎么算达成」，不规定实现细节**——实现选择由 tools 判断。

## 核心判断（这条决定了设计方向）

**一个采用 quay 的项目只有一个自己的外层。** 三项目扇出是**管理者的特殊用法**，不是通用形态。

⇒ **默认必须是「看本项目自己的外层」，零额外配置**；多目标是可选能力，不是前提。
⇒ 目标与路径应当**在 quay-init 安装时被替换进去**（和两份 tick 文档同一机制），
   **不要在运行时解析 YAML**——bash 解析 YAML 会引入一个不值得的依赖与一类新的失败。

---

## AC

- [ ] **AC1**：`plugin/` 里的源副本**没有任何绝对路径与具体会话名**。
      判据：`grep -E '/home/yale|quay-0:|archguard-2:|meta-cc-4:' plugin/scripts/outer-liveness.sh` 无命中。

- [ ] **AC2**：`quay-init --loop` **铺下它**，并用**已有的**参数完成替换（不新增必填参数）。
      判据：临时项目里 `quay-init --loop --test-command X --tmux-session Y` 之后，
      铺出的脚本中目标与 tick 日志路径指向**该项目自己**，且全文无 `/home/yale/work/quay`。

- [ ] **AC3**：**零配置可用**——新项目装完直接能跑，不需要写任何配置文件。
      判据：铺出的脚本不带参数直接执行，能正确识别该项目自己的外层（活/不活）。

- [ ] **AC4**：**多目标仍可用**（管理者的用法不能被通用化牺牲）。
      判据：`OUTER_TARGETS` 覆盖后三项目模式行为不变；管理者当前挂着的那份换成新版后
      五类事件全部仍能触发（复用 tools 已写的 5 个用例）。

- [ ] **AC5**：**阈值有文档**。四个阈值的含义与默认值写进随包的外层 tick 文档，
      不要只活在脚本注释里——**一个只有作者知道怎么调的参数等于没有参数**。

- [ ] **AC6**：**目标项目没有 tick 日志时不崩**（新项目第一次跑时必然没有）。
      判据：删掉 tick 日志后运行，`OUTER-LOOP-OVERDUE` 静默、其余事件正常，退出码非崩溃。

- [ ] **AC7**：**冷启动 e2e 断言它被铺下且可用**——不只断言文件存在，
      要像 `inner-state.sh` 那样有一个 one-shot 接缝的实跑断言。

- [ ] **AC8**：tools 已写的 5 个用例**全部仍绿**，且测试**仍不触碰三个项目的真实 tick 日志**。

- [ ] **AC9**：管理者自己的三项目配置**从脚本里搬出去**，落在 `orchestration/` 下（管理者的东西），
      **不进 plugin**——plugin 里的是通用默认，不是我这台机器的拓扑。

---

## 明确不做

- **不引入运行时 YAML 解析**（理由见「核心判断」）
- **不改 `.quay/config.yml` 的 schema**——那是产品配置面，动它要走产品评审，不是本规格的范围
- **不做「未发送文字」检测**——管理者已判定：事后无法区分丢 Enter 与灰色 ghost 建议，
  为不可复现的现象造仪器是错的
- **不凭感觉调阈值**——噪声标定要实测数据，没有数据就保持现值

---

## 判据的元规矩（沿用交接文档）

**每条 AC 都要有正控制**：造一个已知会触发的情形，确认它真的触发。
**「干跑没有输出」不是证据**——它与「永远不报」同形。
要退出码就不要管道。`pgrep -f <模式>` 会匹配到你自己那条命令。
