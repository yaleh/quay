# 规格：`outer-liveness.sh` 产品化

**提出**：人 2026-08-03 ——「这个 monitor 脚本应当进一步产品化、通用化和参数化。使用 quay 的项目都需要使用它。」
**定义者**：管理者（`quay-0:manager`）。**实现者**：`quay-0:tools`。
**这份文件只定义「要什么」和「怎么算达成」，不规定实现细节**——实现选择由 tools 判断。

|---|---|

## 核心判断（这条决定了设计方向）

**一个采用 quay 的项目只有一个自己的外层。** 三项目扇出是**管理者的特殊用法**，不是通用形态。

⇒ **默认必须是「看本项目自己的外层」，零额外配置**；多目标是可选能力，不是前提。
⇒ 目标与路径应当**在 quay-init 安装时被替换进去**（和两份 tick 文档同一机制），
   **不要在运行时解析 YAML**——bash 解析 YAML 会引入一个不值得的依赖与一类新的失败。

- [ ] **AC3**：**零配置可用**——新项目装完直接能跑，不需要写任何配置文件。

- [ ] **AC8**：tools 已写的 5 个用例**全部仍绿**，且测试**仍不触碰三个项目的真实 tick 日志**。

- [ ] **AC9**：管理者自己的三项目配置**从脚本里搬出去**，落在 `orchestration/` 下（管理者的东西），

## 明确不做

- **不引入运行时 YAML 解析**（理由见「核心判断」）
- **不改 `.quay/config.yml` 的 schema**——那是产品配置面，动它要走产品评审，不是本规格的范围
- **不做「未发送文字」检测**——管理者已判定：事后无法区分丢 Enter 与灰色 ghost 建议，
  为不可复现的现象造仪器是错的
- **不凭感觉调阈值**——噪声标定要实测数据，没有数据就保持现值

---

## 判据的元规矩（沿用交接文档）

**每条 AC 都要有正控制**：造一个已知会触发的情形，确认它真的触发。
**「干跑没有输出」不是证据**——它与「永远不报」同形。
要退出码就不要管道。`pgrep -f <模式>` 会匹配到你自己那条命令。

# 追加规格（2026-08-03，人问「你和 quay outer 都在用它吗、还需要改进吗」）

## 实测：不是同一个工具，是两个互补的工具

| | 管理者挂的 | quay 外层挂的 |
|---|---|---|
| 工具 | `outer-liveness.sh` | `inner-state.sh` |
| 事件 | `GONE`/`BACK`/`IDLE`/`RESUMED`/`STALL`/`LOOP-OVERDUE`/`STATUS` | `INIT`/`START`/`BATCH-END`/`BLOCKED`/`UNBLOCKED`/`REVERT`/`MASSDELETE` |
| 判据 | 进程存活 + pane 哈希 + tick 日志 mtime | 遥测 JSON + `git log`/`show` + 阻塞信号文件 |
| 看的是 | **会话状态**（活/闲/停滞） | **工作状态**（批次起止/阻塞/危险变更） |

## 缺口：没有任何东西看内层【会话本身】是否还活着

`inner-state.sh` 看的是工作产出。**内层进程死了，它只会看到「没有新遥测」——
而那和「内层在思考一个难题」完全同形。** 这是本仓今天已经栽过两次的那一族失效
（外层空闲被当成健康、监视器盯错层），只是换了个位置。

## 判断：`outer-liveness.sh` 的名字取窄了

进程存活、pane 忙闲、心跳逾期——**这套逻辑对任何 Claude Code 会话都成立，与「外层」无关**。
内层同样需要它，而且更需要：内层跑的是重活，死掉的代价更大。

## AC（追加，编号续前）

- [ ] **AC10**：改名并泛化为**会话存活监视**（名字由你定，`session-liveness` 之类），
      `outer-*` 的字样只应出现在**默认值**里，不应出现在**概念**里。
      判据：事件名与文档不再假设被监视者是「外层」。

- [ ] **AC11**：**心跳文件可参数化**。外层的心跳是 tick 日志，内层的心跳不是——
      内层的心跳应当是它自己的工作产出（遥测 / `.workflow-events/` 之类，**由你判断哪个最可靠**）。
      判据：同一个脚本用不同参数分别监视外层与内层，两边的逾期判据都能正控制触发。

- [ ] **AC12**：**quay 外层能同时挂两个**——`inner-state.sh` 看工作状态、
      泛化后的存活监视看会话状态。两者**不合并**：一个报「它在做什么」，
      一个报「它还在不在」，合并会让一种失效掩盖另一种。
      判据：外层的 tick 文档写明它该挂哪两个、各自答什么问题。

- [ ] **AC13**：**随包走**——泛化后的版本仍由 `quay-init --loop` 铺下，
      且随包的两份 tick 文档（内层那份也要）写明各自该挂什么。

## 不做

- **不把两个工具合并成一个**（理由见 AC12）
- **不在这一轮改 `inner-state.sh` 的事件集**——它的事件是对的，缺的是它旁边少了一个存活监视
