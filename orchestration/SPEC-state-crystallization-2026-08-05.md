# 规格：状态结晶为代码，策略保留为形式化文本

**日期**：2026-08-05（管理者）
**触发**：人指出「agent 和任务的状态应结晶固化到集中的代码中，而不是继续用散文维护；
但对这些状态的**理解和应用**可以保留（形式化）文本驱动——这是自演进与通用性所必要的」。
**性质**：给出一条**可判定的切分判据** + 今晚的实测依据。**AC/DoD 与立案由外层判断。**

## 1. 实测：一个事实，六个源，四个答案

问「现在有几个任务在飞」——2026-08-05 11:0xZ 实测：

| # | 源 | 答案 |
|---|---|---|
| ① | `fast-mode-telemetry --report` | **0** |
| ② | `inner-blocked-signal --read` | 刚被 clear，此前说 **2 个超 90 分钟** |
| ③ | inner pane 状态区 | **1 agent** |
| ④ | `git worktree list` | **3 个**（含 1 个 M239 遗留） |
| ⑤ | `docs/analysis/batch2-queue-state.md` | **211 处**散文提及在飞状态 |
| ⑥ | `tasks/*.md` 的 `status: in-progress` | **0** |

**六个源，四个不同答案。** 而这不是边缘情况——它是今晚每一次判断都要面对的常态。

### 1.1 今晚每个重要问题都要交叉 3–4 个源

| 问题 | 需要的源 |
|---|---|
| inner 是不是冻住了 | transcript + pane 哈希 + heartbeat + 阻塞信号 |
| 有几个在飞 | 遥测 + pane agent 数 + worktree + 阻塞信号 |
| 套件是不是真红 | `state` + `reason` + `note` + 进程列表 |
| 泄漏清干净了吗 | 外层的声明 + `ps` + `/tmp` 目录 |
| 实际并发是多少 | 状态文件 `laneCount` + `ps` 实参 + runner 默认值 |

**管理者今晚的绝大部分工时花在「调和互相矛盾的状态源」上，而不是在判断上。**
这是可量化的浪费，也是「机制无法自演进」的直接原因之一——
**一个连自己有几个任务在飞都说不清的系统，无法对自己做趋势判断。**

## 2. 切分判据（可判定，不靠品味）

> **一段文本若断言的是一个「可被查询的事实」⇒ 它是错位的状态，应进代码。**
> **若断言的是一条「对事实采取行动的规则」⇒ 它正确地是文本。**

**名词进代码，动词留文本。**

### 2.1 用今晚的失败逐条检验

| 实例 | 断言的是 | 判定 | 今晚的代价 |
|---|---|---|---|
| `batch2-queue-state.md` 的「已完成/在飞/待执行」 | 事实 | ❌ 错位 | 外层无法机械读出槽位 ⇒ 12 可派发 vs 1 在飞，**双方都看不见** |
| tick 文档「`red` ⇒ 停止新派发」 | 规则 | ✅ 正确 | —— |
| `note: "ABORT #4 — suite STUCK at session-liveness…"` | 事实 | ❌ 错位 | 手写逃生舱；`suite-state-trigger.ts` 只读 `state`，**读不到 note** |
| `laneCount: 8`（记的是意图不是实参） | 事实 | ❌ 错位 | 实跑 `=8 =8`，状态文件与现实不符 |
| `## Contract` 六键、AC、ADR | 规则/理由 | ✅ 正确 | —— |
| `.halt` 的「在 tick 步骤 0 检查」 | **规则，但缺机械挂载点** | ⚠️ 半错位 | inner 的连续流程绕过步骤 0，halt 后仍派发 5 个 subagent |

**最后一行是这条判据的精细处**：规则可以留文本，但**规则的强制点必须在代码里有挂载**。
否则它就是「写了但不在决策时被调用」——今晚 AC9/AC10 反复踩的同一个坑。

> **挂载补上（2026-08-06，`tasks/gap-supervisor-preemption`）：`.halt` 的机械挂载点现已存在。**
> tick 文档只留规则文本（「`.halt` 存在 ⇒ 本 tick 空转」）；强制点在代码：
> ① `slot-refill.ts` 的 `checkHaltSentinel`（`.halt` 存在 ⇒ `should_refill=false`，新派发被挡）；
> ② `supervisor-preempt.sh halt-check`（读哨兵，fail-closed——读失败 = 停）；
> ③ `supervisor-preempt.sh preempt/preempt-all`（对在飞层进程级停止信号，任意点生效）。
> 规则（动词）留文本，强制点（名词进代码）——与 §3 Session 实体（layer/pid/…）的 pid 账本同构。

## 3. 该结晶的状态实体（名词清单）

| 实体 | 字段 | 现状 |
|---|---|---|
| **Task** | id, status, touches, contract | 已结构化（frontmatter）✅ |
| **Run/Dispatch** | taskId, agentId, worktree, startedAt, endedAt, outcome | **遥测括号从没被调用** ⇒ 形同虚设 |
| **Session** | layer, pid, model, lastActivityAt, busy, inFlightCount | **靠 transcript+pane+ps 反推** |
| **SuiteRun** | state, reason, lanes(实参), startedAt, durationMs, failures | 部分结构化 + 散文逃生舱 |
| **Signal** | kind, taskId, since, question, clearedAt | 结构化，但**真值源与遥测打架** |
| **Resource** | psi, load, gateVerdict | **只在被问时算，从不记录** ⇒ 趋势不可见 |

**这六个实体正好是 supervisor 守护进程该拥有的东西**（见
`SPEC-integration-architecture-2026-08-05.md`）。两份规格在此合流：
**supervisor 是结晶状态的自然宿主**——它不随会话死亡，因此状态也不随会话死亡。

**关键约束**：每个实体**恰好一个写入者**。今晚的矛盾全部来自「多个写入者，无人是权威」。

## 4. 该留作文本的（动词清单）

- **tick 文档的决策规则**——「red 停派」「并发上限 3」「触摸集相交则串行」
- **`## Contract` / AC / DoD / ADR**——判据与理由
- **任务的 Proposal / Plan**——实质内容
- **指令（DIR-*）**——方向性裁定

**为什么必须留文本，而不是「暂时留文本」**：

1. **通用性**：新项目的领域语义不同，文本改一行即可适配，代码要改分支；
2. **未枚举情况**：状态是有限可枚举的，**策略必须处理没预见到的情况**——
   今晚 outer 用 `aborted-no-failure` 这个**新语义值**解决红窗死锁，
   就是 LLM 读规则后的临场判断，写死的代码给不出这个；
3. **自演进**：机制要能改自己的规则。**改文本比改代码的门槛低一个量级**，
   这是「没有人也能演进」的必要条件。

⇒ **这不是妥协，是分工**：状态有限且需要唯一真值 ⇒ 代码；
策略无限且需要适应 ⇒ 文本。

## 5. 形式化的程度（文本不等于散文）

人说的是「**形式化**文本」，不是自由散文。今晚的证据支持三条约束：

1. **规则必须引用状态字段名，不得复述状态**——
   写 `suiteState.reason == 'aborted'`，不写「套件因为资源被中止了」。
   复述即产生第二个真值源。
2. **每条规则必须有机械挂载点**——`.halt` 的教训：规则说「步骤 0 检查」，
   但连续流程没有步骤 0，规则就失效了。挂载点在代码里，规则文本在文档里。
3. **禁止手写逃生舱**——`note` 字段那次：schema 不够用时人会发明一个字段。
   **逃生舱出现的位置，就是缺失字段的位置**，应当补 schema 而不是继续手写。

## 6. 与入口收拢（`quay <名词> <子命令>`）的关系

两件事是同一件事的两面：

- **入口收拢**解决「94 个脚本，调用方找不到」——**发现性**
- **状态结晶**解决「六个源，四个答案」——**权威性**

而且它们的**名词是同一套**：`quay task` / `session` / `suite` / `meter` / `tree`
恰好对应第 3 节的实体清单。⇒ **入口即状态的查询面**：
`quay session list` 返回 Session 实体，`quay meter runs` 返回 Run 实体。
不必设计两套名词。
