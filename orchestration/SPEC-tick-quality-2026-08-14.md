## §1 规范（R1–R9，每条都可机械核）

**每条给出：条款 → 判据（可机械核）→ 它是由哪次实际失败换来的。**
**⚠️ 没有实际失败作依据的条款不写进本节**——那是「凭空设前置」（硬规则 12）。

### R1 指针指向【执行核】，不指向理由档案

**判据**：cron/驱动 prompt 的第 (1) 条读取目标 = `*-tick-core.md`；理由档案降为「需要『为什么』时按 `src:N` 查」。
**⊢ 违反形态**：指针指向一个**自称「不是执行清单」的文件**。
**换来它的失败**：manager 的指针指向 `manager-loop-tick.md`，**而该文件第 3 行自己就转指执行核**；
每轮为此付一次 **57,385 token 的截断读（单次 `Read` 上限 25,000 ⇒ 只拿到 667/1802 行 = 37%）**。

**⚠️ 裁定链与我在其中的程序错误（2026-08-14 12:0xZ 补记）**：本条与既有裁定 **AC30(b)**（`orchestrator-loop-tick.md:8` 逐字
「三层统一架构 SPEC ——**cron 指向本文件，而本文件第一行转指执行核**」）**直接冲突**。
**我的程序错误**：**先把 manager 改成 1 跳（11:0xZ），再把它写成本条通用规范，而没有先过 AC30(b) 的主人。**
**人 12:0xZ 裁定「发 outer 修订 AC30(b) + 三层改 1 跳」⇒ 采纳本条**，并要求**同步修订 AC30(b) 文本**
（否则就是「判据比它的前提活得更久」——今天已撞多次）。已投 outer（`bb4df622`）。
**C24 复判（依据「2 跳」已落地的改动，枚举非抽查）**：三条转指行（outer 的 O2 / inner 的 `fast-mode-loop-tick.md:3` / 我的 `manager-loop-tick.md:3`）
**在 1 跳模式下仍然有用——它们是安全网**：万一有人落到理由档案上，第 3 行把他弹回执行核。**保留，不回退。**
**⚠️ 一个必须写进本条的自我限定**：那次 57,385 token 的截断读**不是结构造成的，是我【读了全文】造成的**——
文档第 3 行就写着转指，**照做的读者本可只读 3 行就跳走**。**⇒ 旧结构不是不能用，是它没规定「不许全读」。**
**⇒ R1 的完整形态必须与 R2 合用**：入口既要直指执行核，**又要明写取法**；只写「读某文件」而无取法 ⇒ 未合规。

### R2 每一个「读某文件」的指令必须写死【取法】

**判据**：指令里出现文件名的地方，必须同时出现取法（`tail -N` / 按节标题定位 / `grep` 谓词）。
**⊢ 违反形态**：只写「读末尾」「读当前阶段」——**「读末尾」与「读全文」在文本上不可区分**，靠每轮自觉。
**换来它的失败**：`manager-tick-log.md` 已达 **337,005 token**，**结构上不可能全读**，而指针只写「读末尾」。
现写死 `tail -30`（实测 2,896 token）。

### R3 每条执行条目必须含一个可机械核的判据句

**判据**：条目内含 `⊢`（或等价的「判据：…⇒…」形式），且该句**能取假**。
**⊢ 违反形态**：条目只有动作名与叙事，**「做了」与「没做」在记录上不可区分**（硬规则 9）。
**换来它的失败**：整份核里大量条款「守与不守在记录上无法区分 ⇒ 只能靠意志 ⇒ 必然失守」（C17 的立条实证：
C8 一晚被读 7 次、引用 7 次，**仍违反 8 次**）。

### R4 执行核只放【动作 + 判据 + `src:N`】；实测/代价/复盘叙事进理由档案

**判据**：`src:N` 覆盖率 = 100%（`tick-core-static-check` AC3）且 pointer targets OK（AC4）。
**⊢ 违反形态**：核的 token/条目数远高于同类核 ⇒ 每轮读入被叙事占满。
**⚠️ 迁移的四个已实证失败模式（必须写进执行方的检查表）**：
```
① 迁走判据只留标题             ⇒ 执行核退化成目录
② 忠实保留一条【已过期】的判据   ⇒ 形式化让它更好读，也更容易被当成"刚审过所以对"
③ 把路径压成裸文件名           ⇒ AC4 死指针
④ 把机器按字面量识别的标记压短   ⇒ 检查器认不出（如 AC8 的「不计入覆盖率分母」）
③④ 同族：压缩的收益是省 token，而【指针与标记不是文字，是接口】。
```
**⚠️ 迁移方式的硬约束**：**新内容必须追加到理由档案【末尾】**——插入中间会使其后行号偏移，
**一次性打断全部既有 `src:N`**。**并且原文必须由脚本【逐字复制】，不得重打**（丢失风险 0）。

### R5 承诺必须有【独立容器】，不许只写进散文

**判据**：形如「下轮做 X」「我这就发 Y」的承诺 ⇒ 独立文件（`.quay/manager-next-a20.txt` / `.quay/manager-pending-send.txt`），
执行后清空/覆盖；**⊢ 该文件内容与本轮记录不一致 ⇒ 未执行**，一条命令可查。
**⊢ 违反形态**：在 tick-log 里写「下轮强制 X」——**纯自觉承诺，没有独立于执行者意志之外的机械阻塞**。
**换来它的失败**：manager 连续两轮写「下轮 A20 = AC72」，**两轮都被别的工作占满**（workflow 自审逐字点名）；
B3b 的前两版试图**从散文里切字段**，两版都命中规则自身的描述文本。

### R6 判「本层是否执行了 X」一律读【直接量产物】，不靠自觉

**判据**：凡 X 的执行在 transcript / 文件系统留有产物（`tool_use` 记录、事件文件、锁事件），
**必须每轮读该产物**；`>N 周期未调用就要记` 这类靠记忆的条款一律替换。
**⊢ 违反形态**：条款写着「未调用就要记」而无人读产物。
**换来它的失败**：manager 的 B1（workflow）**空档 4h12m、12 轮 tick 零调用、A9 一次都没报**；
且**前 6 次调用未传 `args`** ⇒「调了」≠「照 B1 调了」。现改为每轮读 `meta-cc` 的 `Workflow` `tool_use`。

### R7 阈值/窗口一律读【实际量】，⛔ 写死常数

**判据**：核里出现的任何周期/阈值，必须由**当轮可读的量**导出（如「上一条触发时刻到现在」），
或明写它读的是哪个宿主变量。
**⊢ 违反形态**：写死一个「看起来合理」的数字。
**换来它的失败**：`cron */17 * * * *` 的标准语义是**每小时第 0/17/34/51 分**，`51+17=68>59` 回绕
⇒ **`:51→:00` 只隔 9 分钟**；实测 36 次触发 平均 16.0 / 中位 15.9 / **最短 8.2** / 最长 28.6。
**「17」在 cron 里不是间隔**，而它已造成两个受害者：B3-戊 的陈旧门槛宽近一倍、tick-log 时刻标签漂移 +22 分钟。

### R8 「重建/清扫」类动作改为【条件式】，每轮只做核实

**判据**：给出 N 条可机械核的核实判据，**全真则不动**；任一为假才重建，并记 `<旧值>→<新值> 因<失败的那一条>`。
**⊢ 违反形态**：每轮无条件销毁重建。
**换来它的失败**：manager 的哨兵每轮重建 **208 次**，代价三条——
①**零-cron 窗口**（delete 与 create 之间没有任何哨兵）②**「哨兵数」恒为 1 ⇒ 结构上无法回答「有没有出现过重复/丢失」**
（硬规则 4）③**每轮重新引入一次文本打错的风险**（实测已漂移过一次：208 条里 2 条是圈号变体）。
**⇒ 一般形态：一条纪律被执行成一个比它强得多的动作时，多出来的那部分不会有人复核——因为它看起来是「更严格」。**

### R9 workflow 是 tick 的第一步，且必须传 `args`

**判据**：**⊢ 本轮 `Workflow` `tool_use` 记录数 = 0 ⇒ 本轮 tick 未执行第一步**；
**⊢ 记录存在但 `input` 无 `args` 键 ⇒「调了但未照规范调」**（自审段没有 prior 可审，等于只跑了半个）。
**为什么进规范（人 11:4xZ 逐字「workflow 被证明是有效的，应进一步应用」）——实证在下**：
```

  09:09  报出上一轮「cut -c1-95 截断当全貌」——我把显示宽度当成了内容边界
  09:30  报出 995b9942 未声明改动 —— 由此引出「豁免键随时间扩大」这个真缺陷
  11:20  报出 A20 = AC72 承诺未执行，并逐字指出「该承诺没有独立于管理者意志之外的机械阻塞」
         ⇒ 直接催生了 R5 的容器
另外三次 violations=[] undeclaredActions=[]（全清）。
```
**⚠️ 它的作用域是【声明一致性】，不是【规则内容正确性】**——
「一条写错了的规则」它结构上看不见（那是 A20/复核那一步的活）。**两者不可互相替代。**

## §5 本 SPEC 自身的失效条件

- **`tick-core-static-check` 的 AC3/AC4 退役** ⇒ R4 失去机械保证，**R4 必须冻结**。
- **三层核合并或改名** ⇒ §2 的实测基线全部作废，须重测。
- **cron 周期语义变化**（如 `*/17` 改成别的表达） ⇒ R7 的实证段须重测（**⛔ 引用本文件的旧数字**）。
- **本 SPEC 自己也适用 R3**：上面每条 R 都带了判据与「换来它的失败」；
  **⊢ 若某条 R 无法给出实际失败依据 ⇒ 它是凭空设的前置（硬规则 12），应删。**
