# 规格：把「类型化目标」与「动力学量」从习惯变成机制

**提出**：人 2026-08-03 ——「如何应用带闭包的类型化目标和连续动力学层
改进你自己和现有项目的工程方法？」
**定义者**：管理者。**实现者**：quay 外层 + 内层（走项目正常流程）。

---

## 0. 一个约束，它决定本规格的全部形态

**管理者自己写的「每 tick 必记 `cpu some avg10`」，遵守率 39%（15/38）。**

⇒ **任何以「以后记得做 X」形式的改进都会失效。**
本规格所有条目**必须落成脚本或字段，不得落成文档行**。
这不是风格偏好——是当天第三次在管理者身上兑现的实测。

## 2. AC1（优先级最高）：`L_S` 的仪器 —— 对**检查器**做变异测试

**不是对产品代码做变异测试，是对检查器做。**

**当天的立案**（`twelve-instances-and-two-mappings.md` 第 6、10 条）：

- #6 改名负控制**存在、可执行、报绿**——而**探针在缺陷存在时也不会失败**
- #10 `/live` 的降级路径完美——**只测了数据缺失方向，没测数据本该在却不在**

管理者从失败里反推出「**负控制必须能在缺陷存在时失败**」，
**而那正是 `L_S` 的内容**——轴名本可以事先给出。

- [ ] **AC1a**：对每个已注册的检查器，存在一个**变异用例**：
      故意破坏它所检查的对象，**该检查器必须失败**。
      判据：变异用例本身在套件里、且**移除被检查对象的破坏后检查器回到通过**（双向）。
- [ ] **AC1b**：**检查器清单从哪来不许手写** ——
      从 `run_static_checks` 与 CI 工作流里**解析出**已注册的检查器，
      手写清单会漏掉「新加的检查器没有变异用例」这一类。
- [ ] **AC1c（元判据）**：**这个机制自己也要有变异用例** ——
      破坏它，它必须失败。否则它就是它自己要抓的那种东西。

## 3. AC2：`## Contract` 加 `axis:` 字段 —— 把「哪根轴还暗」变成查询

现有六键 `measure/band/invariant/invoke/control/resume` **没有一个说这条测哪根轴**。

- [ ] **AC2a**：契约语法支持 `axis: L_T|L_C|L_D|L_G|L_S`（可多值），
      **每条 `measure` 至少标一根轴**。
- [ ] **AC2b**：`task-contract-check.ts` 能回答「**这个任务的契约里哪几根轴是暗的**」，
      并支持**跨任务库查询**（例：列出所有一个 `L_S` measure 都没有的任务）。
- [ ] **AC2c**：**存量任务不强制回填** ——
      新任务必须带 `axis:`，存量按 `L_T` 缺省，与测试框架策略的存量豁免同款。
      **理由**：强制回填 600+ 任务会逼出敷衍标注，那比不标更糟。
- [ ] **AC2d（负控制）**：造一个只有 `L_T` measure 的任务 ⇒ 查询必须报出 `L_S/L_G/L_D` 暗；
      再补一条 `L_S` measure ⇒ 那一根不再报暗。

## 4. AC3（次优先）：四个动力学量变成常设测量

当天全部**手工一次性算过**，无一常设：

| 量 | 当天值 | 意义 |
|---|---|---|
| Σ/墙钟 | **7.1**（4 核） | 有效并行度；>核数 ⇒ 启动与等待密集非 CPU 密集 |
| run-to-run 方差 | sigma **297.6 s** | **没有它，任何「改善」都可能在噪声里** |
| **按应用机会计的侵蚀速率** | 散文规则 ~10 次机会内首违 | 当天发明；散文 vs 检查的判据 |
| 队列深度 / 消耗速率 | 56 待办 / 1 在飞 | 当天据此判定「瓶颈是串行闸不是 CPU」 |

- [ ] **AC3a**：每次全量套件运行**自动记录** Σ、墙钟、Σ/墙钟、最慢文件及其耗时。
- [ ] **AC3b**：维护一条 **run-to-run 方差基线**；
      **任何「性能改善」的声称必须先与该基线比**——
      当天管理者报过「Σ 降 8.2%」而方差范围是 297.6 s，**那个改善完全在噪声里**。
- [ ] **AC3c**：`L_D` 的**描述长度**读数接上（`archguard` 已是该轴仪器，当天一次未用）。
      现成用例：任务库 608 个任务、`/` 路由随数量线性到 **4.9 s** ——
      **描述长度在增长且已经有人在付费，而没有任何东西跟踪它。**

## 5. 明确不做

- **不引入 Fisher 度量 / 本征维度 / ρ**。举不出一个它们会改变的决定，
  且能说清原因：**它们需要一个这里不存在的状态空间参数化**。
  与 `geometry-as-llm-architecture-interface.md` §4 的自我判决一致。
- **不做 `L_G` 的仪器**（跨 repo 概念级重复探测）——当天零个实例指向它，
  **没有证据就不建仪器**，那会重复「造了没人用」（`L_D` 仪器当天一次未用就是现成教训）。
- **不把这些做成 tick 文档里的检查清单**（见 §0）。

## 6. 与在飞任务的关系

当前在飞 3 个（冷启动 / `live-unwired` / `ac-carryover`），**都在同一道串行闸后排队**。
本规格**不要求插队**：AC1 与 AC2 是**新机制**，AC3 是**测量接线**，
三者都可以等冷启动那条主线让出槽位。

**但 AC1 与 `ac-carryover` 同源**——后者查「收尾时 AC 是否完成」，
前者查「检查器是否真的能失败」，**都是「守卫存在 ≠ 守卫生效」的两面**。
若实现者判断可以并入，比分开做更省。
