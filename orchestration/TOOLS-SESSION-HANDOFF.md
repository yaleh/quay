## 你现在拥有的东西

**`plugin/scripts/outer-liveness.sh`**（管理者写的，已能工作，但没有自动化测试）。
它监视三个项目的**外层**（不是内层），报五类事件：

| 事件 | 触发 |
|---|---|
| `OUTER-GONE` / `OUTER-BACK` | 外层进程消失 / 恢复 |
| `OUTER-STALL` | 活着但 ≥45 分钟无新提交（仅未暂停的项目） |
| `OUTER-LOOP-OVERDUE` | tick 日志 mtime ≥45 分钟未更新（仅未暂停的项目）——loop 可能已死 |
| `OUTER-IDLE` / `OUTER-RESUMED` | 相邻两轮 pane 哈希相同=空闲；**在转换后一个轮询周期内报出** |

`OUTER_TARGETS` 环境变量可覆盖监视目标（每行 `<名字> <仓根> <tmux目标>`）——
**它存在的唯一理由是可测**。

## 三条硬规矩

1. **不碰任何项目的产品代码/任务/CI**——你只做跨项目机件（`plugin/scripts/` 下的监视与令牌类脚本）。
   看到别的问题，报给管理者，不要自己动手。
2. **「干跑没有输出」不是证据**。管理者做这个监视器时连着踩了三个装置错误，
   每一个都被「无输出」掩盖过：探针 cmdline 不含 `claude` 故被判为不存在、
   `sed` 在非终端下缓冲把输出吞掉、`/proc` CPU 增量的对照组量错了进程。
   **每个判据都要有正控制**——造一个已知会触发的情形，确认它真的触发。
2b. **要退出码就不要管道**：`cmd | tail | sed` 之后的 `$?` 是 `sed` 的。今晚这条错了两次。
3. **`pgrep -f <模式>` 会匹配到你自己这条命令**。今晚两次因此杀掉了自己的 shell。
   找进程按 `/proc/<pid>/cmdline` 的 argv 位置判，找监听服务按端口 `ss -ltnp`。
