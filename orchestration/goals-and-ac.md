## 目标（我的判断，不是管理者任务清单的复述）

> **quay 的产品主张是「闸是可运行的，不是被断言的」**
> （`CLAUDE.md` 原话：*the meter is runnable, not asserted*）。
> **今晚的证据表明，这个主张在最重要的那道闸上是假的。**
>
> **⇒ 产品此刻最该走的方向：让「完成」在任何目标项目里都不可零成本取得，
> 且伪造的尝试会留下痕迹。**

**为什么是这个方向而不是别的**（全部是今晚的实测，不是判断）：

| 证据 | 出处 |
|---|---|
| `execute→done` 与 `author→ready` **读同一份 AC 复选框** ⇒ 过第一道自动满足第二道 | 管理者实测 `DIR-102`：建立 30 分钟、零工作量、被认证可关闭 |
| **更下面一层：状态可被直接写入绕过闸** | 今晚 `gap-no-e2e-…` 是 `status: done` + **八条 AC 全未勾** + **分支未合入 master** |
| meta-cc 循环活着、cron 在跳、tick 5 行，**完成任务 0** | 管理者实测 ⇒ **只证明装得上，没证明装上的是方法论** |
| **82 个脚本出厂，0 个声明自己回答什么问题** | 外层实测 ⇒ 目标项目拿到 36 个检查却不知道它们各自答什么 |

**这四条指向同一件事**：quay 交付的是「可运行的判据」，
而**判据本身当前既可被绕过、也无法自述**。**先修这个，其余都是它的下游。**

## AC（每条都能用一条命令或一次实测回答）

- [x] **AC1：`done` 不可零成本取得。**
      判据：造一个 **AC 全勾、DoD 全未勾**的任务 ⇒
      `node --experimental-strip-types packages/quay-native/bin/quay-native.ts task check <id> --json`
      的 `execute-done` **必须 `ok:false`**。
      **已满足（外层 2026-08-04 01:55Z 自造夹具实测，不是读勾选）**：
      临时任务库中造一个 `status: ready`、**AC 2/2 全勾、DoD 0/2 未勾**的任务 ⇒
      ```
      { "gate": "execute->done", "ok": false,
        "acTotal": 2, "acChecked": 2, "dodTotal": 2, "dodChecked": 0,
        "reason": "0/2 DoD checkboxes checked" }
      ```
      **⇒ 两道闸的证据源已分开，`done` 不再零成本可得。**
      **控制同时成立**：`gate-gameability.test.mjs` 仍 `pass 1 / fail 0`——
      **那条「闸永不验声称真假」的 permanent 边界没有被这次改动破坏**
      （这是外层给该任务加的 AC8：**把「两闸冗余」修成「试图判断声称真假」是走进一个已被证明不可行的方向**）。

- [ ] **AC2：绕闸写入的状态必须可被列出。**
      判据：`bash plugin/scripts/task-status-drift-check.ts`（或等价入口）
      **必须报出**今晚这个活标本——`gap-no-e2e-proves-install-is-configuration-driven`
      `status: done` 而 8 条 AC 全未勾、分支未合入。
      **报不出来即不满足**：**一个从没在真实现场报出过东西的漂移检查，与「永远返回空集」不可区分。**

- [ ] **AC3：至少一个目标项目「过闸完成」过一个任务。**
      判据：在该项目里 `fast-mode-telemetry --report` 的 `done ≥ 1`，
      **且**该任务的 `task check` 曾返回 `ok:true`（不是被直接改状态）。
      **当前状态：0**（meta-cc）。**这条不满足之前，quay 只是「装得上」。**

- [ ] **AC4：出厂的每个检查都能自述它回答什么问题。**
      判据：目录命令列出的检查中，**带问题声明的比例 = 100%**。
      **当前：82 个脚本、0 个声明**（外层实测）。
      对应任务 `gap-eighty-two-shipped-checks-and-none-says-what-it-answers`。

- [ ] **AC5：产品的用户面不因方法论层的改动而退化。**
      判据：`curl -s -o /dev/null -w '%{time_total}' http://<host>:<port>/` **< 1.0s**，
      且 `scripts/test.sh` 的 **product 组全绿**（`fail 0` 且 `cancelled 0`）。
      **这条是我要主动提的那个冲突，见下。**

- [ ] **AC6（长自我错误）：我给内层的每一条涉及删除或清理的指令，必须写明硬前提。**
      判据：指令文本含「**仅限已合入的分支**」这类前提；
      且事后核实**无未合入分支的 worktree 被移除**。
      **来源**：2026-08-04 01:22Z 我请求清理三个 worktree 时写了「三者分支都已 merged 我核过」，
      **但没把它写成硬前提**；随后 e2e 的 worktree（**分支未合入**）也被移除，
      工作只剩一个孤立分支。**认下来不是客气**：
      **若我把它记成纯粹的内层失误，下一次我还会用同样松的措辞。**

**但我要指出它的代价，因为它与我的 AC5 直接冲突：**

- 今晚 6 小时，**唯一触及 quay 产品用户面的工作是任务列表路由的性能**

  它们测的是「装得上、装的是同一份、升级不丢、闸认得模板」。
