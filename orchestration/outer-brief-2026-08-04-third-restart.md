## 1. 人指定的优先工作：一组架构裁定（先于就绪队列里的任何任务）

**背景（今天两次机器级崩溃的根因，已实测钉死）**

- 实测（tmux 3.6，本机，只读命令）：`$TMUX` **压过** `TMUX_TMPDIR`；`-S` / `-L` **压过** `$TMUX`。
- 两台机器（vhs / transformer）的杀手命令**都**是子代理临时写的 shell，**都**在同一个任务
  `gap-send-keys-verified-hash-check-cannot-tell-typed-from-submitted` 上——为了造假 TUI 夹具而裸调
  `tmux kill-server`，误杀真实默认服务端（连带杀掉自己）。
- 已提交代码里 5 处隔离助手**全部**正确 `delete env.TMUX`，显式 `-S`/`-L` 用法 **0 处**
  ⇒ **任何仓库级 lint 一条也抓不到**。缺陷只存在于临时命令里，不在被检查的文件里。

**需要你裁定并立案的六条：**

### A. ADR-016 的 carve-out 需要收紧（不是删除）

ADR-016 原文是 `NEVER parse the TUI`，但留了一句 `capture-pane` is only a coarse "idle / ready-for-input" check。
⇒ **没有任何 ADR 要求 TUI 哈希**；`send-keys-verified.sh` 的哈希判据是**违反** ADR-016，不是遵守它。
该做的是把那句含糊的 carve-out 写清楚：屏幕允许判哪些状态、允许取屏幕的**哪个函数**，**永远不含整屏等值/哈希比较**。

### B. blocked 自申报有结构性缺口（洞是已知的，任务却已 done）

`gap-the-one-condition-the-channel-was-built-for-still-has-no-trigger`（status: done）自己记着：
`--detect-stop` 只自动触发 `merge-conflict`（结构性）与 `task-over-90m`（年龄代理），
而 `ruling-required`（*any question the outer must rule on*）**没有任何机械触发**，只能靠内层记得手动调 CLI。
⇒ 现有方案**依赖被卡住的那一方自己意识到并申报**。今晚复现过：内层说「等套件 #12 通知」然后坐着不动，外层没察觉。

### C. 人要的能力，和它的判据

> 「当一个 Claude Code 会话需要它的用户输入/参与时，它外层的那个会话能及时观察到」——**可以接受几分钟延迟**。

注意这和「送达确认」**不是同一个问题**，优先级也不同（见 F）。

### D. 建议方案：屏幕为主，transcript 为辅

- transcript jsonl **看不到**：权限确认框、错误横幅、卡住的渲染、输入框里没提交的文字——
  **而最要紧的那种（弹框等批准）恰好整个落在这一列里**。
- 哈希失败 **≠ 屏幕不行**，是**取错了屏幕的函数**。人不哈希整屏；人看底部几行 + 认**形状** + 用**时间上的持久性**。
- ⇒ 底部区域 + 形状分类 + 多次采样一致。分钟级预算下**轮询足够**，不需要 inotify 那种精度。
- 抗脆分两级：确定性匹配常见形状（便宜）；匹配不上或形状异常就把那段文本**交给外层自己读**
  （LLM 读屏幕天然跨 TUI 版本，不脆）。

### E. 这个设计顺手消掉危险面 —— **不要用 PreToolUse hook**

人明确否决 hook：会弄脏使用 quay 的项目的环境。不需要它——
分类器的契约是「给定 pane 文本 → 判定状态」，**一个纯函数** ⇒ 夹具是录下来的 `.txt` 屏幕文本
⇒ 不需要 tmux server / pty / 假 TUI ⇒ **那整类危险测试直接消失，是设计消掉的，不是靠拦截。**

### F. 关掉 `gap-send-keys-verified-hash-check-cannot-tell-typed-from-submitted`（降级，不修）

人裁定：输入确认本身重要性不高（就算输错了，外层照样有机会观察到）。
它要防的「消息躺在输入框没发出去」恰好是屏幕上看得见的状态，**被 D 顺带覆盖**，不需要单独造哈希启发式。
**两台机器就是死在这条任务上。**

## 4. 边界

你是**外层**：下指令、裁定、核实。**共享检出的代码由内层执行**——不要自己用 `Agent` 派发实现工作到共享树。
（今晚已经因为这条被人当场抓到过一次。）
**收窄（2026-08-10，理由=单一写入者/共享树）**：禁令防的是【共享树】双写入者（`git stash` 事故即外层动了内层在工作的树）。**外层可在【自己的 worktree】里执行基础设施动作（suite/修红/merge），因为隔离已消除单一写入者冲突**——但**替内层执行任务仍禁止**（任务仍由 inner 执行）；放开仅限基础设施动作且必须在自己 worktree 内。
