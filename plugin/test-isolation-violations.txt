# test-isolation-violations.txt — known violations of the TEST-ISOLATION CONTRACT
# (gap-test-isolation-contract-is-unwritten + gap-tests-never-clean-up-their-tmpdirs).
#
# POLICY: a test must never touch something it does not exclusively own. Six rules
# (details in docs/analysis/test-isolation-contract.md, sourced from the three
# isolation-green/suite-red failures of 2026-08-02/03 + the 2026-08-03 /tmp leak):
#   R1 fixed-path-write             write only to per-run-unique paths (mkdtemp / os.tmpdir()),
#                                   never a fixed __dirname/.tmp-* path under the shared checkout
#                                   (relation-sync's 8-copy 7/8 crash is the type specimen).
#   R2 shared-build-artifact-write  never rebuild/overwrite the SHARED build artifacts
#                                   (packages/<pkg>/dist/, plugin/vendor/) — build to a temp tree
#                                   (M136, three rounds).
#   R3 spawns-test-sh               never spawn the whole scripts/test.sh runner inside the suite
#                                   (AC11's 60s-budget nested run).
#   R4 process-exit-1               a hand-rolled harness's failure path must use process.exitCode,
#                                   never process.exit(1) (can drop async stderr writes under a
#                                   POSIX pipe — relation-sync's silent suite-red).
#   R5 (doc-only)                   never depend on the running repo's git history (shallow clone
#                                   must stay green) — documented in the contract, no scanner rule.
#   R6 mkdtemp-no-cleanup           a file that mkdtemp()s but has NO cleanup construct (rm/rmSync/
#                                   t.after/after/finally) leaks a tmpdir per run — /tmp (tmpfs)
#                                   accumulated 166,923 entries / 6.3 GB over 9 days (2026-08-03).
#                                   NEVER matches /tmp/claude-* (session data) / /tmp/quay-wt-*
#                                   (in-use worktrees) prefixes (AC6).
#
# The scanner (plugin/scripts/test-isolation-check.ts) REPORTS every current violation on every
# scripts/test.sh run but does NOT block on the ones listed here (AC6, "报出而不阻断"). This list
# is the SHRINK-ONLY known-violation baseline (AC5): the check FAILS if
#   - a CURRENT violation has no entry here (a new violation was introduced — fix the test),
#   - an entry is ADDED vs git HEAD (the list can only get SHORTER),
#   - an entry is STALE (the code was fixed but the entry kept — remove it),
#   - the entry count exceeds `# baseline-count` (commit-surviving backstop).
# To remove an entry: fix the test FIRST, then delete its line here — the check then fails on the
# stale entry until it is removed, which is the nudge that makes the list actually shrink.
