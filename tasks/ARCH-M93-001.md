## Finding

**WHAT:** The `gate/` sub-package (directory `packages/quay/src/gate/`) is the largest concentration point in the quay codebase by relation count. It has fanOut=62 (all outgoing cross-entity relations are within the gate sub-package itself) and fanIn=7 (7 external entities import from it). It contains 7 files, 52 entities, 31 interfaces, 21 functions, and 150 fields — more than 59% of all entities in the analyzed codebase (87 total).

**WHERE:** `packages/quay/src/gate/` — specifically:
- `gate/registry.ts` (736 lines, outDegree of GatesConfig=5)
- `gate/lifecycle.ts` (222 lines)
- `gate/engine.ts` (66 lines)
- `gate/gate-event-store.ts` (91 lines)
- `gate/gate-log.ts` (53 lines)
- `gate/acceptance-runner.ts` (80 lines)
- `gate/driver.ts` (147 lines)

**METRIC:**
- fanOut = 62 (package-level, archguard_get_package_metrics)
- fanIn = 7 (package-level)
- entityCount = 52 (archguard_get_package_stats: package "gate")
- fieldCount = 150
- interfaceCount = 31, functionCount = 21
- Total codebase entities = 87; gate holds 52 = 59.8%

**WHY:** A single sub-package holding 60% of all entities and 62 internal cross-entity relations indicates an architectural concentration that will resist decomposition. The `gate/registry.ts` file alone (736 lines) aggregates all gate factory functions (makeIt0Gate, makeFixedScriptGate, makeAdrGate, makeTestPassGate, makeCoverageFloorGate, makeRedGreenGate, makeDocumentContractGate — 7 factories) plus the resolver and loader. As new gate types are added, registry.ts will continue to grow. Any change to the gate mechanism touches this one file.
