## Finding

**WHAT:** `startMcpServer` in `packages/quay/src/mcp-server.ts` is the highest-outDegree entity in the entire codebase (outDegree=10 per archguard_summary). The function is 797 lines long and registers 15 MCP tool handlers (task_list, task_get, task_write, task_check, gate_run, gate_log, lifecycle_complete, lifecycle_adjudicate, lifecycle_promote, lifecycle_retreat, adr_list, adr_get, adr_write, action_list, action_run) all inlined in a single function body. There is no router abstraction or handler decomposition.

**WHERE:** `packages/quay/src/mcp-server.ts`, function `startMcpServer` (line 102 to end, ~695 lines of function body).

**METRIC:**
- outDegree = 10 (highest in codebase, archguard_summary topByOutDegree rank 1)
- File size = 797 lines

**WHY:** Inlining 15 distinct MCP tool handlers into one function creates a high-friction surface for any future change: adding a tool, changing a schema, or debugging one handler requires navigating 797 lines of mixed concerns (server setup, connection logic, all 15 handler implementations). Any refactoring or security audit of tool handlers must work through this monolithic surface.
