## Finding

**WHAT:** `startServer` in `packages/quay/src/serve.ts` is 675 lines of function body (lines 411–1085, the entire remainder of the file after helper declarations). It contains: HTTP server setup, 5 inline route handlers (`GET /`, `GET /adr`, `GET /adr/:id`, `GET /task/:id`, `POST /task/:id/action/:actionId`), URL security checks (isSafeRelativeRedirect), redirect logic, and all HTML rendering inline-called. It ranks second in the codebase by outDegree (outDegree=6 per archguard).

**WHERE:** `packages/quay/src/serve.ts`, function `startServer` starting at line 411; total file = 1085 lines (largest in the codebase).

**METRIC:**
- outDegree = 6 (archguard_summary topByOutDegree rank 2)
- File size = 1085 lines (largest single source file in the analyzed codebase per wc -l)
- Function body size = 675 lines (computed: 1085 total - 410 lines of top-level helpers before startServer)

- Top-level helper functions before startServer: `html`, `escapeHtml`, `stripHeadings`, `pageStyles`, `renderMarkdown`, `inlineMarkdown`, `relativeTime`, `isSafeRelativeRedirect` — 8 rendering/utility helpers defined outside but directly called inside

**WHY:** `serve.ts` conflates three concerns: (1) HTTP server lifecycle and routing, (2) task/ADR domain HTML rendering (5 distinct route handlers with full page templates), and (3) security/redirect logic. The 675-line function body means any change to one route (e.g., adding a filter parameter, fixing a redirect bug) requires navigating and risk-assessing unrelated sections. The archguard outDegree=6 reflects the coupling: `config.ts.activeProvider`, `config.ts.loadConfig`, `provider-client.ts.connectProvider`, `provider-client.ts.ProviderClient`, `provider-env.ts.resolveProviderEnv` — all directly tied to one function scope with no separation between setup and serving.
