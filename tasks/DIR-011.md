DIR-009's design needs to write rich, structured metadata onto quay tasks (milestone grouping, selection rationale, execution provenance). Investigating the task store's actual edit surface and cross-provider support this conversation surfaced two concrete, product-code-level facts: (1) the Core CLI `task edit` is the lone status-only bottleneck (QN-024) — the native provider CLI and MCP task_write beneath it already support full-field writes; (2) `extra{}` is not provider-portable (GitHub cannot write it — M09 PR-ABI-001 hard-errors), so portable metadata must live in the task body with extra{} as a native-only mirror.
