## Finding

`M-TASK-BACKLOG-PROJECTION` (backlog.md row, DIR-009 + DIR-010 sourced) is the fix
that would make exp5's own non-directive work — milestones, backlog candidates,
selection/execution provenance, and discovered gaps — visible and trackable as
quay tasks (generalizing M05's directive-only projection). Its design was
delivered and marked **DONE at m13**, its row ending: "still requires a future
SELECT to charter and dispatch the actual implementation." But:

- **There is no `M-TASK-BACKLOG-PROJECTION-IMPL` candidate row** (grep confirms the
  only `-IMPL` row in the whole backlog is `M-CLI-EDIT-PARITY-IMPL`). SELECT
  (`OUTER-LOOP.md` step 1) only considers **non-DONE candidate rows**; a DONE row
  is skipped and no implementation candidate exists, so **SELECT has nothing to
  pick and this implementation can never be chosen** — the "deferred to never"
  pattern.
- Contrast the sibling design-only milestone `M-CLI-EDIT-PARITY` (DONE at m14):
  its ABSORB **did** create `M-CLI-EDIT-PARITY-IMPL`, which was then SELECTed and
  completed at m16. M13's ABSORB simply omitted the equivalent row for
  `M-TASK-BACKLOG-PROJECTION`. Same design→implementation shape, one materialized a
  selectable follow-up, one did not — a pure ABSORB-time inconsistency.
- It is doubly self-referential: this is precisely the fix that would make such
  forgotten, invisible work surfaceable in quay, and it is itself invisible/
  unselectable for the same reason it was meant to cure.

The complete implementation spec already exists: the design doc
`docs/proposals/exp5-task-backlog-primitive-projection.md` §15 ("Done-when clauses
a future implementing milestone would need") is a dispatch-ready checklist covering
all 13 DIR-009 items + the 4 DIR-010 items (incl. the resolved experiment-prefixed
task-id namespace decision that fixes the DIR-004/DIR-005 cross-experiment
collision — the same 2 divergences the anti-drift check still reports).

## Requested action

Materialize and charter the implementation. Specifically:

1. **Create the selectable candidate row** `M-TASK-BACKLOG-PROJECTION-IMPL` in
   `backlog.md` (non-DONE), sourced to this DIR + the m13 design doc, mirroring the
   `M-CLI-EDIT-PARITY-IMPL` precedent's row shape, so SELECT can actually reach it.
2. **Charter and dispatch it** at a SELECT boundary, implementing
   `docs/proposals/exp5-task-backlog-primitive-projection.md` §15's checklist:
   project exp5's milestones, backlog candidates, and selection/execution
   provenance as quay tasks; the one-time M01-M12 backfill; the experiment-prefixed
   id namespace (fixing the DIR-004/DIR-005 collision and the remaining 2 anti-drift
   divergences DIR-010 deliberately left open); the stronger-than-boundary reconcile
   cadence; the `resolved`-vocabulary extension; and the backlog.md/dashboard.md
   generated-view regeneration — with the standing anti-drift/backlog-projection
   check that §15 specifies. Full existing test suite must pass; `git diff --stat`
   confirms only the expected files.
3. **Value type** capability-growth (task-store/methodology infra + Web UI
   self-hosting) + governance-integrity (removes the "quay only shows DIRs" distortion
   this conversation surfaced — the board becomes a faithful view of the stream, not
   just the human-directive channel). Δv̂ likely small/method-infra-dominated; size at
   SELECT time. This is DIR-012-item-3-class work (build-not-just-design) but for the
   DIR-009/010 self-hosting mechanism, and is a natural early-SELECT candidate since
   it makes every subsequent milestone's own tracking visible.

Coordinate with DIR-016 (filed together): DIR-016 makes this class of omission
impossible going forward (mandatory `-IMPL` row at ABSORB) and includes a
retroactive sweep — this DIR is the specific, highest-value instance to materialize
first, and can be the worked example that DIR-016's sweep would otherwise generate.

Non-goals: do not re-open M13's design (it is sound and canonical); do not fold this
into the task-to-plan work (DIR-014) — that is a separate deferred implementation.
