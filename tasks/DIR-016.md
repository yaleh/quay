Source: `experiments/quay-perpetual-stream/directives/pending/DIR-016-absorb-must-materialize-an-impl-candidate-row-for-every-design-only-milestone.md`

Recurring structural failure: a design-only milestone completes, marks DONE, defers its implementation to "a future SELECT" in prose — but no selectable candidate row is created, so SELECT (which only considers non-DONE rows) can never reach it. Evidence: M-CLI-EDIT-PARITY (DONE m14) DID spawn M-CLI-EDIT-PARITY-IMPL (done m16) ✅; but M-TASK-BACKLOG-PROJECTION (DONE m13) and M-TASK-TO-PLAN-SKILL-DESIGN (DONE m17) did NOT — the only `-IMPL` row in the whole backlog is M-CLI-EDIT-PARITY-IMPL. Whether an implementation ever becomes reachable currently depends on the ABSORB agent remembering to hand-author an `-IMPL` row (2 of 3 recent design milestones forgot). DIR-002 "enforcement half never built" recurring on the loop's own design→implementation hand-off. Requested: (1) amend ABSORB (OUTER-LOOP.md + inherited-core.md) so a design-only milestone MUST create a selectable non-DONE `<M-NAME>-IMPL` row, as a HARD block on milestone_counter++; (2) make it mechanically checkable (it0-style script, exit 0/1/2, fixture-testable) so this DIR isn't itself the pattern it warns about; (3) retroactive sweep creating missing `-IMPL` rows (at least M-TASK-BACKLOG-PROJECTION-IMPL per DIR-015; reconcile task-to-plan per DIR-014); (4) project each `-IMPL` row into quay once DIR-015's self-hosting lands.
