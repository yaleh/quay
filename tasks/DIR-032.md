## Proposal
Restore and HARD-enforce the independence of the per-milestone ABSORB adversarial audit — the strongest gate in the loop (the verification-asymmetry guarantee, ADR-005's binding constraint). Two changes: (1) fix OUTER-LOOP.md to dispatch the audit as a **generic, always-available** fresh-context subagent (matching the only pattern that has ever actually worked), and (2) make **loss of audit independence a machine-detectable HARD FAIL** at ABSORB, so it can never again silently degrade to a same-context self-audit while still reporting "NO REFUTATION FOUND". This is the exact silent-transition-failure class the experiment steward has named fatal.

## Finding
Session-history evidence (meta-cc, all recorded audit dispatches): **every** independent audit in this project's history was launched from the **top-level (outermost) session** — `caller=direct`, Agent tool directly available — using **generic agent types** (`Explore` / `general-purpose`), NEVER `baime:iteration-executor`. But two things drifted from that working pattern:

1. **The doc encodes a fragile, never-used vehicle.** `OUTER-LOOP.md` §6 (per-milestone acceptance audit, lines ~268-270) hardcodes "a fresh-context `baime:iteration-executor` call, dispatched by the OUTER loop itself." That plugin agent-type was never the one the working audits used, and is not reliably registered in every runtime.

2. **The runtime degraded from top-level to nested, silently.** M41 and M42 audit.md both self-report that the orchestrator could NOT dispatch the audit subagent — it reached for `ToolSearch` (the wrong mechanism for an Agent `subagent_type`) and the `manda` broker (`cap request requires to=`), both failed, and it **fell back to a same-context self-audit**. That fallback signature (hunting via ToolSearch/broker instead of calling the Agent tool) is exactly what a **nested subagent context** looks like — in Claude Code, subagents cannot spawn subagents, so the Agent tool is absent from their toolset. The loop is currently being driven nested (manda-dispatched) rather than as the top-level session `OUTER-LOOP.md` line 3 assumes.

**Consequence — the fatal class:** across TWO consecutive milestones the strongest gate silently collapsed from independent-fresh-context audit to self-audit, while both reported "NO REFUTATION FOUND". `it0-dod-check` does not check audit *independence*, so the mechanical gate stayed green. A self-audit — however refute-first with fresh fixtures — shares the audited context's priors and blind spots; it is not the independent refuter the loop's verification asymmetry depends on. The degradation was disclosed only in prose buried in audit.md, undetected by any gate: a silent transition failure.

## Requested action
1. **Generic audit vehicle.** Change `OUTER-LOOP.md` §6 to dispatch the ABSORB audit as a fresh-context **`Explore` or `general-purpose`** subagent (whichever is available), NOT `baime:iteration-executor` — matching the only pattern with a working track record. State that the audit MUST be dispatched by the **top-level loop session** (where the Agent tool is available); if the loop finds itself unable to dispatch a real subagent, that is a BLOCKING condition, not a license to self-audit.
2. **Independence as a HARD gate (ADR-011: enforcement lands with the rule).** The audit artifact must carry a machine-checkable proof of independence — a distinct session/agent id (and/or transcript path) different from the orchestrator's own. A mechanical check (a new `scripts/*.mjs`, TDD, wrappable by `quay gate`) HARD-FAILS the ABSORB — blocking VT append and `milestone_counter++` — when that independent-audit evidence is absent or its id matches the orchestrator's. **Self-audit ≠ pass; fail-closed.**
3. **Retro-flag M41/M42.** Record on the dashboard's deviation table that M41 and M42 ran a self-audit (independence not met), as `caught-by: human`, so the two known-degraded milestones are not silently treated as fully audited.

## Acceptance Criteria
- [ ] `grep -n 'baime:iteration-executor' experiments/quay-perpetual-stream/OUTER-LOOP.md` returns NO line inside the §6 acceptance-audit block (the vehicle is now a generic `Explore`/`general-purpose` subagent); the block states the audit is dispatched by the top-level loop and that inability to dispatch a real independent subagent is BLOCKING, not self-auditable.
- [ ] A mechanical check (`scripts/audit-independence-check.mjs` or equivalent) exits 1 when an ABSORB audit artifact's session/agent id equals the orchestrator's (self-audit) or is absent, and exits 0 when a distinct independent id is present; RED-then-GREEN fixtures pin both directions (ADR-001).
- [ ] The check is wired into the ABSORB gate set so a self-audit HARD-blocks `milestone_counter++` (not prose-only); `it0-dod-check` or a sibling ABSORB gate invokes it.
- [ ] The dashboard deviation table has rows flagging M41 and M42 as self-audited (independence not met).

## Definition of Done
References the standard inherited-core DoD clauses; the bar is REAL LANDING, not artifacts. A script existing / a fixture green / a doc edited are necessary but NOT sufficient — done ONLY when:
- [ ] A REAL milestone's ABSORB actually dispatched a genuinely independent fresh-context audit (distinct session/agent id, generic agent) AND the independence check RAN at that real ABSORB and passed on the real audit artifact — verifiable by the durable audit artifact's id + the gate's recorded PASS, with the ABSORB entry pasting the real command output.
- [ ] The independence check HARD-FAILS a real self-audit attempt (demonstrated once against the M41/M42-style self-audit artifact as the RED fixture), proving the silent-degradation hole is now closed, not merely designed.
- [ ] Single-source (independence logic once, wrapped by a gate); `baime:iteration-executor` no longer named as the audit vehicle; DIR-027 loop-on-master preserved.
