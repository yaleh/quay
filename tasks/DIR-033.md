## Proposal
Make the outer loop's ABSORB clean up after itself, and HARD-enforce the one part that is drift (not just cruft): a milestone's NON-primary iteration report/evidence must land on `master`, and the milestone's iteration worktrees + merged branches must be pruned — so `git branch`/`git worktree list` stay readable and a genuinely-dangling branch is a real signal, not lost in noise. Sibling of [[DIR-031]] (that one keeps the main tree clean *between* commits; this one keeps *branches/worktrees* clean *after* each milestone). Ships the mechanical half per ADR-011.

## Finding
The loop runs two independent iterations per milestone, merges ONE as primary, and today leaves the non-primary branch and every completed milestone's iteration worktrees dangling forever. Live measurement (2026-07-20): **38 registered iteration worktrees** (M01…M42, nearly all long-completed) and **38 merged iteration branches**, all prunable cruft; plus **4 un-merged branches**. Of those four, three are healthy (non-primary, whose report DID reach master: M41-iter1, M32-iter1; and M10-iter0 has no unique content) — but **one, `exp5-m07-iteration-0`, orphaned a 273-line iteration-0 report that was ABSENT from master** (only `iteration-1.md`, the primary, was captured). That is a silent evidence gap: the non-primary iteration's provenance existed only in a dangling branch, invisible to master and buried among 38 lookalike stale branches. This was surfaced only because a human manually noticed one dangling SHA (`9954a4c`). The reconcile decision to keep a branch is fine and disclosed; the failure is (a) not capturing the non-primary REPORT to master uniformly, and (b) never pruning, so the signal-to-noise makes (a) undetectable.

## Requested action
1. **Capture then prune at ABSORB.** Add an ABSORB close-out: for the milestone just merged, (a) if the non-primary iteration produced a report/audit `.md` not already on master, cherry-pick JUST that evidence file onto master (never the superseded code/OUTER-LOOP/ledger edits — the primary's are canonical); (b) `git worktree remove` the milestone's iteration worktrees and delete their now-merged branches; (c) for a deliberately-kept non-primary branch, delete it once its evidence is on master (keeping the branch is not how provenance is preserved — the report on master is). Wire this into `OUTER-LOOP.md`'s ABSORB step.
2. **Enforce the drift half mechanically.** The shipped `scripts/worktree-branch-hygiene-check.sh` HARD-FAILS (exit 1) when any un-merged `exp5-m<N>-iteration-<0|1>` branch holds a milestone `.md` absent from master, and reports prunable-cruft counts informationally. Wire it into the ABSORB gate set and/or `restart-readiness-check.sh` so orphaned evidence blocks, not drifts.
3. **Backfill the known gap.** M07 iteration-0's 273-line orphaned report is rescued onto master by THIS change (so the check goes GREEN on landing); the 38 merged worktrees/branches are pruned as the first application.

- [x] After the first prune, `git worktree list | grep -c worktrees/iteration` and the merged-iteration-branch count are both materially reduced (bulk of the 38 gone), leaving only the current milestone's and genuinely-un-merged branches.
- [x] `OUTER-LOOP.md`'s ABSORB step states the capture-then-prune close-out; `worktree-branch-hygiene-check.sh` is wired into ABSORB and/or `restart-readiness-check.sh`.
