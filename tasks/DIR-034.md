## Proposal
Close the two residual soft spots that a real-landing audit of the post-restart milestones (M41–M46) exposed. Both are about making enforcement that already EXISTS un-bypassable: (1) three shipped checks are runnable but only wired as OUTER-LOOP.md prose close-outs, not into the mechanical ABSORB gate that actually blocks `milestone_counter++`; (2) the audit-independence gate reduces independence to a self-declared session-id string, which a self-auditing context can satisfy by fabricating a distinct string. Generalizes the INV/[[exp5-M-CRYST-INV]] + ADR-011 principle (enforcement lands WITH the rule) one level deeper: enforcement must be MECHANICAL and UNFORGEABLE, not prose-plus-honesty. Builds on [[DIR-031]] (tree hygiene), [[DIR-032]] (audit independence), [[DIR-033]] (worktree/branch hygiene).

## Finding
Verified live on master (2026-07-20, after M46):
1. **Soft wiring.** `tree-hygiene-check.sh` (DIR-031), `worktree-branch-hygiene-check.sh` (DIR-033), and `audit-independence-check.mjs` (DIR-032) are all runnable + (for audit-independence) engine-registered, and M46 wired the two hygiene checks into `OUTER-LOOP.md` ABSORB **prose close-outs**. But `grep tree-hygiene\|worktree-branch-hygiene\|audit-independence experiments/quay-perpetual-stream/scripts/it0-dod-check.mjs` returns ZERO — none is invoked by the mechanical DoD meta-enforcer (Clauses 0–9) that HARD-blocks `milestone_counter++`. Consequence: a future ABSORB that simply forgets/omits the prose close-out passes the mechanical gate silently. The enforcement's un-skippability rests on the loop remembering to run a prose step — the exact "declare/wire loosely, then paraphrase away" failure DIR-014/DIR-002 keep hitting.
2. **Forgeable independence.** `audit-independence-check.mjs` FAILs when the audit artifact's session-id is absent or equals the orchestrator's, and PASSes on any DISTINCT string. It genuinely catches the silent M41/M42/M43 self-audit (absent/same id → FAIL — confirmed by running it against the real M43 artifact). But a self-auditing context that WRITES a plausible distinct id (e.g. `top-level-...-explore-agent-...`) into its own artifact PASSes — the gate cannot distinguish a genuinely dispatched independent subagent from a fabricated id. M44/M45 both declare independence via such a string; that claim is honesty-dependent, not mechanically corroborated. The real guarantee (a genuinely dispatched fresh-context subagent) is a runtime property the current check does not verify.

## Requested action
1. **Mechanize.** Fold all three checks into the mechanical ABSORB enforcement: `it0-dod-check.mjs` (or an it0 ABSORB counter-gate it invokes) must run `tree-hygiene-check.sh`, `worktree-branch-hygiene-check.sh`, and `audit-independence-check.mjs` and HARD-FAIL `milestone_counter++` when any fails — un-skippable, independent of any prose close-out being remembered. Single-source: WRAP the existing scripts (never reimplement their logic). The OUTER-LOOP prose close-outs stay as human-readable guidance but are no longer the enforcement.
2. **Anti-forgery.** Raise the audit-independence bar from "any distinct string passes" to "the id must be CORROBORATED by an independent dispatch-side record the auditing/orchestrator context cannot self-fabricate" — e.g. the dispatched subagent's own runtime/harness agent-id or transcript path, recorded at dispatch, cross-checked by the gate; fail-closed when the id is absent, equals the orchestrator's, OR is uncorroborated by that dispatch record. Where a runtime-provided unforgeable id is genuinely unavailable, the gate must treat the audit as BLOCKING (hand back to top-level) rather than passing on a bare string.
