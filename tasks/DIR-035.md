## Proposal
Delivery-boundary separation per ADR-013: make the product (`packages/`) stand alone from the experiment layer, eliminating `../../../` cross-boundary imports, data-driven gate set (no hardcoded experiment paths), experiment state out of the product store. Acceptance = `delivery-standalone-smoke` 5→0 RED.

## Finding
The product code in `packages/` currently has implicit dependencies on experiment-layer paths (`experiments/`, `tasks/`), making it impossible to deploy quay outside of this specific workspace. ADR-013 defines the validation ladder (Levels 1-3) for proving the product stands alone. This is a prerequisite for DIR-036 (off-repo transfer).

## Requested action
Execute the delivery-boundary separation: audit cross-boundary imports, remove or data-parameterize them, wire the `delivery-standalone-smoke` acceptance test.

## Acceptance Criteria
- [ ] `delivery-standalone-smoke` passes with 0 RED cases (was 5 RED).
- [ ] No `../../../` cross-boundary import from `packages/` into `experiments/` or `tasks/`.
- [ ] Gate set is data-driven (no hardcoded experiment paths in product code).

## Definition of Done
- [ ] `delivery-standalone-smoke` 5→0 RED confirmed by a real test run.
- [ ] ADR-013 Level 1 validation ladder step satisfied.
- [ ] Product deployable standalone (as a milestone-candidate, not just a fixture).
