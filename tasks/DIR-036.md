## Proposal
Point the now-standalone quay **product + methodology kit** at a FOREIGN repo — archguard or meta-cc, the owner's own tools (CLAUDE.md; [[reference_archguard-metacc-tools]]) — as the **successor value source** to exp5's saturated inward loop. This executes ADR-013's own Validation Ladder (Levels 2–3), the first time the target leaves quay's own repo.

Rationale (2026-07-20 evaluation): exp5's VT has been frozen at **111.55/120 (≈0.93, near the 120 ceiling) for 16 consecutive milestones (M34–M49)**; the inward coverage-based VT has exhausted its dynamic range and can no longer register real value (M45 shipped a genuine new product capability — document-management — and scored 0, "no VT chart cell"). The self-referential attractor (the loop optimizes governance / `L_G` / `L_C` because those are the only lenses still yielding a gradient) is resolved NOT by re-tuning the inward evaluation with rules/weights, but by **moving the target off-repo**, which regenerates an external, unbounded, honest value gradient and re-lights `L_T` (ADR-006/ADR-010). This is exp5's graduation move: **not HALT — TRANSFER.**

**DEPENDS ON [[DIR-035-D]]** — the delivery boundary must be fully locked first: the methodology kit single-sourced (one versioned drop-in unit, not a per-experiment `inherited-core` copy) and `delivery-standalone-smoke` wired as a named delivery conformance gate. Level 1 of the ladder (`bash packages/quay/test/delivery-standalone-smoke.sh` → 0 RED) is ALREADY met (verified 2026-07-20, post M48/M49). Level 3 (kit application) cannot start until DIR-035-D lands; Level 2 (product deployment) is technically unblocked now but is gated behind DIR-035-D here so the transfer is one coherent, boundary-locked hand-off rather than racing ahead of the kit's single-sourcing.

Per DIR-026 SPLIT-OR-COMMIT this program SPLITS into completable children (authored via this same skill once [[DIR-035-D]] is done):
- **DIR-036-A (Level 2 — deployment):** quay-the-product drives a real task on archguard OR meta-cc via the Provider ABI — a `.quay/config.yml` in the foreign repo enables a quay provider; `quay task list/gate/serve` operates on that repo's REAL tasks/issues, never quay's own `tasks/` store and never a `../../../` file-path reach.
- **DIR-036-B (Level 3 — application):** the methodology kit drives one real OUTER-LOOP milestone DEVELOPING archguard, DoD-audited by the it0 meta-enforcer keyed to that real foreign-repo milestone.

## Finding

1. **VT frozen** at 111.55/120 across M34–M49 (16 milestones); every ABSORB records "no VT chart cell". Recent-window product-value rate ≈0.64 Δv / 5-milestones (m29–35) and ≈0 for m41–49, vs 3.26 full-stream. `dashboard.md:341` computed BOTH and reports the reassuring qualifying-subset slope 3.80 — whose denominator structurally excludes zero milestones and therefore cannot detect the stall.
2. **Root cause = a saturating bounded ruler.** VT = Σ weight·cov, cov∈[0,1]; at 0.93 with Provider-ABI maxed at 1.0 since m12, ~8 points of headroom remain across all six surfaces. It can only measure filling pre-enumerated surfaces, not adding capability — M45's new document-management kind scored 0. `L_T` (product-truth lens) is dark; the loop optimizes `L_G`/`L_C` by default.
3. **The blocker to off-repo transfer is down.** `delivery-standalone-smoke` = 0 RED (verified 2026-07-20). DIR-035 A/B/C done; only D (kit single-source + named gate) remains. ADR-013's Consequences already names the exact ladder (L2 deployment, L3 application).
