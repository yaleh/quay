## Proposal
Fix the quay-side blocker(s) the [[DIR-036-A]] deployment attempt surfaced when pointing quay-github at a REAL foreign repo (yaleh/archguard, ~44+ open issues). Confirmed first blocker: `quay task list` connects to archguard's backend via the ABI but crashes with `spawnSync gh ENOBUFS` — `packages/quay-github/src/github-client.js` calls `execFileSync("gh", ["api", ...], { encoding: "utf8" })` at lines 31 and 40 with NO `maxBuffer`, so `gh api`'s response for a repo with many issues overflows Node's default child-process buffer. quay's own tiny backlog never triggers this; a real foreign repo does immediately. This is the read-path prerequisite for the stated north star: migrating archguard's tasks (BOTH its Backlog.md board and its GitHub issues) INTO quay. Scope: make `quay task list` + `quay task get` work end-to-end against yaleh/archguard's real issues via the ABI — fix every blocker surfaced, STARTING with the confirmed ENOBUFS/maxBuffer, each with a deterministic RED→GREEN regression test (ADR-001 TDD). **Loop-executable** (in-repo quay work; `milestone-candidate`, NOT `human-steered` — unlike the off-repo [[DIR-036]] parent).

## Finding
Live-verified 2026-07-20 from a temp quay workspace with the `github` provider `QUAY_GITHUB_REPO: yaleh/archguard`:
- ABI connects: `quay-github mcp: serving tasks from github.com/yaleh/archguard (read-only v1)`.
- Then: `Error: spawnSync gh ENOBUFS` at `provider-client.js:33` → root cause `github-client.js:31/40` `execFileSync("gh",["api",...],{encoding:"utf8"})` has no `maxBuffer` (Node default overflow on archguard's issue-set size).
This is the FIRST real fruit of the off-repo transfer ([[DIR-036]]) — a robustness gap invisible on quay's own repo, exactly the external `L_T` signal the 2026-07-20 evaluation called for.

## Requested action
1. Fix `ghApiJson` / `ghApiRun` (github-client.js:31/40) to not overflow on a large `gh api` response — set an adequate `maxBuffer` AND/OR paginate so arbitrarily many issues stream safely. Single-source: fix the shared helper(s), not each call site.
2. Run `quay task list` + `quay task get <a real issue>` against yaleh/archguard end-to-end; fix any FURTHER blocker surfaced the same way (SPLIT-OR-COMMIT into children if more than one distinct fix).
3. Keep it read-path only (v1 quay-github is read-only); the Backlog.md→quay + issue-import MIGRATION is a downstream DIR, not this one.
