## Proposal
Re-base exp5's own evaluation mechanism. The 2026-07-20 quantitative evaluation established that the RULER — not the product's value — is what flatlined. Three compounding pathologies form a self-referential attractor; fix the SIGNAL, not SELECT (no weights/hard rules on selection):

**(1) Add an unbounded, OUTWARD VT term.** `VT = Σ weight·cov`, `cov∈[0,1]`, sits at 111.55/120 = 0.93 with Provider-ABI maxed at 1.0 since m12 — ~8 points of total headroom left. A bounded coverage ruler saturates and can only score FILLING pre-enumerated surfaces, never ADDING a capability/surface: M45's genuinely new document-management kind scored 0 ("no VT chart cell"). Add ≥1 unbounded outward term — external deployment / real foreign-repo tasks driven ([[DIR-036]]) / adoption / competitive-bench result (M27) / new-capability count — so capability-adding and external use register value without a pre-enumerated cov cell.

**(2) Add an opportunity-cost / governance:product first-class health signal.** The value-typed ledger (`inherited-core.md:281-321`) counts governance-integrity/risk-option/discovery/instrument-correction as value while explicitly "not touching VT," and its ranking rule (`inherited-core.md:317`) lets a zero-VT candidate outrank capability-growth — with NO counterfactual/opportunity-cost term. Aggregate result: a loop that spent hours / ~10k lines building its own instruments while the product froze; governance:product ≈ 8:1 this window. Make the governance:product ratio (milestone-type mix and/or code:prose line ratio per window) a first-class checkpoint metric, and wire a threshold breach to the standing "hypothesis-falsified / degradation across tracks" HARD self-halt clause (`OUTER-LOOP.md:484`) — a runaway ratio IS degradation and must be able to trip the halt, not just be narrated.

**(3) Compute the self-halt slope on a rolling ALL-milestone window, not the qualifying-only subset.** self-halt is `VT slope < +1.0` (`OUTER-LOOP.md:484`). But slope is measured per QUALIFYING milestone (capability-growth with non-zero Δv); zero-VT milestones are EXCLUDED from the denominator, freezing it at 3.80 forever — the detector structurally cannot see the stall. `dashboard.md:341` ALREADY computes the honest number (recent window m29-35 ≈ 0.64/5, m41-49 ≈ 0) and reports the reassuring 3.80. Retire the qualifying-only denominator: compute slope over a rolling window of ALL last-K milestones (zeros included) and feed THAT to the halt evaluation.

**Common thread (GIT lens, ADR-006):** `L_T` (product-truth) went dark because VT saturated and dogfooding is inward, so the loop optimizes `L_G`/`L_C` — the only lenses still yielding gradient. This DIR is the EVALUATION-layer counterpart of [[DIR-036]]'s product-layer `L_T` re-illumination: fix #1 lets the ruler READ the external signal DIR-036 produces. It applies the repo's OWN crystallization doctrine (single-source + hard-checks-over-prose; `docs/proposals/exp5-crystallization-strategy.md`) to the evaluation mechanism itself, which is currently molten prose (5 value types + no-VT-cell convention + qualifying denominator = a ledger that self-justifies any outcome). This is the LAST necessary inward fix — it makes the ruler tell the truth so the loop stops rewarding inward churn; not more self-referential governance.

**Driver-self-rewrite → `human-steered`** (`OUTER-LOOP.md:78`; DIR-030 driver-rewrite fence): this changes the loop's own value ruler AND halt criterion; it MUST NOT be autonomously self-selected (a loop rewriting its own halt test is a governance hazard, and could re-score itself favorably). Executed by a human off-loop, or under the D3 behavior-preserving + golden-replay discipline.

Per DIR-026 SPLIT-OR-COMMIT, SPLIT into completable children (recommended order — #3 FIRST: highest leverage, smallest change, pure honesty):
- **DIR-038-A** (fix #3): rolling all-milestone slope denominator; retire the qualifying-only convention.

- **DIR-038-C** (fix #1): unbounded outward VT term + re-score ≥1 case (M45 or the [[DIR-036]] transfer) to non-zero.
