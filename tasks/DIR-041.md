## Proposal
quay's reason to exist is a **provider-agnostic task board**, but the GitHub provider is **read-only v1** — it can VIEW GitHub issues ([[DIR-036-A]]/[[DIR-037]]) but cannot MANAGE them. The task view-model's write fields (status / title / body / labels / parent-children) are implemented fully by quay-native but only partially by quay-github: today `github-client.js` has a status-only PATCH (the dashboard's own scoring: github write ≈ 1/5), and PR-ABI-001 flagged that unsupported write fields are **silently dropped**. This is a hole in the product's core promise, NOT an archguard-specific need — a GitHub-backed project can only be viewed, not managed, through quay.

Implement quay-github `task_write` through the ABI so Core `task create` / `task edit` / MCP `task_write --provider github` actually mutate GitHub Issues:
- **create** → POST a new issue (title + body + labels).
- **title / body** → PATCH the issue.
- **status** → map to issue state (open/closed) + the provider's status↔label/state convention — no silent drop.
- **labels** → set issue labels.
- **children** → the task-list checkbox convention already parsed on READ (`- [ ] #N` in the body; `CHILD_CHECKBOX_RE` in `github-client.js`) — write the parent's body checklist; `parent` stays derived (GitHub has no native parent field in v1 — document the boundary, do NOT silently drop).

This lifts quay-github from "read-only v1" to a WRITE-CAPABLE provider, restoring the ABI's write half for a heterogeneous backend (the thing quay exists to prove). **Product completeness** — archguard (yaleh/archguard) is only the real-landing VALIDATION vehicle. **LOOP-EXECUTABLE** (in-repo quay provider work) → `milestone-candidate`, NOT `human-steered`.

Writes reuse the single `execGh` helper ([[DIR-037]]) via `gh api` POST/PATCH/PUT (`ghApiRun` already does PATCH) — single-source (ADR-004). Requires the `gh` token to have write scope on the target repo; **fail-closed with a clear error** if not (never a silent no-op).

## Finding
- quay-github serves "read-only v1"; Core `task create`/`edit` against the github provider are refused/no-op for most fields.
- Scaffolding already exists: `ghApiRun` supports PATCH; `github-client.js:645/655` already PATCHes (status-only); `CHILD_CHECKBOX_RE` parses children from the body on read. So this EXTENDS a partial write, it doesn't start from zero.
- The view-model write fields are quay-native-complete but github ≈ 1/5 (status only), and PR-ABI-001: unsupported fields silently dropped. Consequence: a GitHub-backed project cannot be managed through quay — a gap in "provider-agnostic task board."
- Surfaced concretely by the archguard deployment (you can `quay task list/view` archguard's issues but not create/edit them). Same class as [[DIR-037]]/[[DIR-040]] — the off-repo transfer surfacing real product gaps.

### Finding (correction, M57 build)
The framing above ("read-only v1", "github write ≈ 1/5", "status-only PATCH") was **stale by the time this milestone was actually built**: reading the live `github-client.js`/`mcp-server.js` at build time showed title/body/labels write (M09-gh-write) and parent/children write via the body-checkbox convention (M12-abi-parent-write) had ALREADY landed and were already live-tested against real yaleh/quay issues (gh-3/gh-4/gh-5/gh-7/gh-11/gh-12/gh-13/gh-14). PR-ABI-001's "silent field drop" was likewise already closed (a `TASK_WRITE_SUPPORTED_FIELDS` allowlist + zod `.catchall` hard-error floor in `mcp-server.js`, pinned by `provider-abi-conformance.test.mjs`'s `task_write-hard-error-floor-probe`). The genuinely missing piece was narrower than the Proposal states: **CREATE** (POST a brand-new issue) — GitHub assigns issue numbers itself, so there was no existing convention for a caller to name an as-yet-nonexistent id. This build closes that one remaining gap (see `create()`/`CREATE_SENTINEL_ID` in `github-client.js`, DESIGN.md §3.8) and leaves the finding above in place, uncorrected in-line, as the historical record of what motivated the milestone — this addendum is the honest reconciliation for whoever audits AC/DoD against real landing.
