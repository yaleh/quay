## Proposal
The archguard bring-up exposed that quay's gated continuous-dev LOOP, as a PRODUCT, is under-delivered in two runner/exp5-coupled ways. Fix the coupling, keep the ABI/engine design (which is already correct).

**The correct-already part (do not regress):** quay's gate ENGINE is data-driven (ADR-013). `makeIt0Gate(scriptPath, …)` / `makeAdrGate` / `makeFixedScriptGate` run whatever check command the WORKSPACE names (`.quay/gates.yml` / task `extra.acceptance`). So quay-the-engine is NOT bound to vitest or node:test — a runner string is workspace DATA, not product code.

**The two real gaps:**
1. **The reusable DoD-check LOGIC is not a product deliverable.** test-pass / coverage-floor≥N% / RED→GREEN-evidence exist ONLY as exp5's `experiments/quay-perpetual-stream/scripts/it0-*.sh` — node:test-shaped and exp5-located. A foreign project (archguard/vitest, a go/pytest project) must REIMPLEMENT them. Only the engine is delivered, not the discipline.
2. **The loop driver is not a shippable product skill.** `OUTER-LOOP.md` is the exp5 driver, entangled with the research layer (VT / value-ledger / checkpoints). There is no slim, product-level "SELECT→execute→gate→done→repeat" driver a foreign project can install.

**Deliver both, RUNNER-AGNOSTIC:**
- **(A) Data-driven DoD gate SET.** Ship generic, reusable DoD gate definitions — `test-pass`, `coverage-floor`, `red-green` — whose actual COMMANDS + THRESHOLDS are workspace config (`.quay/gates.yml`: e.g. `test: <cmd>`, `coverage: <cmd>`, `coverageFloor: <n>`). Extract the runner-agnostic essence of exp5's `it0-*.sh` into these product gates; **exp5 then CONSUMES the product gates** with its node:test commands supplied as data (single-source + dogfood, ADR-004). Zero runner/language name in delivered `packages/**`.
- **(B) Slim loop-driver skill.** A shippable Claude Code skill: SELECT a ready task → execute (`quay:execute`) → `quay gate` (the DoD gate set) → mark done / `needs-human` → repeat. Runner-agnostic, research-layer-free.

**Delivery-boundary confirmation (ADR-013):** the product delivers Core+providers, the gate engine, author/execute + this driver skill, and the runner-agnostic DoD gate set. It does NOT deliver the exp5 RESEARCH layer (value-typed ledger, VT scoring, checkpoints, `inherited-core`) — experiment-only. HARD requirement: no test-runner or language name in delivered code; every runner-specific thing is workspace config.

**Relationship:** [[DIR-040]] packages the authoring half (MCP + author/execute + portable directive skill); THIS DIR delivers the gated-LOOP half (DoD gate set + driver). Together = quay delivers a portable, gated continuous-dev loop for ANY project. LOOP-EXECUTABLE (in-repo quay product work) → `milestone-candidate`.
