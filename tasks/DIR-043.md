## Proposal
Observation (recent exp5 sessions): the loop already runs dev + audit phases effectively via background subagents. And EVERY product DIR now queued (DIR-037/039/040/041/042) came from a HUMAN manually dogfooding quay on archguard and hitting a real gap. Formalize that into a STANDING loop mechanism: a **continuous background-subagent track — separate from the task-driven milestone track** — whose job is to persistently USE quay (its own deliverable) on REAL EXTERNAL targets, reproduce real friction/gaps/improvement-directions, and file them as evidence-backed DIRs into the queue.

**Why this is structural, not cosmetic (ties to the 2026-07-20 evaluation):** the loop went self-referential because `L_T` (product-truth) went dark — dogfooding was inward, VT saturated. A continuous EXTERNAL dogfooding channel MANUFACTURES the `L_T` signal continuously instead of depending on a human to find gaps in a conversation. It is the PROCESS-layer counterpart of [[DIR-036]] (which pointed the target off-repo ONCE); this points it off-repo CONTINUOUSLY. Builds on exp5's existing "discovery" value type (persona-sweep milestones) but makes it continuous, non-task-driven, and self-filling.

**This is the most autonomy-expanding change proposed — it MUST ship with 5 mechanical guardrails:**
1. **External targets ONLY.** The channel dogfoods quay on REAL foreign repos (archguard/meta-cc), NEVER quay-on-quay — else it re-introduces the inward self-reference this exists to cure. Target recorded/logged per run.
2. **Real reproduction, not speculation.** Every filed DIR MUST carry a REAL captured failure/friction (a command that actually fails / is-awkward on a real target — like [[DIR-037]]'s live ENOBUFS), never a brainstormed idea. Same real-landing evidence bar (DIR-026).
3. **Dedup + backlog-aware.** Before filing, check existing DIRs / milestone-candidates; never re-file a known or queued gap; merge into an existing DIR when it is the same root.
4. **Rate cap + quality gate + escrow.** Auto-filed DIRs land as `label:directive` WITH evidence but are NOT auto-promoted to `milestone-candidate` until they pass a quality gate (real-repro present, deduped, scoped); the filing rate is capped. Prevents a runaway self-generated queue.
5. **The channel is a DRIVER change → this DIR is `human-steered`.** Granting the loop the ability to generate its OWN backlog is a compounding autonomy expansion (DIR-030 / DIR-027 fence). The human authorizes the design + guardrails; once authorized, the track runs autonomously.

**Honest boundary:** this does NOT replace the human-insight frontier (irreducible). It industrializes the currently-manual dogfood→discover→DIR pipeline, amplifying discovery THROUGHPUT; genuinely novel, judgment-heavy directions still settle as human-steered DIRs (e.g. [[DIR-038]]).
