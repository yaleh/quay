## Proposal
Add a continuous EXTERNAL-dogfooding / discovery channel to the loop: a standing loop-driver routine that exercises quay from outside the experiment layer on a recurring cadence, filing evidence-backed findings as directive tasks.

## Finding
All product DIRs (DIR-037/039/040/041/042) came from manual human dogfooding/auditing, not from the autonomous loop's discovery engine. The loop has no standing external-dogfooding channel — it only discovers gaps when a human manually exercises the product.

## Requested action
Create a standing external-dogfooding routine in the loop-driver that exercises quay against a real foreign workspace (archguard) on a per-N-iterations cadence, filing real gaps as directive tasks.

## Mechanism — tmux remote-drive contract (crystallized + PROVEN 2026-07-22)
The missing "how" for driving a *foreign workspace's* Claude Code session autonomously (a Claude in
workspace A cannot launch a `/loop` in workspace B directly). Vehicle: **tmux**. Proven live on 2026-07-22
driving the DIR-051 real routine-fire on archguard from the quay session's Bash (shared tmux server).

- **Drive with `send-keys`, verify from the filesystem/meta-cc — NEVER parse the TUI.** `send-keys` injects
  the kickoff a human would type; the RESULT is read from the board (did a task get filed?), `git status`
  (FILE-only), and meta-cc (session transcript). `capture-pane` is only a coarse "idle / ready-for-input"
  check + a settle. TUI text (spinners, redraws) is too fragile to parse for "is it done / what happened."
- **Reliable send primitive = THREE separate `send-keys` calls** (a real gotcha found in practice):
  `send-keys <pane> C-u` (clear line) → `send-keys <pane> "<message>"` (type) → `send-keys <pane> Enter`
  (submit). Sending `"<message>" Enter` in ONE call races — the text lands but the Enter is dropped and the
  message sits unsubmitted.
- **Single-driver hygiene (the cross-session analog of DIR-027):** exactly ONE operator per foreign session
  at a time; never `send-keys` while a human is typing there. Distinguish real input from Claude Code's
  **gray ghost-suggestions** (autosuggest text that Enter does NOT submit) before assuming the session is busy.
- **Prereqs for a drivable foreign session:** launched with `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1
  CLAUDE_CODE_DISABLE_MOUSE=1` (clean `capture-pane`, no alt-screen redraws) + `--permission-mode
  bypassPermissions` (no prompt blocks) + a reachable tmux session (shared server or `tmux -S <socket>`).
- **Alternatives rejected:** `claude -p` (headless/print) is one-shot — it does not fit a *perpetual* loop
  with background agents + scheduled wakeups; the Agent SDK is the "proper" programmatic control but a real
  build effort; **NOT manda** (banned for real dispatch — reliability envelope; routines never dispatch manda).
