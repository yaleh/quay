## Proposal
[[DIR-042-B]] ships a slim loop-driver skill. This follow-on makes it GENERAL and FORMAL, per the 2026-07-20 analysis of how exp5 actually launches vs the ad-hoc archguard prompt.

**The finding that motivates it:** exp5 launches via a THIN invocation — `/loop @experiments/quay-perpetual-stream/OUTER-LOOP.md 持续迭代。除非遇到中止条件，不得停下。` — where ALL discipline lives in a fat driver DOC. The ad-hoc archguard launch prompt instead inlined a fat PROSE driver with hardcoded params (task ids, worktree paths, gate names, pause-hooks, one-shot) — the wrong abstraction level. **Both are the SAME universal driver with different PARAMS.** Refactor the DIR-042-B skill so the driver is expressed ONCE, formally, and projects differ only in a params file.

**(1) The driver becomes ONE formalized `iterate` contract** (baime prompt-doc style — `name :: In → Out -- ⊨ invariant`, same house style as `/quay-directive`):
```
iterate :: Board × Kit × Gates → Milestone        -- once ; or iterate* until Stop
  select  :: Board ⇀ Task        -- ready·top-ranked ; ⊨ exclude label:human-steered
  isolate :: Task → Worktree     -- git worktree off HEAD ; ⊨ ¬on-master (DIR-027)
  build   :: Task × Worktree → Diff  -- TDD ; ⊨ behavior-preserving
  gate    :: Task → {PASS, FAIL}     -- runner-agnostic ; ⊨ fail-closed ; ⊨ runner ∉ driver
  record  :: Diff × Gate → Evidence  -- ⊨ real-object (DIR-026) ≠ fixture
  land    :: Diff → Commit ⊕ needs-human  -- ⊨ done ∨ needs-human (SPLIT-OR-COMMIT)
invariants (∀ iteration): worktree ⊥ master · gate fail-closed · coexist: pause(peer-loop)
  · evidence real ≠ fixture · runner ∈ workspace .quay/gates.yml ONLY (never the driver)
```
**(2) Per-workspace params in `.quay/loop.yml`:** `board` (provider) · `gates` (refs into `.quay/gates.yml`) · `stop` (once | until(∅ ready) | until(.halt) | until(K·ΔV<ε)) · `coexist` (pause-hook) · `policy` (select-ranking).
**(3) A THIN launcher** (`/quay-loop`, or the skill invocation) reads `.quay/loop.yml` and runs the contract; the fat driver lives ONCE in the skill.

**Real-landing = universality proof:** the SAME skill drives a REAL archguard dev iteration from archguard's `.quay/loop.yml` (external dogfood: real diff + a `quay gate` PASS), AND an exp5 `.quay/loop.yml` exists capturing exp5's own settings — proving one contract + two params files, NOT a per-project fork.
- exp5 params: `{board:native, gates:it0-set, stop:until(.halt), policy:value-typed-ledger, coexist:∅}`
- archguard params: `{board:native, gates:vitest(testPass), stop:once, policy:ready-first, coexist:pause(backlog/.loop-stop)}`

**Out of scope (a SEPARATE `human-steered` driver-rewrite):** re-expressing exp5's OWN `OUTER-LOOP.md` AS the universal contract — that rewrites the live loop's control structure (DIR-030/DIR-027 fence). This DIR only PROVES exp5 maps to params + drives archguard; migrating exp5's actual driver is a later human-authorized step.
