## Proposal
Make the loop-driver's `build` and `record` steps **two-layer BY DEFAULT** — the build runs in a fresh background subagent, and an independent fresh-context subagent adversarially audits before `land` — and expose the single-context/self-gated mode as an explicit **opt-OUT** via two `.quay/loop.yml` keys:

```yaml
# existing schema (DIR-045): board, gates, stop, policy, coexist
execution: dispatched    # dispatched (DEFAULT) | inline — where the build step runs
audit:     adversarial   # adversarial (DEFAULT) | none — fresh-context verify before land
```

- `execution: dispatched` (**DEFAULT**) — the driver SPAWNS a background subagent (harness-tracked, `run_in_background`) to run the `build` step in the worktree, then polls for completion (completion notification is the primary wake; a fallback poll re-arms). The driver stays a lean **orchestrator** that never accumulates build churn in its own context.
- `execution: inline` (**explicit opt-OUT**) — the driver session implements the task itself in its own context. For trivial single-file tasks, or environments where spawning a subagent is impossible (no Agent tool). A conscious downgrade, declared in config, not the silent default.
- `audit: adversarial` (**DEFAULT**) — after gate PASS, before `land`, the driver dispatches a **fresh-context** subagent (`Explore`/`general-purpose`, `run_in_background`) prompted to REFUTE the milestone's AC/DoD claims from the diff; a refutation blocks `land` (routes to `needs-human`). The auditor never saw the build → real verification asymmetry.
- `audit: none` (**explicit opt-OUT**) — `record` captures the gate output only, no independent verify. A conscious downgrade for throwaway/experimental boards, declared in config.

Pure in-repo quay/skill capability → **LOOP-EXECUTABLE** (`milestone-candidate`, NOT `human-steered`).

**Why the default MUST be dispatched + adversarial (not opt-in).** Verification asymmetry and context isolation are not "nice for heavy workspaces" — they are the GIT-lens hard requirements (ADR-004/006 hard-over-soft; the "can't-read-your-own-work" refutation role). A loop that self-gates in the same context that produced the diff has NO independent check — it is structurally blind in exactly the way exp5's own methodology warns against (§2 "can't-read-the-sampling-instrument → blind-axis pseudo-convergence"). Making that the default means every naive consumer silently ships the WEAK model and only the sophisticated ones opt into rigor — precisely backwards. The default should encode the correct discipline; degrading to self-gated inline should require a deliberate, visible config choice that a reviewer can see and question. exp5 itself already runs two-layer (OUTER-LOOP.md "DISPATCH INNER" + "Adversarial-audit role"); the portable skill should carry that same standard by default, not as an upgrade.

Two capabilities the inline/none default was silently withholding:
1. **Context isolation of the build** — inline execution makes per-iteration driver context grow monotonically; a long driver cannot run many milestones without exhausting its window (archguard masks this by having `/loop` re-spawn a fresh driver every ~4 min — a symptom, not a fix). Dispatch keeps the orchestrator lean.
2. **Verification asymmetry** — a fresh-context auditor that did NOT produce the diff. Same-session self-gating structurally lacks it.

**Portability is preserved — the skill stays ONE contract.** DIR-045's goal (one skill, different params, any workspace) is unchanged: `execution`/`audit` are just two more `loop.yml` params. Portability meant "no hardcoded workspace specifics in the skill," NOT "the weakest execution model is the default." A workspace that genuinely cannot dispatch (no Agent tool available) sets `execution: inline` — an honest, visible declaration — rather than every workspace defaulting to the blind model.

**Migration note (this is a deliberate behavior change for skill consumers).** Flipping the default means the next loop run in a consumer workspace (e.g. archguard) that does NOT pin `execution`/`audit` will START dispatching + auditing. That is the intended upgrade. Workspaces that must retain today's inline/self-gated behavior set `execution: inline` + `audit: none` explicitly. exp5 is unaffected: it drives via its own OUTER-LOOP.md, not this skill (and if it ever adopts the skill, dispatched+adversarial is exactly what it already does).

**Out of scope (explicitly NOT this DIR):**
- Migrating exp5's OWN `OUTER-LOOP.md` onto the shared skill. exp5's bespoke driver (charter/proposal-adjudication/dual-iteration/dashboard) is richer than `dispatched`+`adversarial` and stays as-is (DIR-027/DIR-030 fence). This DIR only makes the PORTABLE skill two-layer-by-default; whether exp5 later consolidates onto it is a separate decision.
- Parallel cross-milestone subagents (DIR-044). This DIR dispatches ONE build subagent per iterate (still serial iterations); concurrency is a different, deferred directive.
- Changing `stop`/`policy`/`board`/`gates` semantics — those DIR-045 keys are untouched; `execution`/`audit` are additive and orthogonal.

Value type: **capability-growth + constraint-hardening** (the portable loop-driver's DEFAULT becomes context-isolated execution + independent audit — the robustness exp5 already enjoys, now the baseline not the exception), building on [[DIR-042-B]]/[[DIR-045]] (the portable skill + `loop.yml` schema this extends) and the ADR-009 background-workflow / adversarial-audit discipline exp5 runs.

## Finding
- The portable skill `plugin/skills/loop-driver/SKILL.md` (DIR-045) declares `allowed-tools: Bash, Read` and its step 4 "Build" says "Implement the task in the worktree" — i.e. the driver implements INLINE; there is no dispatch step and no audit step. `record` (step 6) only "captures the gate output". The current default is the WEAK, self-gated model.
- exp5 `experiments/quay-perpetual-stream/OUTER-LOOP.md`: "DISPATCH INNER" runs the milestone as a background subagent (`baime:iteration-executor`, `run_in_background=true`) with poll-don't-conclude waking; a later step dispatches a fresh-context adversarial-audit subagent that "MUST originate from the TOP-LEVEL loop session" (only the top-level context can spawn a genuinely independent fresh-context subagent). exp5's default IS two-layer.
- archguard dogfood evidence (session `bdf78e54`, 2026-07-21): the loop autonomously completed TASK-24/DIR-001/DIR-002/TASK-25/TASK-29, but the main iterate ran inline (124 Bash + 26 Edit + 17 Write in the driver context); the only subagents spawned were TASK-29's task-intrinsic A/B/C experiment groups, NOT a structural build/audit dispatch. Verification was a same-session test run — no independent auditor. This is the weak default in action.
- The correct split: make the disciplined two-layer model the DEFAULT (encode the right behavior); expose inline/none as an explicit, visible opt-OUT for genuinely-constrained or trivial workspaces.

## Definition of Done
References the standard inherited-core DoD clauses; the bar is REAL LANDING, not artifacts. A passing synthetic test alone is necessary-not-sufficient. Done ONLY when:
- [ ] A REAL default (dispatched) iterate ran on a real workspace (DIR-026 real object): with NO `execution` key set, a real task's build executed in a background subagent (subagent session file exists), the driver session did NOT accumulate the build's Edit/Write churn, and the task landed `done` (or `needs-human`) — pasted in the milestone record, not a synthetic fixture.
- [ ] A REAL default (adversarial) audit ran fresh-context: with NO `audit` key set, a real gate-PASS task was verified by an independent subagent that did not produce the diff, and the refute-blocks-land path is demonstrated (a deliberately-broken task routed to `needs-human`).
- [x] The opt-OUT is proven: `execution: inline` + `audit: none` reproduces the old inline/self-gated behavior exactly (a test asserts it), so a constrained workspace has a working escape hatch; the it0 DoD meta-enforcer passes.
- [x] The schema keys are fail-closed on illegal values AND on dispatch-without-Agent-tool (RED→GREEN tests), single-sourced through `readLoopParams` (ADR-004); TDD per ADR-001.
- [ ] Per DIR-026 SPLIT-OR-COMMIT: if `execution` and `audit` land as separate milestones, each is done-or-`needs-human`; this DIR is done only when BOTH default to the two-layer model in the portable skill AND both defaults are proven real on a workspace, with a working inline/none opt-out.
