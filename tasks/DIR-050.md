## Proposal
A workspace's `.quay/` currently holds **3 config files + 1 log** that grew incrementally with distinct
subsystems: `config.yml` (provider map — Core), `gates.yml` (runner-agnostic gate DATA — DIR-042-A),
`loop.yml` (iterate params — DIR-045); plus `gate-events.jsonl` (an append-only gate LOG, gitignored —
NOT config). The three configs have real coupling and indirection:
- `loop.yml.board` references a key in `config.yml.providers` (cross-file coupling);
- `loop.yml.gates: [vitest]` references an entry in `gates.yml` (cross-file indirection);
- all three are per-workspace quay configuration read at loop time.

Consolidate the three into **ONE `.quay/config.yml`** with top-level sections, so a workspace has a
single source of truth and the intra-config references resolve within one file:

```yaml
# .quay/config.yml (unified)
providers: { native: {...}, github: {...} }     # was config.yml
gates:     { testPass: [...], coverageFloor: [...] }   # was gates.yml (still workspace DATA — DIR-042-A preserved)
loop:      { board: native, gates: [vitest], stop: once, policy: ready-first, execution: dispatched, audit: adversarial }
```

DIR-042-A's principle is preserved: the gate command stays **workspace data** (a `gates:` section is
still data, not quay code) — "separate FILE" was never the requirement, "not baked into quay" was.

**Also RETIRE `coexist`** (per the crystallization "no speculative generality / single source"
doctrine). `coexist` is a pause-on-peer-sentinel hook whose ONLY example/motivation is a `backlog.md`
"second loop" (`pause(backlog/.loop-stop)`). A repo-wide grep finds NO live backlog-loop that sets that
sentinel; archguard already sets `coexist: ""`. quay is a provider-agnostic board and MUST NOT special-
case backlog.md. Remove the param from the schema, the skill step, and the deployed configs. If a real
multi-loop scenario ever appears, add a generic sentinel-pause then (YAGNI now).

**Backward compatibility (no flag-day).** The unified reader prefers the sectioned `.quay/config.yml`;
if the `gates:`/`loop:` sections are absent it falls back to reading legacy `gates.yml`/`loop.yml`
