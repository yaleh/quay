## Proposal
Industrialise the single most productive move of this experiment into a STANDING routine. Every recent
milestone (DIR-044/048/049/038) shipped with a fresh-context adversarial audit, and EACH found a real
defect the builder missed — H3/H1 fail-opens (DIR-044), a fail-open manifest (DIR-049), a
classification-laundering hole and a false monotonicity claim (DIR-038-B/A). Those audits were ad-hoc.
Make self-adversarial-probing a **continuous routine** (a rider on the [[DIR-051]] routine mechanism):
periodically dispatch a FRESH-CONTEXT explorer over the CURRENT build whose charge is to REFUTE — find
real bugs, fail-opens, un-verified claims, missing tests, capability gaps in quay's own code/skills —
and FILE each confirmed finding as an evidence-backed task behind a quality/dedup/rate gate.

```yaml
routines:
  - name: self-validation
    trigger: every(5)              # every 5 iterates (tunable)
    dispatch: adversarial-explore  # fresh-context refuter over the current build
    files: tasks
    gate: quality-dedup-rate       # real + not-already-filed + ≤K/window
```

This is the INTERNAL counterpart to [[DIR-043]] (external dogfooding on foreign targets): DIR-043 finds
friction USING quay on archguard/meta-cc; DIR-052 finds defects IN quay itself. Together they keep both
`L_T` (product truth) and `L_C`/`L_S` (constraint/defect honesty) continuously illuminated instead of
depending on a human remembering to audit. It is exactly the outward/honest work the DIR-038 re-based
ruler now scores (each real defect fixed is product value, not cov-cell filling).

**Guardrails:** FILE-only (the routine never fixes what it finds — the SELECT track drives the filed
tasks under normal gates/audit); the explorer is FRESH-CONTEXT (verification asymmetry — it did not
build the code); a quality/dedup/rate gate stops queue spam and duplicate findings; a confirmed finding
must carry real reproduction evidence (a failing command / a concrete diff), not a vague concern.

Pure in-repo capability, rides DIR-051 → **LOOP-EXECUTABLE** (`milestone-candidate`).

**Out of scope:** the routine MECHANISM (DIR-051 owns it); external-target dogfooding (DIR-043);
auto-fixing findings (FILE only).

## Finding

  milestones, each with a real audit finding), never by a standing mechanism.
- DIR-043 covers EXTERNAL dogfooding but not INTERNAL self-defect discovery — a distinct gap.
- The DIR-048 per-iterate audit checks ONE milestone's diff; it does not probe the WHOLE current build
  for latent defects/gaps between milestones. A standing self-probe fills that.
