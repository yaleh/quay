## Proposal
`dashboard.md` has grown to **6470 lines / 545 KB**, of which the append-only `## Log` (SELECT/ABSORB
narrative, m25→m76) is **~6090 lines (92%)** — monotonically increasing, never pruned. The head (VT
curve, health tracks, control limits, homeostatic variables) is only ~380 lines. This is the SAME
pathology exp5 deliberately retired once — exp3's `provenance.md` was a runaway append-only ledger, and
exp5's whole dashboard/v-meta-ledger/VT redesign existed to replace it (2026-07-18 delta-chain
triage). The dashboard has silently reincarnated it.

Two concrete harms, not just aesthetics:
- **Per-iteration context tax:** every agent that opens `dashboard.md` pays the full 545 KB — directly
  against the two-layer model's founding goal of MINIMISING per-iteration context (2026-07-17 "每次迭代
  读取的文本是否过多过长?应否精简?").
- **A latent correctness smell:** the newest ABSORB is at the FILE END (line 6470), but `Read` defaults
  to the first 2000 lines — an agent opening the dashboard without an explicit offset sees the OLDEST
  ~m28 and none of the last ~40 milestones. The live signal is buried under dead narrative.

**The redundancy that makes this safe to cut:** the `## Log`'s detailed content already has more
authoritative homes — `milestones/M<NN>/{audits,iterations,worktrees}/` holds the per-milestone
evidence, and **every ABSORB is a git commit** (immutable provenance). The Log is a third, half-lived
copy, not a single source of truth.

Three additive changes, in the ADR-004 "hard checks over prose" spirit:

1. **ROLLING WINDOW.** `## Log` keeps only the last **N** milestones live (default N=5, aligned to the
   checkpoint cadence). Older blocks move to `dashboard-archive/log-m<lo>-m<hi>.md` (or are dropped —
   git history is the real provenance; the archive is a convenience, not a requirement). Head sections
   (VT curve / health / control limits / homeostatic) are untouched — they are already compact,
   bounded, and regenerable-in-spirit.

2. **SUMMARY-ROW ABSORB.** The ABSORB write-step emits ONE line per milestone into `## Log`, not a
   multi-section block: `m<NN> · <id> · Δv=<x> (v̂=<y>) · audit=<verdict> · merge=<sha> · → milestones/M<NN>/`.
   Detail lives behind the pointer (`milestones/M<NN>/` + the commit), never inline. This mirrors how
   the head's VT curve already records milestones as compact rows.

3. **MECHANICAL LINE-BUDGET GATE.** A new `scripts/it0-dashboard-line-budget-check.sh` (modeled on the
   existing `it0-ceiling-line-budget-check.sh`) HARD-FAILS when `dashboard.md` exceeds a cap (e.g. 1200
   lines) — wired into the ABSORB step as a HARD block on `milestone_counter++`, exactly like the
   Clause-3 charter line-budget and the V_meta-lag ALARM. Prose discipline gets paraphrased away
   (ADR-004); a runnable check does not. This is what stops a THIRD recurrence.

**Why loop-executable (milestone-candidate), not human-steered:** this amends exp5's own ABSORB
write-step + adds an it0 gate — exactly the class of methodology milestone the loop already self-drives
(M39 line-budget-gates, M36 homeostatic-metrics both edited dashboard/scripts the same way). It touches
exp5's OUTER-LOOP dashboard-write mechanics, not the portable skill; it does NOT alter any gate's
verdict logic, VT arithmetic, or the eval ruler (no favorable re-scoring).

**Out of scope:** the head sections' content (VT/health/control-limits stay as-is); the portable
loop-driver skill (this is exp5's bespoke dashboard); rewriting git history; deleting `milestones/M<NN>/`
(a separate call — see the DoD note on the lapsed M48+ archive practice).
