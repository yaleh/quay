## Proposal
Industrialise the single highest-yield discovery move of this experiment that neither DIR-052 nor
DIR-053 covers: **reading the development PROCESS, not the product.** Every recent human-triggered win —
the `.js→.ts` runtime-resolution blind spot (M77), the CHILD-LINK-SYMMETRY modeling hole, the
`provenance.md`→`dashboard.md` recurrence, the "citations drift" losses of exp1→exp5 — came from a human
running meta-cc over past sessions and spotting a recurring defect / a decision that should be an ADR / a
one-off fix that should be a general check. Make that a **standing ROUTINE**.

A meta-cc history-mining routine, fired on a cadence (`on(checkpoint)` / `every(N)`) INDEPENDENT of the
ready-queue SELECT (DIR-051 mechanism), dispatches a fresh-context probe (DIR-048 dispatched infra) that
queries the project's session history with meta-cc (`query_session_content`, `query_session_signals`,
`analyze_errors`, `query_edit_sequences`, …) and produces evidence-backed findings in THREE classes:
- **defect / gap** — a recurring error, an unverified claim, a silently-dropped prior requirement;
- **ADR candidate** — a load-bearing decision made implicitly across sessions that deserves a first-class
  record (quay has `adr` as a first-class object);
- **crystallizable pattern** — a one-off fix or insight that should become a general executable check /
  skill / template (e.g. CHILD-LINK-SYMMETRY: a bug → a `split-or-commit` gate rule).

Findings are FILED as tasks **ROUTED BY finding-type** (defect → `milestone-candidate`; ADR → `adr-draft`;
pattern → `crystallization`) behind the DIR-051 quality/dedup/rate gate. The routine NEVER auto-executes
its findings (FILE-only; the SELECT track drives them under normal gates/audit).

**This is the third axis.** DIR-052 lights `L_T`/`L_C` (does the build work / hold constraints);
DIR-053 lights `L_G`/`L_D` (architecture/dependency); this lights the **process/provenance axis** — what
recurred, what was learned, what drifted — which currently has NO instrument. General across projects:
every Claude Code project accrues session history; meta-cc reads any of them.

**Built on [[DIR-056]] (probe-spec formalization):** this routine is authored as a portable **probe spec**
(`instrument: meta-cc`, `output_routing: {defect, adr, pattern}`, REFUTE-first objective), NOT a magic
`dispatch` string — so it drops into any workspace's `loop.yml` as one line + one shipped probe file.

**Out of scope:** the routine mechanism itself (DIR-051) and the probe-spec schema (DIR-056); auto-executing
findings (FILE-only); replacing the human — this INDUSTRIALISES a move the human still audits via SELECT.

## Finding
- DIR-052 (self-validation) reads the CURRENT BUILD; DIR-053 (arch-analysis) reads the CODE STRUCTURE.
  Neither reads the SESSION HISTORY — the process/provenance axis is dark, yet it is where this
  experiment's highest-value corrections have come from (all human-triggered, ad-hoc, via meta-cc).
- meta-cc is a maintained MCP instrument already used aggressively in this repo; it is project-agnostic
  (any Claude Code project has session history) → a portable routine, not a bespoke one.
- Findings are heterogeneous (defect vs ADR vs pattern) → richer than DIR-052/053's single output; needs
  output-routing by finding-type, which motivates [[DIR-056]]'s probe-spec `output_routing`.
- Anti-gaming risk: a routine that reads its OWN history could file self-congratulatory / eval-favorable
  tasks — MUST be REFUTE-first, file only defects/gaps/candidates, never re-score the loop (ADR-004).

## Requested action
1. Author a portable **meta-cc probe spec** ([[DIR-056]] format): `instrument: meta-cc`; REFUTE-first
   objective (mine defects/ADR-candidates/patterns); evidence requirement (session-id + turn/commit ref,
   else the file-gate rejects); `output_routing: {defect→milestone-candidate, adr→adr-draft,
   pattern→crystallization}`; `fallback: none` (skip + log if meta-cc absent).
2. Wire output-routing into the routine file step (route the filed task's label by finding-type) —
   single-sourced in DIR-056's probe-spec loader, not re-implemented per routine.
3. Ship the probe with the plugin (`${CLAUDE_PLUGIN_ROOT}/probes/…`, per DIR-049/051); add a `loop.yml`
   `routines:` entry referencing it (opt-in; absent = unchanged).
4. Prove one real fire: on a real workspace with history, the routine files ≥1 evidence-backed task of
   each reachable class through the gate (evidence pasted, not a fixture).

## Acceptance Criteria
- [ ] A portable meta-cc probe spec exists ([[DIR-056]] format) declaring `instrument: meta-cc`, a REFUTE-first objective, an evidence requirement (session-id + turn/commit ref), and `output_routing` for defect/adr/pattern — plugin-shipped.
- [ ] The routine FILES findings as tasks ROUTED BY type (defect→`milestone-candidate`, adr→`adr-draft`, pattern→`crystallization`) behind the DIR-051 quality/dedup/rate gate; a finding without a session-id/turn/commit ref is REJECTED (quality) — RED+GREEN.
- [ ] Graceful degrade: when meta-cc is unavailable the routine SKIPS + logs, never fail-closing the loop or the SELECT track — demonstrated (absent-instrument path).
- [ ] FILE-only boundary holds (no auto-execute; post-fire git-status backstop); anti-gaming: the probe files only defects/gaps/candidates and NEVER a loop-favorable/eval re-scoring task (ADR-004) — asserted in the probe spec + audit.
- [ ] A REAL fire on a workspace with history filed ≥1 evidence-backed task through the gate (pasted, not a fixture); opt-in default (no routine) unchanged.

## Definition of Done
References the standard inherited-core DoD clauses; the bar is REAL LANDING, not artifacts. Done ONLY when:
- [ ] A REAL meta-cc routine fired on a real workspace and FILED a real evidence-backed task (with a session-id/turn/commit ref) ROUTED to the correct label through the gate (DIR-026 real object) — pasted in the record.
- [ ] The probe spec is plugin-shipped + single-sources output-routing via [[DIR-056]] (ADR-004); graceful-degrade + FILE-only + anti-gaming proven; TDD per ADR-001; it0 DoD meta-enforcer passes.
- [ ] Fresh-context adversarial audit confirms: findings are evidence-backed (not vague), routing is correct, the probe cannot file a loop-favorable task, and meta-cc-absent degrades soft.
- [ ] Per DIR-026 SPLIT-OR-COMMIT: the probe spec, the routing wiring, and the real fire each land done-or-`needs-human`.
