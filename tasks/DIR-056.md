## Proposal
DIR-051 gave the loop a standing ROUTINE track (`routines: [{name, trigger, dispatch}]`). But `dispatch`
is a **magic string** (`adversarial-explore`, `arch-analyze`, …) whose SEMANTICS live in the skill/driver's
head — what prompt to run, which instrument it needs, what label its findings get. That is only half
loosely-coupled: adding a routine TYPE still means editing the skill. Formalize the missing half.

**Decouple the three concerns:**
- **WHEN** — `trigger` (`every(N)`/`on(<event>)`), lives in `loop.yml` (per-workspace tuning).
- **WHICH / WHAT** — a portable **probe spec**, a small shipped file, referenced by name.
- **HOW** — `routine-scheduler.mjs` + `routine-file-gate.mjs`, a GENERIC mechanism in the skill (unchanged
  per new routine).

Replace `dispatch: <string>` with `probe: <name>` resolving to `${CLAUDE_PLUGIN_ROOT}/probes/<name>.md`
(with a workspace override path allowed). A probe spec declares:

```yaml
# plugin/probes/history-mining.md (frontmatter + objective body)
instrument: meta-cc            # required tool/MCP; if unavailable → SKIP + log (never fail-closed the loop)
fallback: none                 # e.g. architecture-analysis: fallback: madge-proxy
output_routing:                # route a filed finding's board label by its type
  defect:  milestone-candidate
  adr:     adr-draft
  pattern: crystallization
# body = the fresh-context probe's REFUTE-first objective/prompt
```

**Control flow (skill, generic):** each due routine → `readProbeSpec(probe)` → if `instrument` unavailable
and no working `fallback`, SKIP + log → else DISPATCH a fresh-context agent (DIR-048) with the spec's
objective → its findings pass `routine-file-gate.mjs` (quality/dedup/rate) AND are labeled by
`output_routing[finding.type]` → FILE-only. **Zero skill change to add a 4th probe** — drop a spec file +
a `loop.yml` line.

**Backward compatible:** an existing `dispatch: <string>` is still accepted (treated as an inline probe
with `instrument: none`, single output label `milestone-candidate`) — DIR-052/053's current entries keep
working; migrating them to `probe:` specs is additive.

**Why now:** [[DIR-055]] (meta-cc mining) needs `instrument`-declaration + `output_routing` (defect/adr/
pattern) — which the magic-string form cannot express. Rather than special-case DIR-055, generalize:
DIR-052/053/055 all become probe specs. Single mechanism, many portable probes — DIR-051's stated intent,
completed by pushing the routine's WHAT out of the skill into data.

**Out of scope:** the specific probes (DIR-052/053/055 author those); the trigger grammar (DIR-051, unchanged);
auto-executing findings (FILE-only, unchanged).

## Finding
- `routines[].dispatch` is a string the skill must interpret → the routine's WHAT is coupled to the skill;
  a new routine type = a skill edit. Half loose-coupling.
- Three concerns are conflated: WHEN (trigger) is data, but WHAT (probe) and HOW (mechanism) are both in
  the skill. Only HOW belongs there.
- DIR-055 needs to declare a required instrument (meta-cc) + route heterogeneous findings (defect/adr/
  pattern) to different labels — inexpressible as a magic string → forces the probe-spec abstraction.
- DIR-052/053 both re-describe "dispatch a fresh-context probe + file behind gate" in prose — a portable
  probe spec is the single-source form (ADR-004).

## Requested action
1. Define a portable **probe-spec** file format (`instrument`, `fallback`, `output_routing`, objective
   body) and a `readProbeSpec(name)` loader (fail-closed on malformed; resolves plugin path + workspace
   override); RED→GREEN.
2. Add `routines[].probe` to `readLoopParams`/schema (additive; keep `dispatch` back-compat as an inline
   `instrument:none` probe); fail-closed on a routine that has neither.
3. Wire the skill: due routine → readProbeSpec → instrument-availability check (skip+log if absent) →
   dispatch with the spec objective → file behind gate with the routed label. Single-source DIR-051's
   scheduler + file-gate.
4. Migrate DIR-052/053 to probe specs (additive) and ship all probes with the plugin; bump/vendor.
