## Proposal

Context: ADR-012's TS migration program (`exp5-M-TS-MIGRATION`, phases P0–P4) closed at M114 covering
only the `src/` trees of `packages/quay`, `packages/quay-native`, `packages/quay-github`. A repo-wide
sweep run in this conversation (`find packages -path '*/node_modules/*' -prune -o -name '*.js' -print
| grep -v '/test/'`) found 9 remaining product `.js` files under `packages/**`. Human directive
(this conversation, 2026-07-22): 2 of those 9 are a **tolerated permanent exception**
(`packages/quay-native/scripts/manifest.sea-shim.js`, `packages/quay/scripts/version-sea-shim.js` —
esbuild `--alias` substitution targets for the SEA single-executable build only, never on the normal
`node bin/*.js` runtime path; they exist specifically because they must NOT participate in the normal
ESM/TS module graph). The remaining 7 MUST migrate. Proposed approach: extend the ADR-012
behavior-preserving discipline (golden-diff, `tsc --noEmit` gate, full-suite-green before/after, no
build step — Node native type-stripping) to a new phase, `exp5-M-TS-MIGRATION-P5`, covering:

1. **4 CLI entrypoints** (one per package, thin launchers, never in any P3/P4 scope list):
   `packages/quay-native/bin/quay-native.js`, `packages/quay-github/bin/quay-github.js`,
   `packages/quay/bin/quay.js`, `packages/quay-backlog/bin/quay-backlog.js`.
2. **The entire `packages/quay-backlog/` package** (the 4th, read-only Backlog.md Provider, added
   after/outside ADR-012's original P3 scope, which only enumerated quay-native/quay-github/quay
   Core): `src/manifest.js`, `src/backlog-client.js`, `src/mcp-server.js` (plus its `bin/` entrypoint,
   already counted in item 1).

Motivation: partial JS coverage leaves these files dark to archguard's TS-based `L_G`/`L_D`
instrument (ADR-007) — bin/ entrypoints and the entire quay-backlog Provider are currently invisible
to the structural-analysis tooling that M113's post-full-TS audit exercised on the rest of the
product. Full elimination (bar the 2 named SEA shims) closes this observability gap so archguard can
run a genuinely comprehensive analysis across all 4 packages, not 3-minus-entrypoints.
