## Proposal

Split the repo-wide `tsc --noEmit` type-check into per-package invocations (each against its own
tsconfig, scoped to just that package's files) instead of the current single root-level
`npx tsc --noEmit` run — to bound peak memory per invocation and stop it from being the thing that
OOM-kills the host.

Context (established this conversation, 2026-07-22): the currently-wired `ts-typecheck` gate in
`.quay/gates.yml`/`.quay/config.yml` (`command: "npx tsc --noEmit"`, no `-p`, so it resolves the root
`tsconfig.json` which covers all 4 packages' `src/**` + `bin/**` in one compiler invocation) is the
proximate cause of **three confirmed OOM kills on this host today** (`orangevps`), each of which took
down an entire Claude Code session process running the autonomous loop.

## Plan

N/A — resolved via a milestone; the shape is well-defined (add N per-package tsconfig.json files
extending the root one, scoped `include` per package; update the `ts-typecheck` gate command to loop
over them; no design doc needed).

## Finding

1. Root `tsconfig.json`'s own header comment documented ONE root config on purpose, a P0-era decision
   never revisited despite the codebase growing to 40+ `.ts` files across 4 packages.
2. The `ts-typecheck` gate is wired in exactly 2 places (`.quay/gates.yml`, `.quay/config.yml`).
3. No per-package `tsconfig.json` files existed anywhere under `packages/*/`.
4. Confirmed via `sudo dmesg -T` / `sudo journalctl -k`: 3 separate OOM kills of a `tsc` process that
   day, 2 of which took an entire autonomous-loop Claude Code session down with it.

## Requested action

1. Create one `tsconfig.json` per package, each `extends`-ing the root config's `compilerOptions`.
2. Update the `ts-typecheck` gate's `command` in BOTH `.quay/gates.yml` and `.quay/config.yml` to loop
   over the 4 per-package tsconfigs.
3. Keep the root `tsconfig.json` itself as a convenience/CI-parity aggregate.
4. Verify: golden-diff on the gate + measure peak RSS per per-package invocation.
