## Proposal

exp5 is perpetual-by-design (README: "standing, non-terminating OUTER loop… no terminal HALT/CONVERGED
by design"). A perpetual loop needs a **perpetually-expandable value ruler** — but the current
human-gated chart-transition model failed exactly once and catastrophically (chart-1 sat saturated for
108 milestones, m12→m120, until the DIR-038 self-halt forced the issue). This directive installs a
META-MECHANISM for semi-automatic ruler expansion, designed around ONE hard constraint from the human:
**it must add ZERO per-milestone cost and must NOT run a subagent after every milestone.**

The design achieves that by separating cheap DETECTION from expensive DRAFTING and triggering on the
HALT CONDITION, not the milestone boundary. Three tiers, frequency + cost decreasing:

1. **Detection (script, rides the existing checkpoint cadence = every 5 milestones, ~0 cost, NO
   subagent):** a `chart-saturation-check` that reads three already-computed numbers — current chart
   headroom, the DIR-038 rolling slope, and a new `milestones-since-last-transition` counter — and
   emits a `TRANSITION-DUE` flag under hysteresis. It is appended to the self-halt evaluation that
   ALREADY runs at each `cp-NN`; it is not a new run and scans no backlog.
2. **Drafting (subagent, fires ONLY when the self-halt would otherwise fire — historically ~once per
   experiment phase):** the transition-check becomes a PRE-STEP of the self-halt: if slope < threshold,
   run detection; if `TRANSITION-DUE`, escalate to a one-time subagent that drafts candidate value
   surfaces from the open backlog's value classes, each of which MUST pass an objective anti-gaming
   guard; flag `TRANSITION-RECOMMENDED` instead of `HALT-RECOMMENDED`.
3. **Ratification (human, rarest):** the human ratifies a pre-drafted, guard-passed surface set into
   the VT model. The un-gameable judgment ("real value vs inflation?") stays human; the
   detection+drafting bottleneck that caused the 108-milestone stall is removed.

This is the same shape as DIR-038 (cheap detection, human review on fire) and DIR-062 (cheap mechanism,
human-steered driver-wiring) applied one level up — to the ruler itself.

## Finding

Quantified this conversation (2026-07-23) from the real checkpoint record:

1. **exp5's intent is perpetual/expandable, NOT convergent** (README lines 3,5-6). The remaining open
   backlog has real value; it is in "the ruler's blind spot," not absent.
2. **Historical chart-transition cadence** (from cp-01/cp-02/dashboard): chart-0 lived m0→m3 (**3
   milestones**); chart-1 opened at m3 (DIR-001 added the Provider-ABI surface, Σ=120) and its GROWTH
   phase ran m3→m12 (**~9 milestones**) to a 110.65/120 (≈92%) plateau. So the natural transition
   rhythm is roughly **one new chart per ~10-15 productive milestones**.
3. **The 108-milestone flat (m12→m120) is a PATHOLOGY, not the rhythm** — a DOUBLE failure: (a) the
   human-gated transition was never triggered (no one opened chart-2), and (b) the OLD self-halt used a
   qualifying-only denominator, so with qualifying milestones sparse it structurally could NOT detect
   the stall (cp-90: "too sparse to accumulate K consecutive below-threshold readings"). DIR-038 fixed
   (b); this directive fixes (a) without reintroducing the gaming risk.
4. **The automatic-vs-staged tradeoff, both risks grounded:** pure human-gating has already realized
   its risk (108-milestone stall + forced halt); pure automation risks the self-referential attractor
   DIR-038 was built to kill (a loop that can add its own value surfaces to keep its slope positive
   makes VT meaningless). The synthesis — semi-automatic with a MANDATORY objective anti-gaming guard,
   human ratification — is the only option that is both perpetual-friendly and non-gameable.
5. **Nuance (must be guarded):** chart-1 is 92% not 100% — 9.35 pts of real product-capability headroom
   were never pursued. So "chart saturated" ≠ "chart full." The guard MUST require the old chart's
   residual headroom to be explicitly adjudicated (pursue / abandon / fold into new chart) before a
   transition, never silently skipped.

## Requested action

1. Build `chart-saturation-check.*` (halt-free script): reads chart headroom + the DIR-038 rolling
   slope + a `milestones-since-last-transition` counter; emits `TRANSITION-DUE` iff (slope ≈ 0 for ≥K
   consecutive checkpoints) AND (headroom < ε) AND (counter > the historical growth-phase length ~10).
   Rides the existing `cp-NN` cadence; no per-milestone execution; detection is a script, never a subagent.
2. Add the `milestones-since-last-transition` counter as a checkpoint early-warning line (so "transition
   due" is flagged mechanically the way DIR-038 flags "halt due", not left to human memory).
3. Wire the transition-check as a PRE-STEP of OUTER-LOOP's self-halt (DRIVER EDIT, human-steered): when
   slope < threshold, run detection FIRST; if `TRANSITION-DUE`, escalate to a ONE-TIME subagent that
   drafts candidate surfaces and flag `TRANSITION-RECOMMENDED` (human ratifies) instead of `HALT`. The
   subagent-drafting MUST be gated strictly behind the `TRANSITION-DUE` flag — never per-milestone,
   never per-checkpoint.
4. Require each drafted candidate surface to pass an OBJECTIVE anti-gaming guard: a machine-verifiable,
   capped, un-inflatable cov (CI exit-code / GateEvent / registry-bounded — reuse the
   `drivable-workspaces.yml` guard pattern and the DIR-038-C discipline). AND require the old chart's
   residual-headroom adjudication (Finding #5) as an explicit guard clause.
