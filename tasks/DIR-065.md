## Proposal

**Context:** cp-125 fired HALT-RECOMMENDED on a governance:product = 431:1 breach and named a real blind
spot in the classifier: M122's highest-value fix of the window (the Windows SEA archive missing
`.quay/config.yml`) lives in `.github/workflows/release.yml` and is therefore INVISIBLE to the ratio, which
counts product = a non-prose file under `packages/`/`plugin/` only. A ratio that cannot see "fixed a
shipped-artifact defect via the release pipeline" as product value has a genuine measurement gap.

**Approach:** redefine "product" in `governance-product-ratio-check.ts` from a **directory rule** to a
**delivery-manifest single-source rule**. Product = the files the delivery-manifest
([[exp5-M-PRODUCTIZED-DELIVERY-B]]) declares get shipped, PLUS the pipeline that produces exactly that
manifest (`.github/workflows/release.yml`, the SEA build scripts, the manifest file itself) — non-prose
only. GOVERNANCE stays everything else, and the existing **prose-extension guard is preserved unchanged** (a
`.md` is governance wherever it lives, so nothing can be laundered into product by parking prose under a
shipped path). Anchoring the product set to the manifest single source (not a hand-kept path list) keeps the
classifier and the release gate reading ONE list, per this repo's single-source-of-truth discipline.

**Framing this directive MUST carry (anti-misuse):** this is an **INSTRUMENT FIX** — closing a real
classifier blind spot — **NOT a way to clear the cp-125 HALT.** The arithmetic is explicit: reclassifying
M122's few dozen `release.yml` lines as product moves the window from 431:1 to only ~88:1 — still an order
of magnitude over the 5:1 threshold. The HALT is cleared ONLY by real S2/S3 product work
([[exp5-M-PRODUCTIZED-DELIVERY]]), never by re-tuning the meter that reported the breach.

## Finding

- `governance-product-ratio-check.ts::classifyPath` classifies product purely by directory
  (`packages/`/`plugin/`, non-prose). `.github/workflows/`, SEA build scripts, and any release-pipeline
  file are all GOVERNANCE.
- Real consequence (cp-125): M122's real, user-facing distribution fix contributed 0 product lines; the
  window's PRODUCT total was 13 lines (essentially M121's `gate/registry.ts` fix alone).
- The strictness is deliberate and load-bearing: the classifier comment records that classifying by
  directory alone once let prose be laundered into product, collapsing a recorded 8:1 runaway to 0.78:1.
  So the fix must ADD shipped-pipeline visibility WITHOUT reopening that laundering channel.

## Requested action

1. Extend `classifyPath` (or add a manifest-aware layer) so a non-prose file is PRODUCT iff it is
   manifest-declared-shipped OR is part of the manifest-producing pipeline (release.yml, SEA build scripts,
   the manifest itself); everything else stays GOVERNANCE. Keep the prose-extension guard first and
   unchanged.
2. Anchor the product path set to [[exp5-M-PRODUCTIZED-DELIVERY-B]]'s manifest single source, not a
   duplicated hardcoded list.
3. Add a golden-oracle test proving the recorded restart-window ratio (~8:1, ~6249:756) is PRESERVED (the
   fix must not retroactively collapse a known-real runaway) and that the cp-125 window still reads BREACH.
