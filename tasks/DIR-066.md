## Proposal

**Context / supersedes [[DIR-038-B]].** DIR-038-B wired the governance:product **line ratio** to the HARD
self-halt clause: a checkpoint breach trips HALT-RECOMMENDED and stops the loop. cp-120 and cp-125 both
fired it. Analysis (this session) found three independent defects: wrong **layer** (the concern "did SELECT
pick a deliverable?" is live at every SELECT, not at a 5-milestone checkpoint), wrong **hardness** (a binary
accumulate-then-halt controller with a fixed ~700-line/milestone process-prose tax is structurally
unsatisfiable — even a pristine product milestone, M121, is 55:1 alone — so it always fires), and wrong
**unit** (a line ratio counting mandatory audit/iteration prose as "governance" cannot tell "building my own
instruments" from "writing the required audit for a product fix", and cannot see executable-text
deliverables — skills, methodology — as deliverables at all).

**This directive replaces the hard checkpoint halt with a SOFT, per-SELECT, 2-round deliverable governor.**
The original *intent* (don't let the loop focus only on itself for long) is preserved but implemented as a
continuous composition bias on the SELECT shortlist instead of a discrete circuit-breaker. It is strictly
better at that intent (pressure every milestone, not a 5-milestone runaway then punish) and it never halts.

**It fits exp5's existing SELECT as-is.** OUTER-LOOP step 1 already distinguishes the candidates *actually
considered this pass* (compared against the winner) from the winner and from the unconsidered backlog — an
implicit **Round 1 (shortlist) / Round 2 (pick)** split. The governor is a composition constraint on Round 1
only; Round 2 (the VT Δv̂ + value-typed ledger + governance/infra hard-floor ranker) is **untouched**.

**Mechanism (fully pinned — no free knobs beyond S_max):**
1. **(丙) per-task classification** at SELECT: each candidate is `deliverable:yes|no`. YES iff its landed
   output is consumed OUTSIDE this loop: (a) shipped product/provider/ABI/CLI/config code, (b) a
   skill/ADR/transferable methodology run beyond this loop, or (c) a fix observed in a real downstream (e.g.
   archguard). Otherwise NO (the loop's own gate/DoD/VT/dashboard/directive/SELECT machinery, or bookkeeping).
   **Ambiguous → default NO** (bias toward pressure). Recorded as a task field AND in the SELECT rationale.
2. **Streak** = consecutive SELECTed `deliverable:no` milestones. A `deliverable:yes` SELECT resets it to 0.
   **Mandatory cadence milestones (the §4.5 explore/arch-audit slot) are EXEMPT — streak-neutral** (neither
   increment nor reset): they are cadence-forced, not SELECT-chosen.
3. **Rising D-quota floor** `f = min(1, streak/6)` (this folds the agreed penalty slope K=0.5 / CAP=3.0:
   0.5/3 = 1/6).
4. **Round-1 shortlist composition** (the only new step). Let `S_max` be the shortlist upper bound
   (**S_max = 4**). Over the *autonomous-selectable* candidates only (status `todo`, `label:human-steered`
   already excluded per OUTER-LOOP step 1 — so "available D" means autonomous D):
   - `N_seats = round((1 − f) · S_max)` — N seats vanish as f→1, independent of how much D exists.
   - `D_seats = S_max − N_seats`.
   - shortlist = `min(availD, D_seats)` best D + `min(availN, N_seats)` best N.
   - **Shortlist size S ∈ [1, S_max].** Lower bound 1 is reached exactly when f=1 forces all-D and only one D
     exists (or only one candidate exists at all) — Round 2 then just executes it, nothing to deliberate.
     Upper bound S_max keeps Round 2 always finite. "best D"/"best N" use Round 2's own existing ranking —
     the governor imposes only the COUNTS, never a new ranker.
5. **Round 2 = existing ranker, untouched** — picks the winner from the ≤S_max shortlist.
6. **Pure-soft starvation signal (no hard stop).** Emergent self-limiting property: at f=1 the shortlist is
   all-D whenever ≥1 autonomous D exists, so Round 2 MUST pick D and streak resets — therefore **streak can
   only exceed 6 when there is NO autonomous-selectable D.** So `streak ≥ 6 with availD = 0` is a single,
   unambiguous condition: emit a prominent, greppable `DELIVERABLE-STARVATION` banner (SELECT log/stdout +
   dashboard flag) so a human WATCHING the session sees it immediately, then **run the best N and
   auto-continue** — the loop sets no `.halt` and emits no HALT-RECOMMENDED. (Continuing N when no D exists is
   correct, per design.)

**Retires DIR-038-B's hard halt** (removes the ratio→HALT-RECOMMENDED clause from OUTER-LOOP; the line ratio
may remain as an informational metric that no longer halts). **Subsumes [[DIR-065]]:** the (丙) consumer test
classifies a `release.yml` shipped-artifact fix as `deliverable:yes` by construction, so DIR-065's
`.github/workflows` blind spot disappears without patching the line classifier — DIR-065 is dispositioned
`superseded`. The [[exp5-M-PRODUCTIZED-DELIVERY]] split (this session) is independent and stands (it refilled
the autonomous-selectable deliverable backlog — children A/B — the governor steers toward).
