## Proposal

**Context / supersedes [[DIR-038-B]]:** DIR-038-B wired the governance:product **line ratio** to the HARD
self-halt "degradation" clause — a breach at a checkpoint trips HALT-RECOMMENDED and stops the loop at the
next milestone boundary. cp-120 and cp-125 both fired it. Analysis (this session) shows three independent
defects: (1) wrong **layer** — the concern is "did SELECT pick a deliverable?", which is live at every
SELECT, not at a 5-milestone checkpoint; (2) wrong **hardness** — a binary accumulate-then-halt controller
with a fixed ~700-line/milestone process-prose tax is structurally unsatisfiable (even a pristine product
milestone, M121, is 55:1 alone) so it either never fires or always fires; (3) wrong **unit** — a line ratio
that counts mandatory audit/iteration prose as "governance" cannot distinguish "building my own instruments"
from "writing the required audit for a product fix", and cannot see executable-text deliverables (skills,
methodology) as deliverables at all.

**This directive replaces the hard checkpoint halt with a SOFT, per-SELECT deliverable governor** whose
original *intent* (don't let the loop focus only on itself for long) is preserved but implemented as a
continuous proportional bias instead of a discrete circuit-breaker. Empirically the soft governor is
strictly better at that intent: it applies pressure every milestone rather than permitting a 5-milestone
runaway then punishing.

**Mechanism:**
1. **Per-task deliverable classification, criterion (丙) — consumer-outside-loop.** At SELECT, each candidate
   is `deliverable:yes|no`. YES iff its landed output is consumed OUTSIDE this loop: (a) shipped
   product/provider/ABI/CLI/config code, (b) a skill/ADR/transferable methodology run beyond this loop, or
   (c) a fix observed in a real downstream (e.g. archguard). Otherwise NO (the loop's own gate/DoD/VT/
   dashboard/directive/SELECT machinery, or bookkeeping). **Ambiguous → default NO** (conservative: bias
   toward pressure). Recorded as a task field AND in the SELECT rationale (auditable).
2. **Streak counter** = consecutive SELECTed `deliverable:no` milestones. A `deliverable:yes` SELECT resets
   it to 0. **Mandatory cadence milestones (explore / arch-audit) are EXEMPT — streak-neutral** (neither
   increment nor reset): they are cadence-forced, not SELECT-chosen, so penalizing them is unfair.
3. **Penalty coefficient** `p = min(CAP, K·streak)`, **K=0.5, CAP=3.0** (saturates at streak=6). Applied as a
   SOFT re-weighting of the SELECT ranking — deliverable candidates get `priority·(1+p)` (equivalently
   non-deliverable get `priority/(1+p)`). **Bounded**: a critical defect fix or a mandatory explore can still
   outrank it. It is a tilt, not a gate. **It NEVER halts the loop.**
4. **Pure-soft starvation signal (no hard stop).** When `streak ≥ 6` (the saturation point), SELECT emits a
   prominent, greppable, unmissable signal (a `DELIVERABLE-STARVATION` banner in the SELECT log / stdout +
   a dashboard flag) so a human WATCHING the session sees it immediately — but the loop **auto-continues
   without pause and sets no `.halt` and emits no HALT-RECOMMENDED.** Two message forms: backlog has no
   selectable deliverable candidate → "refill product backlog"; backlog HAS deliverable candidates but SELECT
   keeps declining them → "why is SELECT refusing available deliverables?". Visibility, not interruption.

**Retires DIR-038-B's hard halt** (the ratio→HALT-RECOMMENDED wiring in OUTER-LOOP's self-halt clause). The
line-ratio check may remain as an INFORMATIONAL metric but no longer trips a halt. **Subsumes [[DIR-065]]:**
the (丙) consumer test classifies a `release.yml` shipped-artifact fix as `deliverable:yes` by construction,
so the ".github/workflows blind spot" DIR-065 targeted disappears without patching the line classifier —
DIR-065 should be dispositioned `superseded` by this directive (its instrument is being retired). The
[[exp5-M-PRODUCTIZED-DELIVERY]] split (this session) is independent and stands (it refilled the deliverable
backlog the governor steers toward).

## Finding

- Validation over the real stream M63–M125 (classified per (丙), mandatory explores exempt, `p=min(3.0,0.5·streak)`):
  - **Both historical halts fire where the governor reads healthy/mild:** cp-120 (M120) penalty **0.0**
    (M116–M122 was deliverable-heavy — TS ports + distribution fixes); cp-125 (M125) penalty **1.0**
    (streak=2, mild). The old VT-slope and line-ratio halts were instrument-blindness artifacts, not real
    deliverable starvation.
  - **The real self-focus runs are where the governor rises:** M66–M74 (crystallization/loop-driver, 9-run)
    penalty **saturates at 3.0**; M107–M112 (loop-script migration + bookkeeping, 5-run) reaches **2.5**.
    History shows the loop self-corrected to deliverable work (TS migration at M77) right after — the
    governor's pressure aligns with the actual correction.
  - Deliverable share (excl. exempt) = **23/50 = 46%** — a discriminating, non-degenerate signal.
- Current backlog (23 open milestone-candidates) skews non-deliverable (~14 loop-machinery : ~5 deliverable);
  selectable deliverable targets DO exist (`exp5-M-PRODUCTIZED-DELIVERY-A/B`, `exp5-M-CRYST-D2` skills-rewrite,
  `exp5-M-DOCS`) so the governor has somewhere to steer and the pure-soft starvation signal would not fire
  spuriously.
