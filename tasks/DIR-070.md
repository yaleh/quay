## Finding

Structural comparison of `plugin/` (shipped deliverables) vs `experiments/quay-perpetual-stream/` (experiment-local) reveals five gaps where portable capabilities exist but are not packaged for external consumers. The most critical is the gate-engine implementation gap: 17 gates implement standing methodology rules from `inherited-core.md` but their scripts live only in `experiments/scripts/`, making `quay gate --gate <name>` fail on any workspace that doesn't also clone the experiment directory.

A secondary structural issue: 10 scripts exist as identical copies in both `plugin/scripts/` and `experiments/scripts/`. `sync-vendor.sh` copies FROM experiments TO plugin (experiment is canonical source), but there is no drift detection — divergence WILL happen per the DIR-013 pattern.

See `docs/proposals/exp5-deliverable-improvements.md` for the full inventory.

## Requested action

Execute five gaps in dependency order:

### Gap 4: Dual-copy structural problem (FIRST)

1. **Phase 4a — Drift detection:** Add `--check` mode to `plugin/scripts/sync-vendor.sh` that verifies experiment→plugin copies are identical (or expected-different for task-schema files) BEFORE copying. Update `plugin/test/plugin-packaging.test.mjs` to dynamically scan all sync-vendor-managed files instead of hardcoded static lists.

2. **Phase 4b — Eliminate copies:** Replace the 7 identical-copy files (group 1: anti-drift-touches-check, concurrent-batch-scheduler, read-probe-spec, routine-file-gate, routine-scheduler, serial-fanin-absorb, touches-orthogonality-check) in `experiments/scripts/` with symlinks pointing at `../../../plugin/scripts/<name>`. Update `sync-vendor.sh` to skip symlinks (`test -L` guard). Keep group 2 (task-schema.ts, task-schema-check.ts, task-schema-check.sh) as real files with intentional attribution differences.

### Gap 1: Gate engine implementations

3. **Tier A (5 gates, drop-in):** Copy `anti-gaming-guard.ts`, `loadbearing-test-gate.ts`, `tree-hygiene-check.sh`, `worktree-branch-hygiene-check.sh`, `drivable-workspace-check.ts` to `plugin/scripts/`. Add missing `.sh` wrappers for the `.ts` files (following the existing wrapper pattern: arg-check, `command -v node`, `node "$(dirname "$0")/<name>.ts" "$@"`, `exit $?`). Update `.quay/config.yml` gate paths from `./experiments/quay-perpetual-stream/scripts/` to `./plugin/scripts/`. Update `plugin-packaging.test.mjs` to cover these new files (leak check + byte-identity where applicable).

4. **Tier B (5 gates, minor parameterization):** Add configurable CLI flags to `audit-independence-check.ts` (env var name), `vmeta-lag-check.ts` (already parameterized — verify), `it0-split-or-commit-check.ts` (tasks subdirectory), `it0-enforcement-with-design-check.ts` (already parameterized — verify), `it0-impl-row-check.sh` (backlog file path). Move to `plugin/scripts/`. Update `.quay/config.yml`.

5. **Tier C:** Leave `it0-dod-check.ts`, `human-steered-classify.ts`, `it0-dogfood-evidence-gate.sh`, and the three `git-lens-l-*.ts` in `experiments/scripts/` — they are experiment orchestrators, not standalone gates.

### Gap 2: Workflow orchestrator

6. Package `run-routines.js` as a plugin skill at `plugin/skills/routines/SKILL.md` (Claude Code plugins support `commands[]` → skills, not a `workflows/` directory). `execute-milestone.js` is too experiment-coupled to generalize — leave as reference in `.claude/workflows/`.
