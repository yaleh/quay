## Finding

OUTER-LOOP.md step 0 (DRAIN) is the ONLY outer-cycle step with zero mechanical enforcement — it is entirely prose-driven agent judgment. Every other step has a corresponding script or workflow:

| Step | Mechanical |
|---|---|
| 0 DRAIN | ❌ prose only |
| 1 SELECT | human-steered-classify, deliverable-governor, explore-exploit-cadence |
| 3 CHARTER | task-schema-check, gate-hash, line-budget |
| 4 EXECUTE | /execute-milestone workflow |
| 5a ROUTINES | /run-routines workflow |

This structural gap caused a real failure at the M135→boundary: DIR-068 and DIR-069 (created 08:56 and 09:08 UTC, both with `dirStatus: pending`) existed BEFORE M135 ABSORB (10:04 UTC), but the loop never drained them. The loop agent skipped DRAIN ("board looked empty") and jumped directly to SELECT, which only reads `label:milestone-candidate`. The directives were never converted to candidates, the loop entered a 30-minute fallback, and both directives still have `dirStatus: pending`.

A mechanical DRAIN cannot be skipped — a script either runs or it doesn't, and its exit code tells you whether it did anything. Following the exact architecture of the routine track (step 5a: `routine-scheduler.ts` → `/run-routines` workflow → `routine-file-gate.ts`), the DRAIN step should be: `drain-scheduler.ts` → `/drain-directives` workflow.

## Requested action

### 1. `drain-scheduler.ts` — pure, testable trigger logic

Script at `experiments/quay-perpetual-stream/scripts/drain-scheduler.ts` (later: also in `plugin/scripts/` per DIR-070 Gap 1). Pure function + thin CLI:

- **Input:** task store (read via `task_list --label directive --json`, filtered to `extra.dirStatus: pending`)
- **Classification:** for each pending directive, classify disposition:
  - `extra.missionRedirection: true` or `label: human-steered` → `human-steered` (still creates a candidate, just with that label)
  - Otherwise → `autonomous` (default — the directive IS the candidate)
- **Output:** JSON array `[{id, title, classification, disposition}]` to stdout
- **CLI:** `node drain-scheduler.ts --json` (reads from task store via `quay task list`)
- **Exit codes:** 0 = directives due (prints list), 3 = none due (no-op signal)
- Mirror `routine-scheduler.ts`'s code shape: `parseDirective`, `classifyDirective`, `dueDirectives`, `main`

### 2. `/drain-directives` workflow

Saved workflow at `.claude/workflows/drain-directives.js`. Phases:

- **Schedule:** Read directives via `task_list --label directive --json` → filter `dirStatus: pending` → run `drain-scheduler.ts --json` → DUE list. If none due, return `{drained: 0}`.
- **Dispose:** For each DUE directive: add `label:milestone-candidate` to the task (the directive task IS the candidate — follows the SPLIT-OR-COMMIT discipline: if it needs splitting, the directive author should have created children). Set `extra.dirStatus: applied`. Append `## DRAIN disposition` section to the task body recording the classification + timestamp.
- **Verify:** Read back all dispositioned directives → confirm `dirStatus: applied` → return `{drained: N, created: [ids]}`.

### 3. OUTER-LOOP.md step 0 rewrite

Replace the 30+ lines of prose DRAIN with a one-liner:

```
0. **DRAIN** — invoke `/drain-directives` workflow
   (`.claude/workflows/drain-directives.js`). Absent pending directives = no-op (workflow
   returns {drained: 0}). Must complete before step 1.
```

The old prose content (task-canonical discipline, master-direct, human-steering hygiene, reconciliation-note requirement) stays but moves to a reference section or `inherited-core.md` — it's standing methodology, not per-cycle operational instructions.

### 4. Enforce ordering invariant

Step 1 (SELECT) gains a precondition: `/drain-directives` must have completed for this boundary. The loop driver reads the workflow result — if DRAIN was skipped, re-run it before SELECT. This closes the exact failure mode observed (agent enters SELECT without running DRAIN).
