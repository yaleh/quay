## Finding

`execute-milestone` workflow replaced OUTER-LOOP steps 4–7, and `run-routines` replaced step 5a. But steps 1–3 (SELECT preflight) remain un-encapsulated — executed as ~15 manual turns per `/loop` wake-up. Analysis of session `b643aa4d` (2026-07-24) shows each preflight cycle includes this predictable sequence:

```
check .halt → explore-exploit-cadence → 查 directive dirStatus →
deliverable-governor composeShortlist → task-schema-check → 查 ## Touches 段 →
检查 delivery-manifest → 创建 absorb-entry → line-budget-check
```

This is entirely mechanical — the agent reads task state, runs scripts with fixed CLI contracts, creates the absorb-entry temp file. It does NOT involve judgment calls (classification decisions happen at step 2, Round 2 of SELECT, not in preflight). Encapsulating it as a workflow:

- Eliminates ~15 turns per milestone cycle (roughly 5–10 minutes saved per iteration)
- Makes step ordering deterministic (preflight must complete before step 2 can proceed)
- Creates a single artifact (preflight result JSON) that step 2 consumes as input
- Follows the exact same architectural pattern as `run-routines` (Schedule → checks → return structured result)

## Requested action

### 1. `/select-preflight` workflow

Saved workflow at `.claude/workflows/select-preflight.js`. Phases:

- **Check HALT:** Read `.halt` sentinel. If present → return `{halt: true, reason: <contents>}` immediately. The caller (outer loop) decides whether to pause or override.
- **Scan directives:** Run `task_list --label directive --json` → filter `extra.dirStatus: pending` → return pending directive IDs. If any exist, the caller should `/drain-directives` first (DIR-071) — this is a WARNING in the result, not a hard block.
- **Cadence check:** Run `explore-exploit-cadence.ts --json`. Return `{cadence: <D|N>, streak: <count>}`.
- **Compose shortlist:** For each autonomous-selectable candidate, classify `deliverable:yes|no`, maintain streak, run `deliverable-governor.ts composeShortlist`. Return `{shortlist: [{id, deliverable, rank}], s: <N>, streak: <N>, starvation: <bool>}`.
- **Schema check:** Run `task-schema-check.sh` on each shortlist candidate. Return pass/fail per candidate.
- **Touches check:** For each shortlist candidate, verify `## Touches` section exists. Return presence/absence per candidate.
- **Absorb entry:** Create `/tmp/m<NN>-absorb-entry.md` with milestone counter, task id, charter path, value hypothesis, value type, chart, pre-absorb state, narrative header. Return `{absorbEntryFile: <path>}`.
- **Line budget:** Run `it0-ceiling-line-budget-check.sh` on the charter. Return pass/fail.
- **Verify:** Return structured `{milestoneCounter, halt, shortlist, schemaResults, absorbEntryFile, lineBudgetOk, warnings}` — consumed by step 2 (SELECT Round 2) and step 4 (`/execute-milestone`).

### 2. OUTER-LOOP.md step 1-3 rewrite

Replace the prose for steps 1–3 with a single line invoking `/select-preflight`, consuming its structured result into step 2's Round 2 decision. The old prose content moves to a reference section or `inherited-core.md` — it documents the selection *algorithm*, not per-cycle operational instructions.

### 3. Dependency ordering

After DIR-071 (DRAIN workflow), the outer loop's per-cycle sequence becomes:
```
0. /drain-directives
1. /select-preflight
2. SELECT (Round 2: VT Δv̂ + value-typed ledger + ranker — the human-judgment layer)
3. CHARTER (if needed — task-schema/gate-hash/line-budget verify)
4. /execute-milestone
5a. /run-routines
```

Steps 0 and 1 are mechanical — they run every cycle. Steps 2 and 3 remain the judgment layer.
