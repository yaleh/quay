## Finding

`execute-milestone` workflow replaced OUTER-LOOP steps 4–7, and `run-routines` replaced step 5a. But steps 1–3 (SELECT preflight) remain un-encapsulated — executed as ~15 manual turns per `/loop` wake-up. Analysis of session `b643aa4d` (2026-07-24) shows each preflight cycle includes this predictable sequence:

```
check .halt → explore-exploit-cadence → 查 directive dirStatus →
deliverable-governor composeShortlist → task-schema-check → 查 ## Touches 段 →
检查 delivery-manifest → 创建 absorb-entry → line-budget-check
```

**Crystallization analysis (2026-07-24):** decomposed each operation into "needs LLM judgment" vs "pure mechanical." Result: 7 of 9 operations are pure scripts or already have scripts. Only `deliverable:yes|no` per-candidate classification (criterion 丙 — consumer-outside-loop judgment) truly needs an LLM agent. The rest (.halt check, directive scan, cadence check, schema check, touches check, line-budget check) are already scripts or trivial Bash. `deliverable-governor.ts composeShortlist` is already a pure function. A full 9-phase workflow would repeat the same anti-pattern observed in execute-milestone's Verify phase: using agents as script-runners (3 of 5 Verify agents just run shell scripts and return structured exit codes — 60% waste).

**Design principle:** per the experiment's crystallization strategy ("executable invariants over prose"), the mechanical parts should be a **TypeScript script** producing structured JSON. Only the judgment-requiring classification step invokes an LLM agent. This follows the exact pattern of `run-routines` (schedule → dispatch probes → gate) but moves the script-runner parts out of agent prompts and into a deterministic script.

## Requested action

### 1. `scripts/select-preflight.ts` — pure, testable preflight script

Script at `experiments/quay-perpetual-stream/scripts/select-preflight.ts`. Pure functions + thin CLI:

- **Input:** workspace root, milestone counter, task store (via `quay task list` MCP/CLI)
- **Operations (all mechanical, no LLM):**
  1. Check `.halt` sentinel → `{halt: true, reason}` or `{halt: false}`
  2. Scan pending directives: `task_list --label directive` → filter `extra.dirStatus: pending` → `{pendingDirectives: [ids]}`
  3. Cadence check: run `explore-exploit-cadence.ts --json` → `{cadence, streak}`
  4. For each autonomous-selectable candidate, extract `{id, title, rank, labels, extra}` → structured candidate list
  5. Schema check: run `task-schema-check.sh` on each candidate → `{schemaPass, schemaDetail}` per candidate
  6. Touches check: verify `## Touches` section presence → `{hasTouches}` per candidate
  7. Output structured `PreflightResult { halt, pendingDirectives, cadence, candidates: [{id, rank, schemaPass, hasTouches}], milestoneCounter }` to stdout
- **CLI:** `node scripts/select-preflight.ts --json` (reads task store)
- **Does NOT classify `deliverable:yes|no`** — that is the ONE judgment step left to the workflow

### 2. Thin `/select-preflight` workflow

Saved workflow at `.claude/workflows/select-preflight.js`. Two phases only:

- **Run script:** Execute `node experiments/quay-perpetual-stream/scripts/select-preflight.ts --json`. Parse `PreflightResult`. If `halt: true` → return immediately. If `pendingDirectives` non-empty → WARNING (caller should `/drain-directives` first per DIR-071).
- **Classify deliverable:** ONE agent call — for each candidate in the result, classify `deliverable:yes|no` by criterion (丙): YES iff landed output is consumed OUTSIDE this loop (shipped code, release pipeline, skill/ADR, fix observed in real downstream); NO for loop's own machinery; ambiguous → NO. The agent receives the candidate list with ids/titles and returns `[{id, deliverable: "yes"|"no"}]`.
- **Compose shortlist:** Run `deliverable-governor.ts composeShortlist` (pure function) with the classified candidates + current streak. Return `PreflightResult + {shortlist, s, deliverableStreak, starvation}`.
- **Verify:** Return the complete structured result — consumed by step 2 (SELECT Round 2: VT Δv̂ + value-typed ledger + ranker) and step 4 (`/execute-milestone`).

### 3. OUTER-LOOP.md step 1-3 rewrite

Replace the prose for steps 1–3 with a single line invoking `/select-preflight`, consuming its structured result into step 2's Round 2 decision.
