## Finding

Session `b643aa4d` (2026-07-24) ran `execute-milestone` 6 times: 5 failed at Verify phase, 1 resume that passed Verify → Build → Audit but failed at Gate. The Verify phase failure rate is 83% (5/6). Each failure costs 5–9 minutes (5 parallel agents), and each failure triggers a near-identical manual debug loop:

```
读 workflow journal → 找到失败的检查 → 理解失败原因 →
修复 charter 或 task → 删除 .halt → 重新调度 workflow
```

This loop takes 5–10 turns (another 3–5 minutes) and is entirely manual. The specific failures observed:

| Run | Failing Check | Root Cause |
|-----|--------------|------------|
| wf_1caf91bd-719 | ceiling-check | Charter cited directive IDs with stale `dirStatus` |
| wf_7782a177-2a6 | gate-hash-check | ITERATION-PROMPTS.md HARD GATES block hash mismatch |
| wf_d6a5bda0-fdd | ceiling-check | Same class — charter→task alignment not yet corrected |
| wf_1fc8d8f8-4ef | gate-hash-check | Same class — hash still mismatched after partial fix |
| wf_75338146-5cf | ceiling-check | M136 charter: directive IDs cited but not yet drained |

### Root cause: Verify phase uses agents as script-runners

**3 of the 5 Verify agents are LLM calls wrapping deterministic shell scripts.** Looking at `.claude/workflows/execute-milestone.js` lines 15–36:

| Agent | What it actually does | Nature |
|-------|----------------------|--------|
| `ceiling-check` | Runs `it0-ceiling-check.sh` → returns `{ok, detail}` | **Script runner** — exit 0/1 is deterministic |
| `gate-hash` | Runs `it0-gate-hash-check.sh` → returns `{ok, detail}` | **Script runner** — exit 0/1 is deterministic |
| `line-budget` | Runs `it0-ceiling-line-budget-check.sh` → returns `{ok, detail}` | **Script runner** — exit 0/1 is deterministic |
| `domain-misfit` | Applies inherited-core.md §3.2 decision procedure to Done-when list | **Genuinely needs LLM** |
| `dogfood-evidence` | Reads inner iteration reports, checks for pasted evidence | **Genuinely needs LLM** |

Each "script runner" agent costs one LLM call solely to execute a shell script whose exit code is mechanically meaningful. This accounts for 60% of Verify phase agent calls. The fix is to **run those scripts directly in the workflow script body** (JavaScript can `Bash` or read exit codes), keeping only domain-misfit and dogfood-evidence as agents.

### Crystallization analysis: failure types

| Failure type | Can a script diagnose? | Can a script auto-fix? |
|---|---|---|
| `stale-directive` (ceiling-check fails, cited directive dirStatus≠applied) | ✅ Extract directive IDs from charter → `task_get` each → check `dirStatus` | ✅ `task_write dirStatus: applied` |
| `hash-mismatch` (gate-hash-check fails) | ✅ Re-run `it0-gate-hash-check.sh` → capture detail | ✅ Re-compute hash → update charter |
| `line-budget-exceeded` | ✅ Script already produces detail | ❌ Needs scope redesign → LLM required |
| `domain-misfit` | ❌ Needs to interpret Done-when against inherited-core.md §3.2 | ❌ LLM required |
| `dogfood-evidence-gap` | ❌ Needs to read inner iteration reports for evidence presence | ❌ LLM required |

The first two (stale-directive, hash-mismatch) are entirely mechanical — they account for all 5 observed failures in the session. The last three are genuinely complex. **A pure script can handle the auto-fixable cases; a thin workflow handles the rest.**



## Proposal

Refactor execute-milestone.js Verify phase to run the 3 mechanical it0 checks (ceiling, gate-hash, line-budget) as direct Bash calls in the workflow script body instead of LLM agent wrappers. Create diagnose-verify-failure.ts to parse workflow journals and auto-classify Verify failures. Package as a thin diagnose-complex workflow. Reduces Verify phase agents from 5 to 2 (domain-misfit + dogfood-evidence only), eliminating 60% of wasted LLM calls and enabling automated failure diagnosis.
## Requested action

### 0. FIRST: Refactor execute-milestone Verify phase — run scripts directly, not via agents

**This must be done before or alongside the diagnostic script** — the diagnostic script's journal parsing logic depends on the Verify phase's output shape. Edit `.claude/workflows/execute-milestone.js` Verify phase (lines 14–42):

**Replace 3 script-runner agents with direct `Bash` calls in the workflow script body:**

```js
phase('Verify')

// Run the 3 mechanical checks as direct shell commands — no LLM needed.
const ceilingOk = await runShellCheck('it0-ceiling-check.sh', args.charterFile)
const gateHashOk = await runShellCheck('it0-gate-hash-check.sh', '--by-reference', args.charterFile)
const lineBudgetOk = await runShellCheck('it0-ceiling-line-budget-check.sh', args.charterFile)

// Only 2 checks genuinely need LLM judgment.
const judgment = await parallel([
  () => agent(
    `Apply the domain-misfit audit-channel decision procedure...`,
    { label: 'domain-misfit', schema: ... }
  ),
  () => agent(
    `Run it0-dogfood-evidence-gate.sh against each inner iteration report...`,
    { label: 'dogfood-evidence', schema: ... }
  ),
])

const verifyFailed = !ceilingOk || !gateHashOk || !lineBudgetOk ||
  judgment.filter(Boolean).some(c => c === null || !c?.ok)
```

Where `runShellCheck(script, ...args)` is a helper that runs `node experiments/quay-perpetual-stream/scripts/<script> <args>`, captures exit code + stdout/stderr, parses any JSON output for `detail`, and returns `{ok: exit===0, detail}`. This is pure JavaScript — no agent needed.

**Effect:** Verify phase drops from 5 parallel agents (~5-9 min) to 2 parallel agents + 3 synchronous script calls (~1-2 min). The 3 mechanical checks still run; they just don't burn LLM calls to do it.

**The workflow journal MUST record results for all 5 checks** (3 script + 2 agent) in a unified shape `{check, ok, detail, source: "script"|"agent"}` so `diagnose-verify-failure.ts` can parse them uniformly.

### 1. `scripts/diagnose-verify-failure.ts` — pure, testable diagnostic script

Script at `experiments/quay-perpetual-stream/scripts/diagnose-verify-failure.ts`. Pure functions + thin CLI:

- **Input:** workflow journal path (or auto-detect from session workflow directory), charter file path
- **Read journal:** Parse the most recent `execute-milestone` workflow journal JSON. Extract per-check results (ceiling-check, gate-hash, line-budget, domain-misfit, dogfood-evidence). Filter to `ok: false`. Handle both `source: "script"` and `source: "agent"` entries uniformly.
- **Classify mechanically:** For each failed check:
  - `ceiling-check` → extract cited directive/gap IDs from charter → `task_get` each → if any has `dirStatus` ≠ `applied` → classify as `stale-directive`; else classify as `genuine-scope-exceeded`
  - `gate-hash` → classify as `hash-mismatch`
  - `line-budget` → classify as `line-budget-exceeded`
  - `domain-misfit` → classify as `domain-misfit`
  - `dogfood-evidence` → classify as `dogfood-evidence-gap`
- **Auto-fix (mechanical):**
  - `stale-directive`: `task_write extra.dirStatus: applied` on each stale directive. Record action.
  - `hash-mismatch`: re-compute hash from ITERATION-PROMPTS.md HARD GATES block → update charter file hash reference. Record action.
  - `line-budget-exceeded` / `domain-misfit` / `dogfood-evidence-gap`: NO auto-fix. Include the `detail` output in the result for LLM review.
- **Auto-fix verification:** For each auto-fixed check, re-run the corresponding check (as a direct script call — same `runShellCheck` helper as execute-milestone Verify). Return per-check pass/fail.
- **Output:** `DiagnosticResult { autoFixed: [{check, action, recheckPass}], unfixable: [{check, classification, detail}], retryReady: boolean }` to stdout
- **CLI:** `node scripts/diagnose-verify-failure.ts --journal <path> --charter <path> --json`
- **Exit codes:** 0 = diagnostic complete (some fixed, some unfixable), 3 = nothing to fix (no failures found)

### 2. Thin `/diagnose-verify-failure` workflow

Saved workflow at `.claude/workflows/diagnose-verify-failure.js`. Two phases:

- **Run diagnostic script:** Execute `node experiments/quay-perpetual-stream/scripts/diagnose-verify-failure.ts --journal <path> --charter <path> --json`. Parse `DiagnosticResult`.
- **Diagnose complex failures (ONLY if unfixable non-empty):** ONE agent call — receives `unfixable: [{check, classification, detail}]` — for each, produce a structured diagnosis: what specifically is wrong, what needs to change, and whether it's fixable by the loop or needs human intervention. Return `{diagnoses: [{check, diagnosis, fixable: true|false, suggestedAction}]}`.
- **Return:** `{autoFixed: [...], diagnoses: [...], retryReady: boolean}`. `retryReady: true` when ALL failures were either auto-fixed successfully or diagnosed as loop-fixable.

### 3. Integration with `/execute-milestone`

When `/execute-milestone` returns `{outcome: "needs-human", phase: "Verify"}`, the outer loop invokes `/diagnose-verify-failure`. If `retryReady: true`, immediately re-invoke `/execute-milestone`. Only escalate to human attention when `retryReady: false`.
