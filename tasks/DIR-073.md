## Finding

Session `b643aa4d` (2026-07-24) ran `execute-milestone` 6 times: 5 failed at Verify phase, 1 resume that passed Verify → Build → Audit but failed at Gate. The Verify phase failure rate is 83% (5/6). Each failure costs 5–9 minutes (5 parallel agents), and each failure triggers a near-identical manual debug loop:

```
读 workflow journal → 找到失败的检查 → 理解失败原因 →
修复 charter 或 task → 删除 .halt → 重新调度 workflow
```

This loop takes 5–10 turns (another 3–5 minutes) and is entirely manual. The specific failures observed:

| wf_1caf91bd-719 | ceiling-check | Charter cited directive IDs with stale `dirStatus` |

**Crystallization analysis (2026-07-24):** decomposed by failure type:

| Failure type | Can a script diagnose? | Can a script auto-fix? |
|---|---|---|
| `stale-directive` (ceiling-check fails, cited directive dirStatus≠applied) | ✅ Extract directive IDs from charter → `task_get` each → check `dirStatus` | ✅ `task_write dirStatus: applied` |
| `hash-mismatch` (gate-hash-check fails) | ✅ Re-run `it0-gate-hash-check.sh` → capture detail | ✅ Re-compute hash → update charter |

The first two (stale-directive, hash-mismatch) are entirely mechanical — they account for all 5 observed failures in the session. The last three are genuinely complex and should produce a structured diagnostic for LLM review. **A pure script can handle the auto-fixable cases; a thin workflow handles the rest.**

## Requested action

### 1. `scripts/diagnose-verify-failure.ts` — pure, testable diagnostic script

Script at `experiments/quay-perpetual-stream/scripts/diagnose-verify-failure.ts`. Pure functions + thin CLI:

- **Input:** workflow journal path (or auto-detect from session workflow directory), charter file path
- **Read journal:** Parse the most recent `execute-milestone` workflow journal JSON. Extract per-agent results (ceiling-check, gate-hash, domain-misfit, line-budget, dogfood-evidence). Filter to `ok: false`.
- **Classify mechanically:** For each failed check:
  - `ceiling-check` → extract cited directive/gap IDs from charter → `task_get` each → if any has `dirStatus` ≠ `applied` → classify as `stale-directive`; else classify as `genuine-scope-exceeded`
  - `gate-hash` → classify as `hash-mismatch`
  - `line-budget` → classify as `line-budget-exceeded`
  - `domain-misfit` → classify as `domain-misfit`
  - `dogfood-evidence` → classify as `dogfood-evidence-gap`
- **Auto-fix (mechanical):**
  - `stale-directive`: `task_write extra.dirStatus: applied` on each stale directive. Record action.
  - `hash-mismatch`: re-compute hash from ITERATION-PROMPTS.md HARD GATES block → update charter file hash reference. Record action.
  - `line-budget-exceeded` / `domain-misfit` / `dogfood-evidence-gap`: NO auto-fix. Include the agent's `detail` output in the result for LLM review.
- **Auto-fix verification:** For each auto-fixed check, re-run the corresponding it0 check script against the updated charter/task. Return per-check pass/fail.
- **Output:** `DiagnosticResult { autoFixed: [{check, action, recheckPass}], unfixable: [{check, classification, agentDetail}], retryReady: boolean }` to stdout
- **CLI:** `node scripts/diagnose-verify-failure.ts --journal <path> --charter <path> --json`
- **Exit codes:** 0 = diagnostic complete (some fixed, some unfixable), 3 = nothing to fix (no failures found)

### 2. Thin `/diagnose-verify-failure` workflow

Saved workflow at `.claude/workflows/diagnose-verify-failure.js`. Two phases:

- **Run diagnostic script:** Execute `node experiments/quay-perpetual-stream/scripts/diagnose-verify-failure.ts --journal <path> --charter <path> --json`. Parse `DiagnosticResult`.
- **Diagnose complex failures (ONLY if unfixable non-empty):** ONE agent call — receives `unfixable: [{check, classification, agentDetail}]` — for each, produce a structured diagnosis: what specifically is wrong, what needs to change, and whether it's fixable by the loop or needs human intervention. Return `{diagnoses: [{check, diagnosis, fixable: true|false, suggestedAction}]}`.
- **Return:** `{autoFixed: [...], diagnoses: [...], retryReady: boolean}`. `retryReady: true` when ALL failures were either auto-fixed successfully or diagnosed as loop-fixable.

### 3. Integration with `/execute-milestone`

When `/execute-milestone` returns `{outcome: "needs-human", phase: "Verify"}`, the outer loop invokes `/diagnose-verify-failure`. If `retryReady: true`, immediately re-invoke `/execute-milestone`. Only escalate to human attention when `retryReady: false`.
