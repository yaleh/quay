## Finding

M135 (delivery-manifest-check-tighten, 2026-07-24) required **6 workflow invocations** to land,
consuming ~203 minutes and ~800K+ output tokens. Of the 5 Verify-phase failures:

- Attempt 1: gate-hash check — legitimate (charter missing `GATE-HASH-REF`)
- Attempt 2: ceiling-check — legitimate (task ID not in gap-list.md)
- Attempt 3: **dogfood-evidence gate failed because M01-dist's historical report lacked evidence blocks**
- Attempt 4: **dogfood-evidence gate still failing — M01-dist's evidence format was unrecognized**
- Attempt 5: all PASS → Build → Audit → Gate (audit-independence fail — separate issue)

**3 of 5 Verify failures were systemic pollution**: `it0-dogfood-evidence-gate.sh` and
`it0-ceiling-check.sh` scan ALL historical milestone reports under `milestones/M*/`. A format
issue in M01-dist's report (authored months ago, before the current schema crystallized)
caused cascading failures for every new milestone whose Verify phase ran the dogfood gate.

The session log records the loop operator explicitly fixing M01-dist's historical reports
mid-M135-retry ("M01-dist report fixed — 3 evidence blocks added") — work completely
unrelated to M135's scope, forced by the gate's global scan radius.

This is a **correctness problem**, not just an efficiency problem: a gate validating M135's
evidence integrity should not fail because of M01's evidence format. The gate's signal is
diluted by noise from irrelevant historical artifacts.

**Additional data (2026-07-24 `b643aa4d` session):** the same pollution pattern recurred
with the dogfood gate scanning M01-dist, M02-gates, and M03-abi-eval reports — 3 pre-existing
failures in historical milestones that had nothing to do with M135's charter or evidence.

## Requested action

Scope the it0 systematic-explore checks to the **current milestone only** + its direct
dependency chain, rather than scanning all historical `milestones/M*/`.

### 1. `it0-dogfood-evidence-gate.sh` — scope to current milestone

Current behavior: scans all `milestones/M*/iterations/iteration-*.md` for evidence blocks.

Change: accept a `--milestone <M-NN>` parameter. When provided, scan only:
- `milestones/M<NN>/iterations/iteration-*.md` (current milestone's own reports)
- Milestones explicitly listed in the current charter's `## Dependencies` or `## Touches`
  section (direct dependencies)

When `--milestone` is absent, keep the existing global scan (backward-compatible for
checkpoint/snapshot use — the global scan is useful as a periodic health check, just not
as a per-milestone dispatch gate).

### 2. `it0-ceiling-check.sh` — scope to current milestone

Current behavior: scans all `milestones/M*/` directories for gap-list references.

Change: same `--milestone <M-NN>` parameter. When provided, only verify that gap/directive
IDs cited in the current charter exist and are in the correct state. Do not validate
unrelated milestones' gap references.

### 3. `it0-gate-hash-check.sh` — already scoped (no change needed)

This check already operates on the single charter file. No change.

### 4. Add a periodic global-scan checkpoint gate

The global scan still has value as a **periodic health check**. Add a `quay gate --gate
historical-evidence-consistency` that runs the global scan as a checkpoint routine
(DIR-051/056 routine track), not as a per-milestone dispatch gate. This separates:
- **Dispatch gate** (fast, scoped, per-milestone): verifies THIS milestone's evidence
- **Routine probe** (slow, global, every-N): verifies cross-milestone consistency

### 5. Default the execute-milestone Verify phase to scoped mode

Update `execute-milestone.js` Verify phase to pass `--milestone <args.taskId>` (or the
derived milestone number) to the it0 check agents. The workflow's Verify phase should
validate the CURRENT milestone, not the entire historical archive.
