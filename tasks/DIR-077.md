## Finding

The 2026-07-24 `b643aa4d` session recorded a **63-minute gap** (12:02:05 → 13:05:37) where
the outer loop was completely idle. The last assistant message before the gap had 0 output
tokens (a system-level transition), and the loop only resumed when a human manually typed
`/loop @experiments/quay-perpetual-stream/OUTER-LOOP.md 持续迭代。`

This is not an isolated incident. The loop's OUTER-LOOP.md is executed as a prompt document
within a Claude Code session. When the session reaches a "natural end" (all pending work
completed, no more milestones to SELECT, or a workflow returns an unexpected outcome), the
session goes idle. There is no daemon-mode self-restart mechanism. The human must notice the
silence and manually re-invoke `/loop`.

**Quantified impact across 2026-07-22–24:**
- Session `4d2e9f2d` → `145cc0be` gap: **9.3 hours** (Jul 22 15:20 → Jul 23 00:41)
- Session `a8cd3b43` → `b643aa4d` gap: **9.3 hours** (Jul 23 21:36 → Jul 24 06:58)
- Session `b643aa4d` mid-session gap: **1.0 hour** (Jul 24 12:02 → 13:05)

**Total idle time: ~19.6 hours across ~50 hours of wall clock — a 39% duty cycle.**

Some of this is natural (overnight), but the mid-session 63-minute gap and the
session-to-session transitions show that the loop does not self-restart. Each gap requires
either a human noticing or a scheduled cron to bridge.

## Requested action

Make the outer loop self-sustaining: it should continue iterating until `.halt` is
touched, without requiring human re-invocation between sessions or after idle periods.

### 1. Per-session self-continuation via CronCreate

At the end of each outer cycle (after step 5 checkpoint + step 5a routines), the loop
checks whether it should continue:

- If `.halt` exists → log and exit cleanly (existing behavior)
- If the previous cycle produced a `needs-human` outcome AND no more ready candidates →
  schedule a long CronCreate (~1800s = 30 min) to re-check the board for new directives
- Otherwise → schedule a short CronCreate (~60s) to fire the next iteration immediately

The CronCreate prompt is: `/loop @experiments/quay-perpetual-stream/OUTER-LOOP.md 持续迭代。除非遇到中止条件，不得停下。`

### 2. OUTER-LOOP.md: add explicit continue/stop logic

Add a `## Session end` section to OUTER-LOOP.md:

```markdown
## Session end (never exit silently)

After each outer cycle iteration:

1. If `.halt` sentinel exists → log "halt sentinel — stopping" and return.
2. If no ready candidates AND no pending directives: schedule CronCreate 1800s fallback
   → "board empty, rechecking in 30 min".
3. Otherwise: schedule CronCreate 60s → fire next iteration.
4. Never silently return — the loop either schedules its next wake-up or logs WHY it stopped.
```

### 3. Start-of-session liveness check

At session start (before the DRAIN step), the loop checks whether it was invoked by a
CronCreate continuation or a human:

- If invoked by CronCreate: skip the "read pinned references" preamble (they were loaded
  in the prior session; the context carries them via the CronCreate prompt). Go directly
  to step 0 (DRAIN).
- If invoked by human: full preamble load (existing behavior).

This avoids re-loading `inherited-core.md`, `dashboard.md`, etc. on every CronCreate
cycle — the loop stays lean when self-continuing.

### 4. Idle detection watchdog

Add a standalone watchdog: `experiments/quay-perpetual-stream/scripts/watchdog-idle-check.sh`.
The watchdog reads `dashboard.md`'s `milestone_counter` and `last_updated` timestamp.
If `milestone_counter` has not changed in ≥60 minutes, it writes a warning to
`dashboard.md`'s "Human-review cadence" track. This is a **non-blocking** signal — it
surfaces the stall without halting the loop (the CronCreate fallback in item 1 above is
still the active mechanism).

The watchdog can be run via a routine track probe (DIR-051/056), firing `every(1)` to
check each cycle.

## Acceptance Criteria

- [ ] After completing an outer cycle, the loop schedules CronCreate for the next iteration (unless `.halt` is present)
- [ ] Empty-board fallback: CronCreate 1800s when no ready candidates + no pending directives
- [ ] Normal continuation: CronCreate 60s when work remains
- [ ] `.halt` sentinel causes clean exit with NO CronCreate scheduled
- [ ] CronCreate continuation skips preamble load (goes directly to DRAIN)
- [ ] Human-invoked `/loop` still does full preamble load (backward-compatible)
