## Finding

The 2026-07-24 `b643aa4d` session recorded a **63-minute gap** (12:02:05 → 13:05:37) where
the outer loop stopped mid-session and only resumed when a human manually typed
`/loop @experiments/quay-perpetual-stream/OUTER-LOOP.md 持续迭代。`

The root cause is not that the loop needs a CronCreate self-continuation mechanism —
Claude Code's built-in `/loop` (self-paced, no interval) already provides continuous
re-invocation with adaptive intervals. The gap occurred because the loop was NOT running
under `/loop` self-paced mode, or the iteration completed without explicitly signalling
"more work remains."

Claude Code `/loop` self-paced mode (documented at
https://code.claude.com/docs/en/scheduled-tasks#let-claude-choose-the-interval) provides:
- Dynamic interval selection (1 min to 1 hour) based on observed activity
- Short waits when work is active, longer waits when the board is quiet
- Self-stopping via `ScheduleWakeup(stop: true)` 
- 7-day auto-expiry as a safety bound
- Survival across `--resume` (unexpired tasks are restored)

This eliminates the need for manual CronCreate management, session-end logic, preamble-skip
heuristics, and idle-detection watchdogs — all proposed by the original version of this
directive. The fix is to ensure the loop IS running under `/loop` self-paced mode and that
OUTER-LOOP.md ends each iteration with a clear signal.

Cross-session continuity (the 9.3-hour overnight gaps) is explicitly out of scope: `/loop`
is session-scoped by design. Closing that gap requires Desktop scheduled tasks or Routines
(infrastructure-level scheduling), not prompt-level logic.

## Requested action

### 1. Create `.claude/loop.md`

```markdown
@experiments/quay-perpetual-stream/OUTER-LOOP.md
```

This makes bare `/loop` in this project run the outer loop driver. The file is plain
Markdown — Claude Code reads it as the default prompt for `/loop` with no arguments.
When a prompt is supplied on the command line (`/loop 5m ...`), `loop.md` is ignored.

Edits to `loop.md` take effect on the next iteration — the loop instructions can be
refined while the loop is running.

### 2. Add end-of-cycle signal to OUTER-LOOP.md

At the end of each outer cycle (after step 5a routines), the loop must explicitly
indicate whether to continue or stop. Current OUTER-LOOP.md already documents the
`.halt` check in its "The loop runs autonomously" section. Add a single paragraph
at the very end of the `## Outer cycle` section:

```markdown
After completing one outer cycle (steps 0–5a):

- If `.halt` exists: call ScheduleWakeup with stop=true and return. The loop ends cleanly.
- Otherwise: the iteration is complete. /loop self-paced mode handles the next wakeup —
  short interval when work was done, longer interval when the board was empty.
```

This is the ONLY addition to OUTER-LOOP.md. No `## Session end` section. No CronCreate
logic. No preamble-skip heuristics. The `/loop` self-paced mechanism handles everything else.

### 3. Run the loop via `/loop` self-paced

The invocation is: `/loop` (bare, no interval, no arguments).

With `.claude/loop.md` in place, bare `/loop` runs OUTER-LOOP.md on each iteration at
a dynamically chosen interval. Claude observes whether work was done (a milestone landed,
a workflow completed, a directive was dispositioned) and picks shorter intervals when
active, longer intervals when idle.

### Non-goals

- **Cross-session continuity** (overnight gaps): requires Desktop scheduled tasks or
  Routines — infrastructure scheduling, not prompt logic.
- **Idle detection watchdog**: unnecessary — `/loop` self-paced mode naturally adapts
  to idle periods.
- **Preamble skip**: unnecessary — `/loop` keeps the same session, context is maintained
  across iterations.
