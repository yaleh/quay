## Finding

The project's "executed documents" — files Claude Code reads as operational instructions during
`/loop` and `/execute-milestone` sessions — contain ~3,400 lines of prose. The `/home/yale/.claude/agents/`
directory demonstrates a dramatically leaner alternative: formal λ-notation specs averaging ~80 lines
each, with no iteration history, no honesty-note paragraphs, and no reference-file case studies.

## Requested action

Refactor all four groups of executed documents to agent-spec style. This is a **driver-rewrite**
(touches `OUTER-LOOP.md`, `inherited-core.md`, `.claude/skills/`) → `label:human-steered`.

## Agent-spec standard (reference: /home/yale/.claude/agents/iteration-executor.md)

The reference agents demonstrate three structural properties:

**Property 1: Formal density ≥80%.** `::` type signatures, function declarations, constraint
predicates, and code blocks comprise ≥80% of non-blank lines. Prose paragraphs are the exception,
not the default. Reference: iteration-executor.md has 16 `::` signatures in 107 lines (1 per 6.7 lines).

**Property 2: Prose→function signatures, not prose+signatures.** A section does not "have a formal
declaration" if the header carries a `::` type but the body is a prose paragraph. The body must be
formal notation: function definitions, constraint predicates (`⊨`), executable-check pointers
(`exec:`), and code blocks. Prose exists only where formal notation cannot express the constraint.

**Property 3: Scripts are single source (ADR-004).** When an executable script already enforces a
rule (it0-dod-check.ts, human-steered-classify.ts, concurrent-batch-scheduler.ts), the document
does NOT re-describe how the script works. It declares the constraint with a pointer to the script.
The script IS the specification; the document is the index.

### Concrete standard per document

**inherited-core.md:** Every `##` section must have a `::` type signature AND the body must be
formal constraint/function definitions. Target: 400-500 lines, ≥30 `::` signatures, ≤10% prose.

**OUTER-LOOP.md:** The Spec block becomes the primary content. Each cycle step (drain, select,
hypothesize, charter, execute, checkpoint) is a named function with type signature and constraint
predicates. Prose step descriptions shrink to 1-line pointers. Target: ≤200 lines, ≥15 `::` sigs.

**plugin/skills/execute + author:** Already near target. Target: Gaps≤30 (already met), formal
density ≥50%.

**.claude/skills/ methodology:** YAML frontmatter (already done) + `## Spec` with `::` type
signatures for the key constraints being inherited. Target: ≥5 `::` signatures per skill,
prose reduced to Relationship/Implementation sections only.

### Non-goal

`docs/proposals/`, `adr/`, `tasks/DIR-*.md` — reference documents, not executed as instructions.
