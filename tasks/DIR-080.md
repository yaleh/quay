## Finding

The project's "executed documents" — files Claude Code reads as operational instructions during
`/loop` and `/execute-milestone` sessions — contain ~3,400 lines of prose. The `/home/yale/.claude/agents/`
directory demonstrates a dramatically leaner alternative: formal λ-notation specs averaging ~80 lines
each, with no iteration history, no honesty-note paragraphs, and no reference-file case studies.

The gap is structural, not cosmetic:

| Document | Lines | Style |
|---|---|---|
| `inherited-core.md` | 1597 | 15 sections, 12 are dense prose; `## Definition of Done` alone is 495 lines |
| `plugin/skills/*/SKILL.md` | 929 | execute=420, loop-driver=157, author=217, directive=135 |
| `.claude/skills/*/SKILL.md` | 519 | quay-execute=390, methodology skills 113-164, directive=41 |
| `OUTER-LOOP.md` | 370 | Spec block already agent-style; step 1 SELECT is 120 lines of prose |
| `.claude/workflows/*.js` | 489 | Already code — correct format |
| **Total executed prose** | **~3,400** | |

Three categories of bloat recur across all four document groups:

**1. Iteration history embedded as operational instruction.** `inherited-core.md`'s `## Definition of
Done` section (495 lines) narrates how each of the 13 clauses was discovered, refined, and
re-verified across milestones. `plugin/skills/execute/SKILL.md` (420 lines) dedicates ~60% of its
body to a Gaps section that chronologically traces QN-017, QN-020/QN-021, QN-022/QN-023, QN-037,
iteration 28 MCP discovery, and iteration 61 negative-test discipline. This is provenance — it
belongs in `experiments/quay-perpetual-stream/provenance.md` or per-milestone iteration reports,
not in the document the model reads at every session start.

**2. Prose rules that duplicate executable checks.** `inherited-core.md`'s `## Definition of Done`
spends 495 lines describing the 13 DoD clauses in prose. `it0-dod-check.ts` already implements
every clause as an executable check. ADR-004 ("hard checks over prose") requires the executable
check to be the single source — the prose is a second, divergent source that creates drift risk.

**3. Case-study reference files that should be constraints.** `quay-core-bootstrap-methodology`
packages 531 lines of reference files (case studies, diagnostic procedures, reliability envelopes)
that the skill instructs the model to read before acting. Each case study encodes a constraint that
could be stated in 1-3 lines of formal notation. The case study remains as evidence; the constraint
moves into the spec.

The agents at `/home/yale/.claude/agents/` prove this is solvable: `knowledge-extractor.md` is 389
lines but every line is formal spec — it's longer because it defines more functions, not because it
narrates history. The same discipline applied to `inherited-core.md`'s 1597 lines would collapse
~1200 lines of prose into ~300 lines of formal constraints + pointers to evidence.

## Requested action

Refactor all four groups of executed documents toward the agent-spec style: formal λ-notation
specs with constraints as predicates, history in provenance files, and executable checks as the
single source. This is a **driver-rewrite** (touches `OUTER-LOOP.md`, `inherited-core.md`,
`.claude/skills/`) → `label:human-steered`. Execute under `.halt` off-loop.

### 1. `inherited-core.md` — collapse 1597 → ~400 lines

**Principle:** every section has a `λ` signature or formal declaration stating WHAT the rule is.
Explanatory prose shrinks to the minimum needed to disambiguate the formal notation. History of
how the rule was discovered moves to `provenance.md`.

Target structure:
```markdown
# Inherited Core — Tier-B pinned methodology

## Spec (CRYST-D3)
λ(workspace, task) → ConstraintSet

  HumanSteered :: Task → Bool = driverFileEdit ∨ missionRedirection ∨ unauthorizedWorkspace
  Deliverable :: Task → yes|no
  Select :: Board → Task ⊨ exclude HumanSteered ∧ D-quota ∧ explore-cadence
  ClassRoute :: Task → development|methodology
  DoD :: Task × Charter × Evidence → {PASS, FAIL} — 13 clauses (it0-dod-check.ts)
  Terminate :: Milestone[] → CONTINUE|TERMINATION-DUE

## Constraints

### DoD-0: AC+DoD present
  task.extra.schema == "v1" ∧ hasChecklist(AC) ∧ hasChecklist(DoD) ∧ allUnchecked(atSelect) ∧ allChecked(afterAudit)
  ⊨ executable: it0-dod-check.ts clause0

### DoD-1: Adversarial audit
  ∀ milestone: ∃ fresh-context auditor ⊥ build context
  ⊨ UNCONDITIONAL per milestone; ⊨ refutation blocks land
  ...

### Human-steered (DIR-062)
  HumanSteered(t) ⇔ t touches OUTER-LOOP.md ∨ t touches inherited-core.md ∨ t touches .claude/skills/
    ∨ t.extra.missionRedirection ∨ unauthorizedWorkspace(t)
  ⊨ executable: human-steered-classify.ts
  ⊨ label:human-steered = manual override

### Domain-misfit decision procedure
  Step 3 conclusion → no-independent-mechanism-reachable → §3.2 ceiling trigger
  ⊨ source: M02-gates Done-when clause 4
  ...

## Provenance
  → experiments/quay-perpetual-stream/provenance.md (iteration history, gap discovery, consolidation log)
```

Each constraint is 3-8 lines: formal declaration + pointer to executable check + pointer to source
evidence. The 495-line `## Definition of Done` section collapses to ~80 lines of constraint
definitions. The 133-line `## Milestone size definition` collapses to ~10 lines. The prose history
moves to `provenance.md`.

**Reference sections that stay as-is:** `## Kit version` (identity metadata), `## Extracted skills`
(pointers), `## exp4 methodology` (carry-forward artifacts), `## Pinned gate source` (transclusion
block — must stay verbatim per invariant 3).

### 2. `OUTER-LOOP.md` — tighten step 1 SELECT prose

The `## Spec` block (lines 9-30) is already agent-style — keep it. The `## contracts:` section
(lines 32-39) is already executable checks — keep it. The `## Invariants` (lines 61-68) are a
bullet list — keep.

The SELECT step (step 1, ~120 lines of prose) is the main target. Each sub-rule in SELECT should
reference its executable script (it already does this — `deliverable-governor.ts`,
`human-steered-classify.ts`, `explore-exploit-cadence.ts`, `task-schema-check.sh`). The prose
describing HOW each script works should shrink to a 1-line constraint reference. The script IS
the single source (ADR-004).

The `## DRAIN standing methodology` (34 lines, moved from step 0 by DIR-071) can shrink to a
pointer: `/drain-directives` workflow is the single source; this section only captures the
methodology that isn't already encoded in the workflow script.

The `## Lesson recorded (DIR-013)` (22 lines) is a historical lesson, not an operational
instruction. Move it to `provenance.md` and replace with a 1-line constraint reference:
`⊨ no-blanket-ours-theirs merge; ⊨ post-merge cross-reference sweep`.
