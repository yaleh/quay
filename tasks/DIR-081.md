## Finding

The quay Claude Code plugin (v0.3.20) distributes the MCP server, four skills (author, execute, quay-directive, loop-driver), scripts (routine-scheduler, routine-file-gate, etc.), and probes. However, three categories of assets that exist in the quay repository are **not** carried by the plugin and therefore cannot reach target workspaces like `yaleh/archguard`:

1. **Workflows** (`.claude/workflows/{drain-directives,execute-milestone,run-routines}.js`) — the Claude Code plugin manifest has no `workflows` field, and the `Workflow` tool requires scripts to be in `.claude/workflows/` or passed inline
2. **Agent types** (`.claude/agents/*.md`) — the baime plugin ships agent types via `plugin.json` → `agents[]`, proving the mechanism works; quay's plugin does not declare any agents
3. **Gate scripts** (`experiments/quay-perpetual-stream/scripts/it0-*.sh`, `vmeta-lag-check.sh`, `tree-hygiene-check.sh`, `drain-scheduler.ts`, etc.) — mechanical quality checks referenced by the workflows; not bundled in the plugin

Architectural analysis (recorded in `docs/proposals/quay-workflow-agent-distribution.md`) confirms that most target workspaces only need Tier 1 (basic loop) or Tier 2 (loop + routines), both of which are fully covered by the existing plugin. Only Tier 3 workspaces (full methodology adoption) need these additional assets — but when they do, the only path today is manual copying.

## Proposal

Bundle workflows, agent types, and gate scripts into the quay plugin distribution directory (`plugin/`), then implement a `quay:init` skill that copies them from `${CLAUDE_PLUGIN_ROOT}` into a target workspace's `.claude/` directories — idempotent, conflict-aware, selective.

This is Approach A from the proposal ("the bootstrap action"), which works today with zero upstream dependencies. Approach B (extending the plugin manifest with `workflows` and `gateScripts` fields) is deferred as a follow-on; when available, the `quay:init` skill becomes the backend that Approach B's installer delegates to.

## Plan

N/A — directive resolved via a milestone. Implementation phases from the proposal (§7):

1. **Phase 1: Bundle** — create `plugin/workflows/`, `plugin/agents/`, `plugin/gate-scripts/` directories; write `plugin/sync.sh` to populate them from canonical sources; add CI stale-check
2. **Phase 2: `quay:init` skill** — author `plugin/skills/init/SKILL.md`; add to `plugin.json` → `commands[]`; test in quay's own workspace and a clean workspace
3. **Phase 3: Agent vendoring resolution** (gated) — empirically resolve whether `baime:iteration-executor` degrades gracefully without the full baime meta-agent tree; if yes, vendor the single agent file; if no, determine the transitive closure or declare baime as a prerequisite
4. **Phase 4: Plugin manifest extension** (upstream, follow-on) — propose `workflows` and `gateScripts` fields to the Claude Code plugin team

Phase 1 + Phase 2 are in-scope for a single milestone. Phase 3 is gated on an isolation test. Phase 4 is a separate follow-on.
