## Proposal

`lifecycle_complete` and `lifecycle_promote` MCP handlers permanently set `QUAY_ACCEPTANCE_CWD` without saving/restoring the prior value -- unlike `gate_run` which does proper save/restore in a try/finally block. After MCP lifecycle calls, env var is permanently overwritten. Subsequent `gate_run` calls without explicit `cwd` use stale workspace root. `resolveRunnerOptions` reads this env var at highest precedence. No test covers this.

Fix: add save/restore using try/finally in both handlers, matching `gate_run`'s pattern.

## Plan

N/A — fix is trivial (~10 lines per handler): save `prevCwd`, set env var, restore in `finally` block, matching the existing `gate_run` pattern in the same file.

Affected files:
- `packages/quay/src/mcp-handlers.ts`: `lifecycle_complete` and `lifecycle_promote` handlers
- `packages/quay/test/mcp-server.test.mjs`: add env-var-unchanged assertion
