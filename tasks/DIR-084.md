## Finding

**WHAT**: `lifecycle_complete` and `lifecycle_promote` MCP handlers permanently set `QUAY_ACCEPTANCE_CWD` without saving/restoring the prior value -- unlike `gate_run` which does proper save/restore in a try/finally block.

**WHERE**:
- `packages/quay/src/mcp-handlers.ts`: `lifecycle_complete` and `lifecycle_promote` handlers set `process.env.QUAY_ACCEPTANCE_CWD`
- Compare: `gate_run` handler saves `prevCwd`/`prevTimeout`, sets env vars, restores in `finally` block

**WHY**: After MCP lifecycle calls, env var is permanently overwritten. Subsequent `gate_run` calls without explicit `cwd` use stale workspace root. `resolveRunnerOptions` reads this env var at highest precedence. No test covers this.

## Acceptance Criteria

- [ ] `lifecycle_complete` MCP handler saves/restores `QUAY_ACCEPTANCE_CWD` using try/finally (matching `gate_run`)
- [ ] `lifecycle_promote` MCP handler saves/restores `QUAY_ACCEPTANCE_CWD` using try/finally
- [ ] MCP server test asserts env var unchanged after lifecycle calls
- [ ] Existing MCP server tests still pass

## Definition of Done

- [ ] Code change in `packages/quay/src/mcp-handlers.ts`
- [ ] Test added to `packages/quay/test/mcp-server.test.mjs`
- [ ] Full MCP server test suite passes
