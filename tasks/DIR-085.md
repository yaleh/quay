## Proposal

Add a `gate_list` MCP tool to expose `listGates()` (from `packages/quay/src/gate/registry.ts`) over MCP. Currently agents connected via MCP cannot discover registered gates — the CLI has `quay gate --list` but this isn't exposed over MCP. Trivial read-only passthrough, zero new logic.

## Finding

The MCP API surface has no `gate_list` tool — `registerGateHandlers` in `packages/quay/src/mcp-handlers.ts` registers `gate_run` and `gate_log` but not `gate_list`. `listGates()` exists in registry.ts and already returns both built-in and workspace gates. Agents connected via MCP cannot discover available gates without hardcoding names or inspecting files directly.

## Requested action

Add `gate_list` MCP tool to `registerGateHandlers` in `packages/quay/src/mcp-handlers.ts` with optional `provider` parameter, returning `{ gates: string[] }`. Add MCP server test.

## Plan

N/A — trivial: add one tool registration (~15 lines) in mcp-handlers.ts calling existing `listGates()`, plus test (~10 lines) in mcp-server.test.mjs.
