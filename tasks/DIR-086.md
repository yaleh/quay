## Proposal

Lifecycle library functions (`runComplete`, `runPromote`, `runRetreat`) in `packages/quay/src/gate/lifecycle.ts` directly set `process.exitCode = 1` on error paths, coupling a pure library to the process execution context. In MCP server contexts, this stale exit code persists between calls. Fix: either remove `process.exitCode` assignments from lifecycle.ts (Option A) or add `exitCode` field to return types (Option B). Minimum: MCP handlers reset exitCode after lifecycle calls (Option C).

## Finding

4 locations in lifecycle.ts set `process.exitCode = 1`. Callers (CLI, MCP handlers) must manually reset. MCP handlers never reset it, causing stale exit codes in long-running servers.

## Requested action

Apply Option B (pragmatic): add `exitCode: number` to return types, keep existing sets with deprecation comments, AND have MCP handlers reset `process.exitCode = 0` after calls.

N/A — fix is narrow (~20 lines in lifecycle.ts + ~5 lines in mcp-handlers.ts + test).
