## Finding

DIR-075 (M142) wired concurrent multi-milestone execution into exp5. The loop subsequently removed
three components during M135-M137 execution:

1. **Build dispatch** (`549a3c3`): "Workflow agents can't dispatch background tasks" — correct.
   Workflow-internal `agent()` calls cannot spawn background agents. The Build phase was changed
   to inline execution.
2. **Worktree isolation** (`4191a31`): "broke the sequential pipeline" — correct consequence
   of switching to inline Build.
3. **IS_CONCURRENT guard + concurrent path** — removed alongside the dispatch pattern.

The loop correctly identified that Workflow-internal dispatch doesn't work. But it incorrectly
concluded that concurrent execution is therefore impossible. The fix: **dispatch happens at the
correct layer.**

Concurrent dispatch of N workflows works from the **main session** (OUTER-LOOP, /loop prompt),
not from within a workflow. The main session CAN use `run_in_background: true`. The concurrent
architecture is:

```
Main session (OUTER-LOOP step 4b):
  Workflow({name: "execute-milestone", args: {taskId: "A", mode: "concurrent"}}, run_in_background: true)
  Workflow({name: "execute-milestone", args: {taskId: "B", mode: "concurrent"}}, run_in_background: true)
  → wait for both → anti-drift → serial-fanin-absorb → merge → counter += 2

execute-milestone (Workflow internal — inline Build, no dispatch needed):
  Verify → Build(inline) → Audit → Gate → Land(concurrent mode: defer counter)
```

Each workflow does inline Build (already working per the loop's own fix). The concurrency comes
from running N workflows simultaneously, not from dispatching within a workflow.
