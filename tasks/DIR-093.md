## Proposal

The `execute-milestone.js` workflow's Gate phase has a recurring mechanical failure:
the `audit-independence-check.sh` gate fails because the Audit agent generates a fresh
session ID each run (e.g., `m137-dir070b-audit-20260725`, `-reaudit`, `-fresh`,
`-r2`) but the `/tmp/m<NN>-absorb-entry.md` dispatch record — authored by the outer
loop BEFORE dispatch — does not contain that ID. The gate requires the audit artifact's
session ID to appear in the dispatch record (DIR-034 anti-forgery corroboration), and
fails-closed when it doesn't.

**Impact observed (M137, M138):** Both milestones required manual land after 5+ and
2+ workflow re-runs respectively, burning ~6M+ tokens on retries. The implementation
was independently verified correct by multiple adversarial audits; only the
audit-indep gate's session-ID matching was broken.

**Root cause:** The outer loop authors the absorb entry with a hardcoded or absent
session ID. The Audit agent (running inside the workflow) generates its own session
ID during audit. These IDs don't match. The workflow has no step where the Audit
agent writes its session ID back to the absorb entry BEFORE the Gate phase runs.

## Finding

Three structural gaps:

1. **Absorb entry creation timing:** The absorb entry (`/tmp/m<NN>-absorb-entry.md`)
   is authored by the outer loop at charter time, before the Audit agent runs. It
   cannot know the Audit agent's future session ID.

2. **No write-back step:** There is no explicit workflow step between Audit and Gate
   where the Audit agent's session ID is recorded into the absorb entry's dispatch
   record.

3. **audit-independence-check.sh contract mismatch:** The script expects the dispatch
   record to contain ALL valid audit session IDs that might appear in the audit
   artifact. But the current flow produces the dispatch record BEFORE the audit.

## Requested action

Fix the session-ID matching in `execute-milestone.js` so the Gate phase's
audit-indep check passes reliably on the first run:

1. **Option A (preferred):** After the Audit phase completes, have a lightweight
   step (not a full agent) that appends the Audit agent's session ID to the absorb
   entry's dispatch record. The Audit agent already returns its session ID in its
   structured output — use that value.

2. **Option B:** Have the Audit agent read the absorb entry first, extract an
   expected session ID, and use THAT as its session ID in the audit artifact.

3. **Option C:** Modify `audit-independence-check.sh` to accept the audit agent's
   session ID as a command-line argument instead of requiring it in the dispatch
   record file.

Option A is preferred because it preserves the existing script contracts and
requires the smallest change: one additional agent call or a `log()` + file
append between Audit and Gate phases.

Also fix the related `vmeta-lag-check.sh` call — it currently receives the absorb
entry path instead of `v-meta-ledger.md` (already fixed in the script, verify).

- [ ] After Audit phase completes, the Audit agent's session ID is appended to the absorb entry's dispatch record before Gate phase runs.
- [ ] `audit-independence-check.sh` passes on the first workflow run for a new milestone (no re-runs needed).

- [ ] End-to-end: a full `execute-milestone.js` run completes without `audit-indep` gate failure on a clean milestone.
- [ ] The fix does not break the DIR-034 anti-forgery property (the orchestrator still cannot forge an audit session ID — it appends the Audit agent's returned ID, not a self-generated one).
- [ ] Existing milestones (M136-M138) that were manually landed are not broken by the change.
