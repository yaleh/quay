## Finding

Attempting to run `/quay:loop-driver` on archguard and meta-cc (2026-07-25) revealed that
the portable loop driver cannot execute outside the quay project's own workspace. Three gaps:

1. **quay Core CLI not distributable.** `packages/quay/package.json` declares `"quay": "./dist/quay.js"`
   but `dist/` is a TypeScript build artifact — not committed to the repo, not published to npm,
   and not globally installable. External workspaces have no way to run `quay task list`.

2. **quay-native CLI points to TS source.** The globally installed `quay-native` package declares
   `"quay-native": "./bin/quay-native.ts"` — the TypeScript source file, not a compiled JS binary.
   The file `/home/yale/.nvm/versions/node/v25.2.0/lib/node_modules/quay-native/bin/quay-native.js`
   does not exist.

3. **quay-loop-driver uses CLI commands, not MCP.** The skill invokes `quay task list --provider
   <params.board>` (CLI) rather than `mcp__quay__task_list` (MCP). The user-space MCP server is
   already configured in `~/.claude/mcp.json` — it works cross-workspace. The CLI requires
   per-workspace installation and a compiled binary that doesn't exist.

**Impact:** quay product deliverables (loop-driver, workflows, gate scripts) can only be used
within the quay project's own workspace. External workspaces (archguard, meta-cc) cannot run
the loop despite having quay-native task boards, valid `.quay/config.yml`, and user-space MCP.

## Touches

- packages/quay/package.json
- packages/quay-native/package.json
- plugin/skills/loop-driver/SKILL.md

## Requested action

### 1. Ship a distributable quay Core CLI

Build `packages/quay/dist/quay.js` as part of the plugin release pipeline. Options:
- Add a `build` script to `packages/quay/package.json` that compiles TS → JS
- Or: use `quay-native` CLI as a drop-in (`quay-native task list` already works for native provider)
- Or: ship a Node SEA single-file executable (per M01-dist)
The CLI binary must be invocable from PATH in external workspaces.

### 2. Ship a distributable quay-native CLI

Fix `quay-native` package.json `bin` entry to point to a compiled JS file, not a TS source file.
The global npm install should produce a working `quay-native` command.

### 3. quay-loop-driver: use MCP tools, not CLI

Update `plugin/skills/loop-driver/SKILL.md` to use MCP tools (`mcp__quay__task_list`,
`mcp__quay__task_get`, `mcp__quay__task_write`, `mcp__quay__gate_run`, etc.) instead of
CLI commands (`quay task list`, `quay task get`, etc.).

MCP tools are already available cross-workspace via user-space `~/.claude/mcp.json`.
CLI commands require per-workspace binary installation. The MCP path is the correct
portable interface for the loop driver.

### 4. Verify: run /quay:loop-driver on archguard

After fixes 1-3: start a fresh Claude session in archguard, run `/quay:loop-driver`,
and confirm it can SELECT and process tasks from the archguard quay-native board.
