## Proposal

Make the gate loader fail-loud for malformed `.quay/config.yml` gate declarations
instead of silently dropping them. A real meta-cc case (2026-07-25): a `vitest` gate
written as `gates: vitest:` (wrong nesting) was silently skipped, causing `unknown gate:
vitest` at runtime with zero indication a config error caused it.

## Finding

`packages/quay/src/gate/config/loader.ts:83` — the loader sees the `gates:` key, tries to
read the six known arrays, and silently drops a malformed entry (e.g. `vitest:` as a YAML
map instead of an array → `Array.isArray()` false → gate dropped). No error, no warning,
no diagnostic. The correct `vitest` declaration in `.quay/gates.yml` is also invisible
because config.yml's `gates:` section takes precedence (DIR-050). Full root-cause detail
is preserved in each child's own Finding.
