## Finding

Once a task enters `needs-human` status, the lifecycle engine (`lifecycle.js`)
rejects `retreat` with:

```
illegal transition: needs-human cannot back
```

The only way out is a manual `task edit --status <new-status>` — a raw write that
bypasses the lifecycle engine and doesn't record a GateEvent. This was observed in
the meta-cc project (2026-07-25): DIR-001 ended in `needs-human`, the loop driver
attempted `lifecycle_retreat`, and was blocked.

The `needs-human` status exists precisely because the autonomous loop can't resolve
something. But the current lifecycle model treats it as a terminal state with no
automated exit path — even when:
- A human has resolved the issue externally (e.g., installed a missing dependency)
- The task should be re-triaged to `todo` for a fresh attempt
- A subsequent directive or milestone changes the conditions that caused the block

The `retreat` verb's existing semantics are one-step-back (done→ready, ready→todo).
Extending it to `needs-human→todo` (with a required `--reason`) is the natural fit:
the task is retreating to the initial state because the blocking condition has been
addressed.

## Proposal

Allow `lifecycle_retreat` to transition from `needs-human` to `todo`, with these
constraints:

1. **`--reason` is MANDATORY** for this transition (already required for all retreat
   operations). The reason is recorded in the GateEvent.
2. **The retreat records a GateEvent** with gate name `lifecycle:retreat` and the
   reason — preserving the audit trail of WHY the task was unblocked.
3. **No other outbound transitions from `needs-human`.** Only `needs-human→todo` is
   added. `needs-human→ready` and `needs-human→done` remain illegal (a task that
   needed human intervention should be re-evaluated from `todo`, not jumped forward).
4. **`complete` from `needs-human` remains illegal** (same reasoning).

### Legal transition matrix (updated)

```
todo → ready     (promote: todo→ready, dod gate)
ready → done     (complete: acceptance gate)
done → ready     (retreat --reason)
ready → todo     (retreat --reason)
* → needs-human  (any state, on gate failure or explicit adjudicate)
needs-human → todo  (retreat --reason)  ← NEW
```

### CLI

```
quay retreat DIR-001 --reason "missing pre_commit module installed; re-running"
```

Non-goals for v1:
- Automatic detection of when needs-human is resolvable
- Batch retreat of multiple needs-human tasks
- `promote` from needs-human (skipping todo) — a human can always use raw `task edit` for that edge case
