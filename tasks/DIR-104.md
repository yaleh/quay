## Finding

`quay gate --list` returns a flat list of registered gate names:

```
$ quay gate --list
dod
acceptance
doc-quay-directive-skill
```

This tells you WHAT gates exist, but not WHERE they came from or WHY a gate you
expect to see is missing. In the meta-cc vitest incident (2026-07-25), `gate --list`
showed only 3 built-in gates — the vitest gate declared in `.quay/gates.yml` was
invisible because config.yml's malformed `gates:` section silently shadowed it.
There was no way to diagnose this from the CLI; it took 3 separate Bash reads of
config files to understand the problem.

A verbose mode should show each gate's provenance (source file + line or "built-in"),
its type (it0/testPass/fixed/etc.), and any diagnostic warnings. This turns
`gate --list` from a name-dump into a diagnostic tool.

## Proposal

Add `--verbose` (short: `-v`) to `quay gate --list`:

```
$ quay gate --list --verbose
dod                    built-in     (acceptance)
acceptance             built-in     (acceptance)  
doc-quay-directive-skill  built-in  (doc)
vitest                 .quay/gates.yml:10  testPass  command: npx vitest run
tree-hygiene           .quay/config.yml:94  fixed  script: ./scripts/gates/tree-hygiene-check.sh
```

### Verbose output columns

1. **NAME** — gate name (as registered)
2. **SOURCE** — where the gate was defined:
   - `built-in` for `dod`, `acceptance`, `doc-*`
   - `<file>:<line>` for workspace gates (e.g., `.quay/config.yml:64`)
3. **TYPE** — gate factory type: `it0`, `adr`, `fixed`, `testPass`, `coverageFloor`, `redGreen`, `doc`, `acceptance`
4. **DETAIL** — type-specific summary:
   - `it0`: `script: <path> argsKey: <key>`
   - `testPass`: `command: <cmd>`
   - `fixed`: `script: <path>`
   - `coverageFloor`: `command: <cmd> floor: <N>%`
   - `redGreen`: `red: <cmd> green: <cmd>`
   - `adr`: `adr: <id>`
   - `doc`: `skill: <name>`
   - `acceptance`: `(runs task.extra.acceptance)`

### Diagnostic section

When gates are declared but NOT registered (shadowed, malformed, missing required
fields), append a `## Diagnostics` section below the gate list:

```
## Diagnostics (2 warnings)

WARNING: gate 'vitest' declared in .quay/gates.yml:10 as testPass but NOT registered
  — .quay/config.yml has a `gates:` section that takes precedence (DIR-050).
  — The config.yml gates section does not include a testPass entry for 'vitest'.
  — Fix: add vitest to config.yml's gates.testPass section, or remove the config.yml
    gates: section to restore legacy gates.yml behavior.

WARNING: it0 entry 'impl-row' at .quay/config.yml:65 missing required field 'script'
  — gate will not be registered. Required fields: name, script, argsKey.
```

### CLI

```
quay gate --list                  # flat name list (current behavior, unchanged)
quay gate --list --verbose        # table + diagnostics
quay gate --list -v               # short flag
quay gate --list --json           # current JSON format, unchanged
quay gate --list --json --verbose # JSON with source/type/detail/diagnostics fields
```

Non-goals for v1:
- Color-coded output (plain text columns, defer to a future `--color` flag)
- Interactive drill-down into a specific gate
