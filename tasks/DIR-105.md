## Finding

The quay-native task store's hardcoded creation default is `status: "todo"`:

```ts
// packages/quay-native/src/store.ts:125
const storeDefaultStatus = opts?.defaultStatus ?? "todo";
```

DIR-047 added the per-provider `default_task_status` config key as an override,
but deliberately kept the hardcoded fallback at `"todo"` — the design intent was
"human-release by default": new tasks sit invisible to the loop driver until a
human promotes them to `ready`.

In practice, both consuming workspaces (meta-cc, archguard) immediately set
`default_task_status: ready` — the auto-drive default is the natural fit for
autonomous-loop-driven projects. The `todo→ready` promote step is purely
mechanical (checking that Proposal/Plan/AC/DoD artifacts exist), and those
artifacts are authored at task creation time in the directive workflow. The
promote step adds friction without adding value when the task is created
complete.

The `quay init` generated template (`packages/quay/src/init.ts:81`) also
defaults to `# default_task_status: todo   # uncomment to...` — teaching new
users a default they will likely override.

## Proposal

Change the hardcoded creation default from `"todo"` to `"ready"`:

### Code changes

1. **`packages/quay-native/src/store.ts:125`**: `?? "todo"` → `?? "ready"`
2. **`packages/quay-native/bin/quay-native.ts:83`**: update comment "fall back to todo" → "fall back to ready"
3. **`packages/quay/src/init.ts:71,81`**: update template comments and the generated commented-out line to reflect `ready` as the default
4. **`packages/quay-native/test/default-status.test.mjs:96-100`**: update the backward-compat test — "no defaultStatus → 'todo'" becomes "no defaultStatus → 'ready'"

### Behavior change

| Scenario | Before | After |
|---|---|---|
| No `default_task_status` in config, create task without `--status` | `todo` | **`ready`** |
| `default_task_status: ready` in config | `ready` | `ready` (unchanged) |
| `default_task_status: todo` in config | `todo` | `todo` (unchanged) |
| Explicit `--status done` on create | `done` | `done` (unchanged) |

### Rationale

- **Auto-drive is the primary use case.** quay is designed for autonomous loop
  drivers; tasks are created by directives/workflows that produce complete
  Proposal/Plan/AC/DoD artifacts at creation time.
- **Opt-out, not opt-in.** Workspaces that want human-release can set
  `default_task_status: todo` — the knob already exists (DIR-047). The question
  is only which end of the knob is the default.
- **meta-cc + archguard precedent.** Both consuming workspaces independently
  chose `ready` as their default.
- **`quay init` teaches the right thing.** The generated template will document
  `ready` as the default and show `todo` as the override, matching real usage.

### Non-goals

- Changing the lifecycle model (`todo` remains a legal status)
- Removing the `todo→ready` promote step
- Changing `default_task_schema` (DIR-101 — separate concern)
