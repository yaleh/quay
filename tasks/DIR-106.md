## Finding

Concurrent milestone execution (OUTER-LOOP `concurrent_execute`, DIR-075/DIR-092) has never
triggered. All 14 milestones in the 2026-07-25 16:00–2026-07-26 04:00 UTC window (M153–M166)
ran serially. meta-cc session-history analysis identified three root causes, validated by
running `concurrent-batch-scheduler.ts` against the actual M153–M166 charter files:

### Root cause 1 (CRITICAL): `## Touches` annotations break glob matching

Charter authors (human and AI) naturally annotate touched files with parenthetical notes:

```markdown
## Touches
- experiments/.../select-preflight.ts (new)
- .claude/workflows/select-preflight.js (new)
- experiments/.../OUTER-LOOP.md (rewrite steps 1-3)
```

`parseTouches()` extracts these verbatim: the glob `select-preflight.ts (new)` matches zero
files because `globToRegExp` escapes `(` `)` as `\(` `\)`, producing a regex that matches a
file literally named `select-preflight.ts (new)` — which does not exist. `expandGlobs`
returns empty for every annotated glob, triggering the conservative "ill-declared touches"
deferral for ALL 14 charters.

**Evidence**: running the scheduler against the raw M153–M166 charters produces `BATCH
(0-wide, concurrent): (none)` — every candidate is deferred with "globs matched nothing
(empty expansion — likely a typo)".

### Root cause 2 (HIGH): SELECT produces a single candidate per cycle

The OUTER-LOOP `select` function returns the top-ranked ready task. `batch_assemble` is
called with ONE charter, so `|batch|` is always ≤ 1 and `concurrent_execute` (which gates
on `|B| ≥ 2`) is never reached. The `concurrency: 4` setting in `.quay/loop.yml` is
honored nowhere in the actual SELECT→EXECUTE pipeline.

### Root cause 3 (MEDIUM): Directory-level globs with trailing `/` don't match files

`milestones/M155/` (trailing `/`) produces regex `^milestones/M155/$` which matches the
literal directory string, not `milestones/M155/report.md`. Similarly `tasks/` matches
nothing. Charter authors write `milestones/M155/` intending "files under that directory"
but the scheduler sees an exact string match against a non-existent path.

### Validation: simulated fix against M153–M166

With Fix 1 alone (strip annotations from parsed globs):

```
BATCH (10-wide): M153, M154, M157, M158, M159, M160, M161, M163, M164, M165
  deferred: M155 — directory globs (milestones/M155/, tasks/) expand empty
  deferred: M156 — genuine overlap with M154 (both touch execute-milestone.js)
  deferred: M162 — touches shared state (dashboard.md)
  deferred: M166 — genuine overlap with M153 (both touch OUTER-LOOP.md)
```

10 of 14 charters are batchable. With all three fixes, the 14-milestone window projects
to 6 rounds (4 concurrent batches + 2 serial) instead of 14 — **~2.3× throughput**.

## Requested action

### Fix 1 (CRITICAL): Strip parenthetical annotations from Touches globs

**File**: `plugin/scripts/touches-orthogonality-check.ts` — `parseTouches()`

After extracting the glob from a bullet line, strip trailing `(<text>)` annotations:

```typescript
// In the bullet-extraction loop, after stripping backticks and ./ prefix:
g = g.replace(/\s*\([^)]*\)\s*$/, '').trim();
// "select-preflight.ts (new)" → "select-preflight.ts"
// "OUTER-LOOP.md (rewrite steps 1-3)" → "OUTER-LOOP.md"
// "packages/quay/test/init.test.mjs (new)" → "packages/quay/test/init.test.mjs"
```

Also update the existing `parseTouches` unit tests to cover annotated glob inputs;
verify that annotation-bearing bullets are cleaned before expansion.

### Fix 2 (HIGH): SELECT N candidates at once, capped at concurrency

**Files**: `experiments/quay-perpetual-stream/OUTER-LOOP.md` step 1 (select function),
`plugin/skills/select-preflight/SKILL.md` (or `.claude/workflows/select-preflight.js`
if the skill delegates to a workflow)

The `select` function currently returns the single top-ranked candidate. Change it to
return a ranked shortlist of up to `.quay/loop.yml`'s `concurrency` value (default 4).
`batch_assemble` already accepts multiple candidates — it just never receives ≥ 2.

The `concurrent_execute` path already gates on `|B| ≥ 2`; a 1-wide result falls through
to the existing serial path unchanged. No new dispatch code is needed — the OUTER-LOOP.md
`concurrent_execute` function (DIR-092) already defines the dispatch + fan-in sequence.

### Fix 3 (MEDIUM): Normalize trailing-slash directory globs

**File**: `plugin/scripts/touches-orthogonality-check.ts` — `parseTouches()`

For globs that end with `/` and contain no wildcard (`*`, `?`), append `**`:

```typescript
if (g.endsWith('/') && !/[*?]/.test(g)) {
  g += '**';  // "milestones/M155/" → "milestones/M155/**"
}
```

`isOverbroadDeclaration('milestones/M155/**')` returns `false` (2 concrete segments
before `**`). `tasks/` → `tasks/**` IS overbroad (1 segment) and will still be deferred
by the conservative gate — correct behavior since `tasks/` is de facto shared state. If
a charter genuinely needs to declare "new tasks only" for batch compatibility, a future
follow-up can add a `(new tasks only)` annotation convention (out of this directive's
scope — see Non-goal).

### Fix 4 (LOW): Log batch assembly diagnostics

**File**: `experiments/quay-perpetual-stream/OUTER-LOOP.md` step 1

After `batch_assemble`, emit the result and deferral reasons to the loop log so the
operator can see why concurrency is (or isn't) happening. Currently the scheduler output
is consumed but not surfaced; a 0-wide result silently falls through to serial.

### Non-goal

- Do NOT restore Workflow-internal dispatch (DIR-074 background Build agent). The loop's
  fix to use inline Build is correct. Concurrency comes from N simultaneous workflows
  dispatched from the MAIN session, not from dispatch within a workflow.
- Do NOT change `tasks/` handling beyond the existing conservative gate. `tasks/` IS
  shared state; batching milestones that both create task files requires a separate
  annotation convention (follow-up directive).
- Do NOT add new dispatch code. DIR-092 already defines `concurrent_execute` with
  anti-drift + fan-in. The fixes here are about PRODUCING `|batch| ≥ 2` so that path is
  reached for the first time.

## Proposal

The concurrent execution infrastructure (DIR-075/DIR-092) is architecturally correct:
dispatch N workflows from the main session, each doing inline Build in its own worktree,
fan-in with anti-drift check. The problem is upstream: the SELECT step never produces a
multi-candidate batch, and even if it did, the Touches parser can't read the annotations
charter authors naturally write.

Fix the parser to handle real-world charter annotations. Fix SELECT to produce a pool of
candidates. The existing `concurrent_execute` path then fires for the first time.
