## Finding

The DIR-075 wiring audit (2026-07-26) found four pre-existing gaps in the concurrent
execution path. None block a 1-wide serial run, but the first pair make a real ≥2-wide
concurrent batch UNSAFE — they must be fixed BEFORE `.halt` is removed to let the loop
attempt concurrency.

### Root cause (Gaps 1+2): concurrent Land phase merges to master itself

`plugin/workflows/execute-milestone.js` IS_CONCURRENT Land phase (line ~258) step 1 is
"MERGE the iteration worktree into master". This contradicts DIR-092's design intent: if
N concurrent workflows each merge their own worktree into master, that IS the shared-state
collision the design was built to avoid — N workflows writing the git index concurrently
is a race.

This single design flaw produces two audit findings:

1. **Land-merge-vs-fan-in-merge spec conflict**: `execute-milestone.js` merges in Land step 1;
   OUTER-LOOP.md `concurrent_execute` step f says "merge each survivor one at a time in plan
   order". Two components claim merge ownership. The fan-in merge step is unreachable (the
   branch was already merged + pruned by the workflow).

2. **Safety sequencing gap**: the anti-drift check (`concurrent_execute` step d) is labeled
   NON-WAIVABLE but runs AFTER the workflow Land phase already merged into master. A
   cross-build overlap is caught POST-merge — master is already tainted when the guardrail
   fires. The check is post-hoc detection, not a pre-merge gate.

### Gap 3: concurrent fan-in has no audit-independence gate

`execute-milestone.js` line ~203: "audit-indep gate removed from Workflow per DIR-097, runs
at fan-in ABSORB". The serial path's inline ABSORB runs the 7 absorb gates including
audit-independence. But OUTER-LOOP.md `concurrent_execute` fan-in steps (d-h) do NOT include
any audit-independence check. For concurrent batches, a self-audited milestone (DIR-032/034
forgery) could merge unverified.

### Gap 4: `|batch| = 0` dispatch branch undocumented

Dispatch logic covers `execute where |batch|=1` and `concurrent_execute where |B|≥2` but not
`|batch|=0` (empty shortlist, or all candidates deferred). Behavior is implicit (no-op →
routines), not an explicit branch — an operator cannot tell "nothing selected" from a bug.

## Requested action

Driver-rewrite (touches `execute-milestone.js`, `OUTER-LOOP.md`, gate scripts) →
`label:human-steered`. Execute under `.halt` off-loop.

### Fix 1+2: Move merge ownership from workflow Land to fan-in

In `execute-milestone.js` IS_CONCURRENT Land branch:
- REMOVE step 1's "MERGE the iteration worktree into master".
- REPLACE with: `git commit` the build in its OWN worktree branch; LEAVE the branch (do NOT
  merge, do NOT prune). Prune happens at fan-in after a successful merge.
- ADD `buildBranch: "<branch name>"` to the return schema (input to the fan-in merge plan).
- KEEP `touchedFiles` (from `git diff --numstat`) and `dashboardEntry` — unchanged.
- The serial path (mode absent/"serial") is UNCHANGED — it still merges + counter++ inline.

In `OUTER-LOOP.md` `concurrent_execute`:
- Step d (anti-drift) now genuinely runs BEFORE any merge — it is a pre-merge gate.
  HARD FAIL → abort the batch, diagnose, master stays clean.
- Step f (merge each survivor serially) becomes the SOLE merge owner, consuming
  `buildBranch` from each survivor's result. Prune each branch after its merge.

### Fix 3: Add audit-independence gate to concurrent fan-in

In `OUTER-LOOP.md` `concurrent_execute`, add a pre-merge sub-step alongside anti-drift:
- ∀survivor: verify the workflow's audit session ID ≠ its build session ID (DIR-032/034
  anti-forgery). Use the existing audit-independence check (inline verification per DIR-093).
  Any survivor failing → route to `needs-human`, EXCLUDE from fan-in (partial-batch: the
  independent survivors still land).

### Fix 4: Document the empty-batch dispatch branch

In `OUTER-LOOP.md`, make the dispatch cardinality explicit:
```
dispatch(batch) =
  |batch| = 0 → log("no batchable candidates; N deferred → next pool") → routines()
  |batch| = 1 → execute(serial)
  |batch| ≥ 2 → concurrent_execute
```

### Non-goal

- Do NOT remove the serial path or change its merge/counter behavior.
- Do NOT restore Workflow-internal Build dispatch (DIR-092: Build stays inline).
- Do NOT weaken anti-drift — it stays NON-WAIVABLE, now correctly sequenced pre-merge.

## Proposal

The concurrent path's Land phase was written to mirror the serial path (which merges inline),
but that mirroring is exactly wrong for concurrency: N inline merges race on master, and the
fan-in's anti-drift + merge steps become dead code. Invert the ownership — workflows produce
committed branches + metadata, the single-threaded fan-in owns anti-drift (pre-merge) and the
merges (serial). This makes anti-drift a real gate and gives the fan-in one clear job.

Fixes 3 and 4 close the remaining verification and observability gaps so a concurrent batch
is gated as strictly as a serial one.
