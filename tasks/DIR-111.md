## Finding

ADR-019 decision item 5: two real "e2e" categories exist outside `node:test` entirely — packaging
e2e (the `dist-verify-node-floor` CI job: builds the real tarball, installs it, runs it on the
declared Node floor) and browser/agent-driven e2e (ADR-010, milestone-cadence, MCP-tool-driven,
`status: proposed`/enforcement `deferred`). Neither is currently labeled as distinct from the
`node --test` suite in the places a reader would naturally look (`ci.yml`, `CLAUDE.md`), so a green
test run can be mistaken for covering either.

## Requested action

1. Add a clarifying comment to `.github/workflows/ci.yml`'s `dist-verify-node-floor` job naming it
   explicitly as packaging e2e — build+install+run the real distributed artifact, not a
   `*.test.mjs` suite.
2. Add a short note to `CLAUDE.md` (Commands or Process section) stating plainly that
   browser/agent-driven e2e (ADR-010) is a milestone-cadence manual/agent process, not covered by
   `scripts/test.sh` or any other automated command, with a pointer to `adr/ADR-010-...md`.

## Acceptance Criteria

- [ ] `.github/workflows/ci.yml`'s packaging-e2e job carries an explicit comment naming it as such
- [ ] `CLAUDE.md` documents the browser/agent e2e category with an explicit pointer to ADR-010,
  placed near (not folded silently into) the Commands section's test-invocation documentation
- [ ] `grep -n "ADR-010" CLAUDE.md` returns a hit (mechanical evidence the pointer exists)

## Definition of Done

- [ ] Both edits committed
- [ ] A fresh reader can `grep` `CLAUDE.md`/`ci.yml` and immediately tell which test categories
  are, and are not, covered by the canonical `scripts/test.sh` command

## Proposal

Small, low-risk documentation fix that closes the last gap in ADR-019's taxonomy: the categories
that were never going to be mechanically enforceable (real distribution artifacts, real browser
sessions) still need to be named honestly rather than silently absent from the discussion.
