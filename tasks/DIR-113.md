## Proposal

把并发批次调度的 touches-orthogonality 预检，从"charter-authoring 之后"前移到"charter-authoring
之前"。当前流程是先花一次 LLM/fork 调用把每个候选的 `## Touches` 写进 charter（昂贵），再用
`checkTouchesPair`（纯函数、近零成本）去判断是否正交（便宜）——顺序反了：便宜的检查应该先跑，替
调度器筛掉明显不该批的候选，避免为注定被丢弃的 charter 付费。

## Plan

N/A — directive resolved via a milestone; no staged design doc needed. 方案形状已在讨论中定型：
(1) 一个机械式 Touches 抽取脚本 + 软性 schema 检查；(2) `select-preflight.ts` 在派发
charter-authoring fork 之前先跑一遍粗筛；(3) 把当前 11 个自主可选候选补上真实 `## Touches`；(4)
`anti-drift-touches-check.ts` 的 PRE-MERGE 权威门保持不变。

## Finding

1. **当前 11 个自主可选候选任务（DIR-099/100/101/103/104/105/109/110/111/112、
   exp5-ADR-TOOLSEARCH-DEFERRED-SCHEMA-PATTERN）里，0 个在任务本体声明了 `## Touches`**——只有
   DIR-070-F 和 DIR-073 声明了，但这两个都不在自主可选池里（分别是 human-steered 和
   needs-human）。核对方式：`grep -q '^## Touches' tasks/DIR-NNN.md`，逐个跑过。
2. **`## Touches` 目前只在 charter-authoring 阶段临时生成**——M173 实测单个候选耗时 5m2s（fork
   `SELECT step: charter + batch_assemble for M173`）；而 `concurrent-batch-scheduler.ts` 的正交性
   判定（`checkTouchesPair`，纯函数、O(候选数²) 字符串比较，近零成本）只能在 charter 文本已经存在
   之后才能跑。
3. **真实案例（M173, 2026-07-26）**：SELECT preflight 从候选池选出 DIR-070/DIR-109/DIR-110 三个
   （排除了被机械分类器漏放的 DIR-057 之后），fork 花 5m2s 给三个都写了 charter，写完才发现：
   DIR-110 依赖 DIR-109 自己要新建的 `scripts/test.sh`（DIR-109 任务体自己写着"DIR-110 ...
   depends on this directive's `scripts/test.sh` existing"）；DIR-070 是个 epic，唯一未完成子任务
   DIR-070-F 带 `label:human-steered`。批次收窄成 1-wide serial（只剩 DIR-109），三份 charter 的
   成本只有一份真正被用上。
4. **`.quay/loop.yml` 的 `concurrency: 4` 从 M167（DIR-107 落地并发 fan-in 安全机制：merge 所有权
   移到 fan-in、audit-independence + anti-drift 前置门）就开始生效，但到 M173 为止，并发路径从未
   真正产出过 ≥2-wide 批次**——机制空转了至少 7 个里程碑（M167→M173）。
5. **信息本身通常已经在任务的 prose 里了**：DIR-109 charter 最终生成的 Touches 列表
   （`scripts/test.sh` + 3 个测试文件 + `CLAUDE.md` + `.github/workflows/ci.yml`），跟它自己
   `## Requested action`/`## Acceptance Criteria` 里点名的文件几乎逐字重合——结构化这份信息不需要
   新调查，只是格式搬运。
6. **已有的安全网足以覆盖"提前声明不准"的风险**：`anti-drift-touches-check.ts`（DIR-107 的
   PRE-MERGE 硬性门，NON-WAIVABLE）会在真正合并前拿 `git diff --numstat` 核对实际改动文件跟声明
   是否一致，跟这次改动完全独立、不受影响——任务级 Touches 提前声明即使不精确，最坏后果是调度偏
   保守（少并发一次），不会让脏数据合并进 master。

## Requested action

1. 新增一个机械式/启发式 Touches 抽取脚本（如
   `experiments/quay-perpetual-stream/scripts/derive-touches-heuristic.ts`）：DRAIN 把一个
   directive disposition 成 milestone-candidate 时，若任务体没有 `## Touches`，从
   `## Requested action`/`## Acceptance Criteria` 里用正则识别形如文件路径的 token，自动生成一段
   标注为 "auto-derived, unverified" 的 `## Touches`。
2. 在 milestone-candidate 的 schema 检查（`task-schema-check.ts`/`.sh` 或等价位置）加一条**软性**
   （warn，不 fail-closed）检查：milestone-candidate 任务既没有人工声明也没有 auto-derived 的
   `## Touches` 时给出警告，不阻断流程。
3. 把 `select-preflight.ts` 的 shortlist 组装步骤改成：在派发 charter-authoring 之前，先用现成的
   `checkTouchesPair` 对 shortlist 里的候选（任务级 Touches，人工声明优先，auto-derived 兜底）两两
   粗筛一遍，主动把正交组合往前排；粗筛结果必须显式记录到日志/dashboard——不管是"发现可并发的正交
   对"还是"top-N 里没有正交对"，都要打印，不能沉默。
4. 把当前 10 个自主可选 directive（DIR-099/100/101/103/104/105/109/110/111/112）+
   exp5-ADR-TOOLSEARCH-DEFERRED-SCHEMA-PATTERN 补上真实（人工/LLM 复核过，不是纯 auto-derived）
   的 `## Touches`，复用 DIR-070-F/DIR-073 已经验证过的格式。
5. `anti-drift-touches-check.ts` 的 PRE-MERGE 硬性门保持不变、不做任何调整——任务级 Touches 只是
   调度阶段的提示信号，永远不能替代这道权威门。
