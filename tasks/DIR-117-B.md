**Key design decisions.**

- *CLI-dispatch, not import, for the wiring check.* Workflow scripts cannot import (sandboxed/resumable); the agent-dispatched `node --experimental-strip-types` call is the same pattern the Receipt and Prepared phases already use — no new mechanism class introduced — and keeps the call site grep-confirmable in a plain-text workflow file.
- *Extend `wiring-coverage-check.ts` with the CLI, never duplicate into `milestone-preparation-check.ts`.* The wiring module is the single production source DIR-122 already calls; duplicating its claim-extraction recreates the two-implementations drift DIR-122's AC forbids.
- *Findings enter the ledger as BLOCKING via the script's own `_upsertFindings` path, not reviewer judgment.* An uncovered mechanism claim is one of DIR-125's enumerated blocking categories ("missing production callsite/ownership enforcement" / "a new behavior with no falsifiable AC"), consistent with the typed-ledger contract, and hash-binding into the receipt comes free; a false positive clears only via explicit ledger disposition (e.g. `accepted-risk`), never silently.
- *Fail-closed reason `preparation-receipt-missing` reuses the existing `revision-needed` outcome, not `needs-human`.* A missing receipt is a caller-fixable shape error semantically identical to a stale receipt; `needs-human` is reserved for human-decision terminals.
- *The flip is uniform at the args level.* Missing param fails closed for every dispatch shape including DIR-119-B composites (which supply a primary-task receipt); no carve-out, because a carve-out recreates the back-compat hole this milestone exists to close.
- *M195 prepares itself.* The M193/M194 prepare-skip precedent is explicitly inapplicable (charter §"Why this milestone does NOT skip prepare-milestone"): the skip exists for tasks already carrying review-derived Proposals; here it would destroy the milestone's own primary evidence.

**Defaults and failure behavior.** After the flip, every `execute-milestone.js` dispatch defaults to: receipt required, checker must exit 0, else `revision-needed` at phase `Prepared` before any Build work. Stale proposal/charter/plan/source/ledger hashes, N/A Plan, touch-set expansion, and a missing parameter all fail closed with distinct actionable codes (existing per-reason codes plus `preparation-receipt-missing`). A wiring verdict with uncovered claims → blocking ledger findings → DIR-125 convergence caps apply (delta-round cap/budget exhaustion → `needs-human`, never silent retry). The wiring sub-step failing to return parseable output (agent crash, CLI exit 2) fails the ProposalReview phase closed (`needs-human`, mirroring the existing revise-failed path) rather than silently skipping coverage. Receipt self-check failure → existing `{outcome:"revision-needed", reason:"receipt-selfcheck-failed", phase:"Receipt"}` behavior, unchanged.
