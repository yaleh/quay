## Proposal

Introduce a non-bypassable, post-Land wiring-verification lifecycle for changes whose correctness
depends on being reached through a real runtime path. Keep the existing in-workflow Acceptance Audit
focused on task AC/DoD, but make it read-only and distinguish its verdict from proof that the change
is operationally wired.

The lifecycle becomes:

```text
Verify → Build → Acceptance Audit (read-only) → Gate → Land
       → Post-Land Wiring Audit (fresh runtime generation)
       → Reconcile → lifecycle promotion
```

`execute-milestone` must stop after Land in an explicit `landed-awaiting-wiring` state whenever the
task's verification contract requires wiring proof. `OUTER-LOOP` then cold-dispatches a separate
`wiring-audit` workflow from a content-addressed `scriptPath`, not a cached workflow name. Only a
mechanical reconciler may write checkboxes, ABSORB dispositions, deviation rows, and lifecycle
state after it has validated the wiring-audit receipt.

### Verification contract

Add a machine-readable verification contract to the selected task/charter preparation artifacts.
It must declare:

- changed surfaces and expected consumers;
- runtime entrypoints and normal triggers;
- tests that must be discovered by the canonical runner;
- required post-Land evidence such as a real workflow journal, CI/release/install run, negative
  control, or cross-milestone observation;
- whether the change touches the active workflow/auditor/gate and therefore requires proof from a
  later runtime generation;
- the source files and workflow hashes the auditor must inspect.

The contract is a verification manifest, not a duplicate source of task requirements. The task
AC/DoD and checked milestone Plan remain authoritative; the manifest records how their wiring claims
will be disproved or confirmed.

### Runtime-generation boundary

Every workflow journal and audit receipt must record the workflow source path, source commit/hash,
dispatch form (`scriptPath` versus `name`), materialization time, parent session id, and runtime
generation id. If a milestone modifies a workflow, audit prompt, runner, gate, or reconciler that
participates in its own execution, that same runtime generation cannot provide final wiring proof.
The task remains `landed-awaiting-wiring` until an unrelated later milestone or an explicitly cold
new-generation replay exercises the checked-in version.

### Test-discovery completeness

Add a mechanical test-discovery completeness check. Every repository test file must either:

1. be reached by the canonical `scripts/test.sh` runner and therefore by CI; or
2. carry a machine-readable classification such as live/manual/platform-specific, with an explicit
   skip condition and owning trigger.

An unclassified or orphaned test must fail CI. This closes the M172/DIR-108 failure mode where a
real, failing `plugin/test/plugin-packaging.test.mjs` existed but Build, internal Audit, and CI all
used a glob that never selected it.

### Wiring-audit profiles

Productize the successful DIR-108 external audit as checked-in wiring-audit profiles. Select
profiles from the verification contract and `## Touches`, covering at least:

- workflow/driver adoption;
- canonical-test/CI reachability;
- packaging, release, and fresh-install paths;
- consumer and mirrored-artifact drift;
- normal-trigger versus manual-trigger evidence;
- negative controls and recurrence of the original defect one layer downstream.

Profiles supplement rather than replace task-scoped Acceptance Audit.

### Lifecycle states and evidence ownership

Distinguish at least:

- `implementation-complete`;
- `landed-awaiting-wiring`;
- `wired`;
- `operationally-proven`.

These may be recorded in derived milestone receipts rather than expanding the provider-wide task
status enum, but `done` promotion must require every verification class mandated by the contract.
The auditor produces an immutable verdict/evidence receipt and must not mutate the task it grades.
A separate deterministic reconciler validates hashes and evidence, performs write-back, and invokes
the existing lifecycle gate.

### Alternatives considered and rejected

- **Only lengthen the current Acceptance Audit prompt:** rejected. It remains pre-Land, shares the
  active runtime generation, and cannot observe later CI, cold-start adoption, or cross-milestone
  effects.
- **Treat green unit tests as wiring proof:** rejected. M172 demonstrated that a test can exist yet
  be unreachable from both the canonical runner and CI.
- **Treat a fresh-context subagent as a fresh runtime generation:** rejected. Fresh conversation
  context can still share workflow caches, session identity, workspace state, and the code snapshot
  being audited.
- **Let the auditor perform checklist/disposition write-back:** rejected. This mixes producer,
  evaluator, and reconciler roles and permits same-turn self-completion evidence.
- **Require every task to run every wiring profile:** rejected. The verification contract selects
  profiles by touched surface; ordinary leaf changes should not pay release/install audit cost when
  those paths are irrelevant.

## Finding

meta-cc analysis of the last 24 hours found a repeatable gap between task-scoped acceptance and
system-level wiring:

1. M172/DIR-108's internal workflow Audit independently confirmed all 9 AC and 7 DoD items,
   including real CI, fresh clone, MCP, and local fallback evidence. It did not inspect
   `plugin/test/plugin-packaging.test.mjs`.
2. A separately dispatched, explicitly wiring-focused audit found that test file still encoded the
   opposite, pre-DIR-108 invariants and failed reproducibly. Build, internal Audit, and CI all used a
   test glob that excluded `plugin/test/`, so no automated gate could observe the contradiction.
3. M175 and M177 showed that correct checked-in workflow code is not sufficient evidence that a
   real `Workflow()` invocation adopted it.
4. Same-session `Workflow({name: ...})` dispatch can reuse a stale materialized script; checked-in
   source and running workflow generation can diverge.
5. M178-M180 showed that an Audit can compute valid verdict/V_meta/surface information without
   writing it into the artifact consumed by the following gate, and that a milestone exercising its
   own fix in the same Audit turn is self-referential proof.
6. M181 finally supplied valid evidence for M180 because an unrelated real milestone exercised the
   checked-in disposition-append behavior and passed the gate in a later run.
7. The current `execute-milestone` Audit prompt is bounded by task AC/DoD and runs before Land. It
   also asks the same auditor to tick task checkboxes, append ABSORB dispositions, update the
   deviation log, and stage its audit artifact. Fresh context therefore does not provide separation
   between evaluator and state reconciler.

The missing mechanism is not another prose reminder to “check wiring.” It is a lifecycle boundary
that makes post-Land, next-generation, system-level wiring evidence a prerequisite for `done`.

## Requested action

1. Add a checked-in `wiring-audit` workflow and wiring-audit profiles covering workflow adoption,
   test/CI reachability, packaging/install/release paths, consumer drift, normal triggers, and
   negative controls.
2. Add a machine-readable verification contract and a checker that derives required profiles from
   task/charter `## Touches`, checked Plan, and declared consumers/entrypoints.
3. Record content-addressed runtime-generation provenance in workflow journals and receipts. Reject
   final proof from the same generation when a task changes its own workflow/auditor/gate/runner.
4. Change `execute-milestone` so its Acceptance Audit is read-only and returns immutable evidence.
   It may Land implementation, but wiring-required tasks return `landed-awaiting-wiring`, never
   `done`.
5. Change `OUTER-LOOP` to cold-dispatch post-Land Wiring Audit via the checked-in `scriptPath` and
   verified source hash, then invoke a separate deterministic reconciler for checklist, ABSORB,
   deviation-log, and lifecycle write-back.
6. Add a test-discovery completeness checker and wire it into `scripts/test.sh` and CI. Every test
   must be discovered or explicitly classified with an owning trigger.
7. Add fixtures/mutation tests for the observed failures: orphaned test file, stale consumer
   assertion, CI glob omission, cached old workflow source, same-generation self-proof, missing
   post-Land journal, and an auditor attempting to mutate the graded task.
8. Prove the mechanism on one unrelated real milestone. The durable record must show Land,
   `landed-awaiting-wiring`, a cold later-generation Wiring Audit, negative-control evidence,
   mechanical reconciliation, and final lifecycle promotion in that order.
9. Consume DIR-124-B's canonical RunIdentity, FindingEnvelope, and StageReceiptEnvelope. Wiring
   findings record observer stage, `earliestDetectableStage`, recurrence/generalization, evidence
   references, and material hashes; this task must not create a second receipt/finding schema.
10. Run cheap deterministic post-Land lifecycle checks before dispatching the content Wiring Audit.
    A mechanical failure terminates with a receipt and spends zero Wiring-Audit agents.
11. Keep lifecycle promotion and detector promotion separate. Wiring Audit may emit a detector
    candidate, but profile/global fail-closed activation follows DIR-124-D authorization and the
    independently executable calibration task; the wiring auditor cannot activate its own rule.

## Definition of Done

Standard `experiments/quay-perpetual-stream/inherited-core.md` DoD clauses apply, including
adversarial acceptance audit, V_meta consolidation-lag, line budget, test floor, tree/worktree
hygiene, split-or-commit, and audit independence. Per DIR-026 Reading A, source code, prompt text,
fixtures, same-generation self-tests, or a manually invoked audit are necessary but insufficient.
Done ONLY when:

- [ ] The verification contract/checker, content-addressed runtime-generation provenance,
  read-only Acceptance Audit, post-Land Wiring Audit, deterministic reconciler, test-discovery
  completeness gate, plugin/runtime mirrors, and OUTER-LOOP ordering are committed and independently
  audited under human-steered discipline.
- [ ] `scripts/test.sh` and real CI both execute the test-discovery gate and wiring-audit regression
  suite; deliberately orphaning a test in a controlled negative replay fails both before promotion.
- [ ] One unrelated REAL milestone—not DIR-118 itself and not a scratch/fixture task—has crossed
  the installed Land → `landed-awaiting-wiring` → later-generation Wiring Audit → reconcile →
  promote path with immutable journals and matching hashes.
- [ ] That real run demonstrates at least one substantive negative control and proves normal runtime
  reachability, not merely direct invocation of the new checker or audit script.
- [ ] A separately dispatched fresh-context wiring auditor, given only primary artifacts, confirms
  the real route and finds no bypass. Its verdict is reconciled mechanically; it does not edit its
  own graded task or evidence.
- [ ] `DIR-118` remains `dirStatus: pending` and is not promoted to `done` until all preceding
  evidence exists. If implementation spans multiple milestones, none may claim this DIR resolved
  until the final real cross-generation proof lands.

## Human verification when exp5 marks this DIR done

1. Can a wiring-required task reach `done` after Build/Acceptance Audit but before a later-generation
   Wiring Audit? Any yes means DIR-118 is not done.
2. Does the real proof come from an unrelated milestone or genuinely cold generation whose executed
   workflow hash matches the checked-in source?
3. Does CI fail if any test becomes undiscovered, including tests outside `packages/*/test/`?
4. Is the wiring auditor read-only, with all state mutation owned by a separate reconciler?
5. Does the real evidence prove a normal entrypoint/trigger and include a negative control rather
   than only a direct checker invocation?
6. Can any alternate workflow, CLI, MCP, or low-level status-write path bypass the wiring receipt?
   Any ungoverned path keeps the directive open.
