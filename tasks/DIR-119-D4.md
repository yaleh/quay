## Proposal

Insert a literal `Reconcile` phase into `meta.phases` between Gate and Land that is the ONLY phase
permitted to write task AC/DoD ticks, status, dashboard rows, and absorb dispositions for a
composite dispatch, and fix Gate's failure-attribution branch to name the specific failing member
task(s) instead of hardcoding `_primaryTaskId`. Fourth child of DIR-119-D's split — these two
mechanisms are combined into one child because Reconcile's own contract requires the complete typed
gate vector (task + milestone scoped) as input, so the Gate-side typing fix and the Reconcile-side
consumer are one coupled unit of work, not two independently landable mechanisms. Depends on
DIR-119-D3's Audit output (`BundleAuditResult`).

### Problem framing (re-verified against current tree, 2026-07-29)

There is no `Reconcile` phase anywhere in `execute-milestone.js`'s six phases. `composite-reconcile.ts`
is referenced only by `composite-land.ts`'s type-only import, reachable only through a `--selftest`
guard in production. Gate-phase failure attribution is confirmed broken for composite batches by
direct inspection: Gate already dispatches one real per-task check with a distinct per-member label
(`split-or-commit-${tid}`, genuine, from DIR-119-B/M189) but its failure branch discards which of
the N per-task results actually failed and always names only the primary task id, identically in
both mirrors. This did not trigger during M-DIR119-C-CANARY (all 7 gates passed), so the real run
never exercised this branch — the exact blind spot this child closes.

## Chosen mechanism

**Typed Gate results.** Gate closures change return shape, not check set: each task gate returns
`{scope:"task", taskId, gate, ok, detail}` and each milestone-scoped gate returns
`{scope:"milestone", gate, ok, detail}` — the existing `split-or-commit-${tid}` label stays present
as observability metadata but is no longer the thing attribution parses; identity is a structural
field.

A new `attributeGateFailures(gates, taskIds)` export on `composite-reconcile.ts` partitions the full
typed vector into `failedTaskIds`/`passingTaskIds` plus separately-reported milestone-scoped
failures; `_primaryTaskId` gets no special treatment and is marked only if it is itself among
`failedTaskIds`.

**Literal Reconcile phase.** Inserted into `meta.phases` between Gate and Land — strictly after Gate
because the existing `reconcile()` contract requires the complete task-and-milestone gate vector as
input. Add non-selftest `--reconcile-json` (wraps the existing, already-exported `reconcile()`,
currently reachable only via `--selftest`) and `--attribute-gates-json` modes to
`composite-reconcile.ts`.

`reconcile()` checks the Build generation ID, complete shard verdicts (from DIR-119-D3), the full
task+milestone gate vector, and exact membership, then returns either the complete success mutation
plan or zero mutations plus a deterministic failure disposition.

A single `reconcile-apply` agent is the ONLY writer in the composite path: on success it applies the
returned complete set of AC/DoD ticks, status changes, absorb dispositions, deviation/write-back
rows, and the consolidated audit artifact, using pre-image/rollback or equivalent all-or-nothing
staging; on any generation/shard/gate/contract failure it applies zero mutations and returns only
the deterministic recovery record.

Given `landPolicy:"atomic"`, a single member failure still blocks the whole bundle from landing —
this is attribution fidelity and recoverability, not a change to atomicity semantics (Land stays
Reconcile's downstream validator, DIR-119-D5's own scope).

### Key design decisions

- **Reconcile is strictly downstream of Gate**, because its existing contract requires the complete
  typed gate vector to decide attribution.

- **Gate identity is typed, never positional/label-parsed for control decisions.** Attribution reads
  structured `{taskId, ok}` records; the `split-or-commit-${tid}` label remains a practical
  correlation key at the journal-evidence layer only.

- **Rollback failure mid-`reconcile-apply`** — mitigated by pre-image capture, transaction
  validation before any edit, all-or-nothing staging, and an inspectable `needs-human` state (never
  a partial success) if final checks or the commit fail.

### Risks and mitigations

- **State-owner ambiguity** if Audit prompts retain any residual write-instruction language — closed
  by DIR-119-D3's own structural grep AC; this child's own AC additionally confirms
  `reconcile-apply` is the ONLY agent in the entire workflow whose prompt instructs the listed
  writes for a composite dispatch.

### Non-goals

No Land/atomicity-transaction wiring (DIR-119-D5's own scope — Reconcile decides, Land validates and
commits). No partial Land under any circumstance — rejected by the existing `landPolicy:"atomic"`
invariant; passing-member identity is recovery information for the human, not authorization to land
part of a bundle.

## Finding

`.claude/workflows/execute-milestone.js`'s Gate phase: `const gatesFailed =
gates.filter(Boolean).some(g => !g.ok); if (gatesFailed) { await agent(\`Mark task ${_primaryTaskId}
needs-human...\`) }`. Regardless of which of N member tasks' own `split-or-commit-${tid}` gate
actually failed, only `_primaryTaskId` is marked `needs-human`; there is no per-task failure
identification. `composite-reconcile.ts`'s `reconcile()` is real and tested but has zero production
callsites — reachable only via `--selftest`.

## Requested action

1. Change Gate closures (both mirrors) to return typed `{scope, taskId/none, gate, ok, detail}`
   records instead of untyped pass/fail.
2. Add `attributeGateFailures(gates, taskIds)` export to `composite-reconcile.ts` (+ `plugin/scripts/`
   mirror).
3. Add non-selftest `--reconcile-json`/`--attribute-gates-json` CLI modes to `composite-reconcile.ts`.
4. Insert a literal `Reconcile` phase into `meta.phases` (both mirrors) between Gate and Land;
   dispatch a `reconcile-apply` agent that is the ONLY agent instructed to write task/dashboard/
   absorb state for a composite dispatch.
5. RED/GREEN fixture: a synthetic ≥2-task composite where one member's gate deliberately fails must
   produce a needs-human record naming that specific member, not `_primaryTaskId` by default; a
   passing-gates run reaches `reconcile-apply` and applies the full mutation set.
6. Real regression proof: using DIR-119-D3's real Audit output, confirm from the real journal a
   literal `Reconcile` entry between the last Audit-shard call and Gate/Land, with `git status`
   showing the tree clean through Audit and dirty only from `reconcile-apply`.
