**type:** execution

## Proposal

Adopt the architecture in
`docs/proposals/quay-adaptive-task-packing-and-overlap-concurrency.md`: make composite formation an
internal stage of SELECT, change SELECT's output from individual tasks to a non-overlapping
`MilestonePortfolio`, and let a milestone execute an arbitrary non-empty set of tasks through a
checked phase DAG, read-only audit shards, deterministic reconciliation, and atomic Land.

Task count is not a milestone-size proxy. The mechanism must support a connected, capacity-valid
group of three, five, ten, or more small tasks while rejecting even a two-task group when a
proof-after-Land, next-generation, learning-feedback, or result-dependent edge crosses the proposed
milestone boundary.

This is an O4 control-plane change. It is split into ordered children so the generation that
implements the selector/workflow cannot certify its own wiring: DIR-119-A implements SELECT candidate
synthesis; DIR-119-B implements arbitrary-width execution; DIR-119-C cold-runs the next generation
and requires SELECT itself to synthesize and land a real composite containing at least three tasks.

**Status update (2026-07-28, real M-DIR119-C-CANARY run + independent audit + follow-up code
read):** DIR-119-C's real cold run genuinely proved the SELECT-side half of this directive — a real

## Finding

The current OUTER-LOOP selects and truncates individual tasks before milestone boundaries are
formed. Its batch scheduler can only compare already-authored single-task charters, and
`execute-milestone` accepts one scalar `taskId`. Recent Claude Code history contains a natural
three-task workflow-hardening cluster, a four-task ADR-019 delivery family, and a ten-task homogeneous
lifecycle reconciliation, while also containing a two-task next-generation proof chain that must not
be combined. The present model therefore both misses valid wide composites and lacks the temporal
dependency vocabulary needed to reject invalid small ones.

## Requested action

1. Make composite candidate synthesis part of SELECT and change final selection to a
   non-overlapping `MilestonePortfolio`.
2. Replace task-count limits with checked coupling, dependency, phase, capacity, resource, and
   atomic-failure gates.
3. Execute arbitrary-width selected groups through phase DAGs, read-only audit shards,
   deterministic reconciliation, and atomic Land while preserving singleton compatibility.
4. Prove real wiring from a cold later generation using a SELECT-synthesized composite of at least
   three real tasks.

## Plan

DIR-119-A → DIR-119-B → DIR-119-C → DIR-119-D. Parent completion is exactly child completion; no
prose-only or source-only shortcut is permitted.
