### Problem framing (verified directly against source, 2026-07-28)

`readGatesConfig()` (`loader.ts:67-101`) and `readLoopParams()` (`loop-params.ts:46-84`) each
collapse two structurally different situations into a single "no unified value found" fallback
that silently reads a sibling legacy file:

- **Branch A** — a governing `.quay/config.yml` exists at `workspaceRoot` (parses or not, has the
  relevant top-level key or not) but the reader still falls through to `.quay/gates.yml` /
  `.quay/loop.yml` beside it. For the repo root this is unreachable *today* only by accident:
  `.quay/config.yml` (6748 bytes) always carries both `gates:` and `loop:` and always parses, but
  the sibling legacy files are still on disk (`.quay/gates.yml` 8410 bytes, `.quay/loop.yml` 295
  bytes) and have already drifted from the canonical section — root `loop.yml` still says
  `gates: [vitest]` while canonical `config.yml` says `gates: [acceptance]`. `vitest` matches no
  gate factory in `packages/quay/src/gate/registry.ts` and no dependency of this repo (confirmed
  zero-hit grep) — a copy-paste leftover from `archguard`'s own `.quay/config.yml`, where `vitest`
  genuinely is the real gate (confirmed by reading `/home/yale/work/archguard/.quay/gate-events.jsonl`),
  never adapted for this project.
- **Branch B** — no `.quay/config.yml` exists at `workspaceRoot` at all. Real, not hypothetical:
  `experiments/quay-perpetual-stream/.quay/` contains only `loop.yml` (3509 bytes, confirmed via
  `ls`) — exp5's real, live shape. exp5 shares the root `tasks/` store and root provider map; it
  structurally cannot "graduate" to its own `config.yml` without duplicating the provider map
  DIR-050 already exists to unify — so it must depend on branch B staying alive.
- **The two readers need a different number of guarded sub-conditions closed, not a uniform
  patch.** `readGatesConfig` swallows a malformed `config.yml` in `try/catch` (`loader.ts:79-81`)
  and falls through to branch A/B for that case too; `readLoopParams` already throws `FAIL-CLOSED`
  immediately on malformed YAML (`loop-params.ts:53-66`) and never reaches its fallback there —
  only for a well-formed `config.yml` missing the `loop:` key. So `readLoopParams` needs closing on
  one sub-condition (missing key only); `readGatesConfig` needs closing on two (missing key AND
  malformed YAML). Any deletion plan must preserve this distinction rather than blur it into one
  uniform rule.
- **Fixture audit, by reading each test's own setup, not by pattern-matching names:**
  `dod-gate-set.test.mjs`'s `tmpWorkspace()` writes only `.quay/gates.yml`, no `config.yml` — pure
  branch B. `gate-ergonomics.test.mjs`'s `makeWorkspace()` builds a branch-A-shaped `config.yml`
  (`providers:` only) used exclusively by its three `--cwd`-flag tests, which never touch
  `gates.yml`; its three `gates.yml`-writing "B" tests (lines 138-206) each `fs.mkdtempSync` their
  own bare workspace and write only `.quay/gates.yml` — zero `config.yml` write in that section.
  `grep -rl readGatesConfig packages/quay/test/` returns zero hits — no test constructs "`config.yml`
  with no `gates:` key + sibling `gates.yml`" today, so closing branch A needs one new,
  purpose-built test. `loop-params.test.mjs` has one real branch-A GREEN case at line 197
  (`"...legacy loop.yml fallback when config.yml has no loop: section"`) that must flip to RED, and
  one real branch-B GREEN case at line 208 (`"...fallback when no config.yml at all"`) that must
  stay GREEN, re-run unmodified.
- `plugin/scripts/drivable-workspace-check.ts`'s `DEFAULT_REGISTRY_PATH`
  (`path.join(__dirname, "..", "drivable-workspaces.yml")`, line 34) resolves from
  `plugin/scripts/` to `plugin/drivable-workspaces.yml` — confirmed absent (only
  `experiments/quay-perpetual-stream/drivable-workspaces.yml` exists on disk, confirmed via
  repo-wide `find`). `main()` (lines 193-233) only calls `usage()`/exits 2 when zero target paths

  `argsKey: drivableWorkspaceArgs`, lines 45-47) — a wired gate, not dead configuration — but
  `grep -rn drivableWorkspaceArgs tasks/` matches zero real tasks (only prose in `tasks/DIR-120.md`
  itself), so the gate factory's own per-task short-circuit — not correct wiring — is what
  currently prevents `loadRegistry(DEFAULT_REGISTRY_PATH)` from ever firing in production.
- `plugin/scripts/drivable-workspace-check.ts`/`.sh` and their
  `experiments/quay-perpetual-stream/scripts/` mirrors are today real, byte-identical,

- **A concrete regression this milestone must account for:**
  `experiments/quay-perpetual-stream/test/drivable-workspace-check.test.mjs` is **not** covered by
  `scripts/test.sh`'s glob (`packages/*/test/*.test.mjs plugin/test/*.test.mjs`, confirmed at
  `scripts/test.sh` line 37 — no `experiments/` pattern). This file imports
  `DEFAULT_REGISTRY_PATH` directly (`loadRegistry(DEFAULT_REGISTRY_PATH)` at line 62) and its 5 CLI
  subprocess tests rely on it resolving correctly with no `--registry` flag. It resolves correctly
  **today only because this specific copy's own `__dirname` sits one directory below the real
  registry file** (`experiments/quay-perpetual-stream/scripts/` → `../drivable-workspaces.yml`) —
  the layering inversion in miniature: the "default" is only ever right for the experiments-side
  copy, never the product-level one. Once this file becomes a symlink to
  `plugin/scripts/drivable-workspace-check.ts`, Node resolves `import.meta.url` through the symlink
  to the real file's location (the same behavior `config-wiring-check.ts`'s own comment, lines
  46-48, already documents), so `__dirname` becomes `plugin/scripts/` and `DEFAULT_REGISTRY_PATH`
  breaks for every caller including this test file — independent of whether the default is also
  removed. The symlink conversion and the `DEFAULT_REGISTRY_PATH` removal are therefore not
  independently optional: they must land together with this out-of-glob test file's own update, or
  a green `scripts/test.sh` run will hide a real, direct-invocation break.

### Chosen mechanism

**Phase 2 — delete root legacy files + the branch-A fallback only, never branch B:**
- Delete `.quay/gates.yml` and `.quay/loop.yml` at repo root. No pre-deletion migration is needed:
  `execution`/`audit` are already in `.quay/config.yml`'s `loop:` section from Phase 1.
- `readGatesConfig()`: once `.quay/config.yml` exists at `workspaceRoot` — parses or not, has
  `gates:` or not — return the config-derived value or the empty `GatesConfig` shape immediately;
  never fall through to `.quay/gates.yml`. Branch B (no `config.yml`) unchanged.
- `readLoopParams()`: once `.quay/config.yml` exists but has no `loop:` key, throw
  `FAIL-CLOSED: <path> has a config.yml but no loop: section — legacy sibling .quay/loop.yml is no
  longer consulted (DIR-120)` instead of falling through. The malformed-YAML case is already
  fail-closed and needs no code change. Branch B preserved.
- Add exactly one new branch-A test for `readGatesConfig` (the one uncovered input shape: a sibling
  `gates.yml` present but `config.yml` has no `gates:` key, which must now be ignored); flip
  `loop-params.test.mjs` line 197's branch-A GREEN case to RED; leave `dod-gate-set.test.mjs` and
  `gate-ergonomics.test.mjs`'s three `gates.yml` tests unmodified, re-run all of them post-change as
  real evidence, not by classification alone.
- Post-deletion proof (charter Done-when #2): a real `quay gate` call against a real task producing
  a real `GateEvent`, plus a real `readLoopParams(repoRoot)` call (directly or via
  `config-wiring-check.ts --driver both`), both resolving purely from `.quay/config.yml`, run
  **after** the files are physically gone (`ls -la .quay/gates.yml .quay/loop.yml` both ENOENT —
  an independent AC item, since a behavioral test alone cannot distinguish "file deleted" from
  "file present but unread").
- Structural grep proof that `existsSync(legacyGatesPath)`/`existsSync(legacyLoopPath)` are
  reachable only inside the "no `config.yml`" branch — a check on *where the guard sits*, not a
  substring-absence grep (both strings correctly remain in source for branch B).

**Phase 3a — exp5 profile-fragment schema, enforced inside the existing branch-B reader:**
- Harden branch B of `readLoopParams` in place rather than adding a second, separately-named
  reader — a fragment and a unified `loop:` section validate identically field-by-field; only the
  top-level key set differs.
- Inside branch B only: if the parsed object carries a `providers:` key at all, throw
  `FAIL-CLOSED: <path> is a loop-only profile fragment — providers: is not allowed here; it may
  only live in a workspace's own .quay/config.yml`. This is precisely the DIR-050 drift-prevention
  concern: exp5 shares the root provider map, so a second `providers:` section anywhere is a bug
  by construction, not a style violation.
- The "`gates:` as a smuggled full gate-definitions object" shape is already rejected by the
  existing `gates` type check (`must be Array.isArray or a non-empty string`,
  `loop-params.ts:110-113`) — no new code needed there, but add one explicit new test naming this
  invariant directly (today true only incidentally, never asserted).
- RED/GREEN reuses `config-wiring-check.ts --workspace <path>` (confirmed to accept the flag at
  line 241 and call `readLoopParams(workspaceRoot)` internally, printing the thrown message and
  exiting non-zero) rather than inventing a new flag: RED = a temp dir with a `providers:`-carrying
  `loop.yml` fails with the named reason; GREEN = exp5's own real, unmodified `.quay/loop.yml`
  (confirmed no `providers:` key today) succeeds against
  `--workspace experiments/quay-perpetual-stream` — a stronger proof than a synthetic fixture,
  since it needs zero config edits to pass.

**Phase 3b — `drivable-workspaces.yml` layering fix, file stays where it is:**
- Do not move the file — matches the charter's own Touches path and DIR-120's stated reasoning for
  an independent, separately-audited registry file (the `/etc/sudoers` analogy).
- Remove `DEFAULT_REGISTRY_PATH` entirely, not repoint it (repointing only relocates the same
  layering violation and would silently break again on the next relocation). `--registry <path>`
  becomes required; a missing `--registry` is a clean, distinguishable usage error, exit 2 — the
  same failure class as today's already-passing "no target paths supplied" short-circuit (line
  209), not the confusing downstream `ENOENT`-shaped `DrivableCheckEnvError` it produces today.
  Update `--selftest`'s own `fs.existsSync(DEFAULT_REGISTRY_PATH)` check to point at the real path
  directly, so the "real registry" self-test cases run unconditionally rather than silently
  no-op'ing.
- Convert `experiments/quay-perpetual-stream/scripts/drivable-workspace-check.ts` (and `.sh`) into
  real symlinks to the `plugin/scripts/` originals, matching Phase 0's `config-wiring-check.ts`
  precedent exactly.
- **Land atomically with the above**: update
  `experiments/quay-perpetual-stream/test/drivable-workspace-check.test.mjs` — replace its
  `loadRegistry(DEFAULT_REGISTRY_PATH)` unit test and its 5 no-`--registry` CLI subprocess tests
  with versions passing an explicit `--registry <real-path>`, and re-run this file directly
  (`node --test experiments/quay-perpetual-stream/test/drivable-workspace-check.test.mjs`) with
  pasted real output, since `scripts/test.sh` will not catch a regression here.

### Concrete control/data flow (post-change)

```

  if config.yml exists at workspaceRoot:
      gates := config.yml's `gates:` key (parses & has key), or {} otherwise   [branch A — no
                                                                                 fallback ever,
                                                                                 incl. malformed YAML]
  else:
      gates := gates.yml at workspaceRoot, or {} if absent                    [branch B — unchanged]

readLoopParams(workspaceRoot):
  if config.yml exists at workspaceRoot:
      if malformed YAML → throw FAIL-CLOSED                    [branch A — pre-existing, unchanged]
      if has `loop:` → validate+return it                      [branch A success]
      else → throw FAIL-CLOSED                                 [branch A fail — NEW, was: fall through]
  else:
      if loop.yml exists at workspaceRoot:
          parsed := loop.yml
          if "providers" in parsed → throw FAIL-CLOSED          [Phase 3a — NEW]

  --registry omitted → usage error, exit 2                      [NEW — was: silent DEFAULT_REGISTRY_PATH
```

### Key design decisions

1. **Split fallback deletion into branch A (delete) and branch B (harden, keep).** Branch B is
   exp5's real, live production path and is exercised today by ~20 tests across
   `dod-gate-set.test.mjs`/`loop-params.test.mjs`; deleting it too would be a substantially larger,
   not-currently-scoped change the charter's Done-when items do not ask for.
2. **Harden the existing branch-B reader in place, not a parallel `readLoopProfileFragment()`.** A
   fragment and a unified `loop:` section validate identically field-by-field; only the top-level
   key set differs — one rule set, a 3-line key-presence check, not a duplicated rule set.
3. **Both readers keep the same branch-A/B structural split despite differing failure philosophies**
   (`readGatesConfig` fails quiet by design — absent gate config is a valid "no gates" state;
   `readLoopParams` fails closed — no valid loop config means the workspace cannot run) and
   differing pre-existing parse-error handling (two sub-conditions closed for gates, one for loop).
   The structural shape is unified; the philosophies inside it are not silently forced into one
   uniform rule.
4. **`drivable-workspaces.yml` stays put; the reader stops guessing instead of guessing
   differently.** A hardcoded `<script-dir>/../` default is inherently layering-inverted for a
   `plugin/scripts/`-housed script with an experiments-layer caller at a different relative depth;
   requiring an explicit `--registry` removes the guess rather than relocating it.
5. **Symlink, not re-copy, `drivable-workspace-check.ts`/`.sh`**, following the Phase-0
   `config-wiring-check.ts` precedent — the two files are today real, hand-maintained,
   byte-identical duplicates imported as a library by two other real files.
6. **The symlink conversion, the `DEFAULT_REGISTRY_PATH` removal, and the out-of-glob
   experiments-side test-file update must land in one atomic change.** Landing any one alone
   breaks `experiments/.../test/drivable-workspace-check.test.mjs` via a different mechanism
   (stale relative default vs. symlink-resolved `__dirname`), and `scripts/test.sh` would report
   green while that direct-invocation path is provably broken.
7. **No `execution`/`audit` config.yml migration step remains** — verified directly against the
   live file: Phase 1/M186 already landed both into `.quay/config.yml`'s `loop:` section (lines
   99-100). Treating this as an outstanding prerequisite would add redundant work against an
   already-closed gap.

### Defaults and failure behavior

- `readGatesConfig`: `config.yml` present (parses or not, `gates:` or not) → that section or `{}`,
  never an error, never a fallback read. `config.yml` absent → unchanged branch-B behavior.
- `readLoopParams`: `config.yml` present, parses, missing `loop:` → `FAIL-CLOSED` (the one
  genuinely new failure mode). `config.yml` present but malformed → `FAIL-CLOSED`, pre-existing,
  unchanged. `config.yml` absent → unchanged branch-B behavior, now additionally `FAIL-CLOSED` on a
  `providers:` key.
- `drivable-workspace-check.ts` registry resolution: no `--registry` → usage error, exit 2, same
  failure class as today's "no drivable-workspace arguments defined" short-circuit — never a
  silent pass, and no longer a confusing downstream `ENOENT`-shaped error either.
- No new fail-open branch anywhere; every new failure mode introduced by this milestone is
  fail-closed, consistent with `readLoopParams`'s existing philosophy and with the repo-wide
  fail-closed convention this directive line traces back to (`checkHalt()`'s own fail-closed fix,
  already landed at Phase 1, out of this milestone's scope).

### Compatibility

- Root workspace: zero behavior change for any currently-passing path — `config.yml` already
  carries both sections, always parses, and already carries `execution`/`audit`. The deleted files
  are, by construction, never read for this workspace today.
- exp5: its real `.quay/loop.yml` (no `providers:` key today) keeps validating exactly as today
  unless later edited to add one — which is the exact drift this phase exists to prevent from
  landing silently.
- `gate-ergonomics.test.mjs` / `dod-gate-set.test.mjs`: no changes — pure branch B, confirmed by
  reading each test's own setup and by re-running them post-change, not by classification alone.
- `select-preflight.ts` / `human-steered-classify.ts` and their existing tests: must stay green
  through the symlink indirection.
- `experiments/quay-perpetual-stream/test/drivable-workspace-check.test.mjs`: **not** compatible
  as-is — must be edited in this milestone and re-run directly since `scripts/test.sh` does not
  cover it.
- `packages/*/provider.yml` and `plugin/.claude-plugin/plugin.json`: untouched, per DIR-120's
  explicit carve-out.
- `config-wiring-check.ts`'s field-consumption report loop: unaffected — the returned field set
  from `readLoopParams` does not change.

### Risks

- **Touches-list gap.** The M192 charter's own `## Touches` list does not name
  `packages/quay/test/loop-params.test.mjs`, the new `readGatesConfig` test,
  `plugin/scripts/drivable-workspace-check.ts`/`.sh` + its experiments mirror, nor
  `experiments/quay-perpetual-stream/test/drivable-workspace-check.test.mjs` — all of which this
  mechanism edits. Needs explicit sign-off (amend Touches, or confirm test/companion-script edits
  colocated with an already-Touched module don't require separate enumeration).
- **Branch-A/branch-B scoping is interpretive, not mechanically forced.** A literal reading of
  "delete the fallback branch(es)" could be read to require branch B's deletion too — a materially
  larger change. Must be surfaced for sign-off before implementation, not silently resolved either
  way.
- **Undiscovered third consumer of branch A/B.** Mitigate with a repo-wide grep for
  `readLoopParams(`/`readGatesConfig(`/`loadWorkspaceGates(` call sites and for
  `gates.yml`/`loop.yml` string references in docs/skills before landing.
- **Symlink/default-removal ordering hazard.** Landing the symlink conversion without updating
  `experiments/.../test/drivable-workspace-check.test.mjs` breaks its 6
  `DEFAULT_REGISTRY_PATH`-dependent tests silently with respect to `scripts/test.sh` (which never
  runs that file); landing the `DEFAULT_REGISTRY_PATH` removal without the symlink conversion
  breaks the same tests via a different code path (an undefined `registryPath`). All three changes
  must land together, and the file must be run directly as evidence.
- **The `drivable-workspace` it0 gate is real, registered infrastructure**, not hypothetical
  (`.quay/config.yml`'s `gates.it0` names it with `argsKey: drivableWorkspaceArgs`). This milestone
  changes the failure mode of a wired gate. Since no task sets `drivableWorkspaceArgs` (confirmed
  by repo-wide grep), AC coverage here is necessarily the usage-error proof plus a manual
  explicit-`--registry` invocation — must not be overclaimed as "now live in a real gate firing";
  needs an explicit sign-off that this registered-but-never-fed entry stays unexercised end-to-end
  this milestone.
- **`plugin/test/plugin-packaging.test.mjs`'s exp5-label-leak test** names
  `plugin/scripts/drivable-workspace-check.ts`/`.sh` as shipped files that must not leak the
  `experiments/quay-perpetual-stream` path — the symlink conversion only touches the
  experiments-side copy, leaving the plugin-side file (and this test) unaffected, but must be
  verified empirically post-change, not assumed.
