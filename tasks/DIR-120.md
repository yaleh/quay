### Problem framing (re-verified against source)

Two readers each collapse a real branch structure into a single fallback, and a third script
guesses a path it should be told explicitly.

  (or `{}` if the key is missing or the YAML is malformed — malformed YAML is swallowed in a
  `try/catch` at lines 79-81 and falls through to the same branch-A "no key found" state); only
  when `.quay/config.yml` does not exist at all does it fall through to `.quay/gates.yml`. For the
  repo root this fallback is unreachable *today* only by accident: `.quay/config.yml` (6748 bytes)
  always parses and always carries a `gates:` key, but the sibling `.quay/gates.yml` (8410 bytes)
  is still on disk and has already drifted — its own header now documents itself as dead weight
  (`gap-orphaned-check-scripts-not-wired`, M-DIR119-C-CANARY) and warns its own `it0`/`testPass`
  script paths are kept in sync with `config.yml` only "by hand (no automated drift check exists
  yet)". Root `.quay/loop.yml` still says `gates: [vitest]`; canonical `config.yml`'s own committed
  comment already records that `vitest` and `it0-set` were both confirmed dangling references for
  this repo (`vitest` matches no dependency of this project — it's a copy-paste leftover from

  cross-checked equivalent.
- `readLoopParams()` (`loop-params.ts:46-84`) has a materially different pre-existing failure

### Chosen mechanism

**Phase 2 — delete root legacy files + the branch-A fallback only, never branch B:**
- Delete `.quay/gates.yml` and `.quay/loop.yml` at repo root. No pre-deletion migration needed —
  Phase 1/M186 already put `execution`/`audit`/`concurrency`/`gates: [acceptance]` into
  `.quay/config.yml`'s `loop:` section.
- `readGatesConfig()`: once `.quay/config.yml` exists at `workspaceRoot` — parses or not, has
  `gates:` or not — return the config-derived value or the empty `GatesConfig` shape immediately;
  never fall through to `.quay/gates.yml`. Branch B (no `config.yml`) unchanged.
- `readLoopParams()`: once `.quay/config.yml` exists but has no `loop:` key, throw
  `FAIL-CLOSED: <path> has a config.yml but no loop: section — legacy sibling .quay/loop.yml is no
  longer consulted (DIR-120)` instead of falling through. The malformed-YAML case needs no code
  change (already fail-closed). Branch B preserved.
- Add exactly one new branch-A test for `readGatesConfig` (a sibling `gates.yml` present but
  `config.yml` has no `gates:` key — the one input shape zero existing tests cover), which must now
  be ignored; flip `loop-params.test.mjs`'s branch-A GREEN case to RED; leave `dod-gate-set.test.mjs`
  and `gate-ergonomics.test.mjs`'s branch-B tests unmodified, re-run all of them post-change as real
  evidence.
- Post-deletion proof (charter Done-when #2): a real `quay gate` call against a real task producing
  a real `GateEvent`, plus a real `readLoopParams(repoRoot)` call (directly or via
  `config-wiring-check.ts --driver both`), both resolving purely from `.quay/config.yml`, run
  **after** the files are physically gone (`ls -la .quay/gates.yml .quay/loop.yml` both ENOENT —
  its own independent AC item, since a behavioral test alone cannot distinguish "file deleted" from
  "file present but unread").
- Structural grep proof that the surviving `existsSync(legacyGatesPath)`/`existsSync(legacyLoopPath)`
  calls are reachable only inside the "no `config.yml`" branch — a check on *where the guard sits*,
  not a substring-absence grep (both strings correctly remain in source for branch B).

**Phase 3a — exp5 profile-fragment schema, enforced inside the existing branch-B reader:**
- Harden branch B of `readLoopParams` in place rather than adding a second, separately-named
  reader — a fragment and a unified `loop:` section validate identically field-by-field; only the
  top-level key set differs.
- Inside branch B only: if the parsed object carries a `providers:` key at all, throw
  `FAIL-CLOSED: <path> is a loop-only profile fragment — providers: is not allowed here; it may
  only live in a workspace's own .quay/config.yml`. This is precisely the DIR-050 drift-prevention
  concern: exp5 shares the root provider map, so a second `providers:` section anywhere is a bug by
  construction.
- The "`gates:` as a smuggled full gate-definitions object" shape is already rejected by the
  existing type check (`gates` must be `Array.isArray` or a non-empty string, `loop-params.ts`
  lines ~103-112) — no new code needed there, but add one explicit new test naming this invariant
  directly (true today only incidentally, never asserted).
- RED/GREEN reuses `config-wiring-check.ts --workspace <path>` (confirmed to accept the flag and
  call `readLoopParams(workspaceRoot)` internally, printing the thrown message and exiting
  non-zero) rather than inventing a new flag: RED = a temp dir with a `providers:`-carrying
  `loop.yml` fails with the named reason; GREEN = exp5's own real, unmodified `.quay/loop.yml`
  (confirmed no `providers:` key today) succeeds against `--workspace
  experiments/quay-perpetual-stream` — a stronger proof than a synthetic fixture, since it needs
  zero config edits to pass.

**Phase 3b — `drivable-workspaces.yml` layering fix, file stays where it is:**
- Do not move the file — matches the charter's own Touches path and DIR-120's own reasoning for an
  independent, separately-audited registry file (the `/etc/sudoers` analogy: an authorization
  whitelist deserves independent review attention, not folding into general configuration).
- Remove `DEFAULT_REGISTRY_PATH` entirely from `plugin/scripts/drivable-workspace-check.ts`, not
  repoint it (repointing only relocates the same layering violation and silently breaks again on
  the next relocation). `--registry <path>` becomes required; a missing `--registry` is a clean,
  distinguishable usage error, exit 2 — the same failure class as today's already-passing "no
  target paths supplied" short-circuit, not the confusing downstream `ENOENT`-shaped
  `DrivableCheckEnvError` it produces today.
- Re-derive `--selftest`'s three "real-registry-*" assertions to run unconditionally against the
  real checked-in file's actual path (not gated behind an `existsSync(DEFAULT_REGISTRY_PATH)` that
  no longer has a constant to check), and make their execution independently visible — e.g. a
  per-check pass/fail line already exists via the `check()` helper; the aggregate "SELFTEST: all
  fixture cases PASS" line must not be the only visible signal that these three specific checks
  ran.
- Convert `experiments/quay-perpetual-stream/scripts/drivable-workspace-check.ts` (and `.sh`) into
  real symlinks to the `plugin/scripts/` originals, matching Phase 0's `config-wiring-check.ts`
  precedent exactly.
- **Fix both real `DEFAULT_REGISTRY_PATH` call sites found in this audit, not just the test file**:
  remove the now-broken, always-unused `DEFAULT_REGISTRY_PATH` import from `select-preflight.ts`
  (it never referenced the binding — a pure dead-import cleanup, but a load-bearing one, since an
  import of a non-existent named export is a hard module-load failure, not a lint warning); and
  update `human-steered-classify.ts`'s `main()` so its own CLI no longer defaults `registryPath` to
  a deleted constant — either require `--registry` there too (consistent with
  `drivable-workspace-check.ts`'s own new requirement) or hardcode the one real, checked-in path the
  way `select-preflight.ts` already does. This must land in the same atomic change as the symlink
  conversion — landing the symlink or the constant removal alone, without both of these two
  consumer fixes, breaks `select-preflight.ts` (import-time) and/or `human-steered-classify.ts`
  (its own default-registry CLI path) independently of the test file.
- **Land atomically with the above**: update
  `experiments/quay-perpetual-stream/test/drivable-workspace-check.test.mjs` — replace its
  `loadRegistry(DEFAULT_REGISTRY_PATH)` unit test and its no-`--registry` CLI subprocess tests with
  versions passing an explicit `--registry <real-path>`, and re-run this file directly (`node
  --test experiments/quay-perpetual-stream/test/drivable-workspace-check.test.mjs`) with pasted
  real output, since `scripts/test.sh` will not catch a regression here.

### Concrete control/data flow (post-change)

```

  if config.yml exists at workspaceRoot:
      gates := config.yml's `gates:` key (parses & has key), or {} otherwise   [branch A — no
                                                                                 fallback ever,

      gates := gates.yml at workspaceRoot, or {} if absent                    [branch B — unchanged]
```

### Key design decisions

1. **Split fallback deletion into branch A (delete) and branch B (harden, keep).** Branch B is
   exp5's real, live production path, exercised today by roughly twenty tests across
   `dod-gate-set.test.mjs`/`loop-params.test.mjs`; deleting it too would be a substantially larger,
   not-currently-scoped change the charter's Done-when items do not ask for.
2. **Harden the existing branch-B reader in place, not a parallel `readLoopProfileFragment()`.** A
   fragment and a unified `loop:` section validate identically field-by-field; only the top-level
   key set differs — one rule set, a small key-presence check, not a duplicated rule set.
3. **Both readers keep the same branch-A/B structural split despite differing failure philosophies**
   (`readGatesConfig` fails quiet by design — absent gate config is a valid "no gates" state;
   `readLoopParams` fails closed — no valid loop config means the workspace cannot run) and
   differing pre-existing parse-error handling (two sub-conditions closed for gates, one for loop).
   The structural shape is unified; the philosophies inside it are not silently forced into one
   uniform rule.
4. **`drivable-workspaces.yml` stays put; the reader stops guessing instead of guessing
   differently.** A hardcoded `<script-dir>/../` default is inherently layering-inverted for a
   `plugin/scripts/`-housed script with callers at different relative depths (three distinct
   consumers found: the test file, `select-preflight.ts`, `human-steered-classify.ts` — each would
   need a different correct guess); requiring an explicit `--registry`, and hardcoding the one real
   path in the two library-consumer scripts, removes the guess rather than relocating it.
5. **Symlink, not re-copy, `drivable-workspace-check.ts`/`.sh`**, following the Phase-0
   `config-wiring-check.ts` precedent — the two files are today real, hand-maintained,
   byte-identical duplicates imported as a library by two other real scripts.
6. **All four consumer fixes — symlink conversion, `DEFAULT_REGISTRY_PATH` removal,
   `select-preflight.ts`'s dead-import cleanup, and `human-steered-classify.ts`'s default-registry
   rework — plus the out-of-glob test-file rewrite must land in one atomic change.** Landing any
   subset alone leaves at least one of these four files broken by a different mechanism (stale
   relative default vs. symlink-resolved `__dirname` vs. an import of a now-missing export vs. an
   undefined runtime default), and `scripts/test.sh` would report green while one or more of these
   breaks silently (three of the four files are either not covered by its glob at all, or are
   covered but the specific broken code path isn't exercised by existing assertions).
7. **No `execution`/`audit`/`gates`/`concurrency` config.yml migration step remains** — verified
   directly against the live file: Phase 1/M186 already landed all four into `.quay/config.yml`'s
   `loop:` section. Treating this as an outstanding prerequisite would add redundant work against
   an already-closed gap.

### Defaults and failure behavior

- `readGatesConfig`: `config.yml` present (parses or not, `gates:` or not) → that section or `{}`,
  never an error, never a fallback read. `config.yml` absent → unchanged branch-B behavior.

     DIR-113 的存在不构成"可以安全调到 4"的自动理由。这次调整是人工在知悉这个张力的前提下做出
     的明确决定，落地时必须原样记录这个理由链条，不能悄悄抹掉 DIR-049 当初的顾虑。
   - **routines 触发频率**：`loop-params.ts` 的校验正则**已经同时支持** `every(N)` 和
     `on(<event>)`，交付物侧不需要新增能力，这条无需改代码。**本项目自己的取值**：维持
     `on(checkpoint)`（exp5 自己 `.quay/loop.yml` 现状），因为这是本项目唯一真实在触发的值——
     `config.yml`/根 `loop.yml` 里那些 `every(N)` 目前对本项目而言都是死值，改动它们不影响任何
     真实行为，故不作为"贴近实际使用"的目标。
   - **`execution: dispatched` / `audit: adversarial`**：已核对 meta-cc、archguard 两个真实项目
     均显式设置且真实生效（`SKILL.md` 内真实分支消费，非声明未接线）——**结论：保留并接线**，
     不删除。落地时需要把这两个字段显式补进本项目 canonical 的 `config.yml` 的 `loop:` 段
     （目前只在即将删除的根 `loop.yml` 里有，`config.yml` 里缺失——这是 Phase 2 删除 legacy 文件
     前必须先做的迁移，否则删除会导致这两个已确认要保留的字段连同文件一起丢失）。

### Phase 2 — 删除备选项（这才是真正的"结晶"）

4. 删除根 `.quay/gates.yml` 与根 `.quay/loop.yml`，**同时删除 reader 里对应的 fallback 代码路径**
   （`packages/quay/src/gate/config/loader.ts`、`loop-params.ts`）。只要 fallback 还在，就永远是
   两个真相源——删文件而不删 fallback 等于没做。

### Phase 3 — exp5 的 profile fragment 化

5. exp5 保留自己的 loop 配置文件，但其 schema **显式降级为 profile fragment**：只允许携带 loop
   参数，**禁止**出现 `providers:`/`gates:`（那些只能来自根 `config.yml`），由 reader 机械强制
   （出现即 FAIL，不是警告）。这样既保住 `experiments/` 相对 `packages/` 的可分离性，又结构上杜绝
   provider map 漂移。
6. 修正层次倒置：`drivable-workspaces.yml` 要么挪到根（若它是产品级概念），要么让读它的 check 也
   降为 exp5 级。**建议这个文件本身保持独立、不并入 `config.yml`**——它是安全白名单（哪些外部
   工作区允许被驱动），独立文件带来独立的评审注意力、独立的爆炸半径、可单独审计，跟一般配置混在
   一起是负收益（同 `/etc/sudoers` 不并入通用配置的理由）。

### 贯穿全程的不变量

7. 明确写死一条：**配置读取失败 = fail closed，无例外**。据此修正 `select-preflight.ts`
   `checkHalt()` 的 `catch { halt: false }` 为 fail-closed（读不到 → 当作已暂停）。

**Out of scope（明确不做，避免与已归档任务重复）**：
- `packages/*/provider.yml`、`plugin/.claude-plugin/plugin.json` —— **绝对不动**。前者随 Provider
  包发布、是第三方能自己写 provider 的 ABI 契约；后者 schema 由 Claude Code 拥有。跨这一层的合并
  是破坏，不是精简。
- `delivery-manifest.json` 及其孤儿 checker —— 它是对构建产物的**断言**（更接近 test fixture），
  不是"系统该怎么做"的配置，不该并入 `config.yml`；其接线问题已归档在
  [[gap-orphaned-check-scripts-not-wired]]。
- `.halt` 路径本身的修正 —— 已归档在 [[gap-halt-sentinel-path-mismatch]]；本 directive 只接手它
  引出的 fail-open 语义问题（第 7 条）。
