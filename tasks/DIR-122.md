**type:** execution

## Proposal

`task-schema.ts`'s `checkTask` gates its entire assertion set on `hasSchemaMarker` (`extra.schema:
v1`): a task without that marker returns `verdict: "N/A-legacy"` with zero assertions run — not a
partial check. A real survey of all 15 current `tasks/gap-*.md` files (2026-07-28) found this is not
a hypothetical risk: 9 of 15 carry no marker at all (zero structural enforcement, not even
`## Touches` well-formedness); of the 6 that do carry `extra.schema: v1`, 4 currently FAIL — missing
`## Proposal`, missing `## Plan`, missing a standard `## Acceptance Criteria` section (some use
ad hoc headings like "Requested action / Fix (landed same-session)"), or a `## Definition of Done`
that does not reference the standard inherited-core clauses. Gap/defect tasks are exactly the
category most tied to real wiring defects this session (3 of 4 gap tasks filed this session were
discovered auditing real wiring gaps), and they currently sit outside both DIR-117's Proposal-review
pipeline (deliberately — that pipeline is sized for O4-scale directive work) and any structural
schema enforcement at all.

Add a `kind=gap` classification to `task-schema.ts` with a assertion set proportionate to a gap
task's typical size: single-author + one independent review (no dual-proposal-author/adjudication/
multi-round Plan-check machinery — that stays DIR-117's domain for directive-class work). The
`## Finding` section plays the role `## Proposal` plays for directives (problem framing + root
cause, already the de facto convention every well-formed gap task already follows); `## Requested
action` plays the role a Proposal's "chosen mechanism" plays. Require: `## Finding` present and
substantive; `## Requested action` present and substantive; `## Touches` present and well-formed
(the existing `checkTouches` assertion, currently skipped for every unmarked gap task); a standard
`## Acceptance Criteria` and `## Definition of Done` referencing inherited-core; and — carrying
forward DIR-117's mechanism-claim wiring coverage design — every new call/dispatch/enforcement
relationship named in `## Requested action` has a matching, falsifiable AC item requiring real
production evidence for that relationship, not descriptive prose. Do not invent a parallel
"gap contract" artifact; the coverage lives in the same `## Requested action` and `## Acceptance
Criteria` sections that already exist.

Before adding this logic, fix the pre-existing, unrelated drift this work would otherwise silently
inherit: `plugin/scripts/task-schema.ts` (vendored mirror) has already drifted from
`experiments/quay-perpetual-stream/scripts/task-schema.ts` (canonical source) since DIR-113/M178
(`checkTouches`'s `kind` parameter and milestone-candidate soft-warning never reached the mirror —
tracked in [[gap-task-schema-plugin-mirror-touches-drift]]). Landing new `kind=gap` logic on top of
an already-diverged pair would make the divergence worse, not better.
