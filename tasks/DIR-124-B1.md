### Chosen mechanism

A new zero-dependency TypeScript CLI module `experiments/quay-perpetual-stream/scripts/run-identity.ts` (canonical source, experiments copy per A1a DD9) with byte-identical mirror `plugin/scripts/run-identity.ts`, importing only `node:fs`, `node:path`, `node:crypto`, `node:child_process`. None of the `*run-identity*` globs exist at base (`find` returns empty — verified). The module owns the ONE identity-minting entry point for the milestone-execution substrate.

**Typed `RunIdentity`** (exactly the task's field list, versioned from birth):

- `schemaVersion` — `"1"` (the envelope is versioned from birth, matching A1a's `SCHEMA_VERSION` discipline).
- `runId` — `` `${sessionId}::${candidateId}::${attempt}` `` (see DD1).
- `sessionId` — derived from `process.env.CLAUDE_CODE_SESSION_ID` (see DD2).
- `candidateId` — caller-supplied (milestone id for singleton, composite `candidateId` for composite); disambiguates runs in the same session.
- `taskIds` — non-empty array; width 1 = singleton, width N = composite.
- `attempt` — the per-dispatch nonce (default `1` on cold dispatch; journal-monotonic from B3).
- `baseCommit` — DERIVED from `git rev-parse HEAD` (see DD3); a caller-passed value that mismatches fails closed.
- `candidateCommit` — `null` until bound (see DD4).
- `workflowSourcePath` — caller-supplied canonical path of the installed workflow source.
- `workflowSourceHash` — `sha256` of the workflow-source file bytes.
- `workflowSourceCommit` — `git log -1 --format=%H -- <path>`.
- `runtimeGeneration` — fixed derivation `sha256(workflowSourceHash).slice(0,12)`, pinned by fixtures (see DD5).
- `taskHash` — `sha256` over task-file bytes concatenated in sorted-`taskId` order (deterministic for composite width).
- `charterHash`, `planHash` — `sha256` of the charter and plan files.
- `materialInputHashes` — `{path: sha256}` map over every material input (task file(s), charter, plan; the workflow source has dedicated fields).

**One factory, one envelope (AC1/AC3).** `mintRunIdentity(input)` is the single factory; it produces the SAME envelope (one TypeScript interface, one JSON shape) for width-1 and width-N inputs — only `taskIds` cardinality differs. There are no separate `RunIdentitySingleton`/`RunIdentityComposite` types. `composite` is NOT an envelope field: it is a DERIVED property (`taskIds.length > 1`) supplied by the build-manifest projection (Alt3).

**CLI surface** (all modes exit non-zero with a structured JSON error on failure):

- `--create '<json>'` — the workflow callsite (B4 wires it at Verify entry, L66); inputs `{candidateId, taskIds, attempt?, workflowSourcePath, taskFiles, charterFile, planFile, baseCommit?, sessionId?}`; outputs the `RunIdentity` JSON. A caller-supplied `sessionId` that conflicts with the env value is REJECTED (`session-id-conflict`); a caller-supplied `baseCommit` differing from `git rev-parse HEAD` is REJECTED (`base-commit-mismatch`). Mint-time mirror-parity check (DD6): if both workflow mirrors are resolvable and differ, `mirror-drift` fail-closed, no mint.
- `--bind-candidate-commit '<identity-json>' <commit>` — pure, immutable re-derivation returning a NEW identity with `candidateCommit` set (the SOLE bind site is Build-integrate; B4 wires it).
- `--check-candidate-commit '<identity-json>' <observedCommit>` — exits 0 on match; exits 1 with `candidate-commit-moved` on mismatch and `candidate-commit-unbound` if `candidateCommit` is still null.
- `--selftest` — embedded validation: factory round-trip (mint → deterministic-serialize → parse → deep-equal), singleton-vs-composite same-envelope assertion, runId-embeds-sessionId assertion, missing-env fail-closed, conflicting-arg rejection, hash determinism, mirror-drift fixture. Exit 0 all-pass, non-zero with diagnostics JSON otherwise.

**Deterministic serialization.** `serializeIdentity(identity)` uses `JSON.stringify(identity, Object.keys(identity).sort())` (the A1a `emitEvent` precedent) so identical identities serialize byte-identically — making identity equality hashable and testable.

**Build-manifest projection.** `toBuildManifestRunIdentity(identity)` → `{milestoneId: candidateId, taskIds, composite: taskIds.length > 1, attempt, sessionId}` so the canonical identity is consumable where `build-evidence-manifest.ts`'s inline runIdentity shape is expected, WITHOUT editing `build-evidence-manifest.ts` (out of Touches). `manifestRefForReceipt()`'s `{hash, path, candidateCommit}` remains B2's consumable reference.

### Key design decisions

**DD1 — `runId = ${sessionId}::${candidateId}::${attempt}` (session + per-dispatch nonce, deterministic, resume-safe).** The task's "per-dispatch nonce" is realized as `attempt` (default 1 on cold dispatch; journal-monotonic from B3). A session id alone is not per-dispatch unique (one orchestrator session drives many milestones/retries), so `candidateId` disambiguates milestones and `attempt` disambiguates retries of the same milestone. Deterministic (same session + same candidate + same attempt ⇒ same runId), which is what makes a resumed dispatch keep identity — B3's `resumePlan` increments attempt as prior max + 1. A RANDOM nonce was REJECTED (Alt2): it breaks determinism and resume identity (a resumed dispatch would get a new runId). `::` is filename-safe for A1a's `.workflow-events/<runId>.jsonl` convention. FLAGGED as a derivation choice the review should check against AC2's "never a caller-asserted string": the caller supplies `attempt`/`candidateId`, but NEVER the session portion — the non-forgeable half is the env-derived session id.

**DD2 — session id read from `process.env.CLAUDE_CODE_SESSION_ID` inside the CLI subprocess, NOT echoed-and-passed.** The CLI is itself a real shell subprocess that inherits the orchestrator env and reads the var directly — the documented `prepare-admission-check.ts` precedent (L32-37). Echo-and-pass (`--create {sessionId: $(echo ...)}`) lets a caller assert any string and weakens the property to prose; env-read keeps it mechanical. The workflow may still `echo` the value for its own logging/cross-check, but a caller-supplied `sessionId` that conflicts with the env is REJECTED (`session-id-conflict`), never honored. Missing env ⇒ `missing-session-id` fail-closed, never a placeholder. Scope of the guarantee: env-read detects a MISSING session and a CONFLICTING arg; it cannot detect an env var an adversary controlling the caller has set — the "cannot be forged" property is a WIRING fact (the orchestrator harness sets the var), not an in-module forgery detector (R9).

**DD3 — derive-don't-trust for `baseCommit`.** The CLI derives `baseCommit` from `git rev-parse HEAD` (cwd = workspace root at dispatch; the worktree does not yet exist at Verify entry, so HEAD is the shared checkout). A caller-passed `baseCommit` must match or it fails closed (`base-commit-mismatch`). This keeps the binding mechanical rather than prompt-trusted.

**DD4 — `candidateCommit` is a deferred, immutably-bound field (AC4).** `mintRunIdentity` emits `candidateCommit: null` (the candidate commit does not exist at Verify entry, so this is the correct initial state); `--bind-candidate-commit` returns a NEW identity with it set (the identity is immutable; no in-place mutation). `--check-candidate-commit` is the fail-closed re-check for the moved-candidate hazard at Audit/Gate/Land. `baseCommit` (dispatch-time HEAD) and `candidateCommit` (Build tip) are different facts with different semantics: baseCommit is the immutable dispatch binding; candidateCommit is what gets re-checked. The SOLE bind site is Build-integrate (the only commit-creator) — B1 supplies the mechanism, B4 wires the bind/re-check callsites.

**DD5 — `runtimeGeneration` has a fixed derivation, pinned by fixtures.** `sha256(workflowSourceHash).slice(0,12)` (the parent's `proposal-convergence.ts` `recurrenceKey = sha256(taskId::code).slice(0,12)` precedent). Content-derived: a stale materialized workflow body (the documented CLAUDE.md M176 `Workflow({name})` stale-script-cache defect) is literally different content, hence a different generation. A wrong generation is a DISTINCT fail-closed code from "wrong workflow source hash" at B2's validation layer, so the fixed definition cannot drift (a fixture pins the exact derivation).

**DD6 — mint-time mirror-parity enforcement (AC5).** Because the two workflow mirrors must stay byte-identical, `--create` reads BOTH the canonical workflow source and its convention-derived mirror and fails closed with `mirror-drift` if they differ at mint time — converting the Land-time-only `diff` parity gate into a per-dispatch invariant and guaranteeing the identity records the ACTUAL installed workflow content that is executing (staleness is recorded at mint; DETECTION is B2's receipt comparison). The byte-identity of the two `run-identity.ts` copies is asserted by the test (`diff` exit 0) and re-checked at Land (A1a precedent).

**DD7 — hashes only, never content.** The identity stores `sha256` of material inputs, never copies of task/Proposal/charter/Plan content (consistent with the parent's AC10/DD8 — a `RunIdentity` is a binding record, not a content carrier). Missing input file ⇒ `material-input-missing` fail-closed; a hash is never guessed. The mint is deliberately store-free: no journal read/write, no telemetry dependency — B1 has no durability dependency (B2/B3 own the journal).

### Defaults and failure behavior

- **Cold `--create` (no journal):** `attempt` defaults to 1; identity mints cleanly. An absent journal is valid input (B1 has no journal dependency).
- **Missing `CLAUDE_CODE_SESSION_ID`:** `missing-session-id` fail-closed, never a placeholder.
- **Conflicting caller-supplied `sessionId`:** `session-id-conflict` fail-closed.
- **Conflicting caller-supplied `baseCommit`:** `base-commit-mismatch` fail-closed.
- **Empty/duplicate `taskIds`:** `invalid-task-ids` fail-closed (mirrors `composite-args.ts` inline normalization).
- **Missing material input file** (task/charter/plan/workflow-source): `material-input-missing` / `workflow-source-missing` fail-closed, never a guessed hash.
- **Mirror drift at mint:** `mirror-drift` fail-closed — a mid-edit dispatch fails closed rather than running against drifted mirrors.
- **`git rev-parse HEAD` failure:** `base-commit-unresolved` fail-closed — an unbindable identity is a validation failure.
- **`--check-candidate-commit` on an unbound identity:** `candidate-commit-unbound` fail-closed (can't validate against nothing).
- **Moved candidate commit:** `candidate-commit-moved` fail-closed.
- **`--selftest`:** any sub-check fail ⇒ non-zero exit + diagnostics JSON.
- **Post-Land real evidence (DoD 2, "one real milestone dispatch mints at Verify entry") cannot be produced by B1's pre-Land iteration-0** — the Verify-entry callsite is B4's wiring (B1's Touches exclude `execute-milestone.js`). `it0-dod-check.ts` clause 0 HARD-blocks any unchecked DoD box, so iteration-0's Audit is REFUTED-by-construction on that box. Resolved path (the parent's R8 pattern, clause-9-valid evidence-timing): B1 lands human-steered under a declared EXTERNAL `needs-human` reason; the mechanism-level real proof B1 DOES produce pre-Land is a real subprocess `--create` mint against the live tree (which RECORDS whatever installed workflow content exists, even if stale — staleness detection is B2's receipt comparison); the Verify-entry-callsite proof is reached post-Land after B4 lands.

1. **Workflow wiring** — minting at Verify, bind/re-check callsites, cache replacement, resume dispatch are B4's (`execute-milestone.js` Touches). B1 does not edit either workflow mirror.
2. **Stage journal store, `StageReceiptEnvelope`, `FindingEnvelope`** — B2's (`stage-receipt.ts`, `workflow-journal.ts`).
3. **Verify-cache lookup/persist and resume-plan computation** — B3's (`workflow-resume.ts`).
4. **Editing any read-only input**: `build-evidence-manifest.ts`, `workflow-event-schema.mjs`, `composite-*.ts`, `prepare-*.ts`, `gate-script-lib.sh`, `build-evidence-collector.ts`, the four golden-replay test files (G1).
5. **Rewiring `build-evidence-collector.ts`'s legacy inline runIdentity** — a documented seam; the `toBuildManifestRunIdentity()` projection is the forward mechanism, not a back-edit.
6. **New ESM `import` capability in the workflow DSL** — uses the established `node --experimental-strip-types` agent-dispatch pattern (DD9 of the parent).
7. **Copying authoritative task/Proposal/charter/Plan content into the identity** — hashes only (DD7).
8. **Unifying with `.workflow-events/` or `.quay/gate-events.jsonl`** — each stays its own system; B2 owns the migration boundary.
9. **Detecting a forged sessionId** — mechanically impossible in-module; the property is a wiring fact (R9).
10. **Reading or writing the journal / any telemetry store at mint time** — the mint is deliberately store-free so B1 has no durability dependency.

### Alternatives considered and rejected

- **Alt1 — Echo-and-pass the session id from the workflow prompt (`--create {sessionId: $(echo ...)}`).** The task body's literal shape. REJECTED in favor of env-direct reads: the CLI is a real subprocess that genuinely inherits the orchestrator env (`prepare-admission-check.ts`'s documented distinction, L32-37), and echo-and-pass lets a caller assert any string — weakening the "cannot be forged" property to prose. Env-read keeps it mechanical. The workflow may still echo for logging, but the arg is never authoritative.
- **Alt2 — Random nonce per dispatch for `runId` (a `sessionId:hex` form).** REJECTED: breaks determinism and resume identity — a resumed dispatch would get a new runId, defeating the explicit resume behavior the parent exists to make durable. The attempt-based nonce is monotonic and resume-safe.
- **Alt3 — A `composite: boolean` field in the canonical envelope.** REJECTED: it would bloat the envelope beyond the task's field list; `composite` is a DERIVED property (`taskIds.length > 1`) supplied by the `toBuildManifestRunIdentity()` projection instead.
- **Alt4 — Extend `build-evidence-manifest.ts` / `build-evidence-collector.ts` to use the new identity now.** REJECTED: out of Touches (G1); the projection is the non-invasive seam, and B4/future work routes the collector through it without editing it.
- **Alt5 — A single monolithic `stage-substrate.ts` holding identity + journal + receipts + resume.** REJECTED: B1/B2/B3/B4 map one-to-one onto the four Touches globs, each independently landable and testable (the parent's split-or-commit precedent); a monolith defeats B1's isolated landability.
- **Alt6 — Add ESM `import` support to the workflow DSL to call the factory directly.** REJECTED: no such capability exists (L22/L28); the tested `node --experimental-strip-types` agent-dispatch pattern is the documented mechanism.
- **Alt7 — Make identity minting optional / advisory.** REJECTED: the entire DIR-124-B substrate is built on one canonical identity being mechanically bound at dispatch; an advisory identity would leave the binding that crystallization safety invariant 3 requires unimplemented.
- **Alt8 — Accept a caller-asserted `baseCommit` without verification.** REJECTED (derive-don't-trust, DD3): the CLI derives it from `git rev-parse HEAD` and rejects mismatch, keeping the binding a wiring fact.
- **Alt9 — B1 itself wires the mint/bind/check callsites into `execute-milestone.js`.** REJECTED: the parent split table assigns "mint identity at Verify entry" to B4 (M256), B1's task `## Touches` excludes the workflow mirrors, and `anti-drift-touches-check.ts` enforces those globs mechanically. B1 proves the mechanism and B4 does the wiring; B4 consumes `_runIdentity` and must NEVER re-mint (a second mint would change `runId` mid-run and break every downstream receipt).
