## Proposal

Split from DIR-124-B (M236) — mechanism 2, the **durable stage journal store + hash-bound receipt
envelope**. This child owns `stage-receipt.ts` (the versioned contract module) and
`workflow-journal.ts` (the `StageJournalStore`), both in both mirrors. Per the parent's DD1/DD3/DD7/DD8
+ CLAIM-B2/B3/B6/B7/B8/B9/B10/B11 (→ AC2, AC4, AC6, AC8, AC9, AC10, AC11).

### Chosen mechanism

**`stage-receipt.ts`** — the versioned contract module:

1. `FindingEnvelope`, `StageEvent`, `StageReceiptEnvelope`, `ReceiptValidationResult` — one
   authoritative schema family versioned by explicit bump (DD11). `FindingEnvelope` carries occurrence
   identity, stable `recurrenceKey`, observer/earliest-detectable stage, subsystem/claim reference,
   severity/blocking, evidence references, material input hashes, first/last generation,
   disposition/resolution, and the `task-specific|profile|global` generalization (Requested-action
   item 1, AC2). Generalization is descriptive metadata, never a reuse predicate (AC2, CLAIM-B12).
2. `buildReceiptEnvelope`/`bindReceipt` — bind base/candidate commits, workflow source path/hash/commit,
   runtime generation, and every material input hash (AC3).
3. `validateReceipt` — the fail-closed validator with ONE distinct code per AC6 hazard class (wrong
   base, wrong candidate, modified Plan, stale named-workflow materialization, wrong runtime
   generation, missing artifact, moved candidate commit, tampered receipt) (AC6, CLAIM-B9).
4. `validateEvidenceManifestRef` — hash-validates a bounded Build evidence-manifest reference
   (`{path, sha256}` against the file it names) WITHOUT copying authoritative task/Proposal/charter/
   Plan content; `rejectDuplicateAuthority` is the negative that rejects a receipt embedding copied
   requirements (AC10, CLAIM-B8).
5. `migratePrepareLedger` — the one-way Prepare finding-ledger adapter (`proposal-ledger.json`
   entries → `FindingEnvelope`s with source hashes preserved) (AC9, CLAIM-B7).
6. CLI surface: `--validate-receipt`, `--evidence-manifest-ref`, `--migrate-prepare-ledger`.

**`workflow-journal.ts`** — the `StageJournalStore`:

1. Append-only durable journal at `milestones/M<NN>/stage-journal.jsonl` + `receipts/*.json` under the
   CANONICAL milestone root resolved via `gate_resolve_milestone_root` — the same single-sourced
   resolver Build/Audit/Land use, never a new path convention (DD1, AC4, CLAIM-B10).
2. Atomic write (write-temp-then-rename / line-safe framed append); torn-write rejection — a partial
   trailing record is surfaced, never silently parsed (AC4, CLAIM-B11).
3. One-way migration adapters `migrateDir124AEvent(event)` (AC8, pinned to the LANDED DIR-124-A
   20-field schema field-for-field, appended to the SAME journal so no dual authoritative event
   format remains — CLAIM-B6) and `migrateDir126DTelemetry(record)` (AC9, consumes the committed
   prepare-telemetry record preserving `recordId`/`generationId`/hashes, no reverse writer —
   CLAIM-B7).
4. DIR-118 extension fields declared but inert; no `landed-awaiting-wiring` state, no post-Land Wiring
   Audit dispatch, no `done`-promotion enforcement (AC11, CLAIM-B13).
5. CLI surface: `--append-stage`, `--migrate-dir124a`, `--migrate-dir126d`.

The Verify-cache persistence (`persistVerifyCache`/`loadValidatedVerifyCache`) lives in this same
store module and is exercised by DIR-124-B3; the store's cache-load methods are the contract B3
consumes.

**WIRING-CLAIM (B2-DURABLE-STORE):** `execute-milestone.js` appends a `StageEvent` via
`workflow-journal.ts --append-stage` at each of the seven phase boundaries and writes a hash-bound
`StageReceiptEnvelope` on green boundaries; the store resolves its root via `gate_resolve_milestone_root`
and rejects torn/partial writes. → AC4, CLAIM-B2/B3/B10/B11.

## Acceptance Criteria

- [ ] `stage-receipt.ts` declares `FindingEnvelope`/`StageEvent`/`StageReceiptEnvelope`/
  `ReceiptValidationResult` as ONE versioned schema family; a schema change is a new envelope version,
  never silent field drift.
- [ ] `bindReceipt` mechanically binds base/candidate commits, workflow source path/hash/commit,
  runtime generation, and every material input hash; a receipt with empty `materialInputHashes` is not
  reusable.
- [ ] `validateReceipt` returns ONE distinct fail-closed code per AC6 hazard (wrong base, wrong
  candidate, modified Plan, stale named-workflow materialization, wrong runtime generation, missing
  artifact, moved candidate commit, tampered receipt) as fixed RED/GREEN tests.
- [ ] `validateEvidenceManifestRef` hash-validates a Build evidence-manifest reference;
  `rejectDuplicateAuthority` rejects a fixture embedding copied task/Plan requirements.
- [ ] `workflow-journal.ts` persists `stage-journal.jsonl` + `receipts/*.json` under the canonical
  milestone root resolved via `gate_resolve_milestone_root` (no second path convention); atomic write;
  torn/partial trailing record surfaced, never silently parsed; store survives process/session restart.
- [ ] `migrateDir124AEvent` maps the pinned DIR-124-A 20-field schema field-for-field into a `StageEvent`
  appended to the SAME journal (no dual authoritative event format); `migrateDir126DTelemetry` and
  `migratePrepareLedger` migrate one way with source hashes preserved and no dual-write/reverse
  dependency.
- [ ] DIR-118 extension fields are declared but inert; no `landed-awaiting-wiring` state, no post-Land
  Wiring Audit behavior is introduced.
- [ ] Both mirrors byte-identical (`diff` exit 0); tests RED/GREEN per `scripts/test.sh`.

## Definition of Done

Standard exp5 DoD clauses apply.

- [ ] Landed and mirrored through the plugin packaging path with canonical tests green.

  process/session restart (real dispatch evidence).
- [ ] Independent audit checks receipt bytes/hashes and real caller persistence, not just type
  declarations or fixtures.
