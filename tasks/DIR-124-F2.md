## Proposal

Split from DIR-124-F (M232) — mechanism for the **learning-loop prerequisite**: PlanCheck today
returns only `{findings: <count>, findingsDetail: <string>}` (no typed finding objects), so there is
nothing to classify as `grounded-fact-gap`. This child owns the PlanCheck schema upgrade to TYPED
findings: each finding object carries the DIR-125 typed-finding shape already used by ProposalReview,
plus an explicit `classification` field ∈ {`grounded-fact-gap`, `task-specific`, `other`}.

### Chosen mechanism

Per the parent's Requested-action item 4 + CLAIM 3 (→ the learning-loop prerequisite, which currently
has NO dedicated AC — this child's ACs close that coverage gap):

1. **PlanCheck schema change** in both `prepare-milestone.js` mirrors: the PlanCheck result schema
   upgrades from `{findings: <number>, findingsDetail: <string>}` (line 1511) to
   `{findings: <typed array>, findingsDetail: <string>}`; `_planCheckFindings = typedFindings.length`
   so downstream count logic stays valid.
2. **Typed finding shape** — each finding carries the DIR-125 shape reusing the existing
   `_findingSchema` at line 1022: `{subsystem, summary, severity, blocking, evidence, claimRef,
   disposition, rootCauseKey, repairable}` PLUS an explicit `classification` field ∈
   {`grounded-fact-gap`, `task-specific`, `other`}. Classification is agent-assisted + mechanically
   validated (see DIR-124-F6), not NLP.
3. **Legacy-scalar tolerance** — a scalar PlanCheck return is tolerated exactly as ProposalReview
   tolerates legacy scalars: 0 → pass; nonzero → ONE untyped blocking finding filed into `_ledger`;
   promotion requires typed findings (logged, never silent).
4. **E2E mock / resume-cache compatibility** — the e2e mock
   (`plugin/test/prepare-milestone-preparation-e2e.test.mjs:297` currently returns
   `{findings: 0, sessionId}`) returns `{findings: [], sessionId}`; the `--decide-resume` path keys off
   the result shape; `--plancheck-sessions`/`--plancheck-findings` provenance flags count = typed array
   length, so `milestone-preparation-check.ts`'s `--check` reading `receipt.planCheck.findings` as a
   number stays valid.

**WIRING-CLAIM (F2-TYPED-FINDINGS):** `prepare-milestone.js` (both mirrors) emits PlanCheck findings
as typed objects with an explicit `classification` ∈ {`grounded-fact-gap`, `task-specific`, `other`},
reusing the DIR-125 `_findingSchema` shape. → AC: PlanCheck emits typed findings with classification.
