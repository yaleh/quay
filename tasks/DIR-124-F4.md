## Proposal

Split from DIR-124-F (M232) — the **fact-class reconciliation**. The parent references three
inconsistent fact-class counts: Requested-action item 1 says "Seed it from the **five** fact classes
in `docs/references/repo-ground-truth.md`"; the problem framing calls the evidence-surface class "the
**sixth** fact class (§6)"; and the chosen mechanism enumerates **8** seed sections of
`repo-ground-truth.md` (categories: `cli-paths`, `coverage-format`, `touches-matching`,
`provider-defaults`, `module-signatures`, `evidence-surface`, `subprocess`, `gate-resolution`). This
child owns reconciling those counts into ONE canonical fact-class set so the registry category
whitelist and the seed doc never drift.

### Chosen mechanism

1. **Canonical fact-class enumeration** — the registry's category whitelist is the single source of
   truth, mapping 1:1 to the seed doc's 8 sections:
   `cli-paths`, `coverage-format`, `touches-matching`, `provider-defaults`, `module-signatures`,
   `evidence-surface`, `subprocess`, `gate-resolution`. `evidence-surface` is a first-class category
   (seeded from `inherited-core.md`'s `evidenceSurface` content, matching the problem framing's
   "sixth fact class" — it is class 6 of the 8-section set, not an afterthought).
2. **Prose reconciliation** — update the parent task body + any stale references so the "five fact
   classes" language is corrected to the canonical 8-category enumeration; the registry seed doc
   (`repo-ground-truth.md`) headings are the index, and the category list is enforced at validate +
   promote (unknown category → non-zero exit, fail closed).
3. **Whitelist enforcement** — the TS CLI module owns the category whitelist; a fact with an unknown
   category fails `--validate`/`--promote` closed pre-dispatch.

**WIRING-CLAIM (F4-CATEGORIES-CANONICAL):** the registry's category whitelist is the canonical
enumeration of repo fact classes (the 8 seed-doc sections), and both `--validate` and `--promote`
reject a fact whose category is outside the whitelist. → AC1: registry file exists, schema-validated,
versioned, hash-bound, seeded from the 8 sections + `evidenceSurface`.
