## Proposal

Split from DIR-124-F (M232) — the **learning-loop classification trust** mechanism. Once PlanCheck
emits typed findings (DIR-124-F2), a finding classified `grounded-fact-gap` must promote into the
registry with a version bump — but only through a mechanically validated, agent-assisted path, NOT
NLP. This child owns the promotion path: the PlanCheck agent labels `classification`; the workflow/CLI
mechanically validates category whitelist, duplicate exact-match, and non-blocking eligibility.

### Chosen mechanism

1. **Agent-assisted classification, mechanically validated** — the PlanCheck agent labels each
   finding's `classification` field; the workflow/CLI then validates mechanically: category whitelist,
   duplicate exact-match (by id or exact fact text), and non-blocking eligibility. No fragile
   free-text extractor (parent's Key design decision + item 4).
2. **Promotion rides the finding ledger** — a `grounded-fact-gap` finding merges into `_ledger` (thus
   `milestones/M<NN>/proposal-ledger.json`, hash-bound into the receipt) with a `promoted` disposition
   marker; for each such finding NOT already registered, dispatch `--promote <fact-json>` — the real
   production promotion path, version bump + hash recompute, ledger-disposition-tracked.
3. **Already-registered fact re-surfacing** — a `grounded-fact-gap` finding whose fact is already
   registered (by id or exact fact text) is NOT promoted again — it is flagged as a
   registry-injection defect (the injection failed to surface the fact), reported as a finding, never
   promoted twice.
4. **Re-injection** — on a successful promote, refetch the subset and re-inject into the NEXT
   PlanCheck round so the learning loop closes.
5. **Legacy-scalar tolerance** — promotion requires typed findings; a scalar PlanCheck return is
   tolerated but logged, never silently promoted.

**WIRING-CLAIM (F6-PROMOTION-PATH):** a `grounded-fact-gap` PlanCheck finding promotes into the
registry with a version bump via the finding ledger (`_upsertFindings` → `proposal-ledger.json`,
hash-bound into the receipt) — real production path, not fixture-only; an already-registered fact
re-surfacing is flagged as a registry-injection defect, never promoted twice. → AC4.
