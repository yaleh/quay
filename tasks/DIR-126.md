## Proposal

Treat preparation flow efficiency as a first-class control-plane invariant, not a reporting
afterthought. The next newly-chartered human-steered milestone must take this task before other
open milestone candidates unless a human records a dated override and reason on this task.

Before implementation, run DIR-026 SPLIT-OR-COMMIT against the five mechanisms below. The default
decision is to split them into ordered, independently landable children if more than two require
separate production ownership or proof surfaces. Priority belongs to the whole ordered chain, not
only its first child:

1. **Single-flight admission.** At most one live `prepare-milestone` generation may own a
   `(workspace, taskId)` at a time. A second cold or resume dispatch must fail closed before
   `ProposalAuthors` with a typed `prepare-already-running` result naming the owning run/generation.
   Lease acquisition/release must be atomic, stale-owner recovery must be explicit and
   evidence-based, and a crashed run must not create a permanent lockout.
2. **Deterministic preflight before LLM work.** Mechanically reject or normalize the recurring
   failure classes observed in M192/M195/M196/M198 before dispatching Proposal authors/reviewers:
   malformed Markdown list blocks that merge wiring claims, stale AC/DoD counts or references,
   Proposal/Plan/Touches disagreement, non-existent claimed precedent/imports, and non-runnable
   Plan command/path shapes. Each check needs a stable code and fixture; uncertain semantic
   judgments remain reviewer work rather than being guessed by regex.
3. **Generation-aware resume.** Replace reliance on a manually supplied
   `resumeFromAdjudicatedProposal` boolean with a fail-closed resume decision derived from durable
   generation metadata and hashes. Reuse the current adjudicated/repaired Proposal only when the
   task, charter, Proposal, and prior terminal record prove it is safe. A source/charter change,
   missing provenance, or explicit human reset starts a new generation. Keep the explicit flag as
   a temporary compatibility surface only if required.
4. **Phase telemetry.** Persist mechanically queryable start/end/duration, agent-dispatch count,
   retry count, terminal reason, finding yield, Proposal/Plan churn, and available token-usage
   fields for every preparation phase and generation. Metrics must be produced by the workflow,
   hash-bound into the receipt/ledger where applicable, and obtainable without reconstructing raw
   Claude Code JSONL timestamps.
5. **Capacity calibration.** Replace the single 15–25 minute planning assumption with measured
   distributions by risk/task class. Report at least P50/P85 Prepare time, `prepared/attempt`,
   `absorbed-task/prepare-hour`, duplicate-generation minutes, and Build/Audit escaped findings.
   LOC remains descriptive output, never the productivity target.

Keep fail-closed quality gates. This task optimizes duplicated/repeated work and observability; it
must not weaken independent ProposalReview, PlanCheck, Receipt integrity, wiring coverage, or the
human decision boundary.

## Finding

A read-only audit of Git and Claude Code workflow journals at `4f9122b` for the preceding 24 hours
found:

- M192/M195/M196/M198 issued 17 non-fixture `prepare-milestone` calls; only M195 returned the
  strict terminal outcome `prepared`. Several failed calls left valuable artifacts, so this is a
  workflow-yield signal rather than a claim that 16 calls produced no value.
- M195 consumed about 118 workflow-minutes across two calls. Its successful call took about
  80 minutes, of which PlanCheck consumed about 57 minutes, versus the current capacity document's
  15–25 minute Prepare assumption.
- Two M196 generations for the same task overlapped, adding about 54 duplicate workflow-minutes.
  Five M196 calls consumed about 183 summed workflow-minutes and never reached PlanAuthor; the task
  was ultimately split.
- M198 benefited from the M197 resume flag but still used about 70 in-workflow agent-minutes plus
  three external PlanCheck passes before reaching a final Plan; it had not produced a preparation
  receipt at the audit snapshot.
- The final 24-hour diff added 1,968 production/workflow-code lines and 1,737 test/fixture lines,
  but 7,736 task/plan/audit/milestone-artifact lines. The process artifacts are often useful
  evidence, yet their 2.09:1 ratio over code plus tests shows preparation/proof work is now the
  dominant throughput cost.

The existing workflow already documents a 45/75 minute ProposalReview soft budget and a
three-round PlanCheck cap, but it does not prevent concurrent ownership of one task, run all cheap
structural checks before agent work, or emit complete phase timing directly. M197's explicit resume
flag preserves repaired work but still depends on callers knowing when it is safe to set.

## Acceptance Criteria

- [ ] **Priority is operational, not prose-only:** DIR-126 or its first ordered child is the next
  newly-chartered human-steered milestone. `extra.rank` remains numeric `0`; any exception has a
  dated human override on this task before another charter is committed.
- [ ] **Mandatory split decision:** a grounded DIR-026 SPLIT-OR-COMMIT artifact maps the five
  mechanisms to production owners, proof surfaces, dependencies, and independently landable
  value. More than two independently landable mechanisms results in formal ordered children; no
  oversized single Plan may silently bypass this item.
- [ ] **Single-flight RED/GREEN:** two real concurrent attempts for the same fixture task prove
  exactly one reaches its first agent dispatch and the other returns
  `prepare-already-running`; different task IDs remain independently runnable.
- [ ] **Lease recovery is fail-closed:** active owners cannot be stolen; a fixture with a genuinely
  dead/stale owner recovers deterministically with recorded evidence; crash/restart leaves no
  permanent lockout or unowned live agent generation.
- [ ] **Preflight precedes agents:** fixtures for merged Markdown claim blocks, stale AC references,
  Touches disagreement, missing precedent/import, and invalid Plan command/path each terminate
  with a stable code before `ProposalAuthors`/`ProposalReview`. Valid M195/M197-shaped fixtures
  remain GREEN.
- [ ] **No heuristic overreach:** ambiguous semantic claims are explicitly reported as
  reviewer-required and do not get silently rewritten or rejected by a regex-only check.
- [ ] **Automatic safe resume:** a repaired, hash-matching adjudicated Proposal resumes with zero
  ProposalAuthors/Adjudicate calls; task/charter/source mutation or missing provenance starts a new
  generation or returns a typed human-decision result. Real journals and tests prove both paths.
- [ ] **Telemetry is directly queryable:** one real cold run, one resumed run, one contention
  rejection, and one preflight rejection expose phase start/end/duration, dispatch/retry counts,
  terminal reason, finding/churn metrics, generation ID, and available token usage without parsing
  `~/.claude/projects/**.jsonl`.
- [ ] **Telemetry integrity:** receipt/ledger verification detects tampered or mismatched
  generation metrics; instrumentation cannot turn a failed preparation into `prepared`.
- [ ] **Capacity report is reproducible:** a checked-in command over recorded workflow artifacts
  emits sample count, P50/P85 Prepare time by class, `prepared/attempt`,
  `absorbed-task/prepare-hour`, duplicate-generation minutes, and explicit exclusions. The
  throughput-capacity document is updated from that output and no longer asserts 15–25 minutes as
  the general default without supporting current samples.
- [ ] Both workflow mirrors and any new script mirror are byte-identical/canonicalized;
  convergence, preparation E2E, receipt, packaging, vendor-sync, and full canonical suites pass.
