### 与 DIR-128 的连接（二选一落地判定）

- **DIR-128 阻断项 = `claude` 二进制在 B/C 均缺失**（DIR-128「前置实测」表，2026-08-11 outer ssh 探测）。
- **Docker 不解除该阻断**：容器本身不提供 `claude` 二进制；在容器内装 claude-code（npm `@anthropic-ai/claude-code` 或官方安装脚本）是可能的，但那是「容器方案设计」的一部分——人已明确**「不代设计」**。
- **两个方向解决不同问题**：DIR-127（Docker）= 验证 quay 的隔离（隔离规格 `orchestration/SPEC-isolation-and-resource-governance-2026-08-05.md`：6 起事故容器化可挡、cgroup 限额不可被绕过、容器边界）；DIR-128（claude-deepseek）= B/C 上起 outer/inner 的命令行 + env 形态。
- **新证据对判定的影响**：B/C 的 Docker 前置已满足 ⇒ 若未来人选择 Docker 方向作为隔离载体，载体已就绪；但**它不能替代给 B/C 装 `claude`**——DIR-128 保持阻断，其剩余前置仍是「B/C 装 claude + C 的 quay checkout」，与 DIR-127 的容器方案是两个独立的后续落点。

### 决策：转出（不落地方案设计）

- **方向归属记录完整**（DoD ②）：DIR-127=Docker，DIR-128=claude-deepseek，B/C 前置核实后二选一落地——已在本体。
- **前置核实完成且全 met，但未触发落地**（DoD ③）：Docker 可用是「载体就绪」，不是「选择 Docker 方向替代 DIR-128」；DIR-128 的阻断（claude 二进制）与 Docker 正交 ⇒ **不新建执行分支，无未记录分支残留**。
- **容器方案设计**（隔离边界 / 镜像 / A/B/C 覆盖 / quay 自举）留给未来任务，遵循人「不代设计 / 非当前紧急项」约束——AC2 保持未勾，待未来设计容器方案时再更新。
