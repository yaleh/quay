## Proposal

**人的裁定（2026-08-11 14:3xZ，逐字意图）**：在 B/C 上进行开发时，都应使用 `claude-deepseek` + `deepseek-v4-flash`，命令行应与本机当前 outer/inner 的命令行一致。已核实本机实际命令行（`quay-launch.sh --dry-run` 实测）：

```
outer: claude-deepseek --settings <repo>/.claude/launch.settings.json --exclude-dynamic-system-prompt-sections --prompt-suggestions false --model deepseek-v4-flash -n quay-outer
inner: 同上, -n quay-inner
```

**注意**：`--settings` 路径是本机绝对路径，在 B/C 上需指向各自本地 checkout 的对应 `launch.settings.json`（若 B/C 上有 quay 仓库 checkout 的话；若没有，这是 DIR-127 Docker 独立环境方向要解决的前置）。

**按 DIR-028「指令是 task-canonical」立案记录**（label:directive）。**决定权已交 outer**；**不代 outer 判断 B/C 当前是否已具备跑 outer/inner 会话的条件**（`quay-launch.sh` 依赖 jq、需要 `claude-deepseek` 命令本身在 B/C 上可用等前提未核实）。

### 范围约束（人明确）

- **命令形态与本机一致**：`claude-deepseek` + `--settings` + `--exclude-dynamic-system-prompt-sections` + `--prompt-suggestions false` + `--model deepseek-v4-flash`，`-n quay-outer`/`-n quay-inner`。
- **--settings 路径按各自本地 checkout 解析**：B/C 上指向各自 `launch.settings.json`，不是本机绝对路径照抄。
- **前置未核实**：B/C 是否已有 checkout / `claude-deepseek` 是否可用 / jq 是否在位——outer 后续核实；没有则先解决前置（可能归 DIR-127 Docker 方向）。
