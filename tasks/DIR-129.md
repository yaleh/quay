## Proposal

任何"立案新任务"（对方已写好或近乎写好任务体的请求）默认改用 `plugin/skills/quay-file-task/SKILL.md`
（`/quay-file-task`）直接落笔，不再路由给 outer 处理这一类；outer 承担的其它职责（缺陷路由/归因、
方向裁决转达等真正需要判断的类别）不受影响，继续走现有路由。

## Finding

对话中实测审计了 `quay-outer`（tmux `quay-0:@33.%33`）过去 48 小时（2026-08-30T12:39Z ~
2026-09-01T12:39Z）收到的全部 70 条跨会话消息与它自己产生的 52 个持久动作（50 commit +
1 CronDelete + 1 develop push）：按诉求类型归类后，"请立案新任务"这一类命中 15 条、**转化率
100%**，且样本显示对方（director/manager）通常已经把任务体全文写好，outer 在这类请求里做的
判断很薄——校验四件套形状 + 查重 + 落笔提交，机制性动作居多。同期还发现 outer 自己的定时
机制（cron，`*/20 * * * *`）14 次自触发**全部空转/被动观测，0 次直接产出**，且它在窗口内已
自行判定该 cron 驱动的是已退役指令并删除了自己的定时器（`CronDelete`，17:13:04Z）。

**已经做的事**：把"立案新任务"这一薄判断的机制拆成独立 skill——`plugin/skills/quay-file-task/SKILL.md`
（已落 `develop`）。它复用 `quay-directive` 同款 TASK-CANONICAL 纪律（task_write 直写，无副本文件），
补上 `author` skill 之前缺的一环（`author` 推进已存在的 todo→ready，本 skill 负责创建 todo 任务
对象本身），并做了 shape-aware 四件套校验、Touches 纪律、按机制去重、id 冲突检查、落地前
`task-schema-check.ts` + `task check` 自检。

**实测验证（两轮，各覆盖两种宿主）**：
- 第一轮暴露真实问题：`task_write`（MCP）恒定写共享主检出、不跟随调用者 cwd/worktree（隔离
  subagent 与不受约束的直接会话，落盘位置完全一致）；`EnterWorktree` 对 Agent 工具 spawn 的
  pinned-cwd subagent 结构性拒绝。据此把 Step 8 由"两条路径各走 worktree+merge"改正为"两种
  宿主都直接 `task_write` + 直接 `git commit`，无需 worktree"。
- 第二轮复核（改正后）：两种宿主（不受约束的直接会话 / 受 harness worktree-isolation 约束的
  subagent）**均一次成功、全程无 worktree 绕行**，直接确认改正有效。
- 四个验证任务（`gap-quay-file-task-skill-verify-mode-{a,b}-{direct,isolated}[-v2]`）均已创建
  即置 `status: superseded`，不占用活跃池。

**范围限定（不要扩大解释）**：本裁定只覆盖"请立案新任务"这一类诉求（对话中归类的第①类，
15/70、100% 转化）。缺陷路由/归因请求（14/70，86% 转化，需要真诊断）、方向裁决转达
（4/70，需要执行判断）等其它类别**不在本次调整范围**，继续走现有路由，不因本裁定停摆或
自动改道。outer 本身不退役（人 2026-09-01 已裁定，暂不退役），本裁定只是把它承担的诸多职责中
判断最薄、机制性最强的一类挪到一个可直接调用、不依赖 outer 常驻会话的 skill 上。

## Requested action

1. 任何需要"立案一个新任务"的场景（manager 自己发起、或转达 director/human 已经写好任务体的
   请求），默认调用 `/quay-file-task` skill，不再路由给 outer 处理这一类。
2. 若发现某个"立案"请求实际上夹带了需要判断的诊断/路由成分（不是纯粹的立案），仍按现有路由
   处理那部分，不要为了套用本裁定而把判断部分也塞进 quay-file-task skill 的机械流程。
3. `quay-manager` 这一层会话当前（2026-09-01 14:4xZ 核实）**未在运行**（`ps aux` 查无对应进程，
   job 状态文件停在 2026-08-31T03:07，tmux `quay-0` 下只有 `claude`/`outer` 两个窗口，无 manager
   窗口）——本裁定通过 SendMessage 即时通知的尝试因此未能送达，全靠本 directive 作为正本；
   manager 或任何 drain-directives 机制下次运行时应读到并执行第 1 条。
