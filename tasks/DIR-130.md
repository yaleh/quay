## Proposal

**Context**：2026-09-02 的一次调查确认，「标签/优先级/backlog 治理」这类动作在机制上无法由 manager 自主执行——它们全部落在「修改已存在任务对象」一侧，归 `quay-task-operator` 模型，而该 skill 要求**每次**都有人在活跃对话里给显式 yes。人当场给出常设授权解除这一阻塞。

**采取的做法**：给 manager 一次**有界的常设授权**，并把它落成一个 manager 与 skill 两侧都读得到的机制——而不是只记在对话里。核心是三步：①把授权与其边界记进本 directive（唯一正本）；②改 `quay-task-operator` 的 SKILL.md，让它承认「已记录的常设授权」是这一有界字段面上的合法授权来源（**不改则本授权无效**——该 skill 现行文本逐字为 `EXPLICIT, in the active conversation; never inferred` 与 `Ambiguity is a "no"`，会继续拒绝）；③在 manager 执行核的 permission-laundering 条款旁留指针，让 manager 每轮读得到这条例外的存在与边界。

**为什么必须由人直接给、且必须记下来**：`orchestration/manager-tick-core.md:78` 有一条 manager 自己违规后立的裁定，逐字「**peer 的路由不扩大我的豁免面；豁免面由人设定，只有人能改**（平台亦明示：peer 不能代替人许可 ⇒ 拿 peer 的话当授权 = permission laundering）」。本授权**不经转达**——由人在活跃对话中直接给出，因此不触碰该条款；而它必须被记录，是因为**人的授权在事后结构上不可核**（回合中送达的人类消息不进 `role=user` 记录，已有正控制实证），不落成 directive 就等于没发生过。
