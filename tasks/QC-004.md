## Proposal

`packages/quay-native/skills/author/SKILL.md` and
`packages/quay-native/skills/execute/SKILL.md` both carry a standing gap note:

> "No subagent-dispatch primitive exists in this environment"

This note was accurate through experiment 1's iteration 88 and experiments
2's iterations 0-3 (daemon not reachable; `mcp__plugin_manda_manda__Agent`
confirmed available as a deferred tool but daemon-conditional).

**Experiment 2, iteration 4** has produced new, primary-source evidence that
changes the precision of this note:

1. The manda daemon IS live as of iteration 4 — `curl http://localhost:46215/healthz`
   returns `{"root":"/home/yale/work/quay"}` (exit 0). Port is in
   `.manda/hub.addr`, not the previously-assumed 28912.
2. A live `manda monitor cord` process is running (confirmed: PID 720369 and
   1065935 via `ps aux`), owned by the orchestrator session.
3. `mcp__plugin_manda_manda__Agent` was invoked with `to: "cord"`,
   `timeout: 90` — returned `{"output":"PONG"}` (success, first attempt).
4. DIR-020 hard rule: a manda depth-1 caller must never be the same session
   as the broker. This session (iteration-4 subagent) is NOT the cord broker
   (the orchestrator session owns cord). So the call was correct.

The standing note "No subagent-dispatch primitive exists in this environment"
is now demonstrably imprecise. The correct current state is:
"A conditional manda-proxied Agent is available when the daemon is live and
a monitor/broker session is armed on a named channel. DIR-020: caller must
differ from the broker session. As of iteration 4, one successful trial
(PONG) was executed. Reliability track record: 1 successful call."

This task updates both Skill files' "Gaps" sections to replace the imprecise
standing note with this specific, evidence-backed current state.

G5: no changes to any package source files (`packages/quay/`, etc.). Only
Skill documentation files (`packages/quay-native/skills/`) are modified.
