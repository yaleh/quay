## Proposal

The quay-core-bootstrap experiment's iterations 0-3 all probed the manda daemon
at `http://localhost:28912/healthz`, received exit 7 (connection refused), and
concluded the daemon was not reachable. In iteration 4, primary-source inspection
of `.manda/hub.addr` revealed the actual daemon address is `http://localhost:46215`
— a different port. The daemon was likely live in all prior iterations; only the
probe address was wrong.

This is a genuine finding that affects any future iteration, any future experiment,
or any developer working with this repo's manda setup. The `.manda/` directory
currently contains only `config.yml` and `hub.addr` — neither file documents the
discovery convention (always read `.manda/hub.addr` for the actual address; never
assume a fixed port like 28912). A brief `NOTES.md` in `.manda/` would make this
institutional knowledge permanent and checkable, rather than embedding it only in
experiment iteration reports.

The approach: create `.manda/NOTES.md` documenting (a) the hub address convention,
(b) the port-discovery finding from iteration 4, and (c) the precondition check
that future iteration prompts should use.
