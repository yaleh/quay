## Proposal

`quay:execute` (`packages/quay-native/skills/execute/SKILL.md`) is, like
`quay:author` was before iteration 1, a written-but-unexercised v0 port of
the seed's `primitive-executor`/`fixpoint-convergence` pattern. Per the
protocol's fixed per-Skill retirement order (decision §10.2: `quay:author`
retires its seed dependency **before** `quay:execute`), iteration 1's scope
is explicitly authoring-side only — `quay:execute` is deliberately **not**
exercised this iteration (its execute_by remains `seed` for any task driven
to `done` between now and whenever `quay:execute` is retired).

This task (QN-004) is itself an **authoring** task about `quay:execute` — it
is in scope for `quay:author` to drive to `ready` in iteration 1, exactly
like QN-003 (the analogous authoring task for `quay:author` itself). Driving
QN-004 to `ready` does **not** mean `quay:execute` has been exercised; it
means the *plan* for retiring its seed dependency has been authored. Actually
executing that plan (making `quay:execute` self-host for real) is future-
iteration work, per the retirement schedule.

**Approach:** apply the same environment-capability honesty established for
`quay:author` in QN-003 to `quay:execute`'s own SKILL.md — name its Layer-1-
equivalent steps (implement-phase, self-audit-AC, independent-adjudicate)
with explicit dispatch-capable-target vs. degraded-fallback behavior, given
the same demonstrated environment finding (no subagent-dispatch primitive
available). Additionally, since `quay:execute`'s own "Gaps" section already
names the sharpest problem — "No independent adjudicate-style audit is built
into this Skill itself yet... design §5's review independence contract for
execution is not enforced by tooling" — this task's plan must also state,
concretely, what "retiring the seed dependency" will require operationally
when a future iteration actually executes it: a genuinely independent audit
step (G3) wired into the execute path itself, not just relied upon
externally as iteration 0/1 did via a separate `experiments/quay-native-bootstrap/audits/*.md` file.

## Plan

- Phase 1: rewrite `quay:execute`'s "Method" section (currently one
  unstructured sequence) into named steps mirroring `quay:author`'s new
  structure (QN-003): `implement-phase` (Red/Green per Plan phase),
  `self-audit-ac` (check AC boxes only when independently re-verified),
  `gate-check`. Each step states its dispatch-capable-target behavior and
  its degraded-mode fallback, consistent with QN-003's precedent.
- Phase 2: add an explicit "independent audit requirement" note stating that
  `execute`'s own self-audit step is **not** a substitute for G3's
  out-of-band audit — the gate transition to `done` should be treated as
  provisional until a separate adjudicate-style check co-signs it (this
  documents, in the Skill itself, the exact discipline iteration 0/1 have
  been applying manually via `experiments/quay-native-bootstrap/audits/`).
- Phase 3: no code change — this is a SKILL.md-content-only task, same shape
  as QN-003. Verified by re-reading the file for the four required elements
  (named steps, dispatch/degraded statement, independent-audit note, updated
  Gaps).
