## Proposal

The iteration-4 independent audit
(`experiment/audits/iteration-4-independent-adjudicate.md`, "Bugs / concerns
for a real GitHub Provider user") found 3 real, live gaps in
`packages/quay-github/src/github-client.js`:

1. `parent`/`children` are unconditionally `null`/`[]` for every GitHub task
   — no mapping at all, even though a documented, low-cost convention
   (task-list checkboxes in issue bodies) exists and is cheap to read.
2. `list()` has no pagination/scale safety net — `--paginate` alone walks an
   unbounded number of pages for a large repo, with no cap, no per-page size
   control, and no clear failure mode when a repo grows large.
3. Multiple `status:*` labels on one issue silently resolve via
   iteration-order last-write-wins (an accident of GitHub's unspecified
   label ordering), with no documented tie-breaking rule and no test case.

This is the concrete content for this iteration's exercise of the
epic/compound decomposition branch (design §4), which has never been tested
end-to-end in this experiment: every task authored so far (QN-001 through
QN-007) has been a single-leaf primitive task.

**Decompose test (design §4): "declare an epic only if >= 2 independently
mergeable deliverables have real margin over a single-PR ceiling."** Applying
that test here, during this Plan/review-plan step:

- The 3 fixes touch **different files/concerns** in `github-client.js`:
  fix 1 (relations mapping) adds new parsing logic + a `buildParentIndex`
  helper + changes `issueToViewModel`'s signature; fix 2 (pagination) is a
  self-contained change to `createGithubClient`'s fetch loop only; fix 3
  (label tie-breaking) is a self-contained change to the label-parsing loop
  inside `issueToViewModel` only.
- Each is **independently testable and independently mergeable** — none
  depends on either of the others being present to be correct or to be
  verified (fix 3's test does not need fix 1 or 2's code paths touched, and
  vice versa).
- Each has **real margin** over folding all 3 into one undifferentiated
  "fix bugs" leaf task: a reviewer (or this same-session self-audit) can
  accept/reject fix 2 (pagination) without needing to also evaluate fix 1's
  new checkbox-parsing convention, and vice versa — a genuine benefit of
  splitting, not decomposition for its own sake.

**Conclusion: this qualifies as an epic.** Split into 3 children:

- **QN-009** — fix 1: parent/children mapping via task-list checkboxes.
- **QN-010** — fix 2: pagination/scale safety net (capped batch fetch).
- **QN-011** — fix 3: status-label tie-breaking precedence rule + test.

## Plan

**Phase 1 (authoring, this task):** create QN-009/QN-010/QN-011 as `todo`
children, each with its own Proposal/Plan/AC/DoD scoped to exactly one of
the 3 fixes above. Link them via this task's `children` field. This task's
own role then derives to `compound` (design §2: children non-empty =>
compound), and this task's own status moves to `ready` once children exist
and this task's own 4 artifacts (this Proposal/Plan/AC/DoD) pass the
`todo->ready` gate.

**Phase 2 (execution, driven by `quay:execute`'s `executeEpic` branch,
design §4):**
1. Ensure children exist (done in Phase 1).
2. Drive each child through its own full `todo -> ready (author) -> done
   (execute)` lifecycle via `quay:author` + `quay:execute` (recursive
   dispatch, same-session degraded-fallback mode per both Skills' own
   Gaps sections -- no subagent-dispatch primitive exists in this
   environment, confirmed again this iteration).
3. **Integration acceptance** (this epic's own AC/DoD, below) at the
   assembled-system level: once all 3 children are `done`, re-verify
   (a) `packages/quay-github/test/view-model.test.mjs` passes as a whole
   (not just each fix's own isolated assertions), (b) the full quay-native
   regression suite (`abi-symmetry.mjs`, `gate-correctness.test.mjs`,
   `lock.test.mjs`) still passes (no cross-package regression), (c) a live
   `quay task list --provider github --json` call against the real
   `yaleh/quay` repo still returns correct, non-crashing output reflecting
   all 3 fixes simultaneously active.
4. If integration acceptance passes: `quay-native task edit QN-008 --status
   done`. If it fails: `needs-human`, do not force it.
