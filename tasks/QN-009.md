## Proposal

Child task of QN-008 (epic decomposition, design §4). Scopes exactly one of
the 3 independently mergeable fixes from QN-008's Plan: fix 1, the
`parent`/`children` mapping gap in `packages/quay-github/src/github-client.js`
(iteration-4 independent audit, bug #1 — `parent: null, children: []`
hardcoded for every GitHub-backed task).

GitHub's native sub-issues REST/GraphQL API requires an org-level preview
opt-in and a heavier API surface than this read-only v1 Provider warrants
(G5 — disproportionate effort). Instead, GitHub's markdown task-list
checkbox syntax already present in issue bodies (`- [ ] #12`, `- [x] #12`)
is a cheap, git-visible, zero-extra-API-call convention for expressing
parent -> children links: the issue whose body contains the checkbox is the
parent, the referenced issue number is a child.

## Plan

1. Add a `CHILD_CHECKBOX_RE` regex and `extractChildRefs(body)` helper to
   `github-client.js` that parses an issue body for `- [ ] #N` / `- [x] #N`
   lines, returning de-duplicated `gh-<n>` child ids in order of first
   appearance.
2. `issueToViewModel` populates `children` directly from the issue's own
   body (cheap, works for both `list()` and single-issue `get()`).
3. `parent` requires scanning *all* issues' bodies (reverse index) — add a
   `buildParentIndex(issues)` helper that `list()` calls once over the full
   fetched issue set, then passes the resulting map into each
   `issueToViewModel` call. `get()` (single-issue lookup) cannot cheaply
   build this index, so `parent` stays `null` there — a documented,
   narrower limitation, not a silent regression.
4. `role` is re-derived from `children.length > 0` (design §2 convention),
   so a GitHub issue with checkbox-referenced children now correctly
   reports `role: "compound"`.
5. Ambiguity handling: if more than one issue's checkbox list references the
   same child, `parent` resolves to the first found, and the full list of
   referencing issues is surfaced via `extra.multipleParents` (not silently
   dropped).
6. Add `packages/quay-github/test/view-model.test.mjs` covering: children
   parsed + de-duplicated; role derives to compound/primitive correctly;
   parent populated via a caller-supplied parentIndex; parent stays null
   without one; ambiguous multi-parent case surfaces via `extra`.
7. Update `packages/quay-github/DESIGN.md` §3 (view-model mapping table) and
   add a §3.2 subsection documenting the convention, its scope, and its
   deliberately-out-of-scope alternative (sub-issues API).
