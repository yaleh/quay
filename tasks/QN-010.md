## Proposal

Child task of QN-008 (epic decomposition, design §4). Scopes exactly one of
the 3 independently mergeable fixes from QN-008's Plan: fix 2, the missing
pagination/scale safety net in `packages/quay-github/src/github-client.js`'s
`list()` (iteration-4 independent audit, bug #2 — `--paginate` alone walks
an unbounded number of pages for a large repo, with no cap, no per-page size
control, and no clear failure mode as a repo grows).

This is a self-contained change to `createGithubClient`'s fetch loop only —
independent of fix 1 (relations mapping) and fix 3 (label tie-breaking),
neither of which touch how issues are fetched from the API.

## Plan

1. Replace the single unconditional `gh api ... --paginate` call with an
   explicit page-by-page loop: request `per_page=100` and increment `page`
   until a batch returns fewer than 100 results (natural end) or a hard
   ceiling (`DEFAULT_MAX_ISSUES = 500`, overridable via
   `QUAY_GITHUB_MAX_ISSUES`) is reached.
2. If the ceiling is reached without hitting the natural end, throw a clear,
   descriptive error naming the repo and the cap, rather than silently
   truncating results or silently continuing to fetch unboundedly.
3. Do not build a caching layer, a streaming API, or server-side field
   selection — out of scope for v1 (G5); this is a safety net, not a full
   scale solution. Document this explicitly as a known, deliberate
   limitation in `DESIGN.md`.
4. No live large-repo fixture is available to exercise the actual throw path
   without creating an artificially large real GitHub repo (disproportionate
   for this fix) — the fix is verified by code inspection, the documented
   cap/override mechanism, and confirming `yaleh/quay`'s 4 real issues still
   round-trip correctly through the new paged-fetch loop (well under the
   cap, exercising the natural-end path).

## AC

- [x] `list()` fetches issues via an explicit `per_page=100` paged loop
      (not a single unconditional `--paginate` call), stopping at the
      natural end (a page returning fewer than 100 results).
- [x] A hard ceiling (`DEFAULT_MAX_ISSUES`, overridable via
      `QUAY_GITHUB_MAX_ISSUES`) is enforced; reaching it throws a clear,
      descriptive error rather than silently truncating or looping forever.
- [x] The change is scoped to `createGithubClient`'s fetch loop only — no
      change to `issueToViewModel`'s mapping logic (verified via `git diff`
      touching only the intended function).
- [x] `DESIGN.md` documents the cap, the override env var, and the explicit
      scope limitation (no caching/streaming/field-selection).
