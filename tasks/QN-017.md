## Obsolete (2026-07-21)

authored **deliberately-needs-human** to exercise `quay:author`/`quay:execute`'s design-§5 fresh-context
reviewer-independence path under a precondition confirmed absent across exp4's 7 iterations: **no
subagent-dispatch primitive in the executing environment**. That precondition is **now false** — the
exp5 environment HAS subagent dispatch (the `Agent` tool), and every exp5 milestone (M77–M88) runs
dispatched build + fresh-context audit subagents. exp4 is concluded; this fallback-branch probe is no
longer live work. Marked obsolete (NOT `done` — its AC was never satisfied; NOT a live gap — its premise
changed). Kept for provenance; excluded from active selection.

## Proposal

This task is authored **deliberately to fail** — not "hard," but unsatisfiable
by construction, per iteration 6's top-priority recommendation
("author a task with an AC requiring a provably false invariant, or a real
environmental precondition confirmed absent from this environment before
authoring"). Its purpose is narrow and explicit: to genuinely exercise
`quay:execute`'s (and, by extension, `quay:author`'s) `needs-human` fallback
path, which has never been reached in 6 iterations despite two good-faith
"hard task" attempts (iteration 5's QN-008 epic, iteration 6's QN-015
compare-and-swap primitive) — both of which happened to pass on the first
attempt, which is honest but leaves the fallback branch itself completely
unproven.

**The precondition, confirmed absent, not hypothesized:** every iteration
since iteration 1 has run an explicit `ToolSearch` check for a subagent-
dispatch primitive in this environment (a `Task`/`Agent`-equivalent tool
capable of launching a genuinely separate, fresh-context session). None has
ever been found — re-confirmed again at the start of *this* iteration (7),
the seventh consecutive confirmation. `quay:author`'s own SKILL.md (Gaps
section) and `quay:execute`'s own SKILL.md (Gaps section) both already state
this as a standing, real environmental limitation, not a maybe.

**Why this AC is provably false, by construction, right now:** design §5
requires each Layer-1 operation Skill step (`write-proposal`,
`review-proposal`, `write-plan`, `review-plan`) to run in its own fresh-
context subagent for genuine review independence. `review-proposal` cannot
be dispatched to a fresh-context subagent if no subagent-dispatch primitive
exists in the environment executing this task. This is a real environmental
fact (verified this iteration, not assumed from memory), not a subjective
"how hard is this" estimate — which is exactly the distinction iteration 6
identified as missing from its own "hard" tasks (QN-008/QN-015, both of
which turned out to be achievable in one honest pass because their
difficulty was a subjective author estimate, not a structural
impossibility).

**What this task's AC will require, honestly, before any implementation is
attempted:** a specific, unambiguous claim ("Step 2 (`review-proposal`) of
this very task's own authoring pass was performed by a genuinely separate,
freshly-dispatched subagent — not the same session that wrote the
Proposal") that is mechanically false to satisfy in this environment as of
this iteration's own re-confirmed `ToolSearch` result. This is the honest,
deliberately-constructed failure case this experiment has been missing —
distinguished explicitly, in this Proposal itself (not backfilled after the
fact), from a "hard" task that might or might not pass.

**What this task is NOT:** it is not organic backlog work, and it does not
pretend to be. It exists specifically to test the `needs-human` fallback
mechanism itself. This is recorded honestly in this Proposal, in the
provenance log, and in the iteration report — not disguised as ordinary
feature work.

## Plan

1. Attempt to author this task's own `review-proposal` step (the second of
   `quay:author`'s four Layer-1 steps) using the environment's
   dispatch-capable path: search for a subagent-dispatch tool
   (`ToolSearch`), and if genuinely found this iteration (which would itself
   be a significant, unplanned finding), actually use it. This step is
   performed honestly — if a dispatch primitive unexpectedly exists now,
   this AC would in fact be satisfiable and this task would no longer be a
   valid adversarial case; that outcome is itself reported honestly rather
   than suppressed.
2. If (as expected, and as re-confirmed at the top of this iteration) no
   dispatch primitive exists, this task's `review-proposal` step runs in the
   only mode available: the same-session degraded fallback already
   documented in `quay:author`'s SKILL.md. This satisfies "the Skill's
   documented degraded-fallback contract" but does **not** satisfy this
   task's own AC item 1 below, which specifically requires the
   dispatch-capable path, not the fallback.
3. Run `quay-native task check QN-017` honestly. Because AC item 1 cannot be
   checked true without fabrication (there is no genuinely separate
   subagent that reviewed the proposal), it must remain unchecked. The gate
   will therefore report `ok: false` (missing/incomplete AC), which is the
   `author->ready` gate's own honest signal that this task cannot proceed
   past authoring in its current environment — the direct analogue of
   `executeEpic`'s `needs-human` fallback, one status transition earlier
   (`author->ready` here, rather than `execute->done`, since this task's
   impossibility is structural at the authoring/environment-capability
   level, not at the execute/implementation level).
4. Do not force the checkbox. Do not silently relabel the requirement to
   something achievable. Record the honest outcome as this iteration's
   direct answer to the standing "needs-human/fallback path has never been
   exercised" gap: this task demonstrates the analogous authoring-side
   gate correctly refusing to pass a task whose AC cannot be honestly
   satisfied in this environment, and by extension confirms what would
   happen if such a task somehow reached `ready` and were handed to
   `quay:execute` — it would have to report `NeedsHuman`, because its AC
   cannot be honestly checked true either at execute time, for the same
   structural reason.
5. Leave the task at `todo`, with the honest gate-check output
   (`quay-native task check QN-017 --json`) captured verbatim in this
   iteration's report, as the first genuine (not manufactured, not
   organically-arrived-at) exercise of the "gate correctly blocks
   forward progress and the honest next step is `needs-human`/human
   escalation" mechanism in this experiment's history.
6. Explicitly do NOT attempt to "fix" this task by inventing a fake
   dispatch primitive, stubbing one out, or reinterpreting the AC to make
   it pass — doing so would defeat the entire purpose of constructing a
   genuinely unsatisfiable case and would be exactly the kind of dishonesty
   G1/G3 exist to prevent.
