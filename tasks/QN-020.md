## Proposal

Iteration 7's QN-017 genuinely exercised the `needs-human` fallback, but via
`executeLeaf`'s path (a plain, non-compound task whose `execute->done` gate
failed). Iteration 7's own report and this experiment's provenance log both
named, explicitly, that `executeEpic`'s own, structurally distinct
epic-integration-level `needs-human` branch — `integrationAccept: Fail ->
NeedsHuman("integration acceptance failed")` — remains unexercised. This is
a genuinely different code path in `quay:execute`'s own spec: `executeLeaf`
routes to `needs-human` when a single task's own gate fails; `executeEpic`
routes to `needs-human` when a child *cannot* be driven to `done` (so
`driveEach` cannot complete) or when the epic's own integration acceptance
fails *after* all children are done. Iteration 7 left this explicitly open
as a question for a future iteration's honest judgment (not decided by
fiat) — this task decides it: the two branches are structurally distinct
enough (different trigger condition, different pseudocode branch, different
Skill-method step) that the general leaf-level proof does not, by itself,
demonstrate the epic-level branch behaves as documented. This task closes
that open question with a real, mechanically-produced exercise, rather than
leaving it as a permanently-open "maybe adequately covered" assumption.

**The construction, deliberately unsatisfiable (not merely "hard"), mirrors
QN-017's own honest methodology:** this epic (QN-020) has one child
(QN-021) whose AC requires the exact same real, re-confirmed-absent
environmental precondition QN-017 used (no subagent-dispatch primitive
exists in this environment, re-confirmed this iteration, the 8th
consecutive `ToolSearch` confirmation) — so QN-021 cannot honestly reach
`done` for the same structural reason QN-017 could not. Since QN-021 cannot
reach `done`, `executeEpic`'s `driveEach` step cannot complete
(`ensureChildrenExist` succeeds, since QN-021 already exists as a task, but
`driveChildToDone(QN-021)` cannot terminate in `Done`), which is itself a
distinct way to reach `executeEpic`'s `needs-human` outcome — not by a
failing *integration* check after all children complete, but by a child
that structurally cannot complete at all. This is recorded honestly as
testing the "child cannot be driven to done" sub-case of the epic branch,
distinguished explicitly from the "all children done, but integration
acceptance itself fails" sub-case, which remains a further, even narrower
open question after this task (see Gaps note below, added to
`quay:execute`'s own SKILL.md).

**What this task is NOT:** it is not organic backlog work. It exists
specifically to test `executeEpic`'s own distinct code path, exactly as
QN-017 was constructed to test `executeLeaf`'s. This is recorded honestly
here, in the provenance log, and in the iteration report.

## Decompose-test honesty note (read before treating this as a routine epic)

This epic has exactly one child, not "≥2 independently mergeable
deliverables" — on its face this would normally fail design §4's own
decompose test, which this Skill's own Method requires be applied honestly,
not rubber-stamped. This is recorded explicitly: QN-020 is authored as a
compound (epic) task **not** because the underlying work has genuine
multi-deliverable margin, but because `executeEpic`'s own code path is
triggered by `task.role === "compound"`, which is derived purely from
`children.length > 0` (design §2) — a task with even one child is
mechanically compound, regardless of whether the decompose test's
"editorial" justification (≥2 deliverables) would separately endorse
epic-ness. This is a deliberate, honestly-declared exception to the
decompose test's normal editorial judgment, made **solely** to exercise the
`executeEpic` code path itself — exactly as QN-017 was an honestly-declared
exception to "organic backlog work," for the same underlying reason
(testing fallback machinery requires deliberately constructing the
triggering condition, not waiting for it to arise organically). This is
recorded here, prominently, rather than silently pretending QN-020 is an
ordinary 2-deliverable epic.
