## Proposal

QN-022's own Plan requires a real, genuinely-completable child so that
`driveEach` can actually drive it to `done` (unlike QN-020/QN-021, where the
child was deliberately unsatisfiable). This task's own scope: independently
re-verify, by direct code inspection and a live gate-check, that
`store.js`'s compound `execute->done` branch (`check()`'s `"ready"` case)
ANDs `acOk` and `childrenOk` as two genuinely independent boolean terms
(`const ok = acOk && childrenOk;`, `store.js` line ~413) — i.e., that the
gate's own reason-selection logic (`if (!acOk) ... else if (!childrenOk)
...`) correctly attributes failure to the right term rather than conflating
them, which is exactly the property QN-022 needs to hold for its own
adversarial case to mean what it claims to mean. This is real, genuine
verification work with an honestly satisfiable AC — not adversarial by
construction, unlike its parent.
