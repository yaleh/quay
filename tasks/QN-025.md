## Proposal

Iteration 10 discovered, incidentally (not by design), that
`quay-native task create` has no validation on its `id` positional
argument: `bin/quay-native.js`'s `create` handler reads
`const id = positional[0];` and passes it straight to `store.write(id,
patch)` with no check that a value was actually supplied. A `task create`
invocation missing its `id` argument produces the literal JS string
`"undefined"` interpolated into the filename (`tasks/undefined.md`),
polluting the real task corpus with a stray file. Iteration 10 caught and
removed one such stray file via a routine `git status` check, but flagged
this as a real, unfixed CLI-hardening gap and carried it forward as "a
good candidate for a small iteration-11 fix if no larger natural task
exists" (`experiments/quay-native-bootstrap/iterations/iteration-10.md`, Problems §4).

This iteration's mandatory corrective work (retracting the fabricated
DIR-001/DIR-002 attribution) is the first-class priority; this task is
scoped deliberately small and mechanical so it does not distract from
that work, while still closing a genuinely evidenced, not manufactured,
gap.

## Plan

1. In `packages/quay-native/bin/quay-native.js`'s `create` subcommand
   handler, validate that `positional[0]` is present and non-empty before
   calling `store.write`. On missing/empty id: print a clear error to
   stderr, set `process.exitCode = 1`, and return without writing any
   file.
2. Add a regression test (`test/create-validation.test.mjs`) that:
   - confirms `task create` with a valid id still creates the task file
     as before (no regression on the happy path);
   - confirms `task create` with no id argument at all exits non-zero,
     prints an error, and creates **no** file (verified by listing the
     tasks directory before/after and diffing).
3. Re-run the full existing regression suite (all quay-native + quay-github
   test files) to confirm zero regressions.
