## Proposal

`packages/quay-github/DESIGN.md` documented compound/epic (`children`
non-empty) GitHub-backed task support as **deliberately out of scope for
v1**, with the stated justification being that no real compound GitHub
issue had organically appeared in `yaleh/quay`'s backlog. A human-asserted
directive
(`experiment/directives/pending/DIR-006-implement-quay-github-compound-epic-support.md`,
discovered mid-iteration-24 and deferred to iteration 25) explicitly
rejected that reasoning: absence of an organically-appearing compound
issue is a gap in test/verification setup, not a scope boundary, and
convergence criterion 3 ("contract proven: native + GitHub both run")
cannot honestly read anything but NO while native's `childrenStatus()`
recursion has never been exercised against a GitHub-backed equivalent.

This task implements the missing children-recursion in
`packages/quay-github/src/github-client.js`, creates a REAL
(not synthetic/mocked) parent+child issue structure in the live
`yaleh/quay` repo, and live-verifies the whole path end-to-end at the same
evidentiary standard as QN-028/QN-029.

## Plan

1. Port `childrenStatus()` into `github-client.js` — a direct,
   structurally-comparable port of native's `store.js#childrenStatus()`
   (QN-012/QN-016): recursive, cycle-safe, "stale-done" rollup for a
   compound child whose own label says done but whose subtree is not
   fully done. Adapted for live fetching via an injected
   `getChildTask(id)` fetcher (mirrors the existing `pageIssues`/
   `fetchPage` injection convention in this same file), rather than a
   local file-store `get()`.
2. Wire `childrenStatus()` into `checkGate()`'s `ready` and `done`
   branches, gated on `task.role === "compound"` — a primitive task
   (children empty) is completely unaffected (the fetcher is never
   invoked; `.every()` over `[]` is vacuously true).
3. Wire `createGithubClient()`'s own `check(id)` to supply its own live
   `get` function as the child-fetcher.
4. Add `packages/quay-github/test/compound-gate.test.mjs`: injected-
   fixture unit tests mirroring native's own `compound-gate.test.mjs` +
   `compound-gate-recursive.test.mjs` case structure (all-done,
   one-child-todo, dangling-child-reference, nested/stale-done rollup,
   cyclic-reference safety, ready-gate AC-vs-children interaction, and
   primitive-task non-regression) — no live `gh api` call in this file,
   per this package's established convention.
5. Create a REAL compound issue structure in `yaleh/quay`: child A
   (closed/done), child B (open/todo), and a parent epic issue whose body
   references both via the `- [ ] #N` checkbox convention
   `extractChildRefs()` already parses.
6. Live-verify end-to-end: `quay-github task check <parent>` while child B
   is still open (expect `ok:false`, naming the blocking child); close
   child B and re-check (expect `ok:true`); close the parent itself and
   re-check the compound-aware `done` branch; adversarially reopen child B
   while the parent remains `done` and confirm the gate correctly flips to
   `ok:false` (real teeth, not a static pass); restore to the final,
   honest all-done state. Cross-check Core's generic `quay task check
   --provider github --json` passthrough is byte-identical to
   `quay-github`'s own direct CLI output at both the "before" and "after"
   states.
7. Update `packages/quay-github/DESIGN.md` to remove the "deliberately out
   of scope" framing for compound/epic support and record the live
   verification transcript.
8. Update `experiment/provenance.md` and move DIR-006 to `archive/` with a
   `## Resolution` section.

## AC

- [x] `childrenStatus()` exists in `github-client.js`, structurally
      comparable to native's `store.js#childrenStatus()` (same cycle-safety
      and stale-done rollup semantics), covered by 24 passing assertions in
      `test/compound-gate.test.mjs` (injected fixtures, no live `gh api`
      call in that file).
- [x] `checkGate()`'s `ready`/`done` branches require all children `done`
      for a compound task, while primitive tasks are provably unaffected
      (existing `test/gate.test.mjs`'s 19 primitive-only assertions still
      pass unchanged, zero regressions).
- [x] A real parent+child issue structure exists in `yaleh/quay`
      (issues #5, #6, #7 — not deleted, retained as durable evidence), and
      `quay-github task check <parent-id> --json` was live-run against it
      confirming: (a) `ok:false` while a child was still open, naming the
      blocking child; (b) `ok:true` once all children were closed; (c) the
      compound-aware `done` branch re-verifies children (adversarial
      reopen of a child while the parent stayed `done` correctly flipped
      the result back to `ok:false`, exit code 1).
- [x] Core's generic `quay task check <id> --provider github --json`
      passthrough produced byte-identical stdout to `quay-github`'s own
      direct CLI output, at both the "before" (1/4 AC checked, child
      still open) and "after" (4/4 AC checked, both children done) states
      — the reusability/transfer proof, extended from QN-028's
      primitive-only precedent to the compound path.
