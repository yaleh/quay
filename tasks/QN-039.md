## Proposal

Iteration 23 (QN-033) closed `bin/quay.js`'s top-level dispatch-layer
coverage gap (it had zero automated coverage before that task), but its
own test file explicitly named two residual, honestly-scoped-out branches
it deliberately left untested (see `packages/quay/test/cli.test.mjs`'s own
header comment, "Out of scope, named honestly"):

1. **`resolveProviderEnv()`'s absolute-path passthrough branch** — the
   `else` branch of `resolveProviderEnv()` (both copies: `bin/quay.js` and
   `src/mcp-server.js`) that passes an env value through verbatim when it
   does NOT start with `./` or `../`. QN-033's fixture only ever used a
   `./`-relative value, so this branch has never been exercised by any
   automated test in the repo. It is exercised in production, though: the
   real `.quay/config.yml`'s own `github` provider entry sets
   `QUAY_GITHUB_REPO: "yaleh/quay"` — a real absolute (non-relative)
   passthrough value used every time `--provider github` is invoked
   (iteration 4's QN-002, and every later iteration's `quay-github`
   exercise). This task closes the gap with that exact real-shaped value,
   not a synthetic string.
2. **`quay serve`'s own CLI dispatch branch** (`cmd === "serve"` in
   `bin/quay.js`, plus its `process.argv.slice(3)` re-parse quirk for
   `--port`) — `serve.test.mjs` (QN-031) already covers `serve.js`'s own
   HTTP behavior thoroughly, but always by importing `startServer`
   directly; it never spawns `bin/quay.js serve` itself as a real
   subprocess. So the specific dispatch-layer code (the `if (cmd ===
   "serve")` branch, the dynamic `import("../src/serve.js")`, and the
   argv re-parse working around `parseFlags`'s normal `sub`-token
   consumption) has never been exercised end-to-end.

Both gaps were named explicitly (not newly discovered this iteration) in
`cli.test.mjs`'s own header comment since iteration 23, and both remain
open as of iteration 28's own "Problems identified for next iteration"
list (carried forward unchanged since iteration 23-27). This task closes
both, per this iteration's OBSERVE-phase search for genuine, tractable,
already-named work (iteration 28's problem #2).

Scope check against V-factor definitions (protocol §5.1/§5.2), to avoid
double-crediting: this is new automated test coverage of pre-existing,
already-shipped code paths. It does not change `bin/quay.js`'s or
`mcp-server.js`'s runtime behavior at all (confirmed: zero non-test-file
diff expected). It therefore is not a new capability (no `skeleton`
credit), not a new gate-logic change (no `gate_correctness` credit), not
an ABI schema change (no `abi_symmetry` credit — CLI/MCP schemas are
unchanged), and not a Skill-orchestration event in the sense
`skill_convergence` measures (it is regular leaf-task authoring/execution
via `quay:author`/`quay:execute`, the same as every other ordinary task in
this ledger — not a *new kind* of Skill-orchestration evidence). This is
recorded honestly up front so the iteration report does not need to
retroactively justify a flat V_instance.

## Plan

1. Extend `packages/quay/test/cli.test.mjs` with a new fixture workspace
   whose `.quay/config.yml` `github` provider entry uses a real absolute
   passthrough env value (`QUAY_GITHUB_REPO: "yaleh/quay"`, matching the
   real repo's own config verbatim) and assert, via a real spawned
   `bin/quay.js --provider github task list --json` call against a live
   `quay-github mcp` child process, that the passthrough value reached
   the child process's `process.env` unresolved (proven the same way
   QN-033 proved the `./`-relative branch: a correct non-empty/non-error
   result is itself live proof, not an assumption). Reuse
   `packages/quay-github/test/cli.test.mjs`'s own `QUAY_GITHUB_REPO`
   convention for consistency.
2. Add a new test block spawning `bin/quay.js serve --port <ephemeral>`
   as a real child process (not `startServer()` imported directly),
   against an isolated `.quay/config.yml` + tasks dir fixture (reusing the
   pattern already established by `serve.test.mjs`'s own isolation, but
   spawning the actual CLI binary this time), confirming: (a) the process
   starts and a subsequent `GET /` returns 200 with the seeded task's id
   in the body, proving the `cmd === "serve"` branch's dynamic import and
   `startServer()` call actually ran; (b) the `--port` flag is correctly
   read via the `process.argv.slice(3)` re-parse (not swallowed as a
   `sub` token) by requesting the exact ephemeral port passed on the
   command line and confirming the server is listening there, not on the
   4173 default.
3. Update `cli.test.mjs`'s own header comment to remove both items from
   the "Out of scope, named honestly" list (or mark them closed), so a
   future reader does not re-discover a gap that no longer exists.
4. Re-run the full regression suite (all `*.test.mjs` + `abi-symmetry.mjs`)
   and confirm zero regressions.
5. Update `experiment/provenance.md` with this task's record and a fresh
   σ computation.
