## Proposal

`experiments/quay-native-bootstrap/directives/pending/DIR-009-mock-log-file-action-delivery-mode.md`
(human-asserted, 2026-07-15) requests a third, additive delivery mode for
`packages/quay/src/action.js#deliverTrigger()`, distinct from the existing
`manda` path and the existing stdout-print degrade path, per
`docs/proposal/quay-core-scope-expansion-discussion.md` §2.3 (read in full
before authoring this task): the existing manda-unavailable degrade path
only `console.log`s the composed command — there is no deterministic,
file-based record an automated test can assert against, so any test of
action-composition logic that isn't live-manda-gated today has to scrape
stdout or skip verifying delivery entirely.

**Standing constraint applied (DIR-008/§2.3, cited not re-derived):** this
task does not attempt to re-verify or re-test live manda delivery, and does
not make its own gate depend on a live manda session being reachable — per
`experiments/quay-native-bootstrap/directives/archive/DIR-004-*.md` and `DIR-005-*.md`'s
iterations 13-18 findings (the async `Dispatch` queue primitive works but
nothing reliably claims tasks submitted to it; a genuine synchronous
`Agent` fresh-context spawn times out 5/5; a correctly-targeted dispatch
produces no execution unless a live process is watching). This mode's
whole point is to sidestep that per-session unreliability for automated
verification, not depend on or re-litigate it.

**Design decision (activation mechanism, task's own to make per DIR-009
point 1):** `deliverTrigger()` gains an optional `mockLogPath` parameter.
When supplied (non-empty), it takes precedence over both other paths
regardless of whether manda is available — explicit opt-in, not a silent
fallback. Both existing callers (`bin/quay.js`'s `action run` subcommand and
`serve.js`'s POST action-button handler) thread this from a new
`QUAY_ACTION_MOCK_LOG` environment variable (chosen over a `.quay/
config.yml` field or a new CLI flag: it requires zero config-schema
changes, mirrors this repo's existing convention of environment-variable
activation for test/verification-mode toggles — e.g.
`QUAY_NATIVE_TASKS_DIR` — and keeps the change fully additive/optional).

**V-factor attribution (DIR-009 point 6, DIR-008 constraint 4(b) applied,
not re-opened):** this is new Core-level capability code in
`packages/quay/src/action.js` — a new, real, previously-nonexistent
delivery mode with its own new branch, new helper function
(`appendMockDeliveryRecord`), and new wiring in two callers. Per constraint
4(b)'s already-decided mapping ("new Core capability code → `skeleton`"),
this fits **`skeleton`**, not `abi_symmetry` (no CLI/MCP schema surface is
being proven symmetric here — `deliverTrigger()` is host-owned trigger-edge
code, explicitly NOT part of the Provider ABI per its own header comment)
and not `gate_correctness` (no `task check`/gate-logic change). It is
explicitly NOT `effectiveness` (per DIR-009 point 6's own instruction) and
explicitly not a new fifth factor.

   `packages/quay/test/action-mock-delivery.test.mjs`: compose a real
