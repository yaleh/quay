## Plan

1. Read `packages/quay/src/serve.js`, `bin/quay.js`, `src/mcp-server.js` in
   full to confirm the exact asymmetry DESIGN.md §4.4 names.
2. Extract the duplicated `resolveProviderEnv()` logic (previously
   byte-identical in `bin/quay.js` and `src/mcp-server.js`) into a new
   shared module, `packages/quay/src/provider-env.js`.
3. Update `serve.js`'s `startServer()` to call the same shared
   `resolveProviderEnv(cfg, provider)` instead of its own bespoke
   `tasks_dir`-only env-building logic.
4. Update `bin/quay.js` and `src/mcp-server.js` to import the shared
   function instead of each carrying their own copy.
5. Fix the two existing test fixtures (`packages/quay/test/serve.test.mjs`,
   `packages/quay/test/cli.test.mjs`'s test 9) that previously relied on
   `tasks_dir` alone (with no `env` block) -- both now also set
   `env.QUAY_NATIVE_TASKS_DIR`, matching the real repo's own `.quay/
   config.yml` convention, since `tasks_dir` alone is no longer sufficient
   once all three bindings share one resolution path.
6. Add a new, dedicated adversarial regression test,
   `packages/quay/test/provider-env-symmetry.test.mjs`: a config where
   `tasks_dir` points at an empty decoy directory and `env.
   QUAY_NATIVE_TASKS_DIR` points at the real, seeded directory. Confirms
   the Web UI serves from the `env`-named directory (matching the CLI leg),
   not the `tasks_dir` decoy.
7. Run the new test standalone, then the full regression suite (all
   pre-existing test-bearing files plus the new one), to confirm zero
   regressions.
8. Confirm `git diff --stat -- packages/quay-native packages/quay-github`
   is empty (Core-layer-only, consistent with this task's own scope).
9. Update `experiment/provenance.md`, archive DIR-011 with a full
   `## Resolution` section, write `experiment/iterations/iteration-34.md`.
