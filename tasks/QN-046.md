## Proposal

Iteration 34's problem list (and iterations 21/29/31/33's before it) named
`docs/proposal/quay-core-scope-expansion-discussion.md` §2.1 ("Use
browser-automation MCP tooling to test/verify the Web UI") as the one
remaining un-issued proposal from that discussion doc — §2.2 (Core-level
three-way symmetry) closed via DIR-010/QN-044 (iteration 33), §2.3
(mock/log-file action delivery) closed via DIR-009/QN-042 (iteration 31).
This iteration self-selects that remaining item, since
`experiments/quay-native-bootstrap/directives/pending/` is empty (re-confirmed via `ls`).

`packages/quay/test/serve.test.mjs` (QN-031, iteration 21) already proved
`quay serve`'s list/detail/action-button HTTP loop end-to-end via raw HTTP
requests, but its own `## Gaps` section explicitly named "browser-level
rendering" as *not* covered — only a raw HTTP client, never a real browser's
HTML parser/renderer, had ever exercised this code. This task closes that
specific, previously-named gap: `quay serve`'s list page, task-detail page,
and action-button POST are driven through a REAL rendered browser (via
playwright MCP tooling — a session-level capability available to a Claude
Code session, distinct from the Provider-ABI `mcp` transport per
`ITERATION-PROMPTS.md`'s §Core-scope constraint 1; written here as
"browser-automation tooling (playwright MCP)", never bare "MCP testing").

**A genuine, previously-undetected production bug was found during this
live verification, not manufactured:** `serve.js`'s two HTML-emitting routes
sent `Content-Type: text/html` with no charset parameter. The bytes on the
wire are correct UTF-8 (confirmed via `xxd`: the list page's em-dash is
`e2 80 94`, valid UTF-8), but a real browser with no charset hint falls back
to a legacy encoding and mis-decodes non-ASCII glyphs — observed live via
playwright MCP tooling as "Quay â€” task list" (should be "Quay — task
list") and "role: primitive Â· labels:" (should be "role: primitive ·
labels:"). `serve.test.mjs`'s own pre-existing assertions never caught this
because they check raw-byte substring presence against a UTF-8-encoded
string literal that happens to byte-match the response body regardless of
how a browser would decode it — exactly the class of gap only a genuine
rendering engine surfaces, which is the concrete justification for this
verification layer's value over raw-HTTP-only testing.

**V-factor attribution, decided up front (re-deriving against the closest
precedent, per standing discipline, not assumed):** the closest analogous
precedent is QN-031 itself (iteration 21), which credited `skeleton` +0.02
for converting 16 iterations of an unverified prose/manual-walkthrough claim
about `serve.js`/`action.js` into a live, adversarial, re-runnable automated
test — explicitly scored on `skeleton`, not `abi_symmetry` (no CLI/MCP
schema changed) and not `gate_correctness` (no gate logic touched), with the
exact reasoning: "what changed is the evidentiary basis... this test closes

explicitly-named remaining gap ("browser-level rendering... not exercised")
into live, real evidence — the SAME v0-loop chain (`config -> mcp -> serve

## Plan

1. Start `quay serve` against an isolated fixture workspace/tasks dir
   (following the established test-isolation pattern), and drive it live
   via playwright MCP tooling: navigate to `/`, take an accessibility
   snapshot, navigate to `/task/<id>`, click the action button, confirm the
   redirect and the real print-degrade delivery log line, navigate to a
   nonexistent task id and confirm a real 404.
2. Root-cause any rendering discrepancy found live (do not guess) by
   inspecting the raw response bytes (`xxd`) and the exact `Content-Type`
   header sent.
3. Fix the root cause in `packages/quay/src/serve.js` (both HTML-emitting
   routes): declare `charset=utf-8` in the `Content-Type` header and add a
   belt-and-braces `<meta charset="utf-8">` tag to each page's `<head>`.
4. Re-verify live via playwright MCP tooling that the fix resolves the
   mojibake (re-navigate, re-snapshot, confirm correct glyphs).
5. Add a new, dedicated regression test,
   `packages/quay/test/serve-browser-render.test.mjs`, asserting the
   mechanically-checkable root cause (Content-Type header value, raw UTF-8
   byte sequences for the specific glyphs involved, the `<meta charset>`
   tag) — honestly scoped: this file cannot itself drive a real browser (no
   browser-automation MCP tooling or headless-browser npm package is
   importable from a plain `node test.mjs` process in this repo, confirmed
   via `npm ls playwright` returning empty), so it proves the underlying,
   forever-mechanically-verifiable condition rather than fabricating a fake
   in-process "browser" check.
6. Adversarially verify the new test has real teeth: revert the fix
   temporarily, confirm the test fails (2 assertions), restore, confirm
   byte-identical diff and all-pass again.
7. Run the full regression suite (all pre-existing test-bearing files plus
   the new one) to confirm zero regressions; re-run `abi-symmetry.mjs` to
   confirm no ABI surface changed.
8. Confirm `git diff --stat -- packages/quay-native packages/quay-github` is
   empty (Core-layer-only, consistent with this task's own scope).
9. Update `experiments/quay-native-bootstrap/provenance.md`, write
   `experiments/quay-native-bootstrap/iterations/iteration-35.md`.
