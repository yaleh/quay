## Proposal

`packages/quay-github/src/mcp-server.js` (the GitHub Provider's MCP stdio
transport — `provider://manifest`, `task_list`, `task_get`, `task_write`,
`task_check`) has **zero automated test coverage anywhere in the repo**.
Confirmed by grepping every `*.test.mjs` file across all three packages for
any reference to `quay-github`'s own `mcp-server.js` or a subprocess spawn
of `quay-github.js mcp`: zero hits (`packages/quay/test/mcp-server.test.mjs`
exists for Core's MCP transport, and `packages/quay-native/src/mcp-server.js`
is exercised by `abi-symmetry.mjs`, but `quay-github`'s own MCP transport has
never been spawned as a real subprocess with a real MCP client in any test).
This is the sibling gap to QN-034 (iteration 24), which closed the identical
class of gap for `quay-github.js`'s CLI dispatch layer but explicitly named
"the `mcp` subcommand (starting the stdio MCP transport)" as out of scope
for that task, "for its different (long-running, stdio-server)
process-lifecycle shape" — this task closes exactly that named residual.

**Same live-repo constraint as QN-034, not a fresh risk:** `quay-github`'s
MCP tools shell out to the real `gh api` (no local-fixture seam), and this
package's own `write.test.mjs`/`cli.test.mjs` header comments already
establish the standing rule that the real `yaleh/quay` issue backlog is too
small/precious to target with destructive live writes in an automated,
repeatable test file. This task follows the same discipline: only
`task_list`, `task_get`, `provider://manifest`, and `task_check` (all
read-only) are exercised live via a real MCP client; `task_write` (the one
write-capable tool) is exercised only via its "unknown task id" error path
(returns before `client.setStatus` is ever reached), never via a real
status change to a live issue.

## Plan

1. Read `packages/quay-github/src/mcp-server.js` in full (already done this
   iteration) and `packages/quay/test/mcp-server.test.mjs` (Core's sibling
   test) for the connection/assertion pattern to mirror.
2. Live-probe `quay-github.js mcp` manually first (already done this
   iteration: confirms the process starts and prints its banner) before
   encoding assertions.
3. Write `packages/quay-github/test/mcp-server.test.mjs`, spawning the real
   `bin/quay-github.js mcp` subprocess via the MCP SDK's `StdioClientTransport`
   (same pattern as `packages/quay/test/mcp-server.test.mjs`), with
   `QUAY_GITHUB_REPO=yaleh/quay`, asserting: resource enumeration
   (`provider://manifest`, correct `name` field), `task_list` (json array,
   includes real issues #3/#4), `task_get` for issue `gh-3` (byte-identical
   structuredContent to the direct CLI's own `task get gh-3 --json` output),
   `task_get` for an unknown id (isError:true), `task_check` for `gh-3`/`gh-4`
   (byte-identical structuredContent to the direct CLI's own `task check
   --json` output for both), and `task_write` for an unknown id (isError:true,
   no live write attempted).
4. Adversarially break one assertion-relevant line (e.g., `task_check`'s
   `structuredContent: result` line, swap to a wrong shape) and confirm the
   test produces a live FAIL, then restore, confirm byte-identical
   restoration via `diff`/`git diff --stat`, and re-run to confirm a full
   green run again.
5. Re-run the full regression suite (all packages) and confirm no
   regressions.
6. Record the task's own creation-to-execute-done timestamps (this
   iteration's `effectiveness` marginal-timing comparison, scope-matched
   against QN-006's stage-0 baseline (~2m59s) and QN-032/033's own
   comparably-scoped native timings, per protocol §5.2 + decision §10.5).
