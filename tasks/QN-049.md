## Proposal

`packages/quay-github/provider.yml`'s own inline comments — specifically
the file header comment block (lines 1-8) and the `gate:`/`skill:`
capability-boolean comments (lines 27-38) — describe `gate` and `skill` as
scoped to **"primitive tasks only"**, with the `gate:` comment explicitly
stating *"no compound/epic children-recursion — this experiment has never
had a real compound GitHub task"*. This claim has been **false since
iteration 25 (QN-035, DIR-006)**, 12 iterations ago: that iteration
implemented `childrenStatus()`-based compound/epic gate recursion in
`packages/quay-github/src/github-client.js`, created a real compound issue
structure in the live `yaleh/quay` repo (issues #5/#6/#7), and live-verified
the full compound gate path end-to-end (documented in `DESIGN.md` §3.5/§3.6,
which even carries an iteration-37 status-line update referencing "v1.4").

Confirmed still live and current this iteration: `quay-github task check
gh-7 --json` (and Core's `quay task check gh-7 --provider github --json`
passthrough) both correctly return a compound-aware result
(`childrenStatus: [{id:"gh-5",status:"done"},{id:"gh-6",status:"done"}]`)
— proving the capability genuinely works today, while `provider.yml`'s own
comments, which `DESIGN.md` §5 explicitly claims "matches... verbatim,"
still describe a stale, pre-iteration-25 scope. This is a genuine,
previously-undocumented internal-consistency defect: the Provider's own
static self-declaration file (the artifact `provider.yml`'s own header
explicitly says "travels with the Provider" as its self-description) no
longer accurately describes the Provider it travels with.

This is a real gap, not a fabricated one: `git log --oneline -- packages/
quay-github/provider.yml` shows the file has not been touched since
iteration 18 (QN-029), while QN-035 (iteration 25) changed the underlying
capability without updating this file's comments — an honest oversight in
QN-035's own otherwise-thorough DESIGN.md update, which updated §3.5/§3.6
but not `provider.yml` itself.

## Plan

1. Confirm live, current behavior of the compound gate against the real
   `gh-7`/`gh-5`/`gh-6` issues (already created by QN-035, still present)
   via both `quay-github`'s own CLI and Core's generic passthrough.
2. Update `provider.yml`'s header comment block and the `gate:`/`skill:`
   capability comments to accurately state: compound/epic (children
   non-empty) gate support was added at iteration 25 (QN-035/DIR-006), is
   live-verified against real compound issues #5/#6/#7, and both
   capabilities now support both primitive AND compound tasks — matching
   `DESIGN.md` §3.5/§3.6's own accurate text.
3. Re-verify `DESIGN.md` §5's "Matches `provider.yml`'s own capability
   booleans verbatim" claim is still true for the booleans themselves (it
   is — only the comments were stale) and cite this task's fix in that
   section.
4. Re-run the full regression suite (all `*.test.mjs` files across all
   three packages, plus `abi-symmetry.mjs`) to confirm zero regressions —
   this is a documentation/comment-only change, no source-code behavior
   change expected.
5. Confirm via `git diff --stat` that only `provider.yml` and `DESIGN.md`
   changed, with zero diff to any `.js` source file.
