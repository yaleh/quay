## Proposal

`docs/proposal/quay-native-design.md` §8 ("Open decisions") lists five
items as unresolved design questions. All five have, in fact, already been
resolved in practice — by their own recommended option in each case — over
the course of this experiment's 39 prior iterations, but §8 has never been
updated to say so. This is a genuine, previously-undocumented staleness in
the single authoritative design document that every Skill, gate, and prior
iteration's own reasoning cites as "design §N" (e.g. `author/SKILL.md`,
`execute/SKILL.md`, `store.js`'s own header comments, `quay-github/
DESIGN.md`'s cross-references) — a reader following those citations to §8
would be told a decision is "open" when the shipped code has already made
and exercised it for many iterations.

Verified this iteration, item by item, against real, current code/state
(not assumed from memory of a prior iteration's summary):

1. **"native storage format — backlog.md frontmatter vs. a fresh minimal
   schema."** Resolved: markdown+frontmatter, per §2's own description
   and `packages/quay-native/src/store.js`'s actual implementation
   (confirmed: every task file under `tasks/` is a `.md` file with YAML
   frontmatter, e.g. `tasks/QN-049.md`). The doc's own §2 already
   describes this as settled; only §8 still lists it as an open choice.
2. **"`needs-human` — keep as a status vs. demote to a label."** Resolved:
   kept as a real status, exactly as §8 itself recommended. Confirmed via
   `packages/quay-native/src/store.js` line 13:
   `export const VALID_STATUSES = ["todo", "ready", "done", "needs-human"]`
   — a first-class status value, not a label. Exercised for real, repeatedly,
   as a genuine terminal soft-stop (QN-017, QN-020/021, QN-022/023, per
   `packages/quay-native/skills/execute/SKILL.md`'s own Gaps section).
3. **"manda-absent fallback for a trigger — sync inline run vs. print
   command."** Resolved: both, layered as documented delivery modes.
   Confirmed via `packages/quay/src/action.js`'s own header comment
   (lines 6-10), which documents exactly the three-tier fallback chain
   §8 asked about, with the "plain CLI, no agent -> print the command"
   degrade path implemented and exercised (iterations 13-18, DIR-004/
   DIR-005) alongside the later QN-042/DIR-009 mock-log addition.
4. **"`quay:execute` epic branch — actively dispatch children vs. only
   wait vs. both (recommended: both)."** Resolved as the recommended
   "both": `packages/quay-native/skills/execute/SKILL.md`'s own
   `executeEpic` pseudocode (`driveEach: [driveChildToDone(c, provider) |
   c <- task.children]`) actively dispatches/drives each child, and its
   own Gaps section documents this exact branch being exercised for real
   at iterations 5, 8, 9, and 27 (the last of which specifically closed
   the "epic-level recursive orchestration itself, not just gate
   mechanics" residual gap).
5. **"operation-Skill roster — is `decompose` its own Skill or folded
   into `review-plan` (recommended: folded)."** Resolved as the
   recommended "folded": `packages/quay-native/skills/author/SKILL.md`
   step 4 (`review-plan`) explicitly states "this is also where the
   decompose test lives" and implements it inline — no standalone
   `decompose` Skill file exists anywhere in `packages/quay-native/
   skills/` (confirmed via `ls`).

**Scope discipline, matching iteration 38's QN-049 precedent exactly**:
this is a documentation-accuracy correction to an already-accurate set of
underlying facts — no code changes, no new capability, no gate-logic
change. The five decisions were not *made* this iteration; they were made
and exercised across iterations 1-27 and simply never back-ported to §8's
own text, the same class of drift QN-049 found and fixed one file over
(`quay-github/provider.yml`/`DESIGN.md` §5) at the Provider level. This
task closes the identical pattern one level up, in the shared, authoritative
cross-package design document itself.
