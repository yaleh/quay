## Proposal

`quay-native task edit` accepts a missing or empty `<id>` positional
argument silently, producing a stray `tasks/undefined.md` file (or, with
an empty string id, a task with an empty-string id). This is the same
class of defect QN-025 (iteration 11) hardened `task create` against,
but `task edit` was never given the analogous guard clause. Discovered
incidentally and disclosed honestly in iteration 43's own problem list
(item 7), not fabricated or manufactured this iteration.

## Plan

1. Add the same `<id>` presence/emptiness guard clause used by `task
   create` (QN-025) to the `edit` subcommand handler in
   `bin/quay-native.js`, before any patch construction or `store.write()`
   call.
2. Add a new regression test
   (`packages/quay-native/test/edit-validation.test.mjs`) mirroring
   `create-validation.test.mjs`'s structure: missing-id case (exits
   non-zero, no file written, specifically no `undefined.md`),
   empty-string-id case (same), and a happy-path case (editing an
   existing valid-id task still works, no regression).
3. Run the full regression suite and `abi-symmetry.mjs` to confirm zero
   regressions elsewhere.

## Acceptance Criteria

- [x] `quay-native task edit` with no positional `<id>` argument exits

      test).
- [x] `quay-native task edit ""` (empty-string id) exits non-zero and
      writes no file (confirmed live).
- [x] New regression test `edit-validation.test.mjs` passes (7/7
