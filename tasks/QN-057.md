## Proposal

The Status-line staleness class (QN-049/050/051/053/054/056) has now
recurred a third time: iteration 45's own QN-056 fix (which cited "44
iterations... iteration-44.md") went stale the moment iteration 45 itself
completed, since no mechanism keeps these lines current except a human/
agent re-editing them every iteration. This has now happened three times
in a row on the same four files (`experiments/quay-native-bootstrap/README.md`,
`docs/proposal/quay-proposal.md`, `docs/proposal/quay-native-design.md`,
`docs/proposal/quay-bootstrap-experiment.md`), each requiring its own
dedicated fallback task once a given iteration's structural search for
higher-value work comes up empty (iterations 42/43 → QN-053/054; iteration
45 → QN-056; now iteration 46 → QN-057). Iteration 45's own problem list
(item 6) explicitly flagged this as a candidate for "a different, more
durable fix (e.g., a relative 'as of the most recent iteration' phrasing
instead of a hardcoded count)."

## Plan

1. Replace the hardcoded iteration-count / task-ID-count phrasing in all
   four files' Status lines with relative phrasing that points at its own
   source of truth (`experiments/quay-native-bootstrap/iterations/` for iteration count and
   most-recent-report, `ls tasks/QN-*.md | wc -l` for task-ID count)
   instead of a number that goes stale the next iteration.
2. Verify via direct `grep -n "^\- \*\*Status" <file>` that only the
   Status line changed in each of the four files.
3. Verify `git diff --stat` shows only the three git-tracked files
   changed (one line each); confirm the fourth (gitignored) file's edit
   via direct read only.
4. Re-run the full regression suite to confirm zero regressions (expected
   trivially — pure metadata-line change, zero `.js` diff).
