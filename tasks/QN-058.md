## Proposal

Iteration 53's post-hoc audit correction (see `experiment/provenance.md`
"Post-hoc correction (iteration 53 audit)" section) found that iteration
53 falsely claimed `packages/quay/test/cli.test.mjs` line 261 tests
`action run --json` against `--provider github` for a real GitHub-backed
task. It does not: that test invokes `action run` with no `--provider`
flag (defaults to native) against `CLI-1`, a native fixture task.
`cli.test.mjs`'s actual `--provider github` test (test 8, line 307) only
exercises `task list`, never `action run`. A repo-wide grep confirmed no
test anywhere combines `action run`/`composePayload` with
`--provider github`. This is a genuine, currently-open test-coverage gap
surfaced by an audit, not manufactured to produce a data point (G5).

## Plan

1. Add a new end-to-end test block to `packages/quay/test/cli.test.mjs`
   that spawns the real `bin/quay.js` binary with `--provider github`,
   invoking `action run <id> advance --json` against a real, non-fixture
   GitHub-backed task in `yaleh/quay` (issue #3 / task id `gh-3`, which
   carries the `status:ready` label).
2. Use `QUAY_ACTION_MOCK_LOG` (QN-042/DIR-009) to select the
   deterministic, network-independent mock delivery mode, so the test
   makes zero writes back to the real repo and does not depend on a live
   manda daemon.
3. Assert the full real chain worked: exit code 0, correct `taskId`
   (`gh-3`), correct `status_skill_map` skill resolution (`ready` ->
   `quay:execute`) against gh-3's real live status, correct composed
   `channel` name, `delivered: "mock"`, and that the on-disk mock
   delivery log record itself carries the correct fields (not just
   trusting the CLI's own JSON echo).
4. Run the full regression suite (`node --test packages/*/test/*.test.mjs`
   plus `abi-symmetry.mjs`) to confirm zero regressions.
