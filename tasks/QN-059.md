## Proposal

Iteration 54 closed an audit-discovered gap: no test exercised `quay action
run --provider github` end-to-end. Iteration 55 performed the systematic
sweep this suggested: a check of every Provider-parameterized `quay`
subcommand (per `bin/quay.js`'s own branch table — `task list/view/edit/check`,
`action list/run`) confirmed that ONLY `task list` (test 8) and `action run`
(test 10) had ever been tested with `--provider github`. `task view`,
`action list`, and `task check` had zero cross-Provider coverage.

2. Manually exercise all three live against real issue gh-3 before writing
   any test code, to confirm exact expected behavior.
3. Add test 11 to `packages/quay/test/cli.test.mjs`, matching the existing
   test 8/10 style and fixture conventions, covering all three subcommands
   against real GitHub-backed task gh-3.
4. Explicitly document why `task edit --provider github` remains excluded
   (real `gh api` write path; matches the existing, precedented
   `write.test.mjs` convention of not targeting live issues destructively).
5. Re-run the full regression suite and `abi-symmetry.mjs`; confirm
   `git diff --stat -- packages/*/src/*.js` is empty (test-only change);
