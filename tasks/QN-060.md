## Proposal

`packages/quay/test/mcp-server.test.mjs`'s own header (point 2) documented
that genuine multi-Provider aggregation through `quay mcp` was proven
against a second, fully local/isolated native Provider instead of live
GitHub, "so the test suite has zero external-network dependency" —
explicitly deferring the real github+live-repo aggregation proof to a
one-time, by-hand check performed during iteration 26 (see
`experiments/quay-native-bootstrap/iterations/iteration-26.md` §5d/§5e) and never captured as an
automated regression test since.

This is the exact same shape of gap iterations 54/55 closed at the CLI
layer for `bin/quay.js`'s own `--provider github` subcommands (`action
run`; `task view`/`action list`/`task check`) — but at the MCP layer:
`quay mcp`'s fan-out/aggregation path (`packages/quay/src/mcp-server.js`)
had zero automated coverage exercising a live GitHub Provider through the
Core MCP server, as opposed to exercising GitHub directly via
`quay-github mcp`.

## Plan

1. Read `packages/quay/src/mcp-server.js` in full to confirm which of its
   six tools are genuinely read-only (`task_list`, `task_get`,
   `task_check`, `action_list`) versus have a real write path
   (`task_write`, `action_run`, via `github-client.js`'s `setStatus()`).
2. Manually exercise all four read-only tools live against the real
   `yaleh/quay` issue gh-3 through the real `quay mcp` subprocess (not a
   direct `quay-github mcp` spawn) before writing any test code.
3. Add a new test block to `packages/quay/test/mcp-server.test.mjs`
   (block 10), spawning a real `quay mcp` subprocess with both `native`
   and `github` enabled in `.quay/config.yml`, asserting real field
   values for `task_list`/`task_get`/`task_check`/`action_list`, all
   `provider: "github"`, against gh-3.
4. Explicitly document, in the test file itself, why `task_write` and
   `action_run` remain excluded from live GitHub testing, citing
   `write.test.mjs`'s own precedent and iteration 55's identical
   `task edit --provider github` CLI-layer exclusion.
5. Confirm the full regression suite and `abi-symmetry.mjs` still pass,
   and that no live write occurred against issue #3 (`gh issue view 3`
   unchanged before/after).
