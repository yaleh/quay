## Proposal

Iterations 54/55 closed the CLI-layer (`bin/quay.js`) cross-Provider
test-coverage gap; iteration 56 closed the analogous MCP-layer
(`packages/quay/src/mcp-server.js`) gap. The third of the proposal's three
sibling ABI bindings (`quay-proposal.md` §9: CLI, Core MCP, Web UI; see
also `core-three-way-symmetry.test.mjs`'s own header) is the Web UI
(`packages/quay/src/serve.js`, `quay serve`). Reading `serve.test.mjs` and
`core-three-way-symmetry.test.mjs` in full confirms neither file, nor any
other test file in the repo, ever spins up `startServer()` against the
live GitHub Provider — both exclusively use isolated, local native task
stores. `serve.js` itself has never branched on provider id (its own file
header states this explicitly), so this has always been expected to work,
but it was never proven live, end-to-end, against a real GitHub-backed
task — the identical shape of gap iterations 54/55/56 each closed at
their own layer.

## Plan

1. Read `packages/quay/src/serve.js` and `provider-client.js` in full to
   confirm the Web UI's GET routes (`/` list, `/task/:id` detail) call
   only read-only Provider functions (`taskList`, `taskGet`, `manifest`) —
   no write path — and that the POST `/task/:id/action/:actionId` route
   only composes+delivers a trigger (`composePayload`/`deliverTrigger`),
   which does not itself write to the Provider, matching the exact
   write/read classification iteration 56 already established for
   `action_run`/`task_write`.
2. Manually exercise `startServer()` live against the real GitHub Provider
   (`.quay/config.yml` with `github.enabled: true`, `QUAY_GITHUB_REPO:
   yaleh/quay`) and real issue gh-3 via a throwaway exploration script,
   confirming exact expected list/detail HTML content before writing any
   test code, then delete the script.
3. Add a new test file `packages/quay/test/serve-github.test.mjs`,
   matching `serve.test.mjs`'s isolation/fixture conventions, covering:
   - `GET /` renders gh-3's real id/title/status in the task list.
   - `GET /task/gh-3` renders gh-3's real title, status, and the `Advance`
     action button (since gh-3's real live status is `ready`, which
     matches `provider.yml`'s `whenStatus: ["todo", "ready"]`).
   - POST `/task/gh-3/action/advance` is explicitly and correctly excluded
     from live testing (matches `write.test.mjs`/iteration 55/56's
     identical `task edit`/`action_run --provider github` exclusion
     rationale — composePayload+deliverTrigger is a real trigger-delivery
     path, not idempotently safe to fire against a real repo in an
     automated, repeatable test).
4. Re-run the full regression suite; confirm `git diff --stat --
   packages/*/src/*.js` is empty (test-only change); confirm issue #3's
   live label/body state is unchanged after the test run.
