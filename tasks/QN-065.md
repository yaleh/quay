## Proposal

Iterations 58, 59, and 60 each independently found and closed a genuinely
distinct instance of an untested failure mode at an external boundary in
the GitHub Provider / Core-level bindings:

- QN-062 (iteration 58): Provider-subprocess connection/startup failure
  (a malformed `QUAY_GITHUB_REPO` causing `resolveRepo()` to throw),
  verified through both Core CLI's eager-connect and Core MCP's
  lazy-connect paths.
- QN-063 (iteration 59): malformed/absent input shape (`null`/`undefined`
  GitHub issue `body`), previously only exercised via an empty-string
  stand-in.
- QN-064 (iteration 60): live mid-session upstream failure (a real `gh
  api` 404 occurring inside `fetchAllIssues()`, after a successful
  Provider connect).

Each of these was found the same way: grep `experiment/provenance.md`
and the relevant test files to confirm the specific instance was
genuinely open, then close it with a test-only regression addition (zero
source-code change in all three cases). This is real, repeated,
independently-justified practice — but it exists only in
`experiment/provenance.md`'s own per-iteration narration.
`packages/quay-native/skills/execute/SKILL.md`'s own Method (`implement-phase`,
step 1) is silent on it: a future `implement-phase` pass authoring a *new*
feature that touches an external boundary (a Provider subprocess, a
network call, a parsed external data shape) has no standing instruction
in the Method itself to consider this class of failure mode — only a
historical record that three past *test-coverage-closure* tasks happened
to find such gaps in already-existing code.

This is a genuine, previously-unaddressed gap in the Skill's own
self-containedness (§5.2's `completeness`: "Methodology... fully
documented and self-contained") — distinct from iteration 18's rejected
"documenting newly-written capability" (which is expected, ordinary
documentation practice for a new feature, not closure of a named gap) and
from iteration 29's reverted `completeness` credit (which revised
`ITERATION-PROMPTS.md`, an experiment-process document explicitly
out-of-scope for this factor). This task closes it by writing the
generalized discipline directly into `quay:execute`'s Method as a
standing sub-check, with an explicit G5 caveat (do not manufacture a
negative-path test where none is genuinely open).
