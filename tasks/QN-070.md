## Proposal

Iteration 20 (QN-030) proved, live, a permanent structural boundary of
`packages/quay-native/src/store.js#check()`: the gate mechanically verifies
AC checkbox PRESENCE and CHECKED-STATE only — it never verifies that a
checked box's underlying claim is actually TRUE. That proof
(`packages/quay-native/test/gate-gameability.test.mjs`) has stood, native-only,
for 49 iterations. No equivalent test exists for
`packages/quay-github/src/github-client.js#checkGate()` — grepped
`experiment/provenance.md` for "gameability"/"gameable" and confirmed every
hit (iterations 9/11/12/13/16/17/18/19/20 and later cross-references) discusses
`store.js`'s gate only; grepped `packages/quay-github/test/*.mjs` and
`packages/quay-github/DESIGN.md` for the same terms and confirmed **zero**
hits. This is a genuinely open, previously-undiscovered gap, not a stale item.

Live-verified this session, before writing any test, that `checkGate()` has
the structurally identical boundary (same mechanical regex-based checkbox
counting, `packages/quay-github/src/github-client.js` lines ~357-395, no
semantic verification of a claim's truth):

```
$ node -e '
import("./packages/quay-github/src/github-client.js").then(({checkGate}) => {
  const substantive = (label) => label + " — this is real, substantive prose describing the " + label.toLowerCase() + " in enough detail to exceed the minimum content threshold for this section, well past forty characters.";
  const body = "## Proposal\n" + substantive("Proposal") + "\n" +
    "## Plan\n" + substantive("Plan") + "\n" +
    "## AC\n- [x] 2 + 2 === 5 (this is a FALSE claim, checked anyway)\n" +
    "## DoD\n" + substantive("DoD") + "\n";
  const r = checkGate({ id: "gh-game-1", status: "todo", body });
  console.log("todo gate on falsely-checked AC:", JSON.stringify(r));
  const r2 = checkGate({ id: "gh-game-1", status: "ready", body });
  console.log("ready gate on falsely-checked AC:", JSON.stringify(r2));
});
'
todo gate on falsely-checked AC: {"id":"gh-game-1","gate":"author->ready","ok":true,"artifacts":{"proposal":true,"plan":true,"ac":true,"dod":true},"reason":"all four artifacts present; eligible to move to ready"}
ready gate on falsely-checked AC: {"id":"gh-game-1","gate":"execute->done","ok":true,"acTotal":1,"acChecked":1,"reason":"all AC checkboxes checked; eligible to move to done"}
```

Confirmed: `checkGate()` accepts a checked-but-false claim on both the
`author->ready` and `execute->done` gates, exactly as `store.check()` does.
This is the **held-out GitHub Provider transfer target** (protocol §5.2,
decision §10 item 4) — porting a previously native-only methodology-
verification artifact (the gameability-boundary proof) to it, for the first
time since iteration 25's compound/epic gate port. Distinct from every
test-coverage closure since iteration 26 (QN-034, QN-048, QN-063, QN-067,
QN-068, QN-069, etc.), all of which added coverage for behavior *already
tested or already symmetric* between the two Providers — this closes a gap
that has never been closed on the GitHub side at all, on a structural
property protocol G3 itself depends on citing as evidence for why the
out-of-band audit is mandatory.

## Plan

1. Port `packages/quay-native/test/gate-gameability.test.mjs`'s three cases
   (GAME-A: `author->ready` gate accepts a checked-but-false claim; GAME-B:
   `execute->done` gate accepts a checked-but-false claim on the ready->done
   path; GAME-C: negative control, an honestly-unchecked box still correctly
   fails) to a new file `packages/quay-github/test/gate-gameability.test.mjs`,
   adapted to call `checkGate({id, status, body})` directly (injected-fixture,
   no live `gh api` call, matching this package's established convention —
   the same adaptation QN-028 used porting `gate-correctness.test.mjs`).
2. Live-verify each case's claim is genuinely false/true before asserting the
   gate's behavior (same discipline as the native original).
3. Adversarially verify: temporarily break `checkGate()`'s checked-vs-present
   counting (e.g. forcing the checked-count to always read as 0 by
   short-circuiting the regex match), confirming the ported GAME-A/GAME-B
   cases correctly FAIL (proving the test has real teeth, not a tautological
   always-pass), then restore byte-identical and confirm `git diff --stat`
   is empty.
4. No change to `github-client.js` itself is anticipated — this is a
   test-coverage-only port, confirmed by the live-verification above; the
   gap being closed is "no test proves this structural boundary on the
   GitHub Provider," not "the boundary itself needs fixing" (it is
   permanent and structural, same as native's, per G3).
5. Add a header comment to the new file, matching the native original's
   framing but citing this as the GitHub-Provider port, cross-referencing
   `gate-gameability.test.mjs` (native) and QN-030 (iteration 20) directly.
