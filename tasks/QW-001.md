## Proposal
The Web UI currently uses no CSS — raw HTML with `border="1" cellpadding="4"` on the table and no page-level styling. This produces a score of 0.0 for visual_design_quality because no page meets the mechanical Lighthouse threshold (accessibility ≥ 90, best-practices ≥ 90) and no holistic visual review has been dispatched. The fix is to add an inline CSS system (no external dependencies, consistent with G5's "no framework" discipline) applied to all three reachable pages (GET /, GET /task/:id detail, POST /task/:id/action/:actionId redirects back to detail). The CSS should cover: modern page layout (max-width container, comfortable padding), readable typography, a minimal table style replacing border="1", consistent heading hierarchy, accessible button styles, and a visible back-link. This is a single-file change to packages/quay/src/serve.js.

## Plan
Phase 1: Write a `pageStyles()` helper function returning a `<style>` block with minimal but consistent CSS. Apply it in the `<head>` of both the list and detail page HTML templates. Remove `border="1" cellpadding="4"` from the table. Add proper semantic structure: `<main>` wrapper, `<nav>` for the back-link.

Phase 2: Write browser-automation tests in web-ui-browser.test.mjs verifying structural properties that depend on the new styling: (a) `<style>` tag is present in both pages, (b) table no longer has `border="1"` attribute, (c) `<main>` wrapper is present, (d) back-link is in a `<nav>` element.

Phase 3: Run the full test suite (node --test packages/*/test/*.test.mjs) to confirm no regression.
