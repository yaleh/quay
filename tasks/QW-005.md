## Proposal

The task list page (GET /) currently supports filter-by-status (QW-003) and sort (QW-004) but has no label filtering. The ui_read_capability 'Done when' clause explicitly requires filter by label. Tasks may carry zero or more labels in their labels[] frontmatter field. This adds a ?label=<value> query parameter to GET /, which filters tasks to those whose labels array includes the given label value. A label navigation UI is rendered showing all distinct labels present in the current (unfiltered) task list, plus an 'All' link. Label filter composes with the existing status filter and sort (all three params can be combined).

Approach: single-file change to packages/quay/src/serve.js. No external dependency. Core stays dumb.

## Plan

Phase 1 - implement filter-by-label logic (serve.js): Read url.searchParams.get('label') → labelFilter (null | string). Apply label filter to the tasks array: tasks whose t.labels array includes labelFilter. Filter is applied after status filter, before sort. If no label param (or empty string), no label filter applied.

Phase 2 - render label navigation (serve.js): Collect distinct labels across allTasks (before status filter, to always show all possible labels). Render a labelNav string: All + each distinct label as a link. Active label shown as strong. Links preserve active status and sort params via buildHref extension. Render as p.meta in list page HTML. If no tasks have labels, omit the label nav (or show just 'All').

Phase 3 - tests (web-ui-browser.test.mjs): Seed tasks with labels: LBL-1 (labels: [alpha]), LBL-2 (labels: [beta]), LBL-3 (labels: [alpha, beta]). GET /?label=alpha: includes LBL-1 and LBL-3, excludes LBL-2. GET /?label=beta: includes LBL-2 and LBL-3, excludes LBL-1. GET /?label=gamma: empty result (no match). GET /?status=todo&label=alpha: filter by both status and label. Label nav links present in GET /.
