## Proposal

Two visual_design_quality gaps addressed in this task:

1. Heading-order: The detail page (GET /task/:id) has a Lighthouse accessibility finding: h1 → h3 skip. The renderMarkdown() function maps # → h2 and ## → h3 (since h1 is the page title). This causes an h1→h3 jump when the task body starts with a ## heading (e.g. '## Proposal' renders as h3). Fix: add an explicit h2 label before the .body div (e.g. '<h2>Details</h2>' or restructure so the body section is introduced with an h2). This should bring accessibility score from 96 to 100 on the detail page.

2. Mobile-responsive layout (DIR-003): The current CSS in pageStyles() has a fixed max-width: 900px for main but no responsive media queries. DIR-003 requires both desktop and mobile viewport support. Fix: add @media (max-width: 600px) rules in pageStyles() to adapt table overflow (horizontal scroll), reduce font sizes slightly, and adjust padding for narrow viewports. The existing viewport meta tag (already present) is prerequisite.

Both fixes are single-file changes to packages/quay/src/serve.js. No external dependency.

## Plan

Phase 1 - heading-order fix (serve.js detail route): Add '<h2 class="sr-only">Details</h2>' (visually hidden but semantically present) immediately before '<div class="body">' on the detail page. Add .sr-only CSS rule in pageStyles(): position:absolute; width:1px; height:1px; overflow:hidden; clip:rect(0,0,0,0). This preserves heading hierarchy (h1 → h2 → h3) without visual disruption.

Phase 2 - mobile responsive CSS (serve.js pageStyles()): Add @media (max-width: 600px) block: main { padding: 1rem 0.75rem } table { display: block; overflow-x: auto } th, td { padding: 0.45rem 0.6rem; font-size: 0.85rem }.

Phase 3 - test additions (web-ui-browser.test.mjs): Add structural assertions: detail page contains h2 element before .body div; pageStyles() contains @media rule; .sr-only class defined in styles.
