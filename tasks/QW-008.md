## Proposal

QW-008 addresses the second remaining gap in ui_read_capability: the task detail page does
not display parent/children frontmatter fields. The 'Done when' clause requires that the
detail page display parent task link (if any) and child task links (if any) in the meta
section. This is pure read-only rendering of existing frontmatter data already available
from taskGet().

Scope: single-file serve.js modification to the GET /task/:id route — add parent link and
children list to the meta paragraph. No new route, no write surface.

## Plan

Phase 1: Render parent link in detail page meta section.
- Read t.parent from the task object (string id or null/undefined).
- If t.parent is set, add 'parent: <a href=/task/{t.parent}>{t.parent}</a>' to the meta line.
- Append to the existing meta paragraph (role · labels · parent).

Phase 2: Render children links in detail page meta section.
- Read t.children from the task object (array of child ids or null/undefined).
- If t.children is non-empty, add 'children: <a>...</a> ...' list to meta section.
- Use a separate paragraph (p.meta) for children to keep it readable.

Phase 3: Add browser-automation tests.
- Create a task with parent set (PC-CHILD with parent=PC-PARENT), and a compound task
  PC-PARENT with children=[PC-CHILD].
- Verify PC-CHILD detail page shows parent link to PC-PARENT.
- Verify PC-PARENT detail page shows children list with link to PC-CHILD.
- Verify task with no parent/children shows neither field (negative control).
