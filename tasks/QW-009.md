## Proposal

QW-009 addresses the third remaining gap in ui_read_capability: labels are shown on the
detail page meta line but not in the list table. The 'Done when' clause for
ui_read_capability=1.0 requires all frontmatter fields displayed. Adding a labels column
to the list table makes the label information visible at a glance without navigating to
the detail page.

Scope: single-file serve.js modification to the GET / route — add a 'labels' column to
the table header and rows. No new route, no external dependency.

## Plan

Phase 1: Add labels column to list table in serve.js.
- Add 'labels' th to the table header row.
- In each task row, add td showing t.labels joined as comma-separated list.
- Empty labels array shows empty td (not an error).

Phase 2: Add browser-automation test for labels column.
- Verify the list table header includes a 'labels' column.
- Verify task rows with labels show label values in the labels column.
- Verify task rows without labels show empty/blank labels column (not absent).
