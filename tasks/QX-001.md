## Proposal

The Web UI and CLI currently offer filtering by status and label but not by task-id prefix (QN-*, QC-*, QW-*, QX-*). A maintainer managing multiple concurrent experiment workstreams needs to jump between them efficiently in one session. Today that requires either memorizing which IDs belong to which experiment or manually grepping the tasks/ directory — neither is discoverable from the interface.

The human observed this gap directly while using the shipped Web UI (2026-07-17, recorded in experiments/quay-continuous-bootstrap/provenance.md). It is the highest-priority human-observed capability_breadth gap entering experiment 4.

## Plan

1. Extend `task_list` CLI filter to accept `--prefix QX` (or similar) to scope by task-id prefix.
2. Extend the Web UI's filter controls to include a prefix/experiment selector.
3. Alternatively, define a per-experiment label convention (e.g. `experiment:4`) applied at task_write time, and use the existing `--label` filter — evaluate which approach has lower friction for the maintainer persona.
4. Add automated test confirming the filter returns the correct subset.
5. Ship fix AND test in the same iteration.

## AC

- [x] `quay task list --prefix QX` (or equivalent) returns only QX-* tasks and no others
- [x] The Web UI exposes an equivalent filter that a new contributor can discover without reading docs

- [x] The filter works correctly when multiple experiments' tasks coexist in the same tasks/ directory
