## Proposal

Add a `--prefix <string>` flag to `quay task list` so users can filter tasks to a specific experiment prefix (e.g. `quay task list --prefix QX` returns only QX-* tasks). This closes CB-001, the highest-priority cross-persona gap from iteration 0's simulated-user pass.

The current `task list` command returns ALL tasks from ALL experiments in a flat list. For a workspace with 94+ tasks spanning multiple experiments (QN-*, QC-*, QW-*, QX-*), this is unusable for any per-experiment workflow. The prefix filter is the minimal, maximally general fix: it lets users scope to any experiment prefix without changing the data model.

Implementation approach: add `--prefix <string>` flag parsing in `bin/quay.js`'s `task list` branch; after fetching all tasks from the provider, filter client-side to those whose id starts with the given prefix (case-insensitive, with or without trailing `-`).

## Plan

Phase 1: Add `--prefix` flag parsing to `bin/quay.js` `task list` branch.
- Read the current flags via `parseFlags(rest)` (already done)
- If `flags.prefix` is set, filter the returned task array: keep only tasks where `t.id.toUpperCase().startsWith(flags.prefix.toUpperCase())`
- Add a filter indicator to the non-JSON output header (a comment line before the task rows)

Phase 2: Add test to `packages/quay/test/cli.test.mjs`.
- Seed tasks with two different prefixes (PRFA-001, PRFB-001)
- Assert `quay task list --prefix PRFA` returns only PRFA-* tasks and excludes PRFB-*
- Assert `quay task list --prefix PRFA --json` returns a filtered JSON array
- Assert `quay task list` without `--prefix` still returns all tasks (no regression)
