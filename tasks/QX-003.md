## Proposal

Add an optional `prefix` parameter to the `task_list` MCP tool in `packages/quay/src/mcp-server.js`. This closes CB-009 and partially addresses CB-010 (response size reduction when prefix is used).

The MCP `task_list` tool currently returns ALL tasks from the provider with no way to filter by experiment prefix. For a workspace with 94 tasks (550K chars of JSON), this exceeds inline-context limits and makes the MCP interface impractical for any per-experiment workflow. The prefix parameter is the same pattern as the CLI's `--prefix` flag (QX-002): filter client-side after fetching, keeping tasks whose id starts with the given prefix.

## Plan

Phase 1: Add `prefix` parameter to `task_list` tool schema in `mcp-server.js`.
- Add `prefix: z.string().optional()` to the `task_list` tool's `inputSchema`
- After fetching tasks from the provider, if `prefix` is set, filter: `tasks.filter(t => t.id.toUpperCase().startsWith(prefix.toUpperCase()))`
- Update the tool description to mention the prefix parameter

Phase 2: Add test to `packages/quay/test/mcp-server.test.mjs`.
- Seed tasks with two different prefixes
- Assert `task_list` with `prefix` returns only matching tasks
- Assert `task_list` without `prefix` returns all tasks (no regression)
