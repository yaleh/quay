## Proposal
`quay serve --help` and `quay action --help` silently exit with code 0 and produce no output. This is because `printHelp()` only prints content when `!sub || sub === "task"` — all other subcommand names fall through silently. Found by G3 audit (iteration 1); filed as UQ-010 in gap-list.md.

This is not a regression (serve/action help was absent before QX-005), but UQ-010 represents a usability gap that should be addressed.

## Plan
1. In `packages/quay/bin/quay.js` `printHelp(sub)` function, add a fallback branch: when `sub` is provided but does not match a known subcommand (`task`), print a brief stub message: "Usage: quay <sub> [...]\nRun `quay --help` for full usage documentation."
2. Alternatively: fold `serve` and `action` into dedicated help blocks within `printHelp`.
3. Add assertions in test 14 (or new test block) that `quay serve --help` exits 0 AND includes some content.
