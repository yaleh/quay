## Proposal

CB-011: The MCP `task_list` registered schema in Claude Code does not include `prefix` parameter (stale session snapshot). The server-side code (QX-003, iteration 1) already includes `prefix: z.string().optional()` in the inputSchema and the wire protocol exposes it correctly (verified via direct JSON-RPC `tools/list` probe). The gap is that: (a) there is no automated test asserting the `tools/list` wire response includes `prefix`, and (b) the Claude Code session that found CB-011 had a pre-QX-003 MCP snapshot cached.

For (b): the fix is a new session (the schema is already correct on the wire). For (a): add a test that spawns the MCP server, sends a `tools/list` request over stdio, and asserts the `task_list` tool's `inputSchema` includes `prefix`.

## Plan

Phase 1: In `packages/quay/test/mcp-server.test.mjs`, add a test (Block 13) that:
- Spawns `node packages/quay/bin/quay.js mcp` as a child process
- Uses the existing MCP SDK client (connectStdio helper) to call listTools()
- Asserts the `task_list` tool exists and its `inputSchema.properties` includes `prefix`
Phase 2: Also assert all 6 expected tools are present and `task_list` responses include `updatedAt` (QX-008 coverage).
