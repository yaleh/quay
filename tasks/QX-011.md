## Proposal
The task detail page's "← back to list" link hardcodes `href="/"`, dropping any prefix/sort/status/label filter context the user had when they navigated to the detail page. A cross-experiment maintainer confirmed this in iteration 2's simulated-user pass: after drilling into a task from a filtered list view, the back link returns to the unfiltered root page rather than the previous filtered view.

The fix is to pass the current list's URL as a `?from=` query parameter when linking to the task detail page from the list, then use that `from` value as the back link href on the detail page — the same pattern already established for action POSTs in QX-009.

## Plan
Phase 1: In serve.js's list-page row renderer, change each task title `<a href>` link to include `?from=<encodedCurrentListURL>`.
Phase 2: In serve.js's detail-page handler, read the `from` query param and use it as the back link href with open-redirect guard.
Phase 3: Add a serve.test.mjs block verifying the behavior.
