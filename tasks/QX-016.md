## Proposal
Fix CB-013: multi-label filtering is broken on both CLI and Web UI, but with different incorrect behavior. CLI `--label A --label B` silently last-wins (parseFlags() overwrites the key); Web UI `?label=A&label=B` silently first-wins (searchParams.get returns first only). Both surfaces should implement AND-logic: a task must have ALL specified labels to appear in results. This is a blocking capability gap confirmed by the comparison-reviewer simulated-user in iteration 3.

## Plan
Phase 1: Fix CLI (bin/quay.js parseFlags):
- Modify parseFlags() to collect repeated flags as arrays: if a key already exists, convert to array or push to existing array.
- In task list, derive labelFilters = [].concat(flags.label).filter(Boolean); apply AND-filter.
Phase 2: Fix Web UI (src/serve.js list route):
- Replace searchParams.get('label') with searchParams.getAll('label') to collect all label values.
- Apply AND-filter: tasks that have ALL specified labels.
- Update buildHref() to support array of labels (render as repeated ?label=X&label=Y params) — so filter nav still works for single-label case.
Phase 3: Tests:
- cli.test.mjs: test that --label A --label B returns only tasks with BOTH labels; single-label still works.
- serve.test.mjs: test that ?label=A&label=B returns tasks with both; ?label=A (single) still works.
