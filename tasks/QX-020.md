## Proposal
When 2+ labels are active in the Web UI (`?label=A&label=B`), the label navigation links in `serve.js` each call `buildHref(statusFilter, sortKey, [clickedLabel], ...)` — passing a single-element array that replaces the entire filter. Instead of this replace-all behaviour, clicking a label nav link should toggle the clicked label: add it if it is not active, remove it if it already is. Additionally, the "active" indicator (bold) must work for multi-label state, and a "clear all labels" affordance must appear when 2+ labels are active. This closes UQ-019 (significant usability gap found by cross-experiment maintainer persona, iteration 4 simulated-user pass).

## Plan
Phase 1 — Toggle logic in label nav: In `serve.js`, change the label nav `buildHref` call from passing `[l]` (single-element replacement) to passing the toggled array: if `l` is in `labelFilters`, pass `labelFilters.filter(x => x !== l)`; if not, pass `[...labelFilters, l]`.
Phase 2 — Active state: change the bold condition from `labelFilters.length === 1 && labelFilters[0] === l` to `labelFilters.includes(l)`, so any active label is shown bold in multi-label state.
Phase 3 — Clear affordance: when `labelFilters.length >= 2`, render a "clear" link before the label list: `buildHref(statusFilter, sortKey, null, null, prefixFilter)` → "All labels".
Phase 4 — Tests: add test block in `serve.test.mjs` (port+6): verify that with 2 active labels, a nav link for an already-active label produces a URL WITHOUT that label; a nav link for an inactive label produces a URL WITH the current labels PLUS the new one; the active label bold indicator fires for multi-label state.
