## Proposal
CB-007 (significant) has been open for all 4 prior iterations — every comparison-reviewer persona has independently flagged the absence of title/text search as a gap vs. mature trackers (GitHub Issues, Linear). The data model already has `t.title` on every task. A case-insensitive substring filter in both the CLI and Web UI closes the gap with minimal code, no new external dependency, and no backend-specific logic. The Web UI form submits via GET so the URL is bookmarkable. This closes CB-007.

## Plan
Phase 1 — CLI `--search <query>` flag: In `bin/quay.js` `task list` handler, after the existing labelFilters step, add search query filter. Update `printHelp()` to document `--search`.
Phase 2 — Web UI `?q=<query>` param: In `serve.js`, after the label filter step, add case-insensitive title search. Add a search form with GET method. `buildHref` carries `q` param. Show active search badge.
Phase 3 — Tests: CLI test 19 in `cli.test.mjs`; Web UI test in `serve.test.mjs` (port+6, shared with QX-020 block).

## AC
