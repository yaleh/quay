## Proposal

Extend the existing `--search`/`?q=` substring filter to also match task body content in addition to title. Currently search is title-only (CB-016, significant gap vs GitHub Issues / Linear where full-text body search is standard). The body is already present on each task object returned by the provider (`task.body` field from store.js via `toViewModel`).

## Plan

1. `packages/quay/bin/quay.js`: Change the search filter from `t.title.toLowerCase().includes(...)` to `(t.title + ' ' + (t.body || '')).toLowerCase().includes(...)`.
2. `packages/quay/src/serve.js`: Same change in the `?q=` filter step.
3. `packages/quay/test/cli.test.mjs`: Add test cases where a term appears in the body but NOT in the title — verify they are returned by search.
4. `packages/quay/test/serve.test.mjs`: Same for Web UI `?q=` filter.

## AC

- [x] `--search <term>` on CLI returns tasks where term appears in body but not title
- [x] `?q=<term>` on Web UI returns tasks where term appears in body but not title
- [x] Existing title-search tests still pass
- [x] Case-insensitive match applies to body content too
- [x] Full test suite passes (30/30)
