## Proposal
MCP `task_list` tool lacks a `search` parameter. CLI and Web UI both support `--search`/`?q=` with title+body search (including heading exclusion via `stripHeadings()`). MCP is the primary interface for AI agents using quay, yet it has no search capability — closing CB-014 (partial). An AI agent using quay via MCP cannot narrow a large task list by keyword; it must retrieve all tasks and filter in-context.

## Plan
1. Add `search` parameter to `task_list` tool schema in `packages/quay/src/mcp-server.js` (alongside existing `status`, `label`, `prefix`).
2. Inline a `stripHeadings()` helper function in mcp-server.js (do NOT import from serve.js or bin/quay.js — separate entry points; inline a copy).
3. In the handler, after existing prefix/status/label filters, apply: `const sq = args.search ? args.search.toLowerCase() : null; if (sq) tasks = tasks.filter(t => (t.title + " " + stripHeadings(t.body || "")).toLowerCase().includes(sq));`
4. Update tool description to mention search capability with heading exclusion.
5. Add tests in `packages/quay/test/mcp-server.test.mjs` Block 14:
   - `task_list` with `search: "toggle"` returns only tasks with "toggle" in title/body.
   - `task_list` with `search: "Proposal"` does NOT return tasks whose body only has "## Proposal" heading (heading exclusion works).
   - `task_list` with no `search` param behaves as before (no regression).
   - `listTools()` schema includes 'search' property on task_list.
