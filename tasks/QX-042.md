## Proposal

Two pagination contract edge cases identified by G3 PASS-WITH-NOTES (iteration 8) have no regression protection:

1. `totalPages=0` when `total=0` — `Math.ceil(0/50) = 0`. Some consumers expect `totalPages=1` for empty sets. Current behavior is deterministic but not test-locked.
2. `pageSize=0` clamping (`Math.max(1, ...)` → 1) and `pageSize>200` clamping (`Math.min(200, ...)` → 200) are correct but not regression-protected.

Fix option A: keep `totalPages=0` for empty results (document it as correct) and add tests that pin the behavior so regression is caught if it changes.
Fix option B: normalize `totalPages = Math.max(1, Math.ceil(total/size))` for empty sets.

Decision: Option A (pin current behavior). The `totalPages=0` result is self-consistent with `total=0` and `tasks=[]` — the API contract states "total pages needed to represent the result set," and 0 pages are needed for 0 tasks. Changing behavior would be a breaking change; documenting and locking is safer.

Note on pageSize=0: `parseInt(0) || 50 = 50` (0 is falsy), so pageSize=0 actually returns the default 50, not 1. Tests document this actual behavior.

Closes SH-004 (minor).
