## Proposal

Three mobile UX gaps addressable as a single CSS/HTML change cluster:

- **UQ-030**: Search form appears below the label nav wall (46+ labels) on mobile 375px. Users must scroll past the entire label nav to reach the search input. Fix: move search form HTML before label nav, OR use CSS `order` on a flex-column container.
- **UQ-006**: Label filter is a flat inline list of 25+ items that wraps to many lines on mobile. Already truncated at 25 + `<details>` overflow (QX-034), but the visible 25 still create a wall. Fix: CSS `overflow-x: auto` on a scrollable inline strip at mobile, OR add a `max-height` + `overflow-y` on the label nav container.
- **UQ-007**: Table overflow on mobile — already handled by `table { display: block; overflow-x: auto }` and hiding `col-role`, `col-labels`, `col-updated` on mobile (QX-012, QX-017). Verify and close as already-resolved.

Implementation:
1. Reorder HTML: move `searchForm` block before `labelNav` block in the list-page HTML (simplest fix for UQ-030)
2. Wrap label nav in a `<div class="label-nav-wrap">` with CSS `overflow-x: auto; white-space: nowrap` so it scrolls horizontally at 375px rather than wrapping to a wall (UQ-006)
3. Add test assertions to verify search form appears before label nav in response HTML
4. Confirm UQ-007 already resolved; close in gap-list

## Plan

1. In `serve.js` list-page HTML template: move `${searchForm}` above `${labelNav ? ...}`
2. Add `.label-nav-wrap` CSS class: `overflow-x: auto; white-space: nowrap; padding-bottom: 0.2rem`
3. Wrap the label nav in `<div class="label-nav-wrap">` in the HTML template
4. Add test: verify search form `<input name="q"` appears before `<div class="label-nav-wrap">` in response body
5. Run full test suite (30/30)
