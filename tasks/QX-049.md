## Summary

The `pageNav` element (iteration-8 pagination UI) renders "Page 1 of 1 (N tasks)" when totalPages === 1. This is redundant — users can already see the task count in the table. The searchResultBanner (QX-046) already correctly uses `totalPages > 1` as its condition; pageNav's else branch lacks the same guard.

## Fix

Change line 673 of serve.js:
- Before: `... : html\`<p class="meta">Page 1 of ${totalPages} (${totalTasks} tasks)</p>\``
- After: `... : ""`

When totalPages === 1, pageNav should be the empty string (no element rendered).

## Acceptance Criteria

- [ ] With results spanning multiple pages (totalPages > 1): page nav still renders with Previous/Next links and "Page X of Y (N tasks)"
- [ ] With results fitting on one page (totalPages === 1): NO "Page 1 of 1" element rendered anywhere
- [ ] Regression test in serve.test.mjs confirms single-page result has no "Page 1 of 1" text
- [ ] All existing tests still pass
