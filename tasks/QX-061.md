# QX-061: CB-006 — Configurable page size

## Author
native (iteration 16 executor)

## Execute
native (iteration 16 executor)

## Gate
G3 pending (orchestrator dispatch)

## Problem
Page size was hardcoded at 20 in Web UI (QW-007). CLI had no pagination at all — `task list` returned all results. Users with large task sets could not control how many tasks they see at once.

## Implementation

### CLI (`bin/quay.js`):
- `--page-size <N>` option: limits non-JSON output to N rows
- When truncated, shows `# showing N of M tasks (use --page-size to adjust)` hint
- JSON output always returns full result set (unaffected by --page-size)
- Documented in `printHelp()` under "Options for task list"

### Web UI (`src/serve.js`):
- `?pageSize=N` query parameter (default 20, min 1, max 200)
- `pageSizeFilter` const derived from PAGE_SIZE, placed before `buildHref` call to avoid temporal dead zone
- `buildHref()` updated with `pszOverride` optional 7th parameter for pageSizeNav links
- "Per page:" nav rendered with 10/20/50/100 options; active size shown as bold text
- All nav links (filter/sort/label/page) carry active `pageSize` automatically via closure

## Tests
- CLI section 24 (`cli.test.mjs`): --page-size 2 with 5 tasks → 2 rows + hint; --page-size 10 → all 5 rows; --json unaffected
- Web UI (`serve.test.mjs`): ?pageSize=5 with 8 tasks → 5 rows page 1, 3 rows page 2; "Per page:" nav present
