# QX-065: TST-003/TST-004 Test precision improvements

## Gaps closed
- TST-003: `serve.test.mjs` TST-001 assertion used full-body substring match for `pageSize=3` — weakly anchored. Could pass if `pageSize=3` appeared anywhere in the body (pageSizeNav links) rather than specifically in a page navigation href.
- TST-004: No test for Previous link carrying `pageSize` when navigating backward through pages.

## Acceptance Criteria

- [x] TST-001 assertion in the QX-061 block replaced with a href-anchored assertion that extracts the "Next" link href (containing `page=2`) and asserts `pageSize=3` appears in that href specifically
- [x] New TST-004 block: fetch `/?pageSize=3&page=2`, extract Previous link href, assert `pageSize=3` appears in that href
- [x] All 12 test suites still pass (0 failures)

## Implementation

Modified `packages/quay/test/serve.test.mjs` in iteration-18 worktree:

### TST-003 (tightening TST-001):
Changed from:
```js
assert(body.includes("pageSize=3"), ...)
```
To:
```js
const nextLinkMatch = body.match(/href="([^"]*page=2[^"]*)"/);
const nextHref = nextLinkMatch ? nextLinkMatch[1] : "";
assert(nextHref.includes("pageSize=3"), ...)
```
This ensures `pageSize=3` appears specifically in the `href` attribute of the link that navigates to page 2 (the "Next" link), not just anywhere in the body.

### TST-004 (new test):
```js
const res = await fetch(`http://127.0.0.1:${qx61Port}/?pageSize=3&page=2`);
// ... assert prevHref.includes("pageSize=3")
```
Extracts the Previous link href on page 2 and asserts `pageSize=3` is preserved.

`buildHref` with `pg=(safePage-1)=1` omits the `page` param (guard: `pg > 1`), so Previous link is `/?pageSize=3` (pageSize=3 != default 20, included).
