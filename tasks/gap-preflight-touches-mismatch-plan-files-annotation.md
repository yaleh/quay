## Proposal

Make `preflightTouchesMismatch`'s plan-files path extraction (in
`experiments/quay-perpetual-stream/scripts/prepare-admission-check.ts`, `+ plugin/scripts/` mirror)
robust to the non-deterministic PlanAuthor habit of appending parenthetical annotations to a Plan
stage's `- Files:` line — e.g. `wiring-coverage-check.ts (read-only input: tasks/DIR-126-D.md)`,
`a.test.mjs, b.test.mjs (both run, neither modified)`, `sync-vendor.sh (all read-only)`.

Two defects, both fixed:

1. **Comma-inside-annotation shredding.** The extractor split each `- Files:` value on every comma
   (`.split(",")`), so an annotation containing a comma — `(both run, neither modified)` — was
   shredded into bogus path tokens (`(both run`, `neither modified)`) that can never match a
   `## Touches` entry. Fixed with a paren-depth-aware splitter (`_splitTopLevelCommas`) that splits
   only on commas at paren-depth 0.
2. **Residual `(...)` suffix.** Even without internal commas, the trailing annotation rode along
   inside the path token, so `sync-vendor.sh (all read-only)` never string-/glob-matched the bare
   `sync-vendor.sh` in `## Touches`. Fixed by stripping ONE trailing ` (…)` annotation in the shared
   `_stripWrappingBacktick` helper (applied to both the Touches side and the plan side).

Neither change makes matching over-permissive: repo paths never contain parentheses, and the
stripped path must still exactly/glob-match a declared `## Touches` entry via the unchanged
`_globCoversPath` predicate — only the cosmetic annotation is removed before matching.

## Finding

Discovered 2026-07-30 when M205 (gap-wiring-coverage-check-whose-own-and-bold-marker-splitting) and
M206 (gap-prepare-milestone-split-decision-no-finality) both passed ProposalReview via
`resumeFromAdjudicatedProposal:true` and wrote real Plans, then both failed plan-level Preflight on
`preflight-touches-mismatch` citing annotated path fragments (`neither modified)`,
`wiring-coverage-check.ts (read-only input: tasks/DIR-126-D.md)`, etc.). The annotated `- Files:`
lines are regenerated by the PlanAuthor on every dispatch (it unconditionally rewrites the Plan), so
the mismatch was unfixable by re-dispatch — editing the Plan directly is futile. Reproduced live via
`prepare-admission-check.ts --preflight-plan` against both Plans before and after the fix:
before → `ok:false` (blocking touches-mismatch on annotated fragments); after → `ok:true` (only the
non-blocking `preflight-ambiguous-invalid-plan-command` remains). All 61 existing
`prepare-admission-check.test.mjs` tests still pass.

## Requested action

1. Add `_splitTopLevelCommas` (paren-depth-aware comma splitter) and apply it to the plan-files
   branch of `preflightTouchesMismatch`.
2. Extend `_stripWrappingBacktick` to also strip ONE trailing ` (…)` annotation.
3. Add regression fixtures: (a) a `- Files:` line with a comma-containing annotation
   (`a.test.mjs, b.test.mjs (both run, neither modified)`) where both paths ARE in `## Touches` → no
   mismatch (RED before fix, GREEN after); (b) a `- Files:` line with a trailing annotation on a path
   NOT in `## Touches` → still correctly flagged (proves the fix is not over-permissive).
